# 物語 プロジェクト説明

「物語」は、本の世界にもう一人の登場人物として入り、声で人物と話し、自分の行動を物語に残す 3D ウェブアプリです。18 歳以上の、物語や登場人物との対話を楽しみたい読者を対象としています。書斎の本棚から作品を選ぶ複数作品向けの構成で、現在遊べる作品は太宰治の『走れメロス』一冊です。

## 課題の新規性と解決策の有効性

文化庁の令和 5 年度調査では、全国の 16 歳以上の回答者の 62.6% が、月に本を読まないと答えました。一方、その層の 75.3% は、本以外の文字情報をほぼ毎日読んでいます。2024 年 1〜3 月に実施された調査で、読書冊数には電子書籍を含み、雑誌・漫画は含みません。この結果を「文字を読むことへの関心がない」とは捉えず、デジタルな入口から文学に接する余地に着目しています。[文化庁 令和 5 年度 国語に関する世論調査 結果の概要 23〜24 頁](https://www.bunka.go.jp/koho_hodo_oshirase/hodohappyo/pdf/94111701_02.pdf)

政策面では、UNESCO の 2024 年文化芸術教育枠組みが、年齢を問わない生涯学習と、デジタル空間を含む文化への参加を重視しています。文学も文化表現の一つに位置づけ、技術の活用にはリスクへの対応と、思考・創造性を支える責任ある利用を求めています。本作はこの背景を踏まえ、成人が人物の立場や自分の選択を振り返る、参加型の文学体験を目指します。文化庁の数字は読書行動の実態、UNESCO の枠組みは政策の方向を示す資料であり、本作の教育効果の証明や UNESCO による認証ではありません。[UNESCO Framework for Culture and Arts Education 2024 3〜6 頁](https://www.unesco.org/sites/default/files/medias/fichiers/2024/02/WCCAE_UNESCO%20Framework_EN_0.pdf)

物語を読んで「自分がその場にいたら、どう声をかけただろう」と考えることがあります。本作では、その想像を、人物との会話と世界の中での行動につなげます。目指しているのは、話しかけた相手の返事だけでなく、助けたことや交わした約束が、その後の状況に残る体験です。

人物があなたとの出来事を記憶し、関係を次の対話や行動に反映する仕組みがあります。助けたことや守った約束が、そのプレイでの人物の頼みごとや判断につながります。すべての発言を必ず永久に覚える仕組みではなく、保存された記憶を記憶帳で確認できます。最後には、世界、登場人物それぞれ、そしてあなた自身という三層の結末を扱います。誰と関わり、何を残したかを、自分の体験として振り返れます。

プレイヤーは原作の主人公に置き換わるのではなく、旅人などの立場で物語に参加します。原作を読んでいなくても、選書画面で舞台と人物の基本的な関係を確認し、出会った人に事情を聞きながら行動を選べます。導入には結末を含めず、原作どおりの行動を正解として求めません。

社会的な価値として目指すのは、文学への新しい入口と、選択を振り返る体験です。成人の参加型の文学理解として、次の機会をつくります。

- **人物の立場から考える**：同じ出来事でも、人物によって知っていることや大切にするものが異なります。対話を通じ、その判断の理由を考えます。
- **約束と結果を振り返る**：自分が何を申し出て、何が成立し、誰に影響したかを記録からたどります。選択を道徳的な点数にせず、別の選択肢も考えられる体験を目指します。
- **未読作品にも接する**：原作の暗記や専用機器を求めず、ブラウザと短い会話から入り、関心を持った人物や場面を原作で読み直す入口にします。

原作と AI が生成した体験は区別し、生成内容を原作の正しい解釈として教えるものではありません。読書量、理解力、共感性を高める効果はまだ実証していません。今後は成人の既読・未読の両群で、体験後に複数人物の判断を具体例で説明できるか、自分の選択と結果の関係を説明できるか、実際に原作を読み始めたかを確かめます。楽しさの自己評価と、理解や読書行動の変化を分け、生成内容を原作と混同していないかも確認します。

## 自律性・エージェントらしさ

人物との音声会話には Google の Gemini Live、文字入力への人物の応答には Gemini を使います。人物ごとに口調や目的を持たせ、その時点で知っている事実と、自分が見聞きしたことを会話の文脈に渡します。人物が人間を信じるかどうかという信念と、他人の内心を実際に知っていることは区別します。

人物の発言だけで世界の出来事を確定させることはありません。Claude を使う叙事者が、会話から行動や約束の候補を取り出し、世界モデルの条件と照合します。人物の所在、時間、出来事の前提、変えてはいけない条件などを確認し、成立した変化をイベントと世界状態に保存します。難しい行動は、拒否や部分的な実行になることもあります。口頭で賛成したことと、実際に行動や約束が成立したことを、記録から区別できるようにしています。

叙事者は、場面の移り変わりなどに合わせて、不在の人物の行動や約束の履行も扱います。人物の目標を物語の進行に結びつけながら、状態を書き込む経路を検証処理に集約しています。プレイヤーは連鎖反応マップの「なぜこうなった？」や記憶帳から、自分の体験を振り返れます。

## 実装品質と拡張性

### 書斎から続けられる体験

書斎では本を選び、保存された途中のプレイを再開できます。進行状況はサーバーに保存され、利用者ごとに分離されます。回想録に並ぶのは、その利用者が実際に終え、結末が保存されたプレイです。まだ終わっていない物語を、完成した結末として表示しません。

作品と世界モデルのバージョンを分けて扱うため、今後ほかの本を追加するときも、既存のプレイを別の作品に置き換えずに管理できます。現在は一本目の内容を実装した段階であり、第二作の収録をうたうものではありません。

### Google Cloud とモデルの役割

| 技術 | このアプリでの役割 |
| --- | --- |
| Cloud Run | ウェブ画面、REST、WebSocket を提供するゲートウェイと、叙事者サービスを実行します。 |
| Gemini Live / Gemini | Live が人物とのリアルタイム音声対話を、Gemini が文字入力への人物の応答を担当します。 |
| Model Armor | 入力とモデル出力の安全確認に使います。作品内の知識や因果の検証とは役割を分けています。 |
| Claude | 叙事者の候補抽出、文章生成、判断を伴う処理などに使います。 |
| Cloud SQL for PostgreSQL | イベント、世界状態、記憶、約束、進行状況と結末を保存します。 |
| Secret Manager | サービスが使う秘密情報を管理します。 |

フロントエンドは React と Three.js で構成し、スマートフォンのブラウザでも操作できるようにしています。字幕は手動で折りたためるため、文字が場面を覆うときも、会話の内容を消さずに移動できます。

### 公開範囲と現在の検証状況

製品の説明とデモは公開しますが、アプリの利用にはサイトのパスワードと招待コードが必要です。人物・場面の素材、API、WebSocket もアクセス制御の対象です。認証情報は公開説明や動画に含めません。

クラウド環境では、認証、場面の読み込み、開局、WebSocket の接続と、未認証アクセスの拒否を確認しています。人物の知識範囲や誤った前提への応答も有限の実モデル回帰で確認しましたが、解釈が分かれる例は残っています。限られた実モデル試行では、返答の欠落と結末のテンプレートへの切り替えも観測しており、応答品質は改善課題です。200 局の全量評価と最新状態の全 CI 完了は、今回の成果に含めていません。

音声は逐次再生されるため、一部の安全確認や出力監視は、発声の後に完了します。検査済みの音声だけを出す方式ではなく、事後の検出だけで既に聞こえた内容を取り消すこともできません。この制約を、世界状態の更新前に行う因果の検証とは分けて評価しています。

デモでは、人物の実際の返答と保存された結果を確認できます。申し出を拒む返答もあり、特定の言葉で必ず約束や行動が成立するとは限りません。
