## Goal / 目標

When done:

完了後：

1. After a disconnect (going to the background, switching networks, locking the screen), the player **returns to the same moment of the same game within 5 seconds** and keeps talking with the same character: after reconnecting, tapping the character (`focus`) gives `session_ready` immediately, and the character remembers where the conversation left off.
   切断（バックグラウンドへの移動、ネットワークの切り替え、画面ロック）の後、**5 秒以内に同じプレイの同じ時点に戻り**、同じ人物と話し続けられる：再接続後に人物をタップすれば（`focus`）即座に `session_ready` になり、人物はさっきどこまで話したかを覚えている。
2. Returning within 30 seconds of the disconnect keeps using the **same Live session** (no rebuild, no extra cost, the character's context unchanged); after more than 30 seconds but within 10 minutes, the new session carries the pre-disconnect 「さっきまでの会話」; any longer (resuming on another day) carries only the situation description.
   切断から 30 秒以内に戻れば、**同じ Live セッション**を使い続ける（再構築なし、余分な費用なし、人物の文脈はそのまま）。30 秒を超えて 10 分以内なら、新しいセッションに切断前の「さっきまでの会話」を持たせる。それより長い場合（別の日に再開）は状況説明だけを持たせる。
3. The same applies when the same game is opened in another tab (`4009`): the new connection directly takes over the old connection's sessions and recent conversation.
   同じプレイを別のタブで開いた場合（`4009`）も同じ：新しい接続が古い接続のセッションと最近の会話をそのまま引き継ぐ。
4. How long resuming took and how many sessions were taken over are visible in Trace (without the actual words), for PRD 7.1 "resume" and R1's Q1.
   再開にかかった時間と引き継いだセッション数を Trace で見られる（原文は記録しない）。PRD 7.1 の「再開」と R1 の Q1 に使う。

Already in place (B-0, B-4, #106; this card does not redo them): `hello { lastSeq }` resends missed `commit`s; `welcome.lastTurn` (`settled` / `pending` / `lost`); `welcome.pending`'s `confirm` (with `remainingSec`), `actEnd`, `arrival`; the turn cut off by a disconnect is first written as `lost` or handed over as usual, and only then is `welcome` returned.

既にあるもの（B-0、B-4、#106。このカードでは作り直さない）：`hello { lastSeq }` で取りこぼした `commit` を再送する。`welcome.lastTurn`（`settled` / `pending` / `lost`）。`welcome.pending` の `confirm`（`remainingSec` 付き）、`actEnd`、`arrival`。切断時のターンは、まず `lost` と書くか通常どおり渡してから `welcome` を返す。

## Scope / 範囲

### In scope / やること

**1. Park the voice state on disconnect** (`gateway/voice.py`)

**1. 切断時に音声まわりの状態を預かる**（`gateway/voice.py`）

- When the connection drops (or is kicked out by a new connection for the same game): this connection's Live sessions, each character's text for the last few turns (`recent`), and the situation items sent into each session are parked as a whole in gateway memory (`Gateway.parked[playthrough]`); **the sessions are not closed**.
  接続が切れた（または同じプレイの新しい接続に追い出された）とき：この接続の Live セッション、人物ごとの直近数ターンの文字（`recent`）、各セッションに送った状況の項目を、まとめてゲートウェイのメモリに預ける（`Gateway.parked[playthrough]`）。**セッションは閉じない**。
- Not parked: the session of the character who was mid-turn at the disconnect and recorded as `lost` (the character heard a turn the narrator never processed; as with retraction, close it and rebuild on return); sessions already dead; sessions being opened or swapped (cancelled).
  預けないもの：切断時に話している途中で `lost` と記録された人物のセッション（ナレーターが処理していないターンを人物が聞いてしまっているので、取り消しと同じ理由で閉じ、戻ったときに再構築する）。既に死んでいるセッション。開いている途中、切り替え中のもの（取り消す）。
- A turn that was "finished speaking and still being handed to the narrator" at the disconnect is handed over as usual, and once handed over its text goes into the parked `recent` as usual (the same copy).
  切断時に「話し終えて、ナレーターに渡している最中」だったターンは通常どおり渡し、渡し終えた文字は通常どおり預けた `recent`（同じもの）に入る。
- Parked sessions that nobody picks up within **30 seconds** (`RESUME_HOLD_S`, shortened per `ZJ_SPEED`) are closed; the recent conversation is kept for **10 minutes** (`RECENT_HOLD_S`) and then dropped. Memory only; not persisted to the database and not in Trace.
  預けたセッションは **30 秒**（`RESUME_HOLD_S`、`ZJ_SPEED` に従って短縮）誰も引き取らなければ閉じる。最近の会話は **10 分**（`RECENT_HOLD_S`）保持してから捨てる。メモリ上だけで、DB には保存せず、Trace にも入れない。
- If Live sends GoAway or drops while parked: ignore it; only sessions still alive at takeover are used.
  預けている間に Live が GoAway を送ったり切れたりしても放っておく。引き継ぐときに生きているものだけを使う。

**2. Take over on reconnect** (`hello` in `ws.py`)

**2. 再接続時に引き継ぐ**（`ws.py` の `hello`）

- `hello` first waits, per #106, for the turn cut off by the disconnect to be written, then takes out what was parked for this game and hands it to the new connection: sessions (the live ones), the recent conversation, the situation items. Sessions with no `focus` are closed after 2 minutes under the idle rule.
  `hello` はまず #106 に従って切断時のターンが書き終わるのを待ち、それからこのプレイで預けたものを取り出して新しい接続に渡す：セッション（生きているもの）、最近の会話、状況の項目。`focus` のないセッションはアイドル規則に従って 2 分で閉じる。
- After reconnecting, the frontend sends `focus` again per section 4: if the session is still there, `session_ready` immediately (as with a warm-up hit, no `session_preparing`); if the session has already been closed, open one now per B-10 and push `session_preparing { reason: "reconnect" }` (contract 3.3), with the parked recent conversation in the system instructions. The first connection after the game starts (nothing said yet in this game) does not count as resuming; it uses `switch` as usual.
  再接続後、フロントエンドは第 4 節に従って `focus` し直す：セッションがまだあれば即座に `session_ready`（ウォームアップが当たったときと同じで、`session_preparing` はない）。セッションが既に閉じられていれば B-10 に従って今すぐ開き、`session_preparing { reason: "reconnect" }`（契約 3.3）を送る。システム指示には預けた最近の会話を入れる。プレイ開始後の最初の接続（このプレイでまだ何も話していない）は再開とみなさず、通常どおり `switch`。
- If the situation has changed at takeover (beats that came due and were settled during the disconnect), send a 「【状況の変化】」 section per B-10.
  引き継ぐときに状況が変わっていれば（切断中に時刻が来て決着したビート）、B-10 に従って「【状況の変化】」を 1 節送る。
- `4009`: if the old connection is still there when the new one comes in, park the old connection's state first, then close the old connection, so the new connection's `hello` is guaranteed to get it.
  `4009`：新しい接続が来たときに古い接続がまだ残っていれば、先に古い接続の状態を預けてから古い接続を閉じる。こうすれば新しい接続の `hello` は必ずそれを受け取れる。

**3. When to drop what is parked**

**3. 預けたものをいつ捨てるか**

- When 30 seconds or 10 minutes are up (above).
  30 秒、10 分の期限が来たとき（上記）。
- Service shutdown (`goaway` + `1012`): close all parked sessions (after switching instances they are rebuilt from the situation description; before the first deployment for reviewers there is only one instance).
  サービス停止（`goaway` + `1012`）：預けたセッションをすべて閉じる（インスタンスが替わった後は状況説明から再構築する。最初のレビュー用デプロイまではインスタンスは 1 つだけ）。
- Deleting this game, or deleting the memory book (記憶帳) (B-13, backend 4): call `Gateway.forget(playthrough)`, which closes the sessions and drops the recent conversation. This card provides this method and its tests; B-13 wires it up.
  このプレイの削除、記憶帳の削除（B-13、バックエンド 4）：`Gateway.forget(playthrough)` を呼び、セッションを閉じて最近の会話を捨てる。このカードはこのメソッドとテストを用意し、B-13 がつなぐ。
- Retraction (B-4) as before: retracting a pre-disconnect turn after reconnecting removes it from the recent conversation and rebuilds the session.
  取り消し（B-4）はこれまでどおり：再接続後に切断前のターンを取り消すと、最近の会話からそれを消し、セッションを再構築する。

**4. Trace** (data-design section 8, without the actual words)

**4. Trace**（data-design 第 8 節。原文は記録しない）

- `gateway.resume`: one entry at `hello`: `gap_ms` (from the disconnect to `hello`), `carried` (how many sessions were taken over), `recent_turns` (how many turns of recent conversation were brought back), `kind` (`carried`: a session was picked up / `recent`: only the recent conversation / `cold`: nothing).
  `gateway.resume`：`hello` のときに 1 件記録する：`gap_ms`（切断から `hello` まで）、`carried`（引き継いだセッション数）、`recent_turns`（持ち帰った最近の会話のターン数）、`kind`（`carried`：セッションを引き継げた / `recent`：最近の会話だけ / `cold`：何もない）。
- "Reconnect to able to speak" = from `hello` to the `session_ready` after `focus` is sent again; the frontend's `connection_restored.downMs` and `app_resumed.resumeMs` measure the player's side; the server records its part as `gateway.resume_ready`, separately from `live.session`: `ms`, `reused` (whether the session was picked up).
  「再接続から話せるようになるまで」= `hello` から、`focus` し直した後の `session_ready` まで。プレイヤー側はフロントエンドの `connection_restored.downMs`、`app_resumed.resumeMs` で測る。サーバー側のこの区間は `live.session` とは別に `gateway.resume_ready` として記録する：`ms`、`reused`（セッションを引き継げたか）。

**5. Tests** (all offline, fake Live)

**5. テスト**（すべてオフライン、偽 Live）

- Reconnect within 30 seconds after a disconnect and `focus` the same character: `session_ready` arrives immediately, no new session is opened, no `session_preparing`; the next turn proceeds as usual; the session's turn count continues (the 8th turn still triggers a rebuild).
  切断後 30 秒以内に再接続し、同じ人物に `focus`：`session_ready` がすぐ届き、新しいセッションは開かれず、`session_preparing` もない。続けて 1 ターン話すのも通常どおり。セッションのターン数は引き続き数える（8 ターン目ではいつもどおり再構築）。
- Parked for more than 30 seconds: the session is closed; reconnect and `focus` opens one now, and the system instructions contain the pre-disconnect recent conversation.
  30 秒を超えて預けた場合：セッションは閉じられている。再接続して `focus` すると今すぐ開き、システム指示に切断前の最近の会話が入っている。
- Disconnected mid-turn (`lost`): that character's session is not parked (it is closed), is rebuilt after reconnecting, and the recent conversation does not contain that turn.
  話している途中で切断（`lost`）：その人物のセッションは預けられず（閉じられる）、再接続後に再構築され、最近の会話にそのターンは入っていない。
- `4009`: the connection in the new tab takes over the old connection's sessions, and the sessions are not closed after the old connection closes.
  `4009`：新しいタブの接続が古い接続のセッションを引き継ぎ、古い接続が閉じた後もセッションは閉じられない。
- `Gateway.forget` and service shutdown: parked sessions are closed and the recent conversation is gone.
  `Gateway.forget`、サービス停止：預けたセッションは閉じられ、最近の会話もなくなる。
- Time from reconnect to `session_ready` (`hello` → `focus` → `session_ready`) is < 1 second under fake Live; adding the frontend's 1–2 second backoff, it is within 5 seconds.
  再接続から `session_ready` までの時間（`hello` → `focus` → `session_ready`）は偽 Live で < 1 秒。フロントエンドの 1〜2 秒のバックオフを足しても 5 秒以内。
- Trace has `gateway.resume` and no actual words.
  Trace に `gateway.resume` があり、原文はない。

### Out of scope / やらないこと

- Carrying the recent conversation across when switching instances (multi-instance, cross-process parking): the first deployment for reviewers has only one instance; when multiple instances are needed, open a separate card, and the recent conversation still isn't persisted (the memory-only rule stays).
  インスタンス切り替え時に最近の会話を持ち越すこと（複数インスタンス、プロセスをまたいだ預かり）：最初のレビュー用デプロイはインスタンス 1 つだけ。複数インスタンスが必要になったら別のカードを立てる。最近の会話も DB には保存しない（メモリ上だけという取り決めは変えない）。
- `welcome.pending`'s `safetyPause` (the safety card), `approach` (the card for characters walking over), `reveal` (key moments): each is done by its own card; this card does not change the shape of `pending`.
  `welcome.pending` の `safetyPause`（安全性のカード）、`approach`（人物が歩いてくるカード）、`reveal`（重要な瞬間）：それぞれのカードでやる。このカードは `pending` の形を変えない。
- Daily voice minutes (`welcome.voice.minutesLeftToday`): the budget card (S-019).
  1 日の音声分数（`welcome.voice.minutesLeftToday`）：予算のカード（S-019）。
- The frontend's `ResumeGate`, Service Worker, telemetry: frontend cards.
  フロントエンドの `ResumeGate`、Service Worker、テレメトリー：フロントエンドのカード。

## Prohibited / 禁止事項

- No Live session resumption (5.4); parking lives only in gateway memory: not persisted, not logged, not in Trace.
  Live のセッション再開は使わない（5.4）。預かりはゲートウェイのメモリの中だけで、DB に保存せず、ログにも書かず、Trace にも入れない。
- Logs and Trace never carry the player's or characters' words.
  ログと Trace にプレイヤーや人物の言葉を入れない。
