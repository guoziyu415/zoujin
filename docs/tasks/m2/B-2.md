## 目标

做完以后：

1. 一轮对话（语音的转写，或一条 `text`）走完 backend-design 2.4 的流水线：分流 → 提取 → 确定性规则 → 模型检查 → 改写、降级或拒绝 → 单事务提交。B-0 那张「只查 W-1 的 `check_effects`、按表暂记到 R 规则」的对应表换成 R1〜R7 本体。
2. 评测入口的文字模式能用：`say` 走整条流水线，`check` 跑第 3、4 步（S-2 靠它），`advance`、`state()`、`events()` 照旧；切片版世界模型（`ZJ_WORLD`）上也判得对。
3. 真模型的客户端写好，只在 zg 的 Mac 上跑（G-7）：截止时间和重发、账本和上限、第一个 429 就停、录回放。项目里的线程和 CI 仍然只用假模型和回放。
4. S-2 的运行脚本和报告写好：公开的 10 条在 CI 里用假模型和回放跑通；Mac 上用真模型调自检的提示；提示定稿后，数据用同一个脚本在 Mac 上跑 50 条留出集。

## 范围

### 做

**1. 流水线**（`narrator/`，接在 B-0 的领任务和单事务提交上）

- **第 0 步的接口**：轮次带筛查标记（`injection`、`pii`，以后由 Model Armor 填），第 3 步的 R6 读它。本卡的网关只填空标记，测试和 fixture 可以塞标记。自伤分类器 v2 和 Model Armor 本身是安全卡。
- **第 1 步 分流**（`triage`，flash-lite）：这一轮有没有可能改变世界、形成约定、说出新的即兴设定。没有 → 只写一条推进时钟的 `say` 事件（`effects` 为空，契约第 3 节），直接到第 7 步。
- **第 2 步 提取**（`extract`，flash，思考 LOW，结构化输出）：
  - 输入：世界模型前缀（放在最前、内容不变，吃隐式缓存）、世界状态、这一轮（原话只放在 `<utterance speaker="…">` 数据字段里）。
  - 输出：0〜3 个候选事件（契约 Event 的子集，`actor` 按契约第 0 节；约定和即兴设定是其中的 `promise`、`improv` 效果）和每个候选要不要确认。
  - 输出过 Schema；不过 Schema 算这次调用失败，按下面「时限」的规则重发一次。
- **第 3 步 确定性规则**（`narrator/rules.py`，不调模型）：R1、R2、R3、R4、R7，加 R6 的规则部分。
  - **`judge()` 能拦住的，第 3 步都要拦住**：判法至少覆盖 `evals/s2/README.md`「确定性规则的最简判法」那张表。
  - 另加 backend-design 2.4 写的：R3 对按排程走的人物看排程，`places.adjacent` 只量玩家的移动和排程以外的 `relocate`；R6 的规则部分对每条要提交的 `summary` 和即兴设定都查（电话、邮箱、地址的模式；第 0 步的标记；和玩家原话连续 8 字相同）。
  - 世界规则（条件求值、应用效果、排程、`valueRequires`、`OCCURRED`）只从 W-1 拿，叙事者里不另写一份。判法要用、W-1 还没有的原语（例：按 `adjacent` 的最短路程、某人此刻知不知道某条事实），先问数据要不要进 W-1：进的话数据加、后端评审；不进就写在 `rules.py`，和 `judge()` 对照测试。
  - 同一轮的几个候选按顺序判，前面通过的先试算进状态（B-0 已是这样）。
- **第 4 步 模型检查**（`check`，flash，思考 MEDIUM）：
  - 范围按 backend-design 2.4：过了第 3 步、`effects` 不为空的全部候选；一轮的候选合在一次调用里。
  - 判 R1 只写在文字里的锚点矛盾、R5 人设与动机、R6 规则部分以外的内容。每条规则给 `pass` / `fail` 和一句日语理由。
- **第 5 步 改写、降级或拒绝**（`rewrite`，flash）：
  - 第 3 或第 4 步不过 → 带着失败的规则和理由改写，回到第 3 步，最多改写 2 次（`attempts` ≤ 3）。
  - 还不过 → 能降级就降级成小影响（`downgraded`，例：「说服花婿」→「花婿开始犹豫」），否则拒绝（`rejected`，日志里那条 `effects` 为空，契约第 3 节）。
  - `check.reason` 写一句日语。写进人物局势说明的圆回提示是局势说明那张卡，从这里读。
- **第 6 步 意图确认**不在本卡（后续卡，和网关的 `confirm` 一起做）。本卡里，提取标了要确认、又是 2.4 第 6 步那类事件（让节拍 `prevented` / `altered`，改变人质或玩家的身份处境）的候选，按「没确认 = 不是」处理：丢弃、不写事件、不花时间（和 30 秒没答一样）。Trace 和 `playthrough_metrics` 记一次。
- **第 7 步 提交**：照 B-0 的单事务提交。`lastSeq` 变了就从第 3 步重来，不重新提取。作废窗口（`turn_complete` 后 3 秒）和作废一起是后续卡，本卡提交前不等。
- **时限**（backend-design 2.4）：
  - 提取、检查、改写每次调用 15 秒，分流 5 秒〔暂定，S-5 定〕。
  - 超时就取消、立刻重发一次。
  - 第二次还超时：分流超时当作「可能」，继续提取；其余的，这一轮只提交时钟事件，候选丢弃，`playthrough_metrics` 记一次。
- **文字模式的人物回答**（`reply`，flash）：`text` 轮和 `eval_api.say` 要人物的文字回答。
  - 本卡用 2.3 的第 1、2、4 段（固定规则、按此刻裁剪的人设、玩家是谁），加一个最小的局势说明（时刻、地点、在场的人、此刻知道的事实）。
  - 完整的局势说明、记忆、圆回提示、本局问过的问题是后续卡。
  - 语音轮的人物回答仍是假 Live。

**2. 不在场的人物和切片**

- 此刻 `absent` 的人物不算在场，例如切片里石工房的セリヌンティウス和フィロストラトス（S-077 ⑩）。
  - 要和他们在同一地点才成立的事件，第 3 步按 R7 判不过。
  - 快照里照样列出，`activity: "absent"`、`talkable: false`。
- S-077 ② 玩家不会被抓：切片世界模型里 `var.player.custody` 没有 `arrested` 这个值，第 3 步按值不合法否决（R7），叙事者不另写判断。本卡加一条测试。
- `ZJ_WORLD`（world.json 的绝对路径，E-0 的运行器这样设，`--slice` 时是切片版）B-0 已经接上（#26 按数据的评审加的）：开新局和 `eval_api.setup()` 用它，没设是完整草稿；已有的局按开局时锁定的版本。本卡只在切片版上补上面两条的测试。

**3. 模型的接口和三种实现**

- 提示类型 `triage`、`extract`、`check`、`rewrite`、`reply`。每种一个输出的 JSON Schema（后端内部，不进契约）和一个版本号（提示文本的哈希，B-0 已是）。提示里的例子自己写。
- `ZJ_MODEL` 认三个值：
  - `fake`（默认）：每种提示有确定的默认输出（分流 = 可能，提取 = 没有候选，检查 = 全过，改写 = 原样，回答 = 一句固定的话）。`fixtures/fake-text/` 按条件覆盖，也能注入延迟和错误，用来测时限、重发和 429。
  - `replay`：照 B-0。
  - `real`：Vertex AI 上的 Gemini，用 Mac 上 gcloud 登录的应用默认凭证，没有 API Key。
    - 项目 ID 和地区只从 Mac 的环境读，只在 `real` 时读，不进仓库、日志、Trace 和回放。
    - SDK 放进 `services/backend` 的可选依赖组 `real`。CI 装它只为类型检查和不联网的单元测试（换成假的传输层），从不调用。
- **账本**：真客户端每次调用前查账本、调用后记账。
  - Google 一本账，JSONL，每行 `kind`、`model`、`usage`、`costUsd`、时间。
  - 单项上限和总上限从命令行传入（`--max-item-usd`、`--max-google-usd`，写法同 E-0 的 live），没有默认值。到上限抛 `BudgetStop`，第一个 429 抛 `RateLimited`。
  - 花费 = 用量 × 价目，价目照 `docs/data/cost/pricing-2026-10-06.md` 写进配置。
  - Claude 那本账在数据的运行器里（评审员、AI 玩家），后端不碰。
- **录回放**：`real` 时设了 `ZJ_RECORD_REPLAYS=<目录>`，每次调用按 B-0 的回放格式存一行。
  - 只录合成输入（S-2 的条目、评测用例），不录真人玩家的话。
  - Mac 上录的回放经协调交回，后端提交进 `fixtures/model-replays/`。
- 串行调用。调用前打印预计花费和完整命令，不带 `--confirm` 就退出；开关用 E-0 live 的同一个环境变量 `ZJ_EVAL_LIVE=1`（只在 Mac 上设）。

**4. 评测入口文字模式**（`eval_api`，api-contract 第 7 节）

- `setup`：照 B-0（含 `ZJ_WORLD`）。`persona` + `seed` 仍抛 `EvalNotImplemented("persona")`（B-3）。
- `say(to, text)`：走上面整条流水线。返回人物的文字回答，和这一步的全部事件（含被否决的，带原本的 `effects` 和 `check`）。
- `check(candidate, turn, model_checks="scoped")`：跑第 3 步，再按 `model_checks` 跑第 4 步；不改写、不提交。
  - `rules` 里每条规则给 `pass` / `fail` / `skipped`；`scoped` 下没轮到模型的记 `skipped`。
  - `check.checker` 写规则版本，加检查提示的模型和版本（例：`rules@<版本>+gemini-3.8-flash/<提示版本>`）。
- `advance`、`state()`、`events()` 照 B-0。其余步骤照旧抛 `EvalNotImplemented`。

**5. S-2 运行脚本**（`uv run zoujin-s2 <标注集.jsonl> --out <目录>`）

- 读一份标注集（格式按 `evals/s2/README.md`），每条按 `setup` 起局，调 `check(…, model_checks="all")`，跑 `--runs` 次（默认 3）。
- 报告：
  - `report.json`：每条每次的判定、规则、理由、trace ID，和 `check` 的提示版本。
  - `report.md`：README「怎么跑、怎么算」里的全部数（一致率的最差一次和多数票、锚点漏检、规则一致、按 `stage` 分的误拒和漏判、三次不一样的条目）。
- `--resume`：中断后接着跑，不重复花钱。
- 没有默认的标注集路径，也不知道留出集放在哪：路径由跑的人给。

**6. Trace 和指标**

- Span 按 data-design 第 8 节：`narrator.extract`、`narrator.check` 每次尝试一个，带 `model`、`prompt_version`、`world_model_version`、`candidate_count`、`status`、`failed_rules`、`attempt`，加耗时和 token 数。不含原话，也不含摘要和理由的文字。
- `playthrough_metrics` 加这些计数：分流跳过、改写、降级、拒绝、超时降级、因要确认而丢弃；叙事者各类提示的花费。

## 接口

- 候选事件、`CheckResult`、`failedRules` 的名字：契约第 3 节。`check()` 的返回形状：api-contract 第 7 节，不变。
- 新的异常 `BudgetStop`、`RateLimited`，和 `EvalNotImplemented`、`ReplayMissing` 一起从 `zoujin_backend.eval_api` 导出。运行器遇到这两个要整次停下，不是跳过这一例；E-0 怎么报由数据定。
- 新的环境变量：`ZJ_MODEL` 多一个 `real`；`ZJ_RECORD_REPLAYS`、`ZJ_EVAL_LIVE`、`ZJ_LEDGER`（账本文件）。上限走命令行参数。E-0 的 live 接真模型时，把它的 Google 上限也传给后端的客户端，怎么传在代码 PR 里和数据对。

## 验收

不联网（pytest 拦截 socket），`uv run pytest services/backend` 和连库的 `-m db` 全过，其中要有：

1. **第 3 步对照 `judge()`**：
   - `evals/s2/s2_dev.jsonl` 每条，`judge()` 报的规则第 3 步都报；
   - 标成 `stage: rules` 的报出主规则；合规的和 `stage: model` 的，第 3 步一条都不报；
   - 每条 R 规则另有自己写的正反例，不取自任何留出样本。
2. **流水线**（假模型 + fixture）：
   - 分流判没有可能 → 只有时钟事件；
   - 提取 → 全过 → 提交；
   - 第 3 步不过 → 改写一次后通过（`rewritten`、`attempts: 2`）；
   - 第 4 步三次都不过 → 降级或拒绝，`effects` 和 `reason` 按契约；
   - 同一轮几个候选，前面的结果影响后面的判定。
3. **时限**：注入延迟，第一次超时会重发；两次都超时 → 只提交时钟事件，候选丢弃，指标加一，库里没有半轮。
4. **范围**：`scoped` 下只推进时钟的和第 3 步没过的不跑第 4 步；`all` 下每条都跑。
5. **切片**：`ZJ_WORLD` 指切片版时，`var.player.custody = arrested` 的候选被否决（R7）；石工房两人不在场，和他们同地点才成立的事件被否决（R7），快照里是 `absent`。切片世界模型进 main 之前这组先跳过。
6. **评测入口**：
   - `check` 在 10 条公开样例上返回过 Schema 的结果，`checker` 带版本；
   - `say` 的结果和逐步用 W-1 推演一致；
   - `ZJ_MODEL=replay` 下用录好的回放，10 条跑出和录的时候一样的判定（回放要等 Mac 第一次跑完才有，之前用假模型录的回放测这条路）。
7. **S-2 脚本**：
   - 用假模型跑 10 条，出 `report.json` 和 `report.md`，数和手算的一样；
   - `--resume` 不重跑已完成的；
   - 没设 `ZJ_EVAL_LIVE`、少一个上限、不带 `--confirm`，三种都只打印、不调用。
8. **真客户端**（假的传输层，不联网）：请求的形状、截止时间、重发、429 → `RateLimited`、到上限 → `BudgetStop`、花费按价目算、录的回放格式和 B-0 一样；项目 ID 不出现在日志和回放里。
9. **不记原话**：跑一轮带标记字符串的对话，日志和 Span 里找不到这个字符串。

CI 照旧只用假模型和回放，全绿。

## 真模型怎么跑（不在 CI 里，开跑前等 PM 通知）

- zg 定了 Z-8 的上限、PM 通知以后才跑。之前代码、提示和回放都在容器里用假模型写。
- 每次跑：
  1. 后端写好命令和预计花费，经协调交 Mac；
  2. Mac 从仓库拉到指定的提交，先不带 `--confirm` 跑一次，打印预计花费；
  3. zg 看过同意，再带 `--confirm` 跑。长任务用 nohup 和 `caffeinate -i`；
  4. 原始输出留在 Mac 的 `out/`，脱敏汇总和回放经协调回后端。
- 预计花费〔推算〕，记在 Google 那本账：
  - 调自检提示：每轮 10 条 × 3 次 ≈ $0.3；
  - 调提取和人物回答的提示：用切片里 E4 的文字用例，每轮约 $1.5；
  - 各调 5〜10 轮，合计约 $10〜15。
  - 正式的 S-2（50 条 × 3 次）约 $2，在数据那张表里，不重复算。

## 留出样本的规矩（S-2）

- 自检的提示定稿之前，后端不读项目文件夹的 `data/evals/holdout/`（包括它的 README），不用留出样本的场面当提示里的例子。调提示只用公开的 10 条和评测 E4。
- **定稿** = 后端在代码 PR 里写下 `check` 提示的版本号，通知数据和 PM。之后数据用 `zoujin-s2` 在 Mac 上跑 50 条留出集，报告交数据核对标注。
- 定稿之后再改 `check` 提示，这次 S-2 的结果就不代表新提示，要数据出新的测量集（`evals/s2/README.md`）。

## 禁止

- 不部署，不建账号、不建 Key，不花 zg 没批的钱。真模型只在 Mac 上、PM 通知之后。
- 凭证、项目 ID、账单 ID、部署地址不进仓库、文档、日志、回放和聊天。代码只在 `ZJ_MODEL=real` 时读 Mac 环境里的项目 ID。
- 日志和 Trace 里不写原话，也不写摘要和理由的文字，只写 ID、计数和规则名（data-design 第 8 节）。
- fixture 和回放里只放自己写的台词和合成输入，不放真人说过的话。
- 不读留出样本（见上）。
- CI 和容器里不调真模型；测试禁网。
