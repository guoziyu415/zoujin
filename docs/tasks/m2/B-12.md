## 目标

做完以后：

1. 玩家每一句话（语音的定稿字幕、文字输入）在送进叙事者之前过一遍安全筛查，和人物回答并行：
   - 自伤、求助信号 → 出戏卡（`safety_pause`），这一轮不进叙事者、不花时间、原话当场清空；
   - 似是而非 → 一局第一次出小提示（`safety_hint`），第二次按信号处理（S-069）；
   - 注入、个人信息、有害内容 → 作为标记交给叙事者（backend-design 5.5 的第二行），不直接拒绝。
2. 分类器是提示 v2 换到 Claude Haiku 5.5（D-028，B-8 的表），温度不可调就按 B-8 的写法关思考；换了模型按 S-072 重量过主集，真实信号全中才用。
3. Model Armor 照旧当第二层（S-085 ②）：玩家输入的注入第二层、个人信息的补充、有害内容只用 HIGH；人物输出的 `sanitizeModelResponse`。
4. 人物说出去的话事后过剧透检测和问句比例（backend-design 2.11）：命中记进 Trace 和指标（不记原话），给这个人物下一次的局势说明加一句纠正提示；同一会话连续命中 2 次就重建会话；问句超过 30% 加「問いかけは控えめにする。相手の言葉に応えて、自分の思いや知っていることを話す。」。
5. 评测的文字模式（`eval_api`）走同一套筛查和监控，切片评测量到的就是玩家会碰到的。

## 范围

### 做

**1. 安全分类器 v2（Claude Haiku）**

- 新的提示类型 `safety`（`models/prompts.py`、`prompt_texts/safety.txt`），走 `models/text.py` 的假模型、回放、真模型三种，和叙事者别的提示同一套时限、账本、回放的键。
- 提示文本 = spike 的 `CLASSIFY_PROMPT_V2` 的判定规则，字不改；只把「発話：{text}」换成和叙事者一样的 `<utterance speaker="player">` 数据字段（玩家的话不进指令段）。输出用 Schema 定死：`{"selfHarm": "signal" | "ambiguous" | "none", "injection": boolean}`。
- 配置：`TEXT["safety"] = claude / haiku-5.5 / 3 秒 / 64 token / 关思考`（B-8 的表）。超时取消、立刻重发一次；第二次还超时或出错 → **没判定**（`unscreened`）：这一轮不暂停，标记交给叙事者按最保守的判（同注入：提取只看故事里的意思、不写记忆），计数。
- 模型拒答（`refusal`，没有输出）→ 按有害输入处理（标记 `harmful`），单独计数（5.5 的「模型拒答」）。
- 文字和语音的定稿字幕都判；半句不判（只判定稿，省钱也少误判）。

**2. 个人信息规则（自己的规则为主）**

- 新模块 `safety/pii.py`：电话 `0\d{1,4}-?\d{1,4}-?\d{3,4}`（全角数字、各种横线）、邮箱、〒和「都道府県＋市区町村＋番地」、卡号 13〜19 位过 Luhn、マイナンバー 12 位过校验位。`find(text)` 返回命中的种类和位置，`mask(text)` 把命中的部分换成「〔個人情報〕」。
- 叙事者第 3 步 R6 的规则部分（`narrator/rules.py` 现在的 `PII` 正则）改用这个模块，只有一套。B-13 的记忆过滤也用它。
- 玩家原话里有个人信息时：存下的原话（`utterances.text`）存掩码后的版本；标记 `pii` 交给叙事者（不写进记忆、`summary`）。

**3. Model Armor 第二层**

- 新模块 `models/armor.py`：`Armor` 接口两个方法 `screen_prompt(text)`、`screen_response(text)`，返回扁平的结果（PI 的置信档、RAI 命中的类别和档、SDP 命中没有、恶意链接）；三种实现：
  - 假的（`fake`）：`fixtures/fake-armor/*.json` 的规则（按文字里的子串命中，也能注入延迟和错误），默认全不命中；
  - 回放（`replay`）：`fixtures/model-replays/armor/*.jsonl`（子目录，文本模型的回放只读上一层），键 = `armor|<模板配置的版本>|<方法>|<文字的 sha256>`；
  - 真的（`real`，只在 Mac 上）：REST 调 `sanitizeUserPrompt` / `sanitizeModelResponse`，区域 us-central1（5.5，asia-northeast1 不支持多语言检测），模板名从环境变量给，凭证用 Mac 上 gcloud 的 ADC，不进仓库。
- 判法（5.5）：注入 = 分类器为准，Model Armor 的 PI 命中（MEDIUM 以上）也算注入，两边都记；RAI 只认 HIGH → `harmful`；SDP 命中 → `pii`（补充自己的规则）。每次 1 秒时限，超时或出错就当没命中（第二层，不挡玩家），计数。
- 模板的配置写在代码里（`armor_template()`，和 spike 的 `make_template` 同形：RAI 四类、SDP basic、PI、恶意链接、多语言检测，**不开日志**），Mac 上有一个建模板的命令（`zoujin-safety armor-template --confirm`）；建模板是在 zg 的 GCP 项目里建一个资源，要 zg 点头才跑（见「真模型怎么调」）。

**4. 网关里的筛查（`gateway/safety.py`，`gateway/ws.py` 只加钩子）**

- 一轮的玩家定稿（文字一轮是 `text`，语音一轮是 Live 的 `input_final`）一到就开始筛查：分类器、Model Armor、个人信息规则三样并行，人物照常回答。
- 幕末说的打算（文字 `act_propose`、声音 `activity_start { purpose: "act_plan" }` 的转写定稿）也筛（UX 评审）：判成 `signal` 时不推 `act_plan_result`、不算试次、不写 plan 任务，推 `safety_pause`；`safety_resume` 以后幕末页照原样回来（`pending.actEnd`）。
- `signal`（或同一局第二次 `ambiguous`）：
  - 停止转发这一轮人物的回答（取消转发任务，不推 `interrupted`、不推人物定稿，3.3 的例外），推 `turn_settled { outcome: "paused", minutes: 0 }` 和 `safety_pause`；
  - 这一轮写一行任务 `status: "done"`、`outcome: "paused"`，原话不写（玩家和人物的都不写），不叫叙事者，也不进网关内存里的最近对话；重连时 `welcome.lastTurn` 是这一轮，`status: "settled"`、`playerText`、`characterText` 都是 `null`（同作废的一轮，前端不重发）；
  - 玩家这时已经按着说话键（新的一轮发了 `activity_start`）：那一轮丢掉，之后它的音频帧和 `activity_end` 都忽略（3.12）；
  - 关掉这条连接上所有人物的会话；这一局记 `safety.paused = true`（`welcome.pending.safetyPause` 读它，重连以后照样是暂停卡）；
  - 暂停期间 `text`、`activity_start`、`action`、`act_*` 回 `invalid_request`；`focus`（重连时前端自动发）不开会话、不回错误；`safety_resume` → 清掉暂停、回 `safety_resumed`，前端重新 `focus`（3.12）。
- `ambiguous` 一局第一次：推 `safety_hint`（一局最多一次，`safety.hinted` 记在局上，重连不重推）；这一轮照常交给叙事者，但标记 `ambiguous`：叙事者这一轮不提取事件（只记时间），局势说明不往死亡、绝望推（UX 的那一句，到这一幕结束，这一局所有人物都带）。
- 暂停时还有没答的意图确认（`pending.confirm`）：这一版不冻结，照原来的时限在卡片底下超时关掉；UX 的默认是冻结、恢复后接着问，记作后续（要改叙事者的超时，不在本卡）。
- 注入、`pii`、`harmful`、`unscreened`：作为 `turns.flags` 交给叙事者（`narrator/rules.py` 的 `Turn.flags` 已经认 `injection`、`pii`，本卡加 `harmful`、`unscreened`、`ambiguous`）。`turns.flags` 只是交给叙事者的传递字段：叙事者在第 7 步提交（和失败、作废）的同一个事务里把它置空，分析不读，也不进 Trace；lost 的轮不写。
- 筛查比人物回答晚到（分类器 p95 约 1 秒）：交给叙事者之前等筛查的结果（最多 3 秒 + 重发一次），不会先提交再暂停。
- 判定结果、分数都不存、不进日志和 Trace（S-057、S-069 ③），`playthrough_metrics` 只记次数和花费（列名按数据评审的表）：`cost_safety_usd`（分类器，含重发和超时取消的那次）、`cost_armor_usd`（只记真 Armor，按价目表单价〔推算〕）、`safety_pauses`、`safety_ambiguous`（含出小提示的那次）、`safety_hints`、`safety_unscreened`、`safety_refused`、`safety_injection` / `safety_pii` / `safety_harmful`（带这个标记交给叙事者的轮数）、`armor_errors`。`playthroughs.safety` 的 `paused`、`hinted` 是重连要用的运行状态，留着。

**5. 输出侧监控（`gateway/monitor.py`）**

- 人物的每一句定稿（`source: "live"` 的，预录和剧本的不查）过两样：
  - **剧透检测**（确定性，不调模型）：调 `zoujin_worldsim.spoilers(world, state, 人物, 这句话, said=玩家这一轮的定稿)`：这个人物此刻不 `knows` 的事实（`knows` 已含还没成立的）的 `spoilerTerms` 在不在这句话里，玩家同一轮自己说过的词不算。命中只记事实 ID。叙事者 R4 的 `op_improv` 也改调它，规则只有一套。原样子串比对，人物定稿是语音的转写，写成假名就漏，所以这里的剧透率只是下限，对外的剧透率以 E2 和 S-068 的判定为准。
  - **Model Armor `sanitizeModelResponse`**（第二层，并行、不等）：RAI HIGH 命中算一次「有害输出」，记次数。
- 命中时（2.11 第 2 条）：Trace 记一个事件（人物 ID、事实 ID 或类别，不记原话）；这个人物下一次局势说明加一句纠正提示，**不点名**（数据评审：写出那个词等于把还没发生的事告诉人物）：「さっき、まだ知らないはずのことを口にした。話すのは、自分の目で見たこと、人から聞いたこと、自分の思いだけにする。その話を振られたら、よく分からないと答える。」（数据的初稿，UX 10fc86d 评审定稿：人物自己的决心和想法可以说，被追问时答「よく分からない」）；词只留在网关内存里（最近 3 个，重建时用来拿掉说漏的那几句）和 Trace 的事实 ID 里；同一个会话连续 2 句命中 → 重建这个人物的会话（走 `_rebuild`，带上提示，说漏的那几句不带进新会话的最近对话）。
- **问句比例**（2.11 第 3 条，口径见 data-design 9.1）：单位是人物的一次定稿，看最后一句：以「？」「?」结尾，或去掉句号、感叹号、省略号后以「か」「かい」「かね」「かしら」结尾（「そうか」「ものか」「ではないか」「じゃないか」除外）算问句；「〜の。」「かな」不算。每个人物在这条连接上问句的定稿数 / 总定稿数；满 6 句以后超过 30% → 局势说明加「問いかけは控えめにする。相手の言葉に応えて、自分の思いや知っていることを話す。」（UX 的写法），降到 20% 以下拿掉。只在内存里数（重连从头数）。同一个人物把同一句问句又问一遍（最后一句 NFKC 后去掉标点比对，内存里只留哈希）记 `output_questions_repeated`（S-023 要 0）。
- 提示怎么进会话：`LiveModel.open(character, recent, notes)` 多一个参数 `notes`（几句日语），假 Live 记下收到的；真 Live 怎么把它放进局势说明由后端 3 的 Live 代理那张卡做。文字模式的 `reply` 把 `notes` 放进 `situation`。
- 指标（列名按数据评审的表）：`output_lines`（过了监控的人物定稿，分母）、`output_spoilers`、`output_harmful`、`output_rebuilds`、`output_questions`、`output_questions_repeated`、`output_question_notes`；Model Armor 两边出错都记 `armor_errors`，花费记 `cost_armor_usd`。Trace 事件 `monitor.hit`（data-design 第 8 节：playthrough_id、turn_id、character、`kind` spoiler / harmful、`fact`、`category`、`rebuild`，不带原话和命中的词）。看板和告警（data-design 第 8 节）读这几列，不在本卡。

**6. 评测入口的文字模式**

- `eval_api` 的文字一轮走同一个筛查：`signal` 时回 `outcome: "paused"`、不进叙事者；结果里带 `safety`（`signal` / `ambiguous` / `none` / `unscreened`），只在评测入口返回，产品的网关不下发。
- 每一步回 `safetyCard: {shown, paused, canReturn}`（第 7 节「每一步返回」）；暂停的那一轮 `utterance_cleared` 答 `true`。幕末的 `propose()` 也筛。
- `reply` 之后走同一个监控，剧透命中写进这一轮的结果（`monitor.spoilers`，事实 ID），数据的 E2 可以拿来对照。

**7. 换模型以后的重量（S-072）**

- 命令 `zoujin-safety eval <样本>`：读 `evals/safety/s4_selfharm.jsonl`，每条过分类器 N 遍（默认 3），按 S-072 打印合格线：真实信号（`selfharm`）每一遍都是 `signal`；故事组和口头禅判成 `signal` 的条数（误判，主集加留出合计 > 10% 要重新评估）；故事组判成 `ambiguous` 的比例（S-069 的观察项，> 1/6 告诉 PM）。只打印 ID 和标签，不打印原话。
- 云端跑假模型和回放；真的只在 Mac 上，`--confirm` 之前打印预计花费。
- **留出集**：后端不打开。`zoujin-safety eval <path>` 能读任意同格式的文件，数据在 Mac 上自己跑留出那一半（B-8 卡）。现在仓库里的 25 条留出 S-072 已用过一次；这次是同一版提示换模型，不是改提示，**我的默认是数据就用这 25 条量换模型**，要不要另写新的留出集请数据在评审里定（S-072 ⑤ 的复核到 M3 本来就要新的）。
- 量过、合格才把网关的分类器从假模型切到真的；不合格回报 PM，按 S-072 先用 v2 + 安全优先，不在本卡调提示。
- 数据定的（评审）：留出就用这 25 条，只出合计（`--counts-only`）；换模型不合格以后谁改了提示，这 25 条就算用完，数据另写新的。
- **2026-10-11 在 Mac 上量的结果**（Claude Haiku，3 遍，账本 b12-safety 主集 $0.00411）：
  - 主集：真实信号 23 条每遍全 `signal`；误判 2/31（6.5%）；故事组 ambiguous 3/22（13.6%）；p50 1294 ms、p95 2180 ms。
  - 留出（数据跑，只有合计）：真实信号 9 条全中；误判 3/14（21.4%）；故事组 ambiguous 3/8（37.5%，超过 1/6）。
  - 合计误判 5/45 ≈ 11.1%，过了 S-072 ② 的 10% 重新评估线；真实信号一条没漏。怎么办由 PM 定（不在本卡调提示）。

- 正式环境的 Model Armor 模板和权限（第一次评审部署前和部署一起问 zg）。

## 验收

CI（假模型、假 Armor、回放，禁网）里：

1. 文字一轮判成 `signal`：推 `turn_settled { outcome: "paused" }` 和 `safety_pause`，没有人物定稿、没有 `interrupted`；库里这一轮 `outcome: "paused"`、没有原话；叙事者没被叫；`playthrough_metrics.safety_pauses = 1`；重连以后 `welcome.pending.safetyPause = true`；重连时 `lastTurn` 是这一轮、settled、两段文字都是 `null`；暂停时 `text` 回 `invalid_request`、`focus` 不开会话；`safety_resume` 回 `safety_resumed`，之后能正常说话，最近对话里没有这一轮。
2. 语音一轮：定稿字幕判成 `signal`，人物正在说 → 停下；玩家这时已经 `activity_start` 了新的一轮 → 那一轮的音频和 `activity_end` 被忽略，库里没有它。
3. `ambiguous`：第一次推 `safety_hint`、人物照常说完、叙事者收到 `ambiguous` 标记不提取；重连不重推；第二次 → 暂停。
4. 分类器第一次超时、重发成功 → 照常；两次都超时 → `unscreened` 标记、不暂停、计数。拒答 → `harmful`、计数。
5. 个人信息：电话、邮箱、住所、卡号（Luhn 对和不对各一）、マイナンバー（校验位对和不对各一）；存下的原话是掩码后的；R6 用同一个模块（`tests/test_rules.py` 原来的用例照过）。
6. Model Armor 假的命中 PI → `injection`；RAI HIGH → `harmful`、MEDIUM 不算；超时 → 当没命中、`armor_errors` 加一。
7. 剧透：人物说出他此刻不知道的事实的 `spoilerTerms` → 命中、下一次 `open` 收到纠正提示；连续两句命中 → 会话重建（`session_preparing reason: "rebuild"`）；知道的事实说出来不算；玩家同一轮说过的词人物接着说不算；纠正提示里没有那个词；日志和 Trace 里没有原话（按 B-2 的 `no_text_in_logs` 那种测法）。
8. 问句比例：6 句里 2 句问句不加提示，6 句里 3 句加；降下来拿掉。「そうか。」「〜ものか。」「〜ではないか。」「〜かな。」「〜の。」不算问句，「本当か？」「行くのか。」算；同一句问句再问记一次重复。
9. `eval_api` 文字模式：`signal` → `paused`；`monitor.spoilers` 有值；E8 的 `safety_card` 检查不再跳过。提交以后 `turns.flags` 是 NULL。
9a. 幕末用文字说的打算判成 `signal`：推 `safety_pause`，没有 `act_plan_result`、没有 plan 任务；恢复、重连以后 `pending.actEnd.freeform.triesLeft` 不变。
10. `zoujin-safety eval` 在假模型上跑通，打印的合格线和用回放里的标签手算的一致；输出里没有原话。
11. `uv run` 的 lint、类型检查、全部测试在本地过（D-032：合并前本地全跑）。

Mac 上（真模型，合并以后）：

12. `zoujin-safety eval` 主集 × 3 遍：真实信号 3 遍全 `signal`，报误判条数和故事组 ambiguous 比例；数据跑留出那一半（`--set … --counts-only`，只出合计）。主集和留出都合格才切到真的；误判主集加留出合计超过 10% 按 S-072 ② 重新评估（跑第二批时加 `--with 第一批的 report.json`，报告直接打印两批合计；不带时「合格」只说真实信号）。
