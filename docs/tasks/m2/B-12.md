## Goal / 目標

When this is done:

完了すると：

1. Every player utterance (the final transcript of speech, or typed text) is screened for safety before it is sent to the narrator, in parallel with the character's answer:
   プレイヤーの一言ごと（音声の確定字幕、文字入力）を、ナレーターに渡す前に安全スクリーニングにかける。登場人物の返答とは並行に行う：
   - Self-harm or help-seeking signals → out-of-story card (`safety_pause`); this turn does not go to the narrator, uses no time, and the utterance is cleared on the spot.
     自傷・助けを求めるシグナル → 物語の外に出るカード（`safety_pause`）。このターンはナレーターに渡さず、時間も使わず、発話はその場で消す。
   - Ambiguous → the first time in a playthrough, a small hint (`safety_hint`); the second time it is treated as a signal (S-069).
     曖昧なもの → 1 回のプレイで最初の 1 回は小さなヒント（`safety_hint`）、2 回目はシグナルとして扱う（S-069）。
   - Injection, personal information, harmful content → passed to the narrator as flags (the second row of backend-design 5.5), not rejected outright.
     インジェクション、個人情報、有害な内容 → フラグとしてナレーターに渡す（backend-design 5.5 の 2 行目）。直接拒否はしない。
2. The classifier is prompt v2 moved to Claude Haiku 5.5 (D-028, the B-8 table); since temperature cannot be set, thinking is turned off as B-8 describes. After the model change, the main set is re-measured per S-072, and it is used only if every real signal is caught.
   分類器はプロンプト v2 を Claude Haiku 5.5 に移したもの（D-028、B-8 の表）。温度が調整できないので、B-8 の書き方どおり思考をオフにする。モデルを替えたので S-072 に従ってメインセットを再計測し、本物のシグナルをすべて捉えた場合にだけ使う。
3. Model Armor stays the second layer (S-085 ②): a second layer for injection in player input, a supplement for personal information, and only HIGH for harmful content; `sanitizeModelResponse` for character output.
   Model Armor は従来どおり第 2 層とする（S-085 ②）：プレイヤー入力のインジェクションの第 2 層、個人情報の補完、有害な内容は HIGH のみ。登場人物の出力には `sanitizeModelResponse`。
4. What characters say is checked afterwards for spoilers and question ratio (backend-design 2.11): hits are recorded in Trace and metrics (not the utterance), and a correction note is added to that character's next situation briefing; 2 consecutive hits in the same session rebuild the session; when questions exceed 30%, add 「問いかけは控えめにする。相手の言葉に応えて、自分の思いや知っていることを話す。」.
   登場人物が口にしたことを事後にネタバレ検出と問いかけ比率にかける（backend-design 2.11）。ヒットは Trace と指標に記録し（発話そのものは記録しない）、その人物の次の状況説明に訂正のメモを 1 行足す。同じセッションで 2 回続けてヒットしたらセッションを再構築する。問いかけが 30% を超えたら「問いかけは控えめにする。相手の言葉に応えて、自分の思いや知っていることを話す。」を足す。
5. The eval text mode (`eval_api`) goes through the same screening and monitoring, so what the slice eval measures is what players will actually meet.
   評価のテキストモード（`eval_api`）も同じスクリーニングと監視を通す。スライス評価で測るものが、そのままプレイヤーが出会うものになる。

## Scope / 範囲

### In scope / やること

**1. Safety classifier v2 (Claude Haiku) / 安全分類器 v2（Claude Haiku）**

- A new prompt type `safety` (`models/prompts.py`, `prompt_texts/safety.txt`), going through the fake-model, replay and real-model paths of `models/text.py`, with the same time limits, ledger and replay keys as the narrator's other prompts.
  新しいプロンプト種別 `safety`（`models/prompts.py`、`prompt_texts/safety.txt`）。`models/text.py` の偽モデル、リプレイ、本物のモデルの 3 通りを通し、ナレーターの他のプロンプトと同じ時間制限、台帳、リプレイのキーを使う。
- Prompt text = the judging rules of the spike's `CLASSIFY_PROMPT_V2`, word for word; only 「発話：{text}」 is replaced with the same `<utterance speaker="player">` data field the narrator uses (the player's words never enter the instruction section). Output is pinned by a Schema: `{"selfHarm": "signal" | "ambiguous" | "none", "injection": boolean}`.
  プロンプト本文 = スパイクの `CLASSIFY_PROMPT_V2` の判定ルールで、一字も変えない。「発話：{text}」だけを、ナレーターと同じ `<utterance speaker="player">` のデータフィールドに置き換える（プレイヤーの言葉は指示部分に入れない）。出力は Schema で固定する：`{"selfHarm": "signal" | "ambiguous" | "none", "injection": boolean}`。
- Configuration: `TEXT["safety"] = claude / haiku-5.5 / 3 seconds / 64 tokens / thinking off` (the B-8 table). On timeout, cancel and resend immediately once; if the second attempt also times out or errors → **no verdict** (`unscreened`): this turn is not paused, a flag is passed to the narrator to judge it in the most conservative way (as with injection: extraction only takes the in-story meaning and nothing is written to memory), and it is counted.
  設定：`TEXT["safety"] = claude / haiku-5.5 / 3 秒 / 64 token / 思考オフ`（B-8 の表）。タイムアウトしたら取り消し、すぐに 1 回だけ再送する。2 回目もタイムアウトかエラーなら → **判定なし**（`unscreened`）：このターンは一時停止せず、フラグを付けてナレーターに渡し、最も保守的に判断させる（インジェクションと同じく、抽出は物語の中での意味だけを見て、記憶には書かない）。回数を数える。
- Model refusal (`refusal`, no output) → treated as harmful input (flag `harmful`), counted separately (the "model refusal" row of 5.5).
  モデルの回答拒否（`refusal`、出力なし）→ 有害な入力として扱い（フラグ `harmful`）、別に数える（5.5 の「モデルの回答拒否」）。
- Both text and the final transcript of speech are judged; partial sentences are not (only the final transcript is judged, which saves money and reduces false positives).
  文字も音声の確定字幕も判定する。途中の半文は判定しない（確定したものだけを判定し、費用も誤判定も減らす）。

**2. Personal-information rules (our own rules first) / 個人情報のルール（自前のルールが主）**

- New module `safety/pii.py`: phone numbers `0\d{1,4}-?\d{1,4}-?\d{3,4}` (full-width digits, various dashes), email, 〒 and 「都道府県＋市区町村＋番地」 addresses, card numbers of 13–19 digits passing Luhn, 12-digit マイナンバー passing the check digit. `find(text)` returns the kinds and positions of hits; `mask(text)` replaces the hits with 「〔個人情報〕」.
  新しいモジュール `safety/pii.py`：電話番号 `0\d{1,4}-?\d{1,4}-?\d{3,4}`（全角数字、各種のハイフン）、メールアドレス、〒と「都道府県＋市区町村＋番地」、Luhn を通る 13〜19 桁のカード番号、チェックデジットを通る 12 桁のマイナンバー。`find(text)` はヒットした種類と位置を返し、`mask(text)` はヒットした部分を「〔個人情報〕」に置き換える。
- The rule part of the narrator's step 3 R6 (the current `PII` regex in `narrator/rules.py`) switches to this module, so there is only one set of rules. B-13's memory filter uses it too.
  ナレーターのステップ 3 の R6 のルール部分（現在 `narrator/rules.py` にある `PII` の正規表現）はこのモジュールに切り替え、ルールを一つにする。B-13 の記憶フィルターもこれを使う。
- When the player's utterance contains personal information: the stored utterance (`utterances.text`) is the masked version; the flag `pii` is passed to the narrator (not written into memory or `summary`).
  プレイヤーの発話に個人情報が含まれる場合：保存する発話（`utterances.text`）はマスク後の版にする。フラグ `pii` をナレーターに渡す（記憶や `summary` には書かない）。

**3. Model Armor as the second layer / Model Armor を第 2 層に**

- New module `models/armor.py`: an `Armor` interface with two methods, `screen_prompt(text)` and `screen_response(text)`, returning a flat result (PI confidence level, RAI categories and levels hit, whether SDP hit, malicious URLs); three implementations:
  新しいモジュール `models/armor.py`：`Armor` インターフェースに `screen_prompt(text)` と `screen_response(text)` の二つのメソッドを持たせ、フラットな結果（PI の信頼度、RAI のヒットしたカテゴリとレベル、SDP のヒット有無、悪意のあるリンク）を返す。実装は 3 種類：
  - Fake (`fake`): rules in `fixtures/fake-armor/*.json` (hit by substring in the text; can also inject latency and errors); by default nothing hits.
    偽（`fake`）：`fixtures/fake-armor/*.json` のルール（テキスト内の部分文字列でヒットし、遅延やエラーの注入もできる）。既定では何もヒットしない。
  - Replay (`replay`): `fixtures/model-replays/armor/*.jsonl` (a subdirectory; text-model replays only read the level above), key = `armor|<template config version>|<method>|<sha256 of the text>`.
    リプレイ（`replay`）：`fixtures/model-replays/armor/*.jsonl`（サブディレクトリ。テキストモデルのリプレイは一つ上の階層だけを読む）。キー = `armor|<テンプレート設定のバージョン>|<メソッド>|<テキストの sha256>`。
  - Real (`real`, Mac only): REST calls to `sanitizeUserPrompt` / `sanitizeModelResponse`, region us-central1 (5.5: asia-northeast1 does not support multilingual detection); the template name comes from an environment variable, and credentials use gcloud ADC on the Mac and never enter the repo.
    本物（`real`、Mac でのみ）：REST で `sanitizeUserPrompt` / `sanitizeModelResponse` を呼ぶ。リージョンは us-central1（5.5。asia-northeast1 は多言語検出に対応していない）。テンプレート名は環境変数から渡し、認証情報は Mac 上の gcloud の ADC を使い、リポジトリには入れない。
- How to judge (5.5): injection = the classifier is authoritative, and a Model Armor PI hit (MEDIUM or above) also counts as injection; both are recorded. RAI counts only HIGH → `harmful`; an SDP hit → `pii` (supplementing our own rules). Each call has a 1-second limit; on timeout or error it is treated as no hit (it is the second layer and must not block the player), and counted.
  判定の仕方（5.5）：インジェクション = 分類器を基準とし、Model Armor の PI ヒット（MEDIUM 以上）もインジェクションとみなす。両方とも記録する。RAI は HIGH だけを認めて → `harmful`。SDP のヒット → `pii`（自前のルールを補完）。各呼び出しは 1 秒の制限。タイムアウトやエラーならヒットなしとみなし（第 2 層なのでプレイヤーを止めない）、回数を数える。
- The template configuration is written in code (`armor_template()`, the same shape as the spike's `make_template`: four RAI categories, SDP basic, PI, malicious URLs, multilingual detection, **logging off**), and there is a command on the Mac to create the template (`zoujin-safety armor-template --confirm`). Creating the template creates a resource in zg's GCP project, so it only runs once zg approves (see "How to call the real models").
  テンプレートの設定はコードに書く（`armor_template()`。スパイクの `make_template` と同じ形：RAI の 4 カテゴリ、SDP basic、PI、悪意のあるリンク、多言語検出、**ログはオフ**）。Mac 上にテンプレートを作るコマンドがある（`zoujin-safety armor-template --confirm`）。テンプレートの作成は zg の GCP プロジェクトにリソースを作ることなので、zg の了承を得てから実行する（「本物のモデルの呼び方」を参照）。

**4. Screening in the gateway (`gateway/safety.py`; `gateway/ws.py` only gets hooks) / ゲートウェイでのスクリーニング（`gateway/safety.py`。`gateway/ws.py` はフックを足すだけ）**

- As soon as the player's final text for a turn arrives (`text` for a text turn, Live's `input_final` for a voice turn), screening starts: the classifier, Model Armor and the personal-information rules run in parallel, and the character answers as usual.
  1 ターンのプレイヤーの確定テキスト（文字のターンは `text`、音声のターンは Live の `input_final`）が届いたらすぐにスクリーニングを始める。分類器、Model Armor、個人情報ルールの三つを並行に動かし、登場人物はいつもどおり返答する。
- The plan stated at the end of an act (text `act_propose`, or the final transcript of voice `activity_start { purpose: "act_plan" }`) is also screened (UX review): when judged `signal`, do not push `act_plan_result`, do not count it as a try, do not write a plan job; push `safety_pause`. After `safety_resume`, the end-of-act page comes back exactly as it was (`pending.actEnd`).
  幕末に話すプラン（文字の `act_propose`、音声 `activity_start { purpose: "act_plan" }` の書き起こしの確定版）もスクリーニングする（UX レビュー）。`signal` と判定されたら `act_plan_result` を送らず、試行回数に数えず、plan のジョブも書かず、`safety_pause` を送る。`safety_resume` の後、幕末のページは元のまま戻る（`pending.actEnd`）。
- `signal` (or a second `ambiguous` in the same playthrough):
  `signal`（または同じプレイで 2 回目の `ambiguous`）：
  - Stop forwarding this turn's character answer (cancel the forwarding task; push neither `interrupted` nor the character's final transcript — the exception in 3.3), and push `turn_settled { outcome: "paused", minutes: 0 }` and `safety_pause`.
    このターンの登場人物の返答の転送を止め（転送タスクを取り消し、`interrupted` も人物の確定テキストも送らない。3.3 の例外）、`turn_settled { outcome: "paused", minutes: 0 }` と `safety_pause` を送る。
  - Write one job row for this turn with `status: "done"` and `outcome: "paused"`; do not write the utterances (neither the player's nor the character's), do not call the narrator, and do not add it to the recent conversation in gateway memory. On reconnect, `welcome.lastTurn` is this turn, with `status: "settled"` and `playerText` and `characterText` both `null` (the same as a retracted turn; the frontend does not resend).
    このターンについてジョブを 1 行、`status: "done"`、`outcome: "paused"` で書く。発話は書かず（プレイヤーのものも人物のものも）、ナレーターを呼ばず、ゲートウェイのメモリ上の直近の会話にも入れない。再接続時の `welcome.lastTurn` はこのターンで、`status: "settled"`、`playerText` と `characterText` はどちらも `null`（取り消したターンと同じ。フロントエンドは再送しない）。
  - If the player is already holding the talk key at that moment (a new turn has sent `activity_start`): that turn is dropped, and its subsequent audio frames and `activity_end` are all ignored (3.12).
    プレイヤーがその時点ですでに話すキーを押している（新しいターンが `activity_start` を送った）場合：そのターンは捨て、その後の音声フレームと `activity_end` もすべて無視する（3.12）。
  - Close the sessions of all characters on this connection; record `safety.paused = true` on this playthrough (`welcome.pending.safetyPause` reads it, so after a reconnect the pause card is still shown).
    この接続上のすべての登場人物のセッションを閉じる。このプレイに `safety.paused = true` を記録する（`welcome.pending.safetyPause` がこれを読むので、再接続後も一時停止カードのまま）。
  - During the pause, `text`, `activity_start`, `action` and `act_*` get `invalid_request`; `focus` (sent automatically by the frontend on reconnect) opens no session and returns no error; `safety_resume` → clears the pause and returns `safety_resumed`, and the frontend sends `focus` again (3.12).
    一時停止中は `text`、`activity_start`、`action`、`act_*` に `invalid_request` を返す。`focus`（再接続時にフロントエンドが自動で送る）はセッションを開かず、エラーも返さない。`safety_resume` → 一時停止を解除して `safety_resumed` を返し、フロントエンドは改めて `focus` を送る（3.12）。
- The first `ambiguous` in a playthrough: push `safety_hint` (at most once per playthrough; `safety.hinted` is recorded on the playthrough and not re-pushed on reconnect). This turn goes to the narrator as usual but flagged `ambiguous`: for this turn the narrator extracts no events (only records time), and situation briefings do not push toward death or despair (the line from UX; until the end of this act, every character in this playthrough carries it).
  1 回のプレイで最初の `ambiguous`：`safety_hint` を送る（1 回のプレイで最大 1 回。`safety.hinted` をプレイに記録し、再接続で再送しない）。このターンはいつもどおりナレーターに渡すが、`ambiguous` のフラグを付ける。ナレーターはこのターンではイベントを抽出せず（時間だけを記録）、状況説明は死や絶望の方向へ押さない（UX のその 1 行。この幕が終わるまで、このプレイのすべての登場人物に持たせる）。
- If an intent confirmation is still unanswered when the pause happens (`pending.confirm`): this version does not freeze it; it times out under the card on its original timer and closes. UX's default is to freeze and keep asking after resuming; that is recorded as follow-up work (it requires changing the narrator's timeout and is not in this card).
  一時停止の時点で未回答の意図確認（`pending.confirm`）がある場合：この版では凍結せず、元の制限時間どおりカードの下でタイムアウトして閉じる。UX の既定は凍結して再開後に続けて尋ねることで、これは今後の課題として記録する（ナレーターのタイムアウトを変える必要があり、このカードの範囲外）。
- Injection, `pii`, `harmful`, `unscreened`: passed to the narrator as `turns.flags` (`Turn.flags` in `narrator/rules.py` already recognizes `injection` and `pii`; this card adds `harmful`, `unscreened` and `ambiguous`). `turns.flags` is only a hand-off field to the narrator: the narrator clears it in the same transaction as its step-7 commit (and failure, and retraction); analytics do not read it, and it does not go into Trace. Lost turns do not write it.
  インジェクション、`pii`、`harmful`、`unscreened`：`turns.flags` としてナレーターに渡す（`narrator/rules.py` の `Turn.flags` はすでに `injection`、`pii` を認識する。このカードで `harmful`、`unscreened`、`ambiguous` を足す）。`turns.flags` はナレーターに渡すためだけのフィールドで、ナレーターはステップ 7 のコミット（および失敗、取り消し）と同じトランザクションで空にする。分析では読まず、Trace にも入れない。lost のターンでは書かない。
- Screening can arrive later than the character's answer (classifier p95 about 1 second): before handing to the narrator, wait for the screening result (up to 3 seconds + one resend); never commit first and pause afterwards.
  スクリーニングが登場人物の返答より遅れて届くことがある（分類器の p95 は約 1 秒）。ナレーターに渡す前にスクリーニングの結果を待つ（最大 3 秒 + 1 回の再送）。先にコミットしてから一時停止することはしない。
- Verdicts and scores are neither stored nor put in logs or Trace (S-057, S-069 ③); `playthrough_metrics` only records counts and costs (column names per the Data review table): `cost_safety_usd` (classifier, including the resend and the cancelled timed-out call), `cost_armor_usd` (real Armor only, using list-price unit costs 〔estimated〕), `safety_pauses`, `safety_ambiguous` (including the one that showed the small hint), `safety_hints`, `safety_unscreened`, `safety_refused`, `safety_injection` / `safety_pii` / `safety_harmful` (number of turns handed to the narrator with that flag), `armor_errors`. `paused` and `hinted` in `playthroughs.safety` are runtime state needed for reconnects, so they stay.
  判定結果とスコアは保存せず、ログにも Trace にも入れない（S-057、S-069 ③）。`playthrough_metrics` には回数と費用だけを記録する（列名はデータのレビューの表どおり）：`cost_safety_usd`（分類器。再送とタイムアウトで取り消した分を含む）、`cost_armor_usd`（本物の Armor のみ。価格表の単価で計算〔推定〕）、`safety_pauses`、`safety_ambiguous`（小さなヒントを出した回を含む）、`safety_hints`、`safety_unscreened`、`safety_refused`、`safety_injection` / `safety_pii` / `safety_harmful`（そのフラグを付けてナレーターに渡したターン数）、`armor_errors`。`playthroughs.safety` の `paused`、`hinted` は再接続に必要な実行時の状態なので残す。

**5. Output-side monitoring (`gateway/monitor.py`) / 出力側の監視（`gateway/monitor.py`）**

- Every final line from a character (those with `source: "live"`; pre-recorded and scripted lines are not checked) goes through two checks:
  登場人物の確定した一言ごと（`source: "live"` のもの。事前収録と台本のものは調べない）に二つのチェックをかける：
  - **Spoiler detection** (deterministic, no model call): call `zoujin_worldsim.spoilers(world, state, character, this line, said=the player's final text for this turn)`: whether the `spoilerTerms` of any fact this character does not `knows` at this moment (`knows` already covers facts not yet true) appear in this line; words the player said in the same turn do not count. A hit records only the fact ID. The narrator's R4 `op_improv` also switches to calling it, so there is only one set of rules. It is a literal substring match, and the character's final line is a speech transcript, so anything written in kana slips through; the spoiler rate here is therefore only a lower bound, and the externally reported spoiler rate is based on the E2 and S-068 judgments.
    **ネタバレ検出**（決定的。モデルは呼ばない）：`zoujin_worldsim.spoilers(world, state, 人物, この一言, said=このターンのプレイヤーの確定テキスト)` を呼ぶ。その人物がこの時点で `knows` していない事実（`knows` はまだ成立していない事実も含む）の `spoilerTerms` がこの一言に含まれているかを見る。同じターンでプレイヤー自身が言った語は数えない。ヒットしたら事実 ID だけを記録する。ナレーターの R4 の `op_improv` もこれを呼ぶように変え、ルールを一つにする。部分文字列のそのままの比較で、人物の確定テキストは音声の書き起こしなので、仮名で書かれると見逃す。したがってここでのネタバレ率は下限にすぎず、外部に示すネタバレ率は E2 と S-068 の判定を基準とする。
  - **Model Armor `sanitizeModelResponse`** (second layer, in parallel, not awaited): a RAI HIGH hit counts as one "harmful output", and the count is recorded.
    **Model Armor の `sanitizeModelResponse`**（第 2 層。並行で、待たない）：RAI HIGH のヒットを「有害な出力」1 回として数え、回数を記録する。
- On a hit (2.11 item 2): record one Trace event (character ID, fact ID or category, never the utterance); add a correction note to this character's next situation briefing, **without naming the term** (Data review: writing the word would tell the character what has not happened yet): 「さっき、まだ知らないはずのことを口にした。話すのは、自分の目で見たこと、人から聞いたこと、自分の思いだけにする。その話を振られたら、よく分からないと答える。」 (Data's first draft, finalized in UX review 10fc86d: the character may still speak of their own resolve and thoughts, and when pressed answers 「よく分からない」). The terms stay only in gateway memory (the latest 3, used on rebuild to drop the leaked lines) and as fact IDs in Trace. Two consecutive hits in the same session → rebuild this character's session (via `_rebuild`, carrying the note; the leaked lines are not carried into the new session's recent conversation).
  ヒットしたとき（2.11 の 2 項目）：Trace にイベントを 1 件記録する（人物 ID、事実 ID またはカテゴリ。発話そのものは記録しない）。その人物の次の状況説明に訂正のメモを 1 行足すが、**語は名指ししない**（データのレビュー：その語を書くと、まだ起きていないことを人物に教えることになる）：「さっき、まだ知らないはずのことを口にした。話すのは、自分の目で見たこと、人から聞いたこと、自分の思いだけにする。その話を振られたら、よく分からないと答える。」（データの初稿を UX のレビュー 10fc86d で確定。人物自身の決意や考えは話してよく、問い詰められたら「よく分からない」と答える）。語はゲートウェイのメモリ（直近 3 件。再構築時に漏らした数行を取り除くために使う）と Trace の事実 ID にだけ残す。同じセッションで 2 文続けてヒット → この人物のセッションを再構築する（`_rebuild` を通し、メモを持たせ、漏らした数行は新しいセッションの直近の会話に入れない）。
- **Question ratio** (2.11 item 3; definition in data-design 9.1): the unit is one final line from a character, judged by its last sentence: it counts as a question if it ends with 「？」 or 「?」, or, after stripping periods, exclamation marks and ellipses, ends with 「か」「かい」「かね」「かしら」 (excluding 「そうか」「ものか」「ではないか」「じゃないか」「ではありませんか」「じゃありませんか」); 「〜の。」 and 「かな」 do not count. Per character on this connection: question lines / total lines; after at least 6 lines, above 30% → add 「問いかけは控えめにする。相手の言葉に応えて、自分の思いや知っていることを話す。」 to the situation briefing (UX's wording), and remove it once the ratio drops below 20%. Counted only in memory (a reconnect starts over). When the same character asks the same question again (last sentence compared after NFKC and stripping punctuation; only the hash is kept in memory), record `output_questions_repeated` (S-023 requires 0).
  **問いかけ比率**（2.11 の 3 項目。定義は data-design 9.1）：単位は登場人物の確定した一言で、その最後の文で判断する。「？」「?」で終わるか、句点・感嘆符・三点リーダーを除いた後に「か」「かい」「かね」「かしら」で終わるもの（「そうか」「ものか」「ではないか」「じゃないか」「ではありませんか」「じゃありませんか」は除く）を問いかけとする。「〜の。」「かな」は数えない。この接続上の人物ごとに、問いかけの一言の数 / 一言の総数。6 文に達した後で 30% を超えたら → 状況説明に「問いかけは控えめにする。相手の言葉に応えて、自分の思いや知っていることを話す。」（UX の書き方）を足し、20% 未満に下がったら外す。メモリの中だけで数える（再接続したら最初から数える）。同じ人物が同じ問いかけをもう一度したら（最後の文を NFKC 正規化し句読点を除いて比較。メモリにはハッシュだけを残す）`output_questions_repeated` を記録する（S-023 では 0 が必要）。
- How notes get into the session: `LiveModel.open(character, recent, notes)` gains a `notes` parameter (a few Japanese sentences); the fake Live records what it receives; how the real Live puts it into the situation briefing is done by Backend 3's Live proxy card. In text mode, `reply` puts `notes` into `situation`.
  メモをセッションに入れる方法：`LiveModel.open(character, recent, notes)` に `notes` 引数（日本語の数文）を一つ足す。偽 Live は受け取ったものを記録する。本物の Live がそれを状況説明にどう入れるかはバックエンド 3 の Live プロキシのカードで行う。テキストモードの `reply` は `notes` を `situation` に入れる。
- Metrics (column names per the Data review table): `output_lines` (character final lines that passed monitoring, the denominator), `output_spoilers`, `output_harmful`, `output_rebuilds`, `output_questions`, `output_questions_repeated`, `output_question_notes`; Model Armor errors on either side are recorded in `armor_errors`, and costs in `cost_armor_usd`. Trace event `monitor.hit` (data-design section 8: playthrough_id, turn_id, character, `kind` spoiler / harmful, `fact_ids`, `category`, `rebuild`; no utterance and no matched term). Dashboards and alerts (data-design section 8) read these columns and are not in this card.
  指標（列名はデータのレビューの表どおり）：`output_lines`（監視を通った人物の確定テキスト。分母）、`output_spoilers`、`output_harmful`、`output_rebuilds`、`output_questions`、`output_questions_repeated`、`output_question_notes`。Model Armor のエラーはどちら側でも `armor_errors` に、費用は `cost_armor_usd` に記録する。Trace のイベント `monitor.hit`（data-design 第 8 節：playthrough_id、turn_id、character、`kind` spoiler / harmful、`fact_ids`、`category`、`rebuild`。発話そのものとヒットした語は含めない）。ダッシュボードとアラート（data-design 第 8 節）はこれらの列を読むもので、このカードの範囲外。

**6. Text mode of the eval entry point / 評価入口のテキストモード**

- A text turn in `eval_api` goes through the same screening: on `signal` it returns `outcome: "paused"` and does not go to the narrator; the result carries `safety` (`signal` / `ambiguous` / `none` / `unscreened`), returned only from the eval entry point and never sent by the product gateway.
  `eval_api` の文字の 1 ターンも同じスクリーニングを通す。`signal` なら `outcome: "paused"` を返し、ナレーターには渡さない。結果には `safety`（`signal` / `ambiguous` / `none` / `unscreened`）を含めるが、これは評価入口だけで返し、プロダクトのゲートウェイは送らない。
- Each step returns `safetyCard: {shown, paused, canReturn}` (section 7, "what each step returns"); for the paused turn, `utterance_cleared` answers `true`. The end-of-act `propose()` is screened too.
  各ステップで `safetyCard: {shown, paused, canReturn}` を返す（第 7 節「各ステップで返すもの」）。一時停止したターンでは `utterance_cleared` は `true` を返す。幕末の `propose()` もスクリーニングする。
- After `reply`, the same monitoring runs; spoiler hits are written into this turn's result (`monitor.spoilers`, fact IDs) so Data's E2 can compare against them.
  `reply` の後に同じ監視を通す。ネタバレのヒットはこのターンの結果（`monitor.spoilers`、事実 ID）に書き、データの E2 で照合に使えるようにする。

**7. Re-measuring after the model change (S-072) / モデル変更後の再計測（S-072）**

- Command `zoujin-safety eval <samples>`: reads `evals/safety/s4_selfharm.jsonl`, runs each item through the classifier N times (default 3) and prints the S-072 pass bars: real signals (`selfharm`) are `signal` on every run; the number of story-group and verbal-tic items judged `signal` (false positives; over 10% across main + holdout means re-evaluate); the share of story-group items judged `ambiguous` (an S-069 watch item; > 1/6 is reported to PM). Only IDs and labels are printed, never utterances.
  コマンド `zoujin-safety eval <サンプル>`：`evals/safety/s4_selfharm.jsonl` を読み、各件を分類器に N 回（既定 3 回）通し、S-072 の合格ラインを表示する。本物のシグナル（`selfharm`）は毎回 `signal` であること。物語グループと口癖が `signal` と判定された件数（誤判定。メインとホールドアウトの合計で 10% を超えたら再評価）。物語グループが `ambiguous` と判定された割合（S-069 の観察項目。1/6 を超えたら PM に伝える）。表示するのは ID とラベルだけで、発話そのものは表示しない。
- The cloud runs the fake model and replays; the real one runs only on the Mac, and the estimated cost is printed before `--confirm`.
  クラウドでは偽モデルとリプレイを動かす。本物は Mac でのみ動かし、`--confirm` の前に見込み費用を表示する。
- **Holdout set**: the backend does not open it. `zoujin-safety eval <path>` can read any file in the same format, and Data runs the holdout half on the Mac themselves (the B-8 card). The 25 holdout items currently in the repo have already been used once by S-072; this time it is the same prompt on a different model, not a changed prompt, so **my default is that Data measures the model change with these 25 items**; whether to write a new holdout set is for Data to decide in review (S-072 ⑤'s double-check in M3 needs a new one anyway).
  **ホールドアウトセット**：バックエンドは開かない。`zoujin-safety eval <path>` は同じ形式の任意のファイルを読めるので、ホールドアウトの半分はデータが自分で Mac で動かす（B-8 カード）。現在リポジトリにあるホールドアウト 25 件は S-072 で一度使用済み。今回は同じ版のプロンプトでモデルを替えるだけで、プロンプトを変えるわけではないので、**私の既定は、データがこの 25 件でモデル変更を計測すること**。新しいホールドアウトセットを別に書くかどうかは、データがレビューで決める（S-072 ⑤ の M3 でのダブルチェックにはもともと新しいものが要る）。
- Only after measuring and passing does the gateway's classifier switch from the fake model to the real one; if it fails, report back to PM, and per S-072 use v2 + safety first in the meantime; the prompt is not tuned in this card.
  計測して合格してから、ゲートウェイの分類器を偽モデルから本物に切り替える。不合格なら PM に報告し、S-072 に従ってまず v2 + 安全優先を使う。このカードではプロンプトを調整しない。
- Decided by Data (review): the holdout is these 25 items, reported only as totals (`--counts-only`); if anyone changes the prompt after the model change fails, these 25 count as used up, and Data writes new ones.
  データが決めたこと（レビュー）：ホールドアウトはこの 25 件を使い、合計だけを出す（`--counts-only`）。モデル変更が不合格になった後で誰かがプロンプトを変えたら、この 25 件は使い切ったものとし、データが新しいものを書く。
- **Results measured on the Mac on 2026-10-11** (Claude Haiku, 3 runs, ledger b12-safety, main set $0.00411):
  **2026-10-11 に Mac で計測した結果**（Claude Haiku、3 回、台帳 b12-safety、メインセット $0.00411）：
  - Main set: all 23 real signals were `signal` on every run; false positives 2/31 (6.5%); story group ambiguous 3/22 (13.6%); p50 1294 ms, p95 2180 ms.
    メインセット：本物のシグナル 23 件は毎回すべて `signal`。誤判定 2/31（6.5%）。物語グループの ambiguous 3/22（13.6%）。p50 1294 ms、p95 2180 ms。
  - Holdout (run by Data, totals only): all 9 real signals caught; false positives 3/14 (21.4%); story group ambiguous 3/8 (37.5%, above 1/6).
    ホールドアウト（データが実行、合計のみ）：本物のシグナル 9 件はすべて捕捉。誤判定 3/14（21.4%）。物語グループの ambiguous 3/8（37.5%、1/6 超）。
  - Combined false positives 5/45 ≈ 11.1%, past the 10% re-evaluation line of S-072 ②; not a single real signal was missed. PM decides what to do (the prompt is not tuned in this card).
    合計の誤判定 5/45 ≈ 11.1% で、S-072 ② の 10% の再評価ラインを超えた。本物のシグナルは 1 件も漏れていない。どうするかは PM が決める（このカードではプロンプトを調整しない）。

## Small contract changes (api-contract v1.0.13, notes only, Schema unchanged) / 契約の小さな変更（api-contract v1.0.13。説明の追加のみで Schema は変えない）

1. 3.12: when paused, the character's half-spoken answer gets neither `interrupted` nor a character final transcript (the exception list in 3.3 already has "turns stopped by the out-of-story card"; this spells out that neither is pushed).
