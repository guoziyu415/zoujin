## 目标

对着 B-1 的 mock，切片从第一幕幕末到结局的书页都能走通：

1. 幕末页：警吏的传闻 →「三日のあいだ、あなたは──」→ 去处卡；「ほかの考えがある」能用声音或文字说出打算，看到成行、不成行和替代去处，第 3 次只剩给定去处。
2. 「その頃」→ 切片跳转页「第四幕　三日目」→ 落地的一行，带 `opener` 时发 `act_landed`。
3. 記憶帳：按人物分页，关系刻度、約束、あなたにしてくれたこと／あなたがしたこと、覚えていること；「忘れてもらう」原地确认后真删；底部说明和「この物語をすべて消す」。
4. 連鎖反応マップ：按日子分段的竖向时间线，四种节点样式、还没到的节拍只出时刻和「？」，人物和「わたしの行動だけ」筛选，节点详情和「なぜこうなった？」。
5. 结局演出的字幕节奏（S-089）：句子自动往下、点一下补全或换句、预录句不叠、和镜头的交接；设置「結末を自動で進める」。
6. 结局页（世界 → あなた → 人物）和结局卡（4:5，1080×1350，Canvas 2D 重画，保存或系统分享）。

## 范围

**做**

1. **幕末页** `ui/actend/`（全屏书页，停 3D）
   - 切片专用的开头：`actEnd.title`、`actEnd.rumor`、`actEnd.melosLeft`、`actEnd.prompt`（这几行写在前端，M3 挪进世界模型）。
   - 去处卡：`label`；副题 = `where` + 全角空格 + `sub`，一行放不下时在全角空格处折行，前半不拆、不截断（CSS 两个 inline-block）；`because` 有就出一行。`enRoute` 的二选一页照 ux-design 4.5 做（切片用不到，按契约做好、单元测试覆盖）。
   - 「この幕であなたが動かしたこと（n）」折叠，展开是 `recapLines`；空的出 `actEnd.summary.empty`；「連鎖反応マップで見る」开地图。
   - 「ほかの考えがある」：书页下半换成输入区。文字发 `act_propose`；声音用 F-1 的说话键发 `activity_start { purpose: "act_plan" }`。等待时破折号慢慢延长，3 秒后出 `actEnd.propose.thinking`。结果：成行 →「あなたは、{plan}ことにした。」然后等 `act_transition`；不成行 → 叙事几行 +〔そうする〕〔ほかの道を選ぶ〕，〔そうする〕发 `act_choose { optionId: alternative.optionId }`；`triesLeft = 0` 时只出给定去处和 `actEnd.propose.giveUp`；空转写（`notHeard`）显示在「どうしますか。」的位置、不算次数。`act_plan_result` 按 `clientMsgId` / `turnId` 对上，对不上的丢掉。
   - 选定以后整页不可再点，等 `act_transition`；中途重连时从 `pending.actEnd` 恢复这一页。
2. **「その頃」和跳转页**
   - `act_transition.recap` 最多 3 件，每件一行，`promise` 时右侧标「果たされた / 破られた」（墨色）；点一件开地图到那个事件；没有 recap 不出这一页。
   - 切片：「その頃」之后翻一页 `jump.*`：一天一行逐行出，点一下剩下的一起出；〔つづける〕才走（不自动翻）；底部试遊版小字。太阳带的滑动由 F-0 的 SunBand 接快照的新时钟，本卡不改 SunBand。
   - 落地：从 `act_transition.snapshot` 换世界，出 `arrival.line`（叙事一行），有 `opener` 时出完这一行发 `act_landed`。
3. **記憶帳** `ui/memory/`（全屏，停 3D）
   - 入口：世界画面的菜单键、蓝色轻提示（`toast.toMemory`）、结局页。打开时 `GET /memories`（TanStack Query，不进 zustand）。
   - 只列有关系记录的人，一人一个标签；5 格刻度 + `relationLabel`；約束栏不显示 `voided`，只剩 `voided` 时整栏不显示；四栏空的整栏不显示；记忆卡片：原文、`tLabel`、`via`。
   - 删除：卡片原地展开确认（`GET …/impact` 取 `keeps`、`voidsPromise`），确认后 `DELETE`，卡片淡出、刻度动到新位置，顶部提示 `memory.forget.done`；不提供撤销。`sessionRebuilt` 交给语音那边（F-1 的会话状态），本卡只转一次。
   - 底部说明、〔この物語をすべて消す〕（原地确认 → `DELETE /playthroughs/{id}` → 回封面）。
4. **連鎖反応マップ** `ui/map/`（全屏，停 3D）
   - `GET /timeline`：按日子分段；事件四种样式（`style`：player 緋点 /「あなた」、caused 墨点 + 緋细线、character 墨点 +「{name}・あなたのために」、system 墨点）；节拍灰框 + 状态词；`known: false` 只出时刻和「？」；「いまここ」放在当前时刻。
   - 顶部期限一行（`deadline.shown` 时），危机时（`forecast.beforeDeadline === false`）换成「このままでは、日没に間に合わない」，点开是 `why?target=forecast`。
   - 筛选：人物 chips（`knownBy` 里有他的）、「わたしの行動だけ」（`causedByPlayer`）。
   - 节点详情原地展开：摘要、时刻、地点名、「知っている人」；〔なぜこうなった？〕调 `/why`，按时间正序画链，`collapsed > 0` 时中间一行「…{n}」。被修正的事件标「修正」。
   - 打开时滚到最新事件，或滚到传进来的 `eventId`。
5. **结局演出的字幕** `ui/ending/stage/`
   - 收到 `ending_started`：释放麦克风（F-1 的接口），挡住输入；人物正说的一句不切断（最多等约 3 秒，再 0.2 秒淡出）。之后到 `ending_ready` 前收到的 `set_piece`、`narration`、`commit.narration` 都进同一条字幕队列；`commit` 的轻提示、期限变化、关键时刻压到演出结束后再出（地图照常可见）。
   - 节奏（ux-design 11.1，S-089）：地の文和没有录音的人物句整句一次出，留 max(1.5 秒, 字数 ÷ 7 秒)（字数含标点，不含 ruby）；有录音的预录句（manifest `setPieceVoices["<pieceId>/<序号>"]`）跟着声音出，留到声音结束后 0.5 秒；字幕一直留到下一句；点一下：整句已出 → 换句，预录句未出全 → 先补全、第二下声音 0.2 秒淡出再换；一句出来或补全后 0.5 秒内的点不算；下一句的录音等上一句淡出完再开始。
   - 镜头：句子对镜头的表（`ending-shots.md`「句子对镜头」，按 `pieceId/序号`）抄成 `ui/ending/stage/shots.ts`。演出层向 3D 发「切到镜头 n」，3D 回「镜头 n 的动作完了」；下一句是新镜头的第一句时，自动往下要等这一句的时间和镜头动作都完，点了就不等、直接切。3D 演出本身不在本卡：没接 3D 时镜头动作当作立即完成。
   - 设置「結末を自動で進める」（默认开，存 localStorage，读写包 try/catch）：关掉时每句等点。
   - 切后台或开全屏浮层时演出和计时一起停；回来点「タップして続ける」那一下不算换句。
   - 演出结束还没 `ending_ready`：出「物語を綴じています（{n}秒）」往上数，超过 20 秒加一行地图入口。
   - 遥测：演出实际时长、点按次数、自动开没开（在 `ending_viewed` 的现有字段装不下时，PR 里列出来给数据，不改契约）。
6. **结局页** `screens/EndingScreen.tsx` 换掉 F-0 的占位
   - `GET /ending`：202 时按 `etaSeconds` 重试，出上面的等待行；200 后一页竖向滚动：世界の結末（标题、尾声每句带出处小标 → 地图那个事件、原作では／あなたの世界では）、あなたの結末（称号、行方、两栏各 1〜2 条带出处）、登場人物の結末（服务端顺序，没受影响的合成「ほかの人々は、原作どおりに。」+ 名字，〔ひらく〕展开）；底部〔結末カード〕〔地図で見る〕〔別の身分で、もう一度〕和原作链接。
   - 文字一律照服务端原样显示，前端不改写、不加引号。
7. **结局卡** `ui/ending/card/`
   - DOM 预览和 Canvas 2D 导出用同一个排版函数（纯函数算每块的字号和换行，单元测试），按 S-051 的表：插画 640、标题 160（称号 ≤ 14 字 64px 明朝，去向 34px）、人物 330（1〜3 行，不满 3 行上下居中，30〜34px，每句最多两行）、原作との違い 130（30px，最多两行）、页脚 90（28px）；超长先缩到 28px，再截断加「…」。
   - 插画：演出层在截帧镜头（ending-shots：赶上了截镜头 6；没赶上截镜头 1 的机位）向 3D 要一帧 1080×640 的像素（接口 `captureFrame(): Promise<ImageBitmap | null>`，3D 卡实现）；拿不到时用 `card.fallbackImageUrl`。
   - 保存：`document.fonts.load()` 后画；`canvas.toBlob` → `navigator.share({ files })`；不支持时桌面下载链接，手机出图片 + `card.saveFallback`。不放原话、个人信息、网址、二维码。
   - 遥测：`ending_card_saved`、`ending_shared`（已有类型）。
8. **共用的东西**：`stores/story.ts`（幕末、演出、浮层状态）；`net/story.ts`（幕末和结局消息的纯函数，单元测试）；`ui/copy.ts` 加上面各节的键；菜单键（記憶帳、地図）挂在世界画面。全屏浮层打开时在 ui store 里标「停 3D」，3D 那边读（F-2d 接）。

- 设置页整页（只做「結末を自動で進める」一项，放在结局演出里能找到的地方：世界画面的菜单里）。
- 分享链接（P1）、结局收藏和分岔树（P1）、「稀有的一件事」（P2）。
- 改 `packages/contracts`、改 mock 的剧本（mock 缺什么，PR 里列出来给后端）。

## 接口

不改 `packages/contracts`。用到的类型：`ActEndedMessage`、`ActPlanResultMessage`、`ActTransitionMessage`、`ActChooseMessage`、`ActProposeMessage`、`ActLandedMessage`、`Pending.actEnd`、`EndingStartedMessage`、`EndingReadyMessage`、`SetPieceMessage`、`ManifestResponse.setPieceVoices`、`TimelineResponse`、`WhyResponse`、`MemoriesResponse`、`MemoryImpactResponse`、`MemoryDeleteResponse`、`EndingView`。

给 3D 的接口（本卡定，3D 那张卡实现）：

```ts
// ui/ending/stage/bridge.ts
type StageBridge = {
  shot(n: number): void;                 // 切到镜头 n（ending-shots.md 的编号）
  onShotDone(f: (n: number) => void): () => void;  // 镜头 n 的动作完了
  captureFrame(): Promise<ImageBitmap | null>;     // 结局卡插画，1080×640
  pause(on: boolean): void;              // 切后台、全屏浮层
};
```

## 验收

- `pnpm -C apps/web typecheck`、`pnpm lint`、单元测试（vitest）全过；新加的纯函数都有测试：幕末状态（成行、不成行、次数用完、空转写、对不上 id 的结果）、字幕节奏（每种句子留多久、点按、0.5 秒防连点、镜头交接、自动关）、结局卡排版（S-051 的字数、1〜3 行居中、缩字号到 28px 再截断）、記憶帳的显示规则（voided、空栏）、地图的筛选。
- Playwright 对 mock（390×844）：`act-end` 剧本走两条路（直接选去处；先说打算不成行 → 〔そうする〕），看到その頃、跳转页、落地一行，带 opener 的那条发了 `act_landed`；`ending` 剧本看到字幕自动往下、点一下换句、结局页三层、结局卡导出一张 1080×1350 的 PNG；記憶帳删一条记忆后刻度变了、`/memories` 里没了；地图筛选和「なぜ」。每屏一张截图给 UX。
- 读屏顺序和键盘：全屏浮层打开时焦点进去、关掉回原处；地图是列表（`<ol>`）；所有按钮能用键盘按。
- 首屏 JS 不变大：这些屏幕都是懒加载的块；记下各块 brotli 后的大小。
- 合并前在本地跑一遍 gitleaks 和大文件检查（D-032）。
