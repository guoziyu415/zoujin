## 目标

做完以后：

1. 数据的运行器能用 `persona` + `seed` 开一局模拟局：
   - 后端照正式开局起这一局；
   - AI 玩家只看得到真玩家看得到的东西，按画像一步一步玩，一直玩到结局。
2. CI 里用假模型能把切片完整走一局到结局，不联网。
3. 在 Mac 上用真模型跑 S-5，量出切片一局的真实花费和每种调用的延迟：
   - 替换 backend-design 第 8 节的推算；
   - 给 PM 定 Q-B8 的数字；
   - 给 B-2、B-9 的时限一个实测的依据。

## 范围

### 做

**1. `setup` 接 `persona` + `seed`**（`eval_api.py`）

- 身份用用例的 `role`。世界模型里没有这个身份时，照旧抛 `ValueError`。
  - 切片只开了 `role.traveler`，用 `role.apprentice`、`role.shepherd-boy` 的画像（hostage-volunteer、wedding-delayer、vigil）在切片上跑不了；
  - 运行器 `--slice` 时按身份筛掉，记「切片外」。
- 起点和正式开局一样：
  - 写局、写一条 `open` 任务、叫叙事者做；
  - 和网关 `POST /v1/playthroughs` 走同一个 `_open`（`startT`、`startAct`、到点的节拍），不用 `opening()` 推演。
- `persona` 只记在这一局 setup 的 Trace 属性上（`eval.persona`），后端不读 `personas.json`（`evals/` 是数据的）。
- `seed`：
  - 传给假模型。假模型现在按输入确定地回答，没有要随机的地方；以后要随机时用它；
  - 真模型和回放不受影响，只记在 Trace（`eval.seed`）。
- 还是不接受的组合：`persona` 和 `checkpoint` / `scenario` / `events` 一起给，抛 `ValueError`。

**2. AI 玩家看什么：`view()` 和 `manifest()`**

- `view(after_seq=0)`：返回 `{ "snapshot": …, "events": […] }`。
  - `snapshot`：api-contract 2.3 的快照，和网关 `GET …/snapshot` 同一个函数（`projection.snapshot`）。里面有：
    - 地点、位置点、在场的人物和能不能搭话；
    - 情境动作、可调查物、场景出口；
    - 时钟、期限一行（玩家知道约定以后才有，S-077 ⑫）；
    - `pending`：幕末待选、意图确认、落地；
    - `status`：结局开始以后是 `ended`。
  - `events`：2.4 的玩家可见事件，`seq` 大于 `after_seq` 的，和网关 `GET …/events` 同一个投影（`projection.visible_event`，玩家写作「あなた」）。
  - 不给变量、节拍结果、不可见的事件。
- `manifest()`：B-7 的生成器给的 manifest，和正式网关 `GET /v1/books/{id}/manifest` 一样，供 AI 玩家看身份的说明、人物的名字和读法。
- 每一步已经返回的这些，AI 玩家也可以看，因为真玩家也听得到、看得到：
  - `reply`：人物的回答；
  - `narration`、`setPiece`：动作的一行叙事和固定演出；
  - `plan`、`alternatives`、`triesLeft`：幕末打算；
  - `confirm`：意图确认的那一句；
  - `error`。
- 每一步返回的 `events`（含不可见的、被否决的）、`state()`、`events()`、`ending()` 是给检查用的，AI 玩家不能看。这一条在运行器里管（数据评审第 2 题）。

**3. 每一步的耗时**

- 每一步的结果加 `elapsedMs`：从调用进 `eval_api` 到返回，含叙事者各次模型调用和提交。
- S-5 用它算「玩家说完到事件提交」的 p50 和 p95。文字模式里没有 Live，这个数不含语音。

**4. 账本多记三列**（共用包 `zoujin_llm.ledger`，数据评审）

- `ms`：这一次调用的耗时，发出到收完；超时的那次记到取消为止。超时重发是另一次调用，另记一行。
- `status`：
  - `ok`；
  - `timeout`：时限到了被取消。现在已经按预计花费记一行（B-8 的 `ClaudeText.call`），只是没标；
  - `bad-output`：回来了但停在 `refusal` / `max_tokens`，或者不过 Schema；
  - `error`：没有回应（连接断了、5xx）。现在不记，以后记一行，花费 0。
- `playthroughId`：在评测的一局里调用时才有。不是个人信息：测试库里的随机 ID。
- 都是可选的，老行没有也照读。还是不写请求和回答的内容。

**5. CI 里走完一局**（假模型）

- 测试里用写死的「玩家」（不是 AI 玩家）在切片上走三条路，每条都走到结局：
  1. 原著路：和老爺、梅洛斯说话，幕末选去处，第四幕等到 beat.24。结局 `canon-reunion`；
  2. 什么都不做：只用 `wait` 和走动。结局 `canon-reunion`（E5-001 的意思）；
  3. 幕末说打算：用 `propose` 说一个能成行的打算，再走到结局。
- 每条路：
  - 最后 `view()["snapshot"]["status"]` 是 `ended`；
  - `ending()` 过契约第 5 节的 Schema；
  - 结局开始以后再调 `say`、`act`，回 `error: "invalid_request"`，不写事件（B-9）。
- 假模型要能撑完一整局：B-9 加的 `ending` 种类之外，分流、提取、检查、改写、叙事、打算在整局里都有规则可回。缺的在本卡补。
- 一整局在 CI 里的耗时记进测试输出，超过 60 秒就看哪里慢（每次调用新建连接、`asyncio.run`）。

**6. S-5 的报告脚本**（`zoujin-s5`，`services/backend/src/zoujin_backend/s5.py`）

- 输入：
  - 账本文件（`ZJ_LEDGER`）和 `item`（`s5`）；
  - 跑模拟局的那个库（`DATABASE_URL`）；
  - 运行器的 `report.json`：每局的用例和画像，要数据给每次运行加 `playthroughId`。
- 输出：`report.json` 和 `report.md`，只有数字：
  1. **每局的产品花费**：
     - 账本里这一局 `use: "product"` 的行，按 `kind` 分；
     - 不算 `reply`：文字模式里它替 Live 当人物（S-085 ①），正式版里人物的话是 Live 说的；
     - Live 那部分按 results-s1 8.5 的公式算：用这一局的轮数，每轮的音频秒数按 R1 前的假设（参数写在报告里，〔推算〕）。会话每 7〜10 轮重建一次（backend-design 第 8 节）。
     - 和 `playthrough_metrics` 的 `cost_*_usd` 对一遍，差超过 1% 就在报告里标出来。
  2. **换算到 20 分钟 40 轮、30 分钟 60 轮**：
     - 切片里有的种类，用实测的每轮平均；
     - 切片里还没有的（世界推进、记忆、候选话语、安全分类），照 B-8「单局成本」的推算，标〔推算〕；
     - 按 1 美元 = 150 日元，和 PRD 7.4 的 300 日元、节约档 240 日元比。
  3. **延迟**：每种调用的 p50、p95、p99、最长，超过各自时限的比例，超时重发的次数；每一步 `elapsedMs` 的 p50、p95；结局从开始到存好的时长。
  4. **叙事者的计数**：每局的轮数、分流就停的、改写、降级、否决、意图确认、幕末打算、结局走模板的。从 `playthrough_metrics` 读。
  5. **AI 玩家和评审员**：`use: "eval"` 的合计，单列，不算进单局成本。
- 时限的建议：每种调用按 p99 加余量给一个数，写在报告里。改代码另开 PR。

- 命令用数据的运行器（live，`--slice`，`item` 写 `s5`），具体参数在代码 PR 里和数据对。串行跑，429 和 529 第一次就停。
- 预计花费〔推算，按 B-8 的单价，切片一局约 15 轮、5 次动作、1〜2 次打算、1 次结局〕：

- 跑完：
  - 结果拷进项目文件夹 `backend/s5/<STAMP>/`，只有数字；
  - 后端报 PM：单局花费、换算、延迟、时限的建议；

## 验收

CI 不联网，只用假模型和回放。

1. **开局**：
   - `setup({"role": "role.traveler", "persona": …, "seed": 1})` 开出来的局，事件和网关 `POST /v1/playthroughs` 开的局一样（ID 除外）；
   - 切片上用 `role.apprentice` 抛 `ValueError`；
   - `persona` 和 `checkpoint` 一起给抛 `ValueError`；
   - Trace 里有 `eval.persona`、`eval.seed`。
2. **`view()`**：
   - `snapshot` 和网关对同一局 `GET …/snapshot` 的响应相同，过 API 的 Schema；
   - `events` 和 `GET …/events?afterSeq=…` 相同，没有不可见的事件；
   - 里面没有 `vars`、`beats`、`schedule`。
3. **`manifest()`**：和正式网关的 manifest 相同（B-7 的生成器）。
4. **走完一局**：「做」第 5 条的三条路都走到结局，结局分类对，`ending()` 过 Schema，之后的输入回 `invalid_request`。
5. **`elapsedMs`**：每种步骤的结果里都有，是非负整数。
6. **账本**：
   - 新行有 `ms`、`status`，评测的一局里有 `playthroughId`；
   - 没有这几列的老行照读，上限照算；
   - 行里没有请求和回答的文字。
7. **`zoujin-s5`**：
   - 用造出来的账本和测试库跑，数字和手算的一样；
   - 不算 `reply` 和 `use: "eval"` 的行；
   - 老行没有 `ms` 时，延迟那一栏写「没有数据」，不报错；
   - 账本和 `playthrough_metrics` 对不上时标出来。
8. **日志和 Trace**：只有 ID、计数、用量、耗时、规则名，没有原话和 AI 玩家说的话。

全量 pytest、ruff、mypy 照旧。CI 停着的时候按 PM 的排法（`pm/ci-freeze-plan.md`），在 PR 上贴本地跑的同一套检查。

## 禁止

- 不部署，不建账号，不建 Key，不花 zg 没批的钱。真模型只在 Mac 上跑，要等 PM 通知。
- Key、项目 ID、账单 ID、部署地址不进仓库、文档、日志、Trace、回放、账本和聊天。Key 只从 Mac 的钥匙串读进环境变量。
- 模型 ID 不写进仓库，只在 Mac 上用环境变量给。
- 日志、Trace、账本、S-5 的报告里不写原话，也不写 AI 玩家说的话、人物的回答、结局的文字，只写 ID、计数、用量、耗时和规则名（data-design 第 8 节）。
- 不读留出样本。
- CI 和容器里不调真模型；测试禁网。

## 评审

- **数据**：
  1. 「分工」那张表对吗？AI 玩家只在运行器里，后端只给 `view()`、`manifest()` 和每一步的结果。
  2. AI 玩家能看的只有 `view()`、`manifest()` 和每一步结果里玩家听得到、看得到的那几个字段（「做」第 2 条）。这条由运行器管，可以吗？
  3. `persona` 的起点照正式开局，不用 `opening()` 推演。E5-001、E7 期望的就是从开局玩起，对吗？
  4. 账本加 `ms`、`status`、`playthroughId` 三列，放在共用包里，你那边的评审员和 AI 玩家要不要也记 `ms`？
