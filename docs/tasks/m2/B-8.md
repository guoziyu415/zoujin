## 目标

做完以后：

1. 除了 Live 的语音和预录句，叙事者用的文字模型都走 Claude。Claude 走 zg 的 Anthropic API 额度（D-028），不走 Vertex 上的 Claude。
2. Claude 的客户端、单价、算钱、账本、回放的键只有一份，后端的叙事者和数据的评审员共用。
3. CI 和容器照旧只用假模型和回放，测试禁网。回放按供应商分开，Google 的回放查不到 Claude 的调用。
4. 每种调用用哪个型号、思考给多深、时限多长，都写在配置里。延迟和单局成本先按推算写在本卡，Mac 上小测一次后换成实数。

### 留在 Google 的（D-028 的「只有 Live 语音和预录句」）

Live 会话里和文字有关的几件事都留在 Live，不拆给 Claude：

- 人物的回答（语音，也包括玩家打字送进去的那一轮）、人物先开口（`speak_first`）；
- 玩家说话的转写（叙事者读的原话就是它）、人物说话的转写（字幕）；
- 幕末用声音说打算的转写（Transcribe Live，Q-B10，M3）；
- B-6 的预录句（Live 照读）和它的自动检查。

拆开的话，同一个人物说话的是 Gemini、打字回答的是 Claude，性格会对不上，还要多一次调用的延迟；而且 Claude 没有实时语音。

**Model Armor**（注入的第二层、个人信息的补充、有害内容只用 HIGH、人物输出的 `sanitizeModelResponse`）不是生成模型，是 Google 的过滤服务。建议照旧当第二层：和 Claude 分类器不是同一家，多一道独立的检查（要 PM 定）。

### 共用的包 `packages/llm`（`zoujin-llm`）

evals 不依赖后端（运行器按模块名载入 `eval_api`），后端也不依赖 evals，所以共用的部分放进一个新的工作区小包，两边都依赖它：

- **账本** `Ledger(path, provider, max_total_usd, max_item_usd=None, item=None, use="product")`：后端现在的 `models/ledger.py` 和数据的 `ClaudeLedger` 合成一个。行格式不变（`at`、`provider`、`kind`、`model`、`usage`、`costUsd`、`item`），加 `use`，按调用属于哪条路径标，不按是不是在评测里跑：叙事者各步、安全分类、记忆、结局、Live、预录句是 `"product"`（在评测里跑也是，Google 那本的行也加）；评审员、AI 玩家是 `"eval"`。S-5 的单局成本只加 `product`。老行没有这一列时按 `kind` 推（`judge`、`player` 是 eval）。上限的算法照旧：总上限只算自己那家，单项上限两本账合起来。
- **单价** `claude-prices.json` 从 `evals/config/` 搬进这个包（数据在 #74 已经按档写了缓存读取：Haiku 是输入价的 0.1 倍，Sonnet、Opus 0.05 倍，Fable 0.025 倍）。按档认模型、算钱、调用前的预计都在这里。Google 的单价照旧在后端 `config.PRICES`。
- **回放的键** `<provider>|<模型>|<提示版本>|<请求的 sha256>`：数据的评审员已经是这个格式；后端的键现在没有 provider，本卡加上。
- **Anthropic 的连接**：同步（评审员、Batch）和异步（叙事者）两个客户端都设 `max_retries=0`，Key 只从环境变量 `ANTHROPIC_API_KEY` 读；SDK 的错误换成不带原消息的异常（429、529 → `RateLimited`，其他 → `ModelCallFailed` 只带状态码）。SDK 放在这个包的可选依赖 `real` 里，后端和 evals 的 `real` 都引它。

评审员的 Batch、校准、`agree` 留在 evals；`judge.py` 改成从共用的包导入，这一步的改动请数据评审。

### 后端的改动

1. **配置**：`TEXT_MODELS` 改成每种提示一行（供应商、型号档、思考、effort、输出上限、时限）。Claude 的型号档写 `haiku`、`sonnet`，回放的键用档名加代号（如 `sonnet-5.5`）；具体的模型 ID 只在 Mac 上用环境变量给（`ZJ_CLAUDE_HAIKU`、`ZJ_CLAUDE_SONNET`），仓库里不写，和数据的评审员一样。ID 里认不出档名的不调。
2. **真客户端** `models/claude.py`（`ClaudeText`，和 `RealText` 同一个接口）：
   - 世界模型前缀放在 system 的第一段，这种提示的说明放第二段，两段后面各打一个缓存点（前缀同一档的各种提示共用，说明同一种提示共用）；状态、这一轮、请求字段放 user，渲染沿用 `vertex.render`（前缀那一段挪出来共用，`models/render.py`）。
   - Schema：发给 API 的那份去掉不支持的关键字、对象一律 `additionalProperties: false`；收到以后照旧用完整的 Schema 在本地验，不过就 `BadOutput`，按时限的规则重发。
   - 不传 `temperature`：Anthropic 的 Python SDK 1.13.0 的 `messages.create`（同步、异步两个）没有 `temperature`、`top_p`、`top_k` 这几个参数（核法：用 `inspect.signature` 看了两个签名，传进去直接报 `TypeError`；只核了 SDK，没拿裸 HTTP 去试 API）。v0.2 写的「不开思考的才传」做不到，输出稳不稳靠 Schema 和思考的档。
   - 调用前按预计花费查账本（`BudgetStop`），调用后按实际用量记账；被时限取消的按预计记（可能已经计费，宁多记）。
3. **按调用选客户端**：一次评测里 Claude 和 Google 的调用可以同时有（`reply` 走 Google）。Vertex 的环境变量只在真要调 Google 那几种时才查，只调 Claude 时不要求。
4. **跑和服务分开处理 429、529**：Mac 上的跑（S-2、评测、小测）第一次就停（S-079）；以后服务玩家时不停服，按时限的规则重发一次，还不行就这一轮只提交时钟事件，计进 `playthrough_metrics`（backend-design 2.4 的降级）。本卡只做跑的那一半，服务那一半写进代码的分支和测试里，等正式网关接上。
5. **两本账的上限**：加 `ZJ_MAX_CLAUDE_USD`（Claude 那本的总上限，真模型时必填，没有默认值）；`zoujin-s2` 加 `--max-claude-usd`。
6. **回放**：键加 provider，CI 的回放（`fixtures/model-replays/`）用假模型重录；E-0 的快照只有 ID 和 `checker` 里的模型名变时照规矩处理（只差 ID 不提交）。
7. **花费补全**（数据在 #76 的评审里提的）：作废的一轮在窗口里已经花的钱（走 `Gone` 的那条路），和失败后重发的那几次，现在都没记进 `playthrough_metrics`，每局的花费和「节约」档会少算。本卡动花费时一起补上，各提示类型的 `cost_*_usd` 都算进去。
8. **小测命令** `zoujin-probe`：从 E-0 切片用例在假模型下录下来的请求（不碰留出样本）里，每种提示取 20 个，在 Mac 上串行调真模型，量首字和全部的 p50、p95，以及输入、缓存、输出、思考的 token。结果文件只有数字，不存请求和回答的文字。

## 单局成本（〔推算〕，S-5 用实测替换）

假设：

- 世界模型前缀加这种提示的说明约 1.7 万 token。我按切片和草稿的世界模型量过前缀约 1.5〜1.7 万 token；数据成本模型里写的提取输入 3,000 token 偏少，两本账重算时按这个改。前缀走缓存，每种提示每局按写一次缓存算（有很多人同时玩时，缓存在局和局之间共用，更便宜）。
- Haiku 的分词器同样的文字多算约 30% 的 token（数据看的模型说明），下表 Haiku 那几行的 token 已经乘上。
- 次数照数据的基准：40 轮，约四成闲聊在分流就停；六成的轮要模型检查、平均 1.3 次；动作约 8 次（每次动作也提取一次）。

|---|---|---|---:|---:|---:|---:|---:|
| 分流 | Haiku | 关 | 0 | 1,200 | 30 | 40 | $0.005 |
| 提取 | Sonnet | `low`，不先思考 | 17,000 | 1,500 | 300 | 32 | $0.29 |
| 模型检查 | Sonnet | `medium`，自适应 | 17,000 | 2,000 | 1,200 | 31 | $0.59 |
| 改写或降级 | Sonnet | `low`，不先思考 | 17,000 | 2,000 | 400 | 6 | $0.10 |
| 地の文 | Sonnet | `low`，不先思考 | 17,000 | 1,200 | 120 | 8 | $0.08 |
| 幕末打算 | Sonnet | `low`，自适应 | 17,000 | 2,000 | 600 | 3 | $0.08 |
| 安全分类 | Haiku | 关 | 0 | 1,600 | 30 | 44 | $0.007 |
| 记忆一句 | Haiku | 关 | 0 | 1,000 | 100 | 20 | $0.003 |
| 候选话语 | Haiku | 关 | 0 | 2,000 | 200 | 24 | $0.007 |
| 删除那一句 | Haiku | 关 | 0 | 800 | 80 | 1 | $0.0001 |

合起来：

| | 20 分钟 40 轮 | 30 分钟 60 轮 | 压力（60 轮，每轮都检查、2 次尝试） |
|---|---:|---:|---:|
| Claude 小计 | $1.61 | $2.07 | $3.43 |
| Live 语音（Google，数据的模型，不变） | $0.39 | $0.58 | $0.58 |

每局 300 日元的上限（PRD 7.4）差不多正好碰到。钱主要花在 Sonnet 的检查、提取和世界推进上，Haiku 那几样合起来不到 4 日元。省钱的办法，按对质量的影响从小到大：

1. 提取换 Haiku：合计约 259 円。
2. 检查的 effort 从 `medium` 降到 `low`：思考少一半左右，约 −30 円〔推算〕。
3. 检查也换 Haiku：合计约 177 円。
4. 叙事者全用 Haiku：约 78 円。

## 风险

- **检查最慢**：Sonnet 加 `medium` 的思考，长尾可能碰到 15 秒。Mac 上小测的 p95 超过 12 秒，就先降 effort。（10-11 小测：p95 3.4 秒，没碰到。）
- **发给 API 的 Schema 太复杂会被拒**：幕末打算原来 10 个联合类型，第一次调用就回 400；压到 4 个就过了。测试按小测里过了的最多 5 个管着（`test_api_schemas_stay_as_small_as_what_passed`），以后加提示的种类先照这个量。
- **结局生成**：Sonnet 写约 3,000 token（含思考），推算 15〜40 秒，盖不住 10〜20 秒的结局演出。这归结局的那张卡：分两次生成（卡面先出、其余后补），或者流式先推卡面。本卡只定型号。
- **Schema 第一次编译慢**：每种提示的 Schema 第一次用要多等一会儿，之后缓存 24 小时。服务起来时先各调一次假请求预热；评测第一轮的延迟不计。
- **速率等级**：新账号的每分钟调用和 token 上限低。开发期都是串行，够用；R2 有多人同时玩以前，按实测的并发看要不要升级（升级要花钱，问 zg）。
- **提示是给 Gemini 写的**：本卡不改提示的字，版本号不变，只换供应商和型号。Mac 上调检查提示（Z-8 那约 1 美元的一项）现在调的是 Claude。

## 验收

1. **假模型和回放**：七种提示都能在 `ZJ_MODEL=fake` 和 `replay` 下跑；全量 pytest、ruff、mypy、E-0 确定性部分照旧通过。CI 不装 Anthropic 的 SDK 也能跑（只有 `real` 需要），测试禁网。
2. **真客户端**（用假的传输层，不联网）：
   - 请求的形状：system 两段、缓存点在世界模型前缀和说明上、`output_config.format` 和 `effort`、思考的设置、不带 `temperature`；
   - 发给 API 的 Schema 七种都过本地的检查（没有不支持的关键字，对象都是 `additionalProperties: false`）；本地验的仍是完整的 Schema（`maxItems` 之类照样拦得住）；
   - 回答解析：取第一段文字；不是 JSON 或不过 Schema → `BadOutput`，带上已花的钱；`refusal`、`max_tokens` 也算这次失败，记账；
   - 账本：行里有 `provider: "claude"`、`use: "product"`、`kind`、`item`；超上限在调用前停，不发；被时限取消的按预计记；
   - 429、529 → `RateLimited`，第一个就停；其他 HTTP 错误 → `ModelCallFailed`，消息里只有状态码；
   - Key 不出现在日志、Trace、回放、账本和异常消息里（测试：把一个假 Key 放进环境，跑一遍，在这些输出里搜不到）。
3. **配置**：真模型时没设 `ANTHROPIC_API_KEY`、`ZJ_CLAUDE_HAIKU`、`ZJ_CLAUDE_SONNET` 或 `ZJ_MAX_CLAUDE_USD` 就退出，不发请求；ID 里认不出档名的不调；只调 Claude 的跑不要求 Vertex 的环境变量。
4. **回放**：键里有 provider；同一个请求在 Google 下录的回放，换到 Claude 查不到（`ReplayMissing`）；CI 的回放重录了，`ReplayMissing` 照旧不悄悄回空。
5. **共用的包**：后端和数据的评审员用同一个账本类、同一份单价、同一个回放键函数；数据的 `test_judge.py` 照旧通过；仓库里只剩一份 Claude 单价。
6. **小测命令**：不带 `--confirm` 打印要调几次、预计花费和完整的命令，不调；带 `--confirm` 串行跑，第一个 429、529 就停，到上限就停；结果文件里只有数字。
7. **花费补全**：一轮在窗口里被作废、一次调用超时重发，这些已经花的钱都在这一局的 `playthrough_metrics` 里（测试用假模型给每次调用记一个固定的花费，对总数）。
8. **文档**：backend-design 第 7 节的选型表、第 8 节的单局成本按本卡改；`services/backend/README.md` 写 Mac 上的跑法（Key 从钥匙串读进环境变量）。
