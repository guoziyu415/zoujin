## Current state (checked when writing the card) / 現状（カード作成時に確認）

- Identities are generic in the backend: the start of a playthrough follows `Role.startT` / `startPlace` / `initialKnowledge`, R7 follows `access` / `conditionalAccess` / the `roles` of situational actions, `{role}` in ending titles and 「顔見知り」 in `player_card` all follow the world model, without depending on IDs.
  身分はバックエンドでは汎用的に扱われている：プレイの開始は `Role.startT` / `startPlace` / `initialKnowledge` に従い、R7 は `access` / `conditionalAccess` / 状況アクションの `roles` に従い、エンディングのタイトルの `{role}`、`player_card` の「顔見知り」もすべて世界モデルに従っており、ID には依存しない。
- The manifest lists only identities with `release` ≤ `ZJ_RELEASE` whose starting scene has a pack: 石屋の弟子 starts in a corner of the square (which has a pack) and can already be chosen; 村の牧童 starts in the village, so **until the village pack exists it is not listed and starting returns 400** (`test_manifest.py`); once the pack arrives it opens automatically, with no further backend change.
  manifest に載るのは、`release` ≤ `ZJ_RELEASE` で開始シーンにパックがある身分だけ：石屋の弟子の開始地点は広場の一角（パックあり）なので、すでに選べる。村の牧童の開始地点は村なので、**村のパックができるまでは載せず、開始すると 400 を返す**（`test_manifest.py`）。パックが届けば自動的に開放され、バックエンドの変更はもう要らない。
- Three things are missing (the table in ux-design 5.1): who speaks first at the start; how characters address the player; the characters' side does not know about the small two-way mutual aid at the start (S-048).
  足りないのは三つ（ux-design 5.1 の表）：開始時に誰が先に話すか。登場人物がプレイヤーをどう呼ぶか。開始時の双方向の小さな助け合い（S-048）を人物の側が知らないこと。

## What was done / 実施内容

`narrator/roles.py`:

`narrator/roles.py`：

1. **Who speaks first at the start**: among the opening mutual aid (entries in a character's `mutualAid` whose `opening` is this identity), the character of the "you for him" (`fromYou`) entry speaks first: 旅人 → 老爺, 石屋の弟子 → セリヌンティウス, 村の牧童 → メロス. At the start, `playthroughs.arrival = {actId: startAct, line: the identity's summary, opener}`, the same mechanism as the landing after an act change (api-contract 3.11): it is in `welcome.pending.arrival`, the frontend shows that line of 地の文 and sends `act_landed`, and the server has him speak first. Identities without opening mutual aid (those in the second version) do not have anyone speak first.
   **開始時に先に話す人**：開始時の助け合い（人物の `mutualAid` のうち `opening` がこの身分のもの）の中で、「あなたが彼のために」（`fromYou`）の項目の人物が先に話す：旅人 → 老爺、石屋の弟子 → セリヌンティウス、村の牧童 → メロス。開始時に `playthroughs.arrival = {actId: startAct, line: 身分の summary, opener}` とし、幕の切り替え後の着地と同じ仕組みを使う（api-contract 3.11）：`welcome.pending.arrival` に入っており、フロントエンドはその 1 行の地の文を表示して `act_landed` を送り、サーバーが彼に先に話させる。開始時の助け合いがない身分（第 2 版のもの）では誰も先に話さない。
2. **Form of address**: under 「# 話し相手」 in the Live situation briefing, add 「呼び方：…」 (旅の方／おまえ／弟子よ／坊主). The world model's `Role` does not have this field yet, so it lives in code for now 〔provisional: switch to reading the world model once Data adds it to the contract〕.
   **呼び方**：Live の状況説明の「# 話し相手」の下に「呼び方：…」（旅の方／おまえ／弟子よ／坊主）を足す。世界モデルの `Role` にはまだこの項目がないので、ひとまずコードに置く〔暫定：データが契約に追加したら世界モデルを読むように変える〕。
3. **Opening mutual aid in the situation briefing**: in the opening act, the "you for him" entry is written for this character (「相手があなたにしてくれそうなこと：…」). The "him for you" entry is not written: that comes later (e.g. entrusting the workshop before being summoned late at night), and writing it would be a spoiler (S-092); the narrator still judges from `mutualAid` in the world model as before.
   **開始時の助け合いを状況説明に入れる**：開始の幕では、「あなたが彼のために」の項目をこの人物向けに書く（「相手があなたにしてくれそうなこと：…」）。「彼があなたのために」の項目は書かない：それはもっと後のこと（例：深夜に呼び出される前に工房を託す）で、書けばネタバレになる（S-092）。ナレーターは従来どおり世界モデルの `mutualAid` を見て判断する。

## For other threads / 他のスレッドへ

If you would rather not show a landing page at the start, tell Backend 4 and it will switch to sending `turn_started { reason: "arrival" }` directly at the start.
  フロントエンド 3：開始時の `welcome.pending.arrival` に値が入るようになった（三つの身分すべて）。フロントエンドは再接続と同じ経路で着地ページを出し、`act_landed { actId: startAct }` を送る。開始時に着地ページを出したくなければバックエンド 4 に伝えてほしい。開始時に直接 `turn_started { reason: "arrival" }` を送るように変える。

  データ：`Role` に任意の呼び方のフィールド（例 `addressedAs`）が加わったら、`roles.ADDRESS` は世界モデルを読むように変える。先に話す一言（`designLines`）は B-6 の事前収録セリフでまかなう。
