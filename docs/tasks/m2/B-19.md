## 现状（写卡时查的）

- 身份在后端是通用的：开局按 `Role.startT` / `startPlace` / `initialKnowledge`，R7 按 `access` / `conditionalAccess` / 情境动作的 `roles`，结局标题里的 `{role}`，`player_card` 的「顔見知り」都按世界模型走，不认 ID。
- manifest 只列 `release` ≤ `ZJ_RELEASE`、起点场景有包的身份：石屋の弟子起点在广场一角（有包），已经能选；村の牧童起点在村子，**村子的包出来以前不列、开局回 400**（`test_manifest.py`），包到了自动开放，后端不用再改。
- 缺的三样（ux-design 5.1 的表）：开局谁先开口；人物怎么称呼玩家；开局的双向小互助（S-048）人物一侧不知道。

## 做了什么

`narrator/roles.py`：

1. **开局先开口**：开局互助（人物 `mutualAid` 里 `opening` = 这个身份的）中「你为他」（`fromYou`）那一条的人物先开口：旅人 → 老爺，石屋の弟子 → セリヌンティウス，村の牧童 → メロス。开局时 `playthroughs.arrival = {actId: startAct, line: 身份的 summary, opener}`，和幕切换的落地同一套（api-contract 3.11）：`welcome.pending.arrival` 里有，前端显示那一行地の文、发 `act_landed`，服务端让他先开口。没有开局互助的身份（第二版的）不先开口。
2. **称呼**：Live 局势说明「# 話し相手」下加「呼び方：…」（旅の方／おまえ／弟子よ／坊主）。世界模型的 `Role` 还没有这一项，先放代码里〔暂定：数据把它加进契约以后改读世界模型〕。
3. **开局互助进局势说明**：开局那一幕里，「你为他」那条写给这个人物（「相手があなたにしてくれそうなこと：…」）。「他为你」那条不写：那是之后的事（例：深夜被召之前托付工房），写了就是剧透（S-092），叙事者照旧看世界模型里的 `mutualAid` 判。

## 给别的线程

- 前端 3：开局时 `welcome.pending.arrival` 现在有值（三个身份都有），前端照重连那条路出落地页、发 `act_landed { actId: startAct }`。不想在开局出落地页的话告诉后端 4，改成开局直接发 `turn_started { reason: "arrival" }`。
- 数据：`Role` 加一个可选的称呼字段（例 `addressedAs`）以后，`roles.ADDRESS` 改读世界模型；先开口的一句（`designLines`）由 B-6 的预录句覆盖。
