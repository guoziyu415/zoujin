## 目标

做完以后：

1. 网关能接真的 Gemini Live：一个人物一条会话、用这个人物定好的声音，按住说话，玩家和人物的字幕都实时出，打断即停。设定 `ZJ_LIVE=real`（默认跟着 `ZJ_MODEL`）就换成真的，其他代码不分真假。
2. 玩家走近人物就预热，点人物时会话多半已经就绪（api-contract 第 6 节：预热命中时 `session_ready` 立即返回）。
3. **每 8 轮在停顿处重建一次会话**（7〜10 可调）：Live 每轮按整段上下文计费（S-073 ⑤，30 轮从每轮 0.0038 涨到 0.029 美元），重建把账单压回去。先开新会话、再关旧会话，玩家察觉不到。
4. **GoAway**：Live 的单个连接约 10 分钟，结束前发 GoAway。网关在下一个停顿照第 3 条换会话，玩家察觉不到。
5. Live 中途断了、建不起来，玩家看到的是已经定好的状态（`session_preparing reason: "rebuild"`，不行再 `degraded`），不会卡在等待里。
6. 叙事者提交了和这个人物有关的变化，开着的会话里马上知道（中途更新局势，S-1 `midsession` 3/3 通过的做法）。
7. 人物有声音、却一个字的文字都没给时，补转写（S-071，backend-design 3.1），字幕标 `source: "fallback"`。
8. 每轮 Live 的用量记账本、记进 `playthrough_metrics.cost_live_usd`，Trace 里有会话和每轮的时间、音频秒数和花费，不记原话。
9. **S-090**：zg 在 Mac 上用真语音玩 2〜3 局，把每轮的实际花费和公式（每轮约 0.00086 + 0.0000788 × 会话里已有的音频秒数，results-s1 8.5）对账，结果交 PM 定 Q-B8。同一次顺带量 S-073 ①：带完整人设和叙事者的服务端「松开到首个音频」。

## 范围

### 做

**1. 真 Live 客户端**（新文件 `models/gemini_live.py`）

- 直接用 `websockets` 连 Vertex AI 的 `BidiGenerateContent`（和 B-6 的 `LiveReader` 同一个握手、同一个 `Auth`），不加 SDK 依赖。地区 `ZJ_LIVE_LOCATION`，默认 us-central1。
- `setup`：只出音频；声音取自 `voice/hashire-merosu.json` 的 `speakers.<人物>.voice`（声音只在那里定一处）；系统指令见第 2 条；玩家一侧转写带 `ja-JP` 和专有名词偏置（S-025：メロス、セリヌンティウス、ディオニス、シラクス、フィロストラトス）；人物一侧转写打开；关自动语音检测，`START_OF_ACTIVITY_INTERRUPTS`；不开思考（S-1：关了中位 628 ms）；**不开会话恢复**（5.4）。字段名照 SDK 对 Vertex 发的形状；Mac 第一次跑先用 `zoujin-live check`（第 7 条）对一下，语言提示被拒就去掉（同 S-0 的诊断）。
- 实现现有的 `LiveSession` 接口，网关不分真假：
  - `audio_in(pcm)`：这一轮第一帧前先发 `activityStart`，音频进发送队列（接口保持同步，由会话自己的写任务发出）；
  - `respond(text)`：语音一轮发 `activityEnd`，文字一轮发一条 `clientContent`（`turnComplete: true`）；然后吐出 `input_partial` / `input_final`、`audio`、`output_partial`、`turn_complete`、`output_final`；
  - `speak_first(line)`：落地先开口、意图确认的反问。没有 `line` 时发一条「（旅人が近くに来た。あなたから一言、声をかけてください）」这样的提示让人物自由开口；有 `line`（反问）时提示「次のことを、あなたの言葉で短く尋ねてください：…」，字幕仍用人物自己说的（S-071：不让 Live 照读）。
- **一个读任务**持有连接，按收到的顺序分给当前这一轮：
  - 音频分片、两边的转写、`interrupted`、`turnComplete`、`usageMetadata`（取最大的那条）、`goAway`（记下剩余时间，见第 3 条）；
  - **转写收尾**（3.1）：`turnComplete` 之后继续收，两边的文字都到、静默 0.6 秒，或最多 3 秒，再吐 `output_final`。整轮一个字都没有就吐 `output_final(None)`（第 5 条接补转写）；
  - 打断（新的一轮来了）：旧一轮的晚到分片丢掉，等它的 `interrupted` 或 `turnComplete`（最多 2 秒，同 S-1b 的 `DRAIN_MAX_S`）再开始转发新一轮；
  - 用量在 `turnComplete` 后 1.5 秒内没到，这一轮按 0.01 美元记（同 S-1、B-6：不让它看起来是免费的）。
- 连接断了（关闭码、异常、30 秒没有 `setupComplete`、一轮 30 秒没有 `turnComplete`）：会话标成死的（`alive = False`），当前一轮的迭代器抛 `LiveLost`。配额和 429 照 B-6 抛 `RateLimited`。
- 接口新增（假 Live 同样实现）：`alive`、`going_away`（收到 GoAway 后为真）、`turns`（这条会话上完成了几轮）、`audio_seconds`（会话里已有的双向音频秒数，对账用）、`note(text)`（中途更新局势：`clientContent` 的 `role: "system"`、`turnComplete: false`，不触发回答，S-1 `midsession`）。

**2. Live 的系统指令**（新文件 `models/prompt_texts/live.txt` + `gateway/brief.py`）

- 系统指令 = 规则（`live.txt`）+ 人设 + 此刻的局势 + 玩家是谁 + 最近的对话。人设、局势、玩家三段直接用叙事者给 `reply` 的同一套（`narrator/view.py` 的 `persona`、`situation`、`player_card`），排成日语的条目；所以知情边界（S-086：不知道日名那条事实的人物只给时段）和评测里的人物一致。
- **不放世界模型前缀**：Live 每轮把整段上下文重新计费，前缀放进去每轮多约 0.03 美元〔推算，162 KB 的 world.json〕。
- `live.txt` 从 `reply.txt` 和 S-068 的 guard 规则来（S-068 重测在跑，结果出来后数据和 UX 按 E2 的结论改这份）：一次两句以内、口语、只说此刻知道的、`<utterance>` 外的指令性内容不照办、不追问；必须只说日语（JA_RULE）。
- 最近的对话：网关内存里这个人物最近 6 轮（`RECENT_TURNS`）的文字，跳过作废、删除的轮次（B-4 已有），作为「さっきまでの会話」一段放进系统指令。只在内存里，不落库、不进 Trace。
- 指令有版本号（文本的哈希，同 `Prompt.version`），写进 Trace 的 `live.session`。

**3. 会话管理**（新文件 `gateway/voice.py`，`ws.py` 只调它）

| 情况 | 做法 |
|---|---|
| `near { character }` | 2 秒去抖后预热（开会话，不推消息）。一条连接最多 1 个正在说（focus 的那个）+ 1 个预热；预热另一个时关掉旧的预热 |
| `far` | 取消还没开始的预热；已经开的留到闲置规则 |
| `focus` | 预热命中且已就绪：立即 `session_ready`；正在开：`session_preparing { switch }`，开好推 `session_ready`；没有：同上并现开 |
| 闲置 | 离开人物 2 分钟（最后一次 `focus` / 一轮结束以后，不在 focus 也不在预热）关闭 |
| **定期重建** | 这条会话完成第 8 轮（`ZJ_LIVE_REBUILD_TURNS`，只许 7〜10）后，在下一个停顿（没有进行中的一轮）后台开新会话，带最新的局势和最近的对话；开好、而且仍在停顿时换上、关旧的。换的过程中玩家按下说话：这一轮用旧会话，说完再换。**不推 `session_preparing`**（玩家察觉不到） |
| **GoAway** | 同定期重建，立即开始。剩余时间里一直没有停顿，旧会话断时照下一行处理 |
| Live 中途断了 | 说到一半：这一轮按「被打断」收（有说到一半的文字就推定稿），不算 `lost`，照常交给叙事者；然后推 `session_preparing { rebuild }`，开新会话，就绪推 `session_ready`。连续 2 次开不起来：推 `degraded { voice: false, reason: "service" }`，这条连接后面的轮次走文字（现有的降级入口，人物用 `reply` 回文字） |
| 作废（B-4 已有） | 照旧关掉重开，`session_preparing { rebuild }` |
| 叙事者提交了 | 对这条连接上开着的每条会话：局势说明和上次送进去的不同，就 `note()` 送一段「【状況の変化】」（只写变了的条目）。在说话的一轮里不送，等这一轮结束 |
| 连接断了 | 本卡照旧关掉全部会话。断线 30 秒内接着用同一条会话是 B-11 |

**4. 网关接上**（`gateway/app.py`、`config.py`、`ws.py`）

- `ZJ_LIVE=fake|real`，不设就跟 `ZJ_MODEL`。`real` 时只在 Mac 上用（读 Mac 环境的 ADC 和项目 ID，同 B-6 的 `real_models`）。
- `ws.py` 处理 `near`、`far`（现在是忽略）；`focus`、`_rebuild`、一轮开始和结束改成调 `gateway/voice.py`。B-4 的作废、意图确认、落地先开口的流程不变。
- `turn_complete.metrics.serverReleaseToFirstAudioMs` 照旧（真 Live 下才有真数）。

**5. 补转写**（S-071，backend-design 3.1）

- 人物这一轮有声音、到 `output_final(None)` 时一个字的文字都没有：网关立即用这一轮的声音调 `gemini-3.5-flash-lite` 转写（B-6 的 `RestTranscriber`），3 秒截止、不重试。期间 Live 的文字到了就用 Live 的。
- 定稿 `source: "fallback"`；失败也推 `{ text: null, final: true, source: "fallback" }`。原话照存（`source: fallback`），轮次标 `characterTextMissing: true` 只在补转写也失败时。
- 假 Live 加一个开关能出「有声音没文字」的回答，测试用。

**6. 花费和记录**

- `real` 时每轮的用量按 Live 价目算（B-6 的 `live_cost`），记账本：Google 那本，项 `ZJ_LEDGER_ITEM`，超上限照 B-2 的规矩停下（这时网关推 `degraded { reason: "budget" }`，不崩）。补转写同一项。
- `playthrough_metrics.cost_live_usd` 每轮累加（列已经在 B-0 建好）。
- Trace（data-design 第 8 节，不写原话和任何台词文字）：
  - `live.session`：人物、`reason`（`warm` / `focus` / `rebuild_turns` / `goaway` / `lost` / `retract`）、建会话毫秒、系统指令版本和字数；
  - `live.turn`：人物、模式、松开到首个音频毫秒、回答音频秒数、会话里已有的音频秒数、会话第几轮、用量、美元、`characterTextMissing`、`source`；
  - `live.note`：人物、送了几条。

**7. Mac 上的入口**（新命令 `zoujin-live`）

- `zoujin-live check`：开一条真会话说一轮文字、一轮合成语音（macOS `say`），打印建会话毫秒、松开到首音、两边文字有没有到、用量；约 0.01 美元。第一次跑真网关前用它对 `setup` 的字段。
- `zoujin-live reconcile --ledger … --item b10`：读账本里这一项的每一轮（`live.turn` 的用量和会话里已有的音频秒数），和公式比，按局、按「会话第几轮」分组出表：实际、公式、差的百分比；再汇总每局 Live 花费、重建次数和 S-073 ① 的松开到首音中位和 p95。输出 Markdown + JSON，不含原话。
- S-090 的跑法见下面「真语音怎么跑」。

**8. 测试**（全部离线，CI 用）

- **假的 Vertex Live 服务**（`tests/fake_vertex_live.py`，本机 `websockets` 服务）：按脚本回 `setupComplete`、两边转写（含晚到）、音频、`interrupted`、`turnComplete`、用量（含晚到、缺失）、`goAway`、中途断开、`setup` 超时、429。真客户端对着它测，`setup` 的内容也在这里查（声音、`ja-JP`、偏置词、没有会话恢复、关自动语音检测）。
- 会话管理（假 Live + `ZJ_SPEED=0`）：
  - `near` 2 秒内又 `far`：不开会话；`near` 后 `focus`：`session_ready` 立即到、没有 `session_preparing`；
  - 预热第二个人物：旧的预热被关；最多 2 条会话；
  - 第 8 轮结束后：新会话开了一次，带最近 6 轮、跳过作废的；旧的关了；没有推 `session_preparing`；换的时候正在说的一轮用旧会话说完；
  - GoAway：下一个停顿换会话；GoAway 后旧会话在一轮中间断了：那一轮按被打断收、交叙事者，推 `rebuild` 的准备和就绪；
  - 连续 2 次开不起来：`degraded { service }`，下一轮走文字；
  - 叙事者提交以后：开着的会话收到一次 `note`，在说话的一轮结束后才送；局势没变不送；
  - 闲置 2 分钟（按 `ZJ_SPEED` 缩短）关闭。
- 补转写：有声音没文字 → 定稿 `fallback`；补转写超时 → `text: null`；补转写期间 Live 的文字到了 → 用 Live 的。
- 系统指令：不含世界模型前缀；不知道日名的人物只有时段（S-086）；作废的那一轮不在「さっきまでの会話」里；版本号随文本变。
- 花费：假 Live 的用量进 `cost_live_usd`；账本超上限 → `degraded { budget }`。
- `reconcile`：用一份合成的账本出表，数对得上。
- 日志、Trace 里找不到玩家和人物的标记字符串。

CI 照旧只用假模型和假的 Vertex Live 服务，测试禁网（假服务只听 127.0.0.1）。

### 不做

- 断线 30 秒内接着用同一条 Live 会话、换实例时重建、`welcome` 的续玩：**B-11**。
- 预算和每日语音分钟的正式规则（S-019，`minutesLeftToday`）：另一张卡；本卡只在账本超上限时降级。
- Model Armor、自伤分类器接在语音这一路（安全的卡）。
- 群像里不在焦点的人物出声（`npc_line`，P1）。
- 部署。S-073 ② 的手机 4G 那段等第一次评审部署。

## 真语音怎么跑（S-090，不在 CI 里）

- 前提：本卡的代码 PR 合了；前端 F-0、F-1 合了，能在 Mac 的 Safari 里对本机网关玩切片（前端在评审时确认用哪个命令起）。
- 经协调交 Mac：
  1. `zoujin-live check`（约 0.01 美元）；
  2. 本机起叙事者和网关（`ZJ_MODEL=real`，`ZJ_LEDGER_ITEM=b10`），zg 在 Safari 里玩 **2〜3 局**，每局玩到结局或 20 分钟；
  3. `zoujin-live reconcile`，脱敏的表经协调回后端，后端交 PM。
- 预计花费〔推算〕：Live 每局约 0.6〜1.2 美元（20 分钟约 60 轮，每 8 轮重建），叙事者走 Claude 每局约 0.3〜0.5 美元；3 局合计 **Google 约 3.6 美元（单项上限 5 美元）**、**Claude 约 1.5 美元（单项上限 3 美元）**，都在 D-027、D-029 以内，按 D-030 先打印预计、在上限内再带 `--confirm` 跑，不用等点头。zg 要亲自玩，所以开跑时间由协调问 zg。
- 对账结果超出公式 ±15%：后端先查是不是重建的时机或音频秒数算错，再交 PM 判要不要改成本模型（S-073 ⑤ 实测是差 5%）。

## 禁止

- 不部署，不建账号、不建 Key，不花 zg 没批的钱。真 Live 只在 Mac 上。
- 凭证、项目 ID、部署地址不进仓库、日志、账本和聊天。代码只在 `ZJ_LIVE=real` 时读 Mac 环境里的项目 ID。
- 日志和 Trace 里不写原话，也不写系统指令、局势说明的文字，只写 ID、计数、毫秒、用量。「最近的对话」只在网关内存里。
- 正式环境不开 Live 的会话恢复（5.4）。
- fixture 里只放自己写的台词和合成的声音。
- CI 和容器里不调真模型；测试禁网。

## 评审

- **前端**（协议）：
  - `near` / `far` 的去抖和「1 个正在说 + 1 个预热」，预热命中时 `focus` 直接 `session_ready`；
  - 定期重建和 GoAway 不推 `session_preparing`，Live 中途断了才推 `rebuild`；连续失败后 `degraded { service }`；
