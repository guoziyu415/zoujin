## Goal / 目標

When this is done:

完了すると：

1. When a playthrough's cost reaches 80% of 300 yen (240 yen) it enters the **economy tier**; at 100% characters switch to **text answers**, and the narrator carries on as usual. All the player sees is the text answers after `degraded { reason: "budget" }`.
   1 プレイの費用が 300 円の 80%（240 円）に達したら**節約モード**に入り、100% に達したら登場人物は**文字での返答**に切り替わる。ナレーターはいつもどおり動く。プレイヤーに見えるのは `degraded { reason: "budget" }` の後の文字の返答だけ。
2. Per account per day: **5 playthrough starts** are actually enforced (429 `daily_limit`, checked before 409); **60 minutes of voice** are actually counted (`minutesLeftToday`, push `limits` when 5 minutes remain, `degraded { reason: "daily" }` when used up).
   アカウントごと 1 日あたり：**プレイ開始 5 回**を実際に制限する（429 `daily_limit`。409 より先に判定）。**音声 60 分**を実際に数える（`minutesLeftToday`、残り 5 分で `limits` を送り、使い切ったら `degraded { reason: "daily" }`）。
3. There is a **global voice switch**: when off, all new connections and new sessions are text mode (`degraded { reason: "service" }`), without redeploying.
   **全体の音声スイッチ**を設ける。オフにすると、新しい接続と新しいセッションはすべてテキストモードになる（`degraded { reason: "service" }`）。再デプロイは不要。
4. The times each playthrough enters the economy tier and degrades go into `playthrough_metrics`, and the `budget` Span records how many yen a playthrough has spent, so Data can compute the "share of degraded playthroughs" (target < 2%).
   各プレイが節約モードに入った時刻と縮退した時刻を `playthrough_metrics` に入れ、`budget` Span に 1 プレイで何円使ったかを記録する。これでデータが「縮退したプレイの割合」（目標 < 2%）を計算できる。
5. `setup.budgetTier: "saving"` at the eval entry point really makes the narrator run in the economy tier (E6).
   評価入口の `setup.budgetTier: "saving"` で、ナレーターが実際に節約モードで動く（E6）。

Already in place (not redone by this card): `Voices.degrade(why)` pushes `degraded` and `session_ready { voiceAvailable: false }`; `can_speak()` degrades when the ledger hits its cap (the development-time hard cap, which is separate from this card's per-playthrough cap; both are kept); the `cost_*_usd` columns. B-10 left "characters switch to text answers" to this card (the "Live drops mid-way" row in the B-10 card).

すでにあるもの（このカードではやり直さない）：`Voices.degrade(why)` は `degraded` と `session_ready { voiceAvailable: false }` を送る。台帳が上限に達すると `can_speak()` が縮退させる（開発期間中のハードな上限で、このカードの 1 プレイの上限とは別物。両方とも残す）。`cost_*_usd` の各列。B-10 は「登場人物を文字の返答に切り替える」ことをこのカードに残した（B-10 カードの「Live が途中で切れた」の行）。

## Scope / 範囲

### In scope / やること

**1. Per-playthrough cost and tiers** (new `gateway/budget.py`) / **1 プレイの費用と段階**（新規 `gateway/budget.py`）

- A playthrough's cost = the sum of all `cost_*_usd` in `playthrough_metrics` × 150. After each turn's costs are written (the narrator's commit and the gateway's Live turn), the tier is recomputed; it only goes up, never down.
  1 プレイの費用 = `playthrough_metrics` のすべての `cost_*_usd` の合計 × 150。各ターンの費用を書き終えた後（ナレーターのコミットとゲートウェイの Live の 1 ターン）、段階を計算し直す。上がるだけで下がらない。
- The cap and ratio are constants (`RUN_CAP_JPY = 300`, `SAVING_RATIO = 0.8`, `USD_JPY = 150`), overridable by environment variable (`ZJ_RUN_CAP_JPY`) for tests and for tuning before R1.
  上限と比率は定数に置き（`RUN_CAP_JPY = 300`、`SAVING_RATIO = 0.8`、`USD_JPY = 150`）、環境変数で変えられる（`ZJ_RUN_CAP_JPY`）。テストと R1 前の調整用。
- Entering the economy tier: `playthrough_metrics.budget_saving_at` records the time (new column; the migration number follows main at the time); entering degraded: write `degraded_at` as before.
  節約モードに入ったら `playthrough_metrics.budget_saving_at` に時刻を記録する（新しい列。マイグレーション番号はその時点の main に合わせる）。縮退に入ったら従来どおり `degraded_at` を書く。
- The tier lives in `playthroughs.budget_tier` (`normal` / `saving` / `degraded`); the gateway recomputes it before each turn starts and on `focus` (`budget.refresh`), so it still holds after switching instances.
  段階は `playthroughs.budget_tier`（`normal` / `saving` / `degraded`）に置き、ゲートウェイは各ターンの開始前と `focus` のときに計算し直す（`budget.refresh`）。インスタンスが替わっても同じように動く。
- New tables and columns use migration 0008 (B-13's 0007 is in #153; whoever merges later wires up `down_revision`).
  新しいテーブルと列はマイグレーション 0008 を使う（B-13 の 0007 は #153 にある。後からマージする方が `down_revision` をつなぐ）。

**2. What the economy tier does** (the four items in backend-design 5.3) / **節約モードで行うこと**（backend-design 5.3 の 4 項目）

- Shorter situation briefing: in the Live system instruction, 「口ぶりの例」 goes from 4 to 2 lines and 「さっきまでの会話」 from 6 to 3 turns (`brief.build(samples=…)`, `Voices._recent`). The character settings and 「知っていること」 are not cut (consistency first).
  状況説明を短くする：Live のシステム指示の「口ぶりの例」を 4 → 2 文、「さっきまでの会話」を 6 → 3 ターンにする（`brief.build(samples=…)`、`Voices._recent`）。人物設定と「知っていること」は削らない（一貫性を優先）。
- Memory injection from 8 to 4: 「覚えていること」 in the Live system instruction is taken per `policy(tier).memory_inject` (B-13's `memories_for_brief`).
  記憶の注入を 8 → 4 件に：Live のシステム指示の「覚えていること」は `policy(tier).memory_inject` に従って取る（B-13 の `memories_for_brief`）。
- Stopping mid-act world progression, and generating candidate lines only when 「？」 is tapped: not yet in the code (B-16, B-21). This card provides `budget.policy(tier)` (`mid_act_progression`, `candidates_on_demand`), and the cards that build those features read it.
  幕の中盤の世界の進行を止めること、候補の発話を「？」を押したときだけ生成すること：まだコードにない（B-16、B-21）。このカードは `budget.policy(tier)`（`mid_act_progression`、`candidates_on_demand`）を提供し、それらを作るカードがこれを読む。
- `setup.budgetTier: "saving"` at the eval entry point sets the playthrough directly to the economy tier (`budget.set_tier`).
  評価入口の `setup.budgetTier: "saving"` で、そのプレイを直接節約モードにする（`budget.set_tier`）。

**3. Degradation** (≥ 100%) / **縮退**（≥ 100%）

- Before the next turn starts (`can_speak`), the gateway checks the tier, and on `degraded` calls `degrade("budget")`. A turn that is mid-speech finishes as usual.
  ゲートウェイは次のターンの開始前（`can_speak`）に段階を見て、`degraded` なら `degrade("budget")` を呼ぶ。話している途中のターンはいつもどおり最後まで話す。
- After degradation (for any reason: budget / daily / service, including Live failing to open repeatedly): push-to-talk gets `voice_unavailable`; text turns work as usual, with the character answering via the text model (the narrator's `reply` prompt, with the same character settings and situation, `Gateway.replier`), first pushing the character's final text (`source: "live"`), then `turn_complete { audio: false }` (contract 3.3). Cost goes into `cost_reply_usd`. Intent confirmation does not ask back aloud; it pushes `confirm` directly.
  縮退の後（理由を問わない：budget / daily / service。Live が続けて開けない場合も含む）：押して話すと `voice_unavailable` を返す。文字のターンはいつもどおりで、人物は文字のモデルで返答する（ナレーターの `reply` プロンプト。同じ人物設定と状況、`Gateway.replier`）。まず人物の確定テキスト（`source: "live"`）を送り、次に `turn_complete { audio: false }` を送る（契約 3.3）。費用は `cost_reply_usd` に入る。意図確認は声で聞き返さず、直接 `confirm` を送る。
- The narrator processes text-answer turns as usual (consistency comes before voice).
  ナレーターは文字で返答したターンもいつもどおり処理する（声よりも一貫性を優先）。
- Degradation that will not recover on its own (budget / daily / switch off): later `focus` opens no session and returns `session_ready { voiceAvailable: false }`; sessions not currently speaking are closed. For `service` (Live failing to open), follow B-10 and retry on the next `focus`.
  自然には回復しない縮退（budget / daily / スイッチがオフ）：その後の `focus` ではセッションを開かず、`session_ready { voiceAvailable: false }` を返す。話していないセッションは閉じる。Live が開けない `service` は B-10 どおりで、次の `focus` で再試行する。

**4. Per account per day** (`gateway/rest.py`, `ws.py`) / **アカウントごと 1 日あたり**（`gateway/rest.py`、`ws.py`）

- The day boundary is Japan time (JST midnight).
  1 日の区切りは日本時間（JST の 0 時）。
- Starting a playthrough: `POST /v1/playthroughs` first counts how many playthroughs this account has started today; ≥ 5 returns `429 daily_limit` (`retryAfterSeconds` = seconds until JST midnight), and only then checks 409. `runsToday` in `/v1/me` uses the real count.
  プレイの開始：`POST /v1/playthroughs` はまずこのアカウントが今日何回開始したかを数え、5 回以上なら `429 daily_limit` を返し（`retryAfterSeconds` = JST の 0 時までの秒数）、その後で 409 を見る。`/v1/me` の `runsToday` は実際の数を使う。
- Voice time: the seconds of audio in and out of Live in each turn (this turn's increment of `session.audio_seconds`) are recorded in `account_days.voice_seconds` (not refunded when a playthrough is deleted) and in the playthrough's `voice_in_seconds` and `voice_out_seconds` (nobody wrote these two columns before). `welcome.voice.minutesLeftToday` and `voiceMinutesLeft` in `/v1/me` use the real numbers (rounded down).
  音声の時間：各ターンで Live に出入りした音声の秒数（このターンの `session.audio_seconds` の増分）を `account_days.voice_seconds`（プレイを削除しても戻さない）と、そのプレイの `voice_in_seconds`、`voice_out_seconds`（この 2 列はこれまで誰も書いていなかった）に記録する。`welcome.voice.minutesLeftToday` と `/v1/me` の `voiceMinutesLeft` は実際の数（切り捨て）を使う。
- When 5 minutes remain, push `limits { voiceMinutesLeft }` once (at most once per connection per day); when used up, `degrade("daily")`.
  残り 5 分になったら `limits { voiceMinutesLeft }` を 1 回送る（1 接続につき 1 日最大 1 回）。使い切ったら `degrade("daily")`。
- The current 409 for "1 concurrent playthrough" stays as is.
  「同時に 1 プレイ」の現在の 409 はそのまま。

**5. Global voice switch / 全体の音声スイッチ**

- `voice_enabled`: one row in the database (a new `settings` table or an existing config location, whichever is less work when writing the code); the gateway reads it every 30 seconds. When off: every new `focus` gets `degrade("service")`, and sessions already open close after finishing the current turn.
  `voice_enabled`：データベースに 1 行置く（新しいテーブル `settings` か既存の設定の置き場所の、コードを書くときに手間の少ない方）。ゲートウェイは 30 秒ごとに読む。オフのとき：新しい `focus` はすべて `degrade("service")`、すでに開いているセッションは今のターンを話し終えたら閉じる。
- Automatically turning the switch off and alerting when "the day's total cost exceeds the global cap, or the Live error rate spikes": **this card only builds the switch and a command to change it manually** (`zoujin-admin voice off|on|status`, connecting only to `DATABASE_URL`); the automatic circuit breaker and alerts go with the deployment card (they need Cloud Monitoring).
  「当日の総費用が全体の上限を超えた、Live のエラー率が急増した」ときに自動でスイッチを切ってアラートを出すこと：**このカードではスイッチと手動で切り替えるコマンドだけを作る**（`zoujin-admin voice off|on|status`。`DATABASE_URL` にだけ接続する）。自動のサーキットブレーカーとアラートはデプロイのカードで行う（Cloud Monitoring が必要）。
- `welcome.voice` and `voice` in snapshots: `enabled` = the global switch, `degraded` = this playthrough has already switched to text, `minutesLeftToday` = the real count.
  `welcome.voice` とスナップショットの `voice`：`enabled` = 全体のスイッチ、`degraded` = このプレイはすでに文字に切り替わっている、`minutesLeftToday` = 実際の数。

**6. Trace and metrics** (no utterances) / **Trace と指標**（発話そのものは記録しない）

- `budget` Span: one record when the tier changes, with `playthrough_id`, `run_cost_jpy_so_far` (rounded), `tier`, `degraded`.
  `budget` Span：段階が変わったときに 1 件記録する。`playthrough_id`、`run_cost_jpy_so_far`（整数に丸める）、`tier`、`degraded`。
- `gateway.degraded`: one per degradation, with `playthrough_id`, `reason`.
  `gateway.degraded`：縮退ごとに 1 件。`playthrough_id`、`reason`。
- `playthrough_metrics`: `budget_saving_at` (new), `degraded_at` (existing, never written before). The reason for this playthrough's first degradation (budget / daily / service) goes into a new column `degraded_reason`.
  `playthrough_metrics`：`budget_saving_at`（新規）、`degraded_at`（既存。これまで誰も書いていなかった）。このプレイで最初に縮退した理由（budget / daily / service）は新しい列 `degraded_reason` に記録する。
- The table in data-design section 8 gains a `tier` entry, changed during Data's review.
  data-design 第 8 節の表に `tier` を 1 項目追加する。データのレビューのときに変更する。

   同じアカウントの今日 6 回目の開始は 429 `daily_limit` を返す。進行中のプレイがあっても同じ（409 は返さない）。JST の 0 時を過ぎれば開始できる。

   `zoujin-live voice off` の後、新しい `focus` は `degraded { reason: "service" }` を受け取る。`on` の後は元に戻る。
5. With `budgetTier: "saving"` at the eval entry point, the playthrough is in the economy tier from the start.
   評価入口で `budgetTier: "saving"` にすると、プレイは開始時から節約モード。
6. The `budget` Span and the new `playthrough_metrics` columns have values, with no text content.

7. All backend tests, ruff and mypy pass locally; no real model calls, no network.

## Risks and things to confirm / リスクと確認事項

- The other three economy-tier items (memory, world progression, candidate lines) wait for the cards that build them to read `policy()`; for now the economy tier only saves a little in the Live system instruction.
  節約モードの残り 3 項目（記憶、世界の進行、候補の発話）は、それらを作るカードが `policy()` を読むのを待つ。今のところ節約モードで節約できるのは Live のシステム指示の少しだけ。
- Cost only goes up, but `cost_*_usd` is written separately by each part; within one turn the tier may change between the narrator finishing and the gateway finishing. This is handled by "check before the next turn starts", never switching mid-turn.
  費用は上がるだけで下がらないが、`cost_*_usd` は各部分がそれぞれ書く。同じターンの中で、ナレーターが書き終えてからゲートウェイが書き終えるまでの間に段階が変わることがある。「次のターンの開始前に見る」として扱い、ターンの途中では切り替えない。
- The 60 minutes of voice per day is computed from `voice_*_seconds`, and these two columns are currently the seconds reported by Live; confirm the definition in Data's review (whether the character's speaking seconds are included).
  1 日の音声 60 分は `voice_*_seconds` で計算する。この 2 列は現在 Live が報告する秒数。定義（人物が話している秒数を含むかどうか）はデータのレビューで確認する。
