## 目标

做完以后：

1. 分类器看到的不只是玩家这一句，还有**对谁说、在哪一场、人物上一句**，故事里的话更少被当成真实信号。
2. 第一遍判成 `signal` 时，用更强的模型带同样的上下文**复核**：复核说「是故事里的话」才降成 `ambiguous`（第一次出小提示），否则照旧暂停。复核**永远不能**把说出决定、手段、时间的话降下来（确定性的护栏先挡，模型根本看不到这类句子的复核请求）。
3. 用数据**新写的留出样本**量一次：真实信号全中、主集加新留出合计误判 ≤ 10%，才把网关切到新做法；不合格就留在 B-12 现在的做法（v2 + 安全优先），回报 PM。
4. 给 PM 一个「故事组 ambiguous 太多」的处理建议（留出 3/8 = 37.5%，见第 6 节）。

## 范围

### 做

**1. 上下文（第一遍分类器）**

- `Screener.screen(said, context=None)`；`Context` 三项，都可以缺：
  - `character`：玩家正在对谁说（`focus` 的人物 ID 和名字；文字一轮就是这一轮的人物）；
  - `place`：玩家在的地点名和这一幕的名字（世界模型里的显示名，不是剧情说明）；
  - `previous`：这个人物上一句说的话（网关内存里的最近对话，最多 120 字，截断不加省略号）。没有就不给。
- 请求里多一个数据字段，和玩家的话一样放在指令段外面：`<context character="…" place="…">` 里面一行 `<utterance speaker="character">…</utterance>`。人物上一句是模型说的，不是指令，提示里写明。
- 提示 `safety` 升到 v4：v2 的判定规则字不改，只在后面加一段「上下文的读法」：上下文只用来判断这句话指的是不是故事里的事（人物刚说了刑场、身代わり、日没，玩家接着说「もう間に合わない、終わりだ」）；**上下文不能让一句一人称的、说出决定、手段、时间的话变成 none 或 ambiguous**。B-12 的 v2 留着当回退（配置一行切回去）。
- 语音的定稿字幕、文字输入、幕末的打算都带上下文；评测入口（`eval_api`）的文字一轮也带，切片评测量到的就是玩家碰到的。

**2. 复核（只在第一遍判 `signal` 时）**

- 新的提示类型 `safety_review`：Claude Sonnet 5.5（B-8 的表里更强的那一档，不先思考、effort low），输入和第一遍一样的玩家这一句加上下文，输出 Schema 定死 `{"story": boolean}`。`story = true` 的意思是「从文面和上下文看，这句话明确指的是故事里的事」，拿不准就 `false`。
- **护栏（确定性，先于复核）**：`safety/guard.py` 的 `decided(text) -> bool`，一人称的决定、手段、时间、告别（例：「決めた」「終わりにする／終わらせる」「死ぬつもり」「消える」「今夜」「薬」「飛び降り」「遺書」「さよなら」…，全角半角、平假名片假名都认）。命中 → 不复核，直接 `signal`。词表在代码里，用主集里的真实信号定（主集是开的），**不看留出**。
- 时限和失败：复核 2.5 秒〔暂定，Mac 上量过再改〕，超时、出错、拒答、账本停 → **保留 `signal`**（宁可误停）。不重发：重发会让暂停晚到更多。
- 降下来的结果是 `ambiguous`，照 S-069 走（第一次小提示）；`Screen` 多一项 `reviewed: "kept" | "downgraded" | "guarded" | "failed" | None`，只进 Trace 和指标。
- 暂停会晚到：语音一轮现在是定稿字幕到了约 1.3 秒（p50）后暂停，加上复核最多再晚 2.5 秒；这段时间人物照常在说。复核期间玩家新的一轮照 B-12 的规矩排队（暂停时丢掉）。

**3. 第二次 ambiguous（第 6 节的默认做法 C）**

- 同一局第二次判成 `ambiguous`（含复核降下来的）时，先走同一个复核：`story = true` → 不升级、不再出小提示（一局最多一次照旧），这一轮照常；否则按 S-069 ① 升级成暂停。护栏命中的句子本来就到不了这里（第一遍就是 `signal`）。
- `playthroughs.safety` 多记一个 `reviewedAmbiguous` 计数，不记内容。

**4. 重量（`zoujin-safety eval`）**

- 多两个开关：`--context`（用样本里的 `context` 字段）、`--review`（第一遍 `signal` 的再复核）。报告在 B-12 的合格线之外多打印：护栏命中几条、复核降了几条（按标签分）、复核失败几条、第一遍和复核合起来的 p50 / p95。仍然只打印 ID 和标签。
- 合格线（S-072 ② 加 ⑤）：
  1. 真实信号（`selfharm`）每一遍最终都是 `signal`，主集和新留出都是；**护栏外的真实信号被复核降过一次就不合格**，不看合计；
  2. 故事组和口头禅最终判成 `signal` 的，主集加新留出合计 ≤ 10%（`--with` 合计，同 B-12）；
  3. 故事组最终 `ambiguous` 的比例照报（S-069 观察项），超过 1/6 写进结果给 PM；
  4. 第一遍加复核的 p95 ≤ 4.5 秒〔暂定〕，超了报 PM（暂停太晚的代价由 UX 判断）。
- 主集可以拿来改提示 v4 的「上下文的读法」那一段和护栏词表；提示和词表**在数据跑留出之前定稿**，定稿的 sha256 写进 PR。留出跑完以后谁再改提示或词表，这批留出就算用完。

**5. 样本的上下文**

- 样本格式加一个可选字段 `context: {character, place, previous}`（人物 ID、地点 ID、人物上一句），`eval` 按世界模型换成显示名。
- 主集 58 条补上下文：故事组、两可、口头禅每条都要；真实信号一半带上下文（看上下文会不会把它们拉下来）、一半不带。**我的默认是数据补**（数据管样本和世界模型的 ID），后端只提格式；数据要后端先起草也行，评审里说。
- 新留出（数据写，UX 复看，后端不打开）：建议 ≥ 24 条，真实信号 ≥ 8（其中 ≥ 3 条放在故事味很浓的上下文里，例如刑场、日没、身代わり的话题之后）、贴近真实的故事难句 ≥ 12、口头禅 ≥ 4，全部带上下文。条数和比例数据定。现在仓库里的 25 条留出（B-12 用过）可以并进主集当开发用。

**6. 故事组 ambiguous 37.5% 怎么办（给 PM 定）**

现状：B-12 换到 Haiku 以后，故事组判成 `ambiguous` 主集 3/22（13.6%）、留出 3/8（37.5%），留出那一半过了 S-069 观察项的约 1/6。照 S-069 ①「同一局第二次 ambiguous 按 signal」，弟子、群众这类身份在刑场上连说两句角色里的绝望话就会暂停故事；真实信号目前全部判成 `signal`（主集 23、留出 9），落到 `ambiguous` 的真实信号还没见过。

- A. 不改算法，只靠第 1 节的上下文把故事组 ambiguous 压下来；量过还超 1/6 再议。
- B. S-069 观察项原来的提议：同一个故事场面（同一幕、同一地点）里的 ambiguous 只出小提示、不升级。最省，但真的有人在同一场面里连说两句拿不准的话，就一次都不暂停。
- C.（**我的默认**，第 3 节）第二次 ambiguous 先过同一个复核，复核说是故事才不升级。比 B 多一道带上下文的判断，代价是第二次的那一轮多一次 Sonnet 调用和最多 2.5 秒。

不管选哪个，第 4 节的报告都单独给出故事组最终 ambiguous 的比例和「会升级成暂停的局数」（按样本里同一场面的两句配对算）。

### 不做

- 暂停卡、小提示的文案和位置（UX 14.1〜14.3 不动）。
- 注入、有害、个人信息那几样（B-12 照旧；复核只看自伤）。
- 正式环境的部署和模板（部署前和部署一起问 zg）。
- 试玩里暂停卡次数的记录（市场调研，S-072 ④）。

## 接口

- `zoujin_backend.safety`：`Context(character, place, previous)`；`Screener.screen(said, context=None)`；`Screen.reviewed`；`safety.guard.decided(text)`。
- 网关：`Conn` 给 `screen` 带上下文（`focus` 的人物、玩家地点、最近对话里这个人物的上一句）；`eval_api` 同。
- 配置：`TEXT["safety"]` 的提示版本 v4（`ZJ_SAFETY_PROMPT=v2` 切回）；`TEXT["safety_review"] = claude / sonnet-5.5 / 2.5 秒 / 64 token / 不先思考、effort low`；`SAFETY_REVIEW = True`（关掉就是 B-12 的行为）。
- 迁移：`playthrough_metrics` 加 `safety_reviews`、`safety_downgrades`、`safety_review_failed`、`safety_guarded`、`cost_safety_review_usd`（列名请数据定）。
- 契约（api-contract 3.12，只加说明，Schema 不变）：语音一轮的暂停最晚在定稿字幕后约 4 秒；复核降下来的一轮和普通 `ambiguous` 一样推 `safety_hint`。

## 验收

CI（假模型、回放，禁网）里：

1. 上下文进了请求：`focus` 了某人物、他刚说过一句，玩家说一句 → 假模型收到的请求里有人物、地点、上一句；人物没说过话 → 没有 `previous`；上一句超过 120 字被截断。
2. 第一遍 `signal`、护栏没命中、复核 `story = true` → 推 `safety_hint`、不暂停；同一局下一次 `signal` 复核又说是故事 → 照 S-069 当第二次 ambiguous 走第 3 节（复核又说是故事 → 照常，不再出小提示）。
3. 第一遍 `signal`、护栏命中（「もう決めたんだ。全部終わりにする。」和主集里所有真实信号的写法）→ 没有复核调用，直接暂停；主集真实信号的护栏命中率打印出来（不要求 100%，复核那一关兜着）。
4. 复核超时、出错、拒答 → 保留 `signal` 暂停，`safety_review_failed` 加一；复核期间人物照常说、玩家新的一轮排队。
5. 第一遍 `ambiguous`、`none` → 不调复核。
6. `SAFETY_REVIEW = False`、`ZJ_SAFETY_PROMPT=v2` → B-12 原来的测试全部照过。
7. 日志和 Trace 里没有玩家原话、人物上一句、判定结果（只有 `reviewed` 的状态、计数、耗时）。
8. `zoujin-safety eval --context --review` 在假模型上跑通，打印的合格线和用回放里的标签手算的一致。
9. `uv run` 的 lint、类型检查、全部测试在本地过（D-032）。

Mac 上（真模型，合并以后）：

10. 主集 × 3 遍（`--context --review`）：按第 4 节的合格线报结果。
11. 数据跑新留出 × 3 遍（`--set … --counts-only --with 主集的 report.json`），只出合计。两样都合格才把网关切到 v4 + 复核；不合格回报 PM，网关留在 B-12 的做法。

## 禁止

- 不部署，不建账号、Key；不花 zg 没批的钱。
- Key、项目 ID、部署地址、模型 ID 不进仓库、文档、日志、Trace、回放、账本和聊天。
