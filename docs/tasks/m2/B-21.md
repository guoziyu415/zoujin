## 做了什么

- 新提示 `suggest`（`models/prompt_texts/suggest.txt`，Haiku、关思考、3 秒）：输入人设、局势、玩家身份、这一轮的两句话（有的话）、此刻能做的动作的 label；输出 2〜3 个 `{text, kind}`（`ask` / `act` / `accept` / `decline`）。规则照 UX 7.8：具体、能通往一件事、不全是问句、人物请帮忙时一个答应一个「いまは、いい」、不说玩家不知道的事。
- `Pipeline.suggest()`：全是问句按不合格重发一次，两次都不行就不出（这一次没有候选）。
- 网关 `Conn.suggest_later()`：
  - 人物说完一轮（语音、文字、落地先开口）交给叙事者以后，后台生成，推 `suggestions { turnId, character, items }`；
  - 会话刚就绪（切换人物、预热命中、续玩接上）推一次，不带 `turnId`；
  - 生成期间玩家又开始一轮、换了人物、进了结局、出戏卡开着：不推（过时了）；
  - 节约档、降级不自动推（backend-design 5.3，`budget.policy().candidates_on_demand`）。
- 花费进新列 `playthrough_metrics.cost_suggest_usd`（迁移 0010），算进单局预算（B-14 按全部 `cost_*_usd` 求和）。不落库候选本身。

## 不做

- 节约档里点「？」才生成：契约里还没有前端请求候选的消息，要加的话是契约的改动（前端 + 后端），另提。现在节约档就是不推。
- 「玩家自己说了 3 次后收起」是前端的规则（ux-design 7.8），服务端照推。

## 测试

`tests/test_gateway_b21.py`：提示的输出和全是问句的重发；会话就绪和一轮之后各推一次；节约档不推。`test_gateway.py` 里按轮次排消息顺序的辅助函数跳过 `suggestions`（到达时间不定）。
