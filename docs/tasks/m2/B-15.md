## 目标

做完以后：

1. 一局的花费到 300 日元的 80%（240 日元）进**节约档**，到 100% 人物改**文字回答**，叙事者照常。玩家看得到的只有 `degraded { reason: "budget" }` 以后的文字回答。
2. 每个账号每天：**开局 5 次**真的拦（429 `daily_limit`，先于 409）；**语音 60 分钟**真的算（`minutesLeftToday`、剩 5 分钟推 `limits`、用完 `degraded { reason: "daily" }`）。
3. 有一个**全局语音开关**：关了以后新连接、新会话全部文字模式（`degraded { reason: "service" }`），不用重新部署。
4. 每局进节约档、降级的时间进 `playthrough_metrics`，`budget` Span 记一局花到多少日元，数据能算「降级局占比」（目标 < 2%）。
5. 评测入口的 `setup.budgetTier: "saving"` 真的让叙事者按节约档跑（E6）。

已经有的（本卡不重做）：`Voices.degrade(why)` 推 `degraded` 和 `session_ready { voiceAvailable: false }`；账本到上限时 `can_speak()` 降级（开发期的硬上限，和本卡的单局上限是两回事，都保留）；`cost_*_usd` 各列。B-10 把「人物改用文字回答」留给了本卡（B-10 卡「Live 中途断了」那一行）。

## 范围

### 做

**1. 单局花费和档位**（新 `gateway/budget.py`）

- 一局的花费 = `playthrough_metrics` 里全部 `cost_*_usd` 之和 × 150。每轮写完花费以后（叙事者的 commit 和网关的 Live 一轮）重新算一次档位，只升不降。
- 上限、比例放常量（`RUN_CAP_JPY = 300`、`SAVING_RATIO = 0.8`、`USD_JPY = 150`），环境变量可改（`ZJ_RUN_CAP_JPY`），给测试和 R1 前调数。
- 进节约档：`playthrough_metrics.budget_saving_at` 记时间（新列，迁移号跟当时的 main）；进降级：照旧写 `degraded_at`。
- 档位放在 `playthroughs.budget_tier`（`normal` / `saving` / `degraded`），网关在每一轮开始前和 `focus` 时重算（`budget.refresh`），换实例以后照样。
- 新表、新列用迁移 0008（B-13 的 0007 在 #153；谁后合谁把 `down_revision` 接上）。

**2. 节约档做什么**（backend-design 5.3 的四件）

- 局势说明缩短：Live 的系统指令里「口ぶりの例」4 → 2 句、「さっきまでの会話」6 → 3 轮（`brief.build(samples=…)`、`Voices._recent`）。人物设定和「知っていること」不删（一致性优先）。
- 记忆注入 8 → 4 条、每幕中段的世界推进停掉、候选话语只在点「？」时生成：这三样代码里还没有（记忆是 B-13 之后、世界推进和候选话语是 M3 的卡）。本卡给 `budget.policy(tier)`（`memory_inject`、`mid_act_progression`、`candidates_on_demand`），做它们的卡读它。
- 评测入口 `setup.budgetTier: "saving"` 直接把这一局设成节约档（`budget.set_tier`）。

**3. 降级**（≥ 100%）

- 网关在下一轮开始前（`can_speak`）看档位，`degraded` 就 `degrade("budget")`。说到一半的这一轮照常说完。
- 降级以后（任何原因：budget / daily / service，包括 Live 连续开不起来）：按住说话回 `voice_unavailable`；文字一轮照常，人物用文字模型回答（叙事者的 `reply` 提示，同一套人物设定和局势，`Gateway.replier`），先推人物定稿（`source: "live"`），再推 `turn_complete { audio: false }`（契约 3.3）。花费进 `cost_reply_usd`。意图确认不出声反问，直接推 `confirm`。
- 叙事者照常处理文字回答的轮次（一致性优先于声音）。
- 降级的不会自己好（budget / daily / 开关关了）：之后的 `focus` 不开会话，回 `session_ready { voiceAvailable: false }`；没在说话的会话关掉。Live 开不起来的 `service` 照 B-10，下一次 `focus` 再试。

**4. 每账号每天**（`gateway/rest.py`、`ws.py`）

- 一天按日本时间（JST 0 点）切。
- 开局：`POST /v1/playthroughs` 先数今天这个账号开了几局，≥ 5 回 `429 daily_limit`（`retryAfterSeconds` = 到 JST 0 点的秒数），再看 409。`/v1/me` 的 `runsToday` 照真的数。
- 语音时间：每一轮 Live 进出的音频秒数（`session.audio_seconds` 这一轮的增量）记进 `account_days.voice_seconds`（删局不退）和这一局的 `voice_in_seconds`、`voice_out_seconds`（这两列以前没人写）。`welcome.voice.minutesLeftToday`、`/v1/me` 的 `voiceMinutesLeft` 用真的数（向下取整）。
- 剩 5 分钟时推一次 `limits { voiceMinutesLeft }`（一个连接一天最多一次）；用完 `degrade("daily")`。
- 「同时 1 局」现在的 409 照旧。

**5. 全局语音开关**

- `voice_enabled`：放数据库一行（新表 `settings` 或现有的配置处，写代码时看哪个少），网关每 30 秒读一次。关了：新 `focus` 一律 `degrade("service")`，已经开着的会话这一轮说完就关。
- 「当天总花费超过全局上限、Live 错误率突增」自动关开关和告警，**本卡只做开关和手动改的命令**（`zoujin-admin voice off|on|status`，只连 `DATABASE_URL`）；自动熔断和告警跟部署的卡（要 Cloud Monitoring）。
- `welcome.voice` 和快照的 `voice`：`enabled` = 全局开关，`degraded` = 这一局已经改文字，`minutesLeftToday` 真的数。

**6. Trace 和指标**（不记原话）

- `budget` Span：档位变的时候记一条，`playthrough_id`、`run_cost_jpy_so_far`（取整）、`tier`、`degraded`。
- `gateway.degraded`：每次降级一条，`playthrough_id`、`reason`。
- `playthrough_metrics`：`budget_saving_at`（新）、`degraded_at`（现有，以前没人写）。这一局第一次降级的原因（budget / daily / service）记进新列 `degraded_reason`。
- data-design 第 8 节的表加 `tier` 一项，数据评审时改。

### 不做

- 自动熔断、告警、全局花费看板（部署的卡）。
- 改单局上限的数（300 日元由 PRD 7.4 定，改要 PM）。
- 前端的提示文案和样式（前端、UX；协议现在就有）。

## 验收

1. 假模型下一局的 `cost_*_usd` 之和越过 240 日元，下一次开会话按节约档（Live 系统指令的「口ぶりの例」≤ 2 句）；越过 300 日元，下一轮开始前推 `degraded { reason: "budget" }`，人物文字回答。
2. 同一账号今天第 6 次开局回 429 `daily_limit`，即使这时有进行中的局（不回 409）；JST 0 点以后可以开。
3. 语音秒数之和到 55 分钟推一次 `limits { voiceMinutesLeft: 5 }`，到 60 分钟推 `degraded { reason: "daily" }`；`welcome.voice.minutesLeftToday` 和 `/v1/me` 对得上。
4. `zoujin-live voice off` 以后新 `focus` 收到 `degraded { reason: "service" }`；`on` 以后恢复。
5. 评测入口 `budgetTier: "saving"` 一开局就是节约档。
6. `budget` Span 和 `playthrough_metrics` 的新列有值，没有文字内容。
7. 后端全部测试、ruff、mypy 本地过；没有真模型调用、没有网络。

## 风险和要对的

- 节约档的另外三件（记忆、世界推进、候选话语）要等做它们的卡读 `policy()`；现在节约档省下的只有 Live 系统指令的一点。
- 花费只升不降，但 `cost_*_usd` 是各部分分别写的；同一轮里档位可能在叙事者写完、网关写完之间变，按「下一轮开始前看」处理，不在一轮中间切。
- 每天语音 60 分钟按 `voice_*_seconds` 算，这两列现在是 Live 报的秒数；数据评审时确认口径（含不含人物说话的秒数）。
