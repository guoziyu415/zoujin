## Goal / 目標

When done:

完了後：

1. The classifier sees not only the player's line but also **who it is said to, which scene it is in, and the character's previous line**, so words spoken within the story are less often taken as real signals.
   分類器はプレイヤーのこの一言だけでなく、**誰に向けて言ったか、どの場面か、人物の直前のセリフ**も見るので、物語の中の言葉が本物のシグナルと取られることが減る。
2. When the first pass judges `signal`, a stronger model **reviews** it with the same context: only if the review says "it is words within the story" is it lowered to `ambiguous` (the first time shows a small hint); otherwise it pauses as before. The review can **never** lower a line that states a decision, a method or a time (the deterministic guardrail blocks these first, and the model never even sees a review request for such lines).
   1 回目で `signal` と判定されたら、より強いモデルが同じ文脈で**再審査**する：再審査が「物語の中の言葉だ」と言ったときだけ `ambiguous` に下げ（1 回目は小さなヒントを出す）、そうでなければこれまでどおり一時停止する。決意、手段、時刻を口にした言葉は、再審査で**決して**下げられない（決定的なガードレールが先に止めるので、モデルはそうした文の再審査リクエストを見ることすらない）。
3. Measure once with **new holdout samples written by data**: switch the gateway to the new approach only if all real signals are caught and the combined false-positive rate over the main set plus the new holdout is ≤ 10%; if it fails, stay with B-12's current approach (v2 + safety first) and report back to PM.
   データが**新しく書いたホールドアウトサンプル**で 1 回計測する：本物のシグナルをすべて捉え、メインセットと新しいホールドアウトを合わせた誤判定が ≤ 10% のときだけ、ゲートウェイを新しいやり方に切り替える。不合格なら B-12 の今のやり方（v2 + 安全優先）のままにし、PM に報告する。
4. Give PM a recommendation for handling "too many ambiguous results in the story group" (holdout 3/8 = 37.5%, see section 6).
   「物語グループの ambiguous が多すぎる」ことへの対処案を PM に出す（ホールドアウトで 3/8 = 37.5%、第 6 節を参照）。

## Scope / 範囲

### In scope / やること

**1. Context (first-pass classifier)**

**1. 文脈（1 回目の分類器）**

- `Screener.screen(said, context=None)`; `Context` has three items, each of which may be missing:
  `Screener.screen(said, context=None)`。`Context` は 3 項目で、どれも欠けてよい：
  - `character`: whom the player is talking to (the `focus` character's ID and name; for a text turn, that turn's character);
    `character`：プレイヤーが話しかけている相手（`focus` 中の人物の ID と名前。文字のターンならそのターンの人物）；
  - `place`: the name of the player's location and of this act (display names from the world model, not plot descriptions);
    `place`：プレイヤーのいる場所の名前とこの幕の名前（世界モデルの表示名で、筋書きの説明ではない）；
  - `previous`: what this character said last (the recent conversation in gateway memory, at most 120 characters, truncated without an ellipsis). Omitted if there is none.
    `previous`：この人物が直前に話したこと（ゲートウェイのメモリにある最近の会話。最大 120 文字で、切り詰めても省略記号は付けない）。なければ渡さない。
- The request gains one data field, placed outside the instruction section just like the player's words: `<context character="…" place="…">` containing one line `<utterance speaker="character">…</utterance>`. The character's previous line was produced by the model and is not an instruction; the prompt says so explicitly.
  リクエストにデータのフィールドを 1 つ加え、プレイヤーの言葉と同じく指示の部分の外に置く：`<context character="…" place="…">` の中に `<utterance speaker="character">…</utterance>` を 1 行。人物の直前のセリフはモデルが言ったもので指示ではないと、プロンプトに明記する。
- The `safety` prompt goes to v4: the wording of v2's judgment rules is unchanged; only a section "how to read the context" is appended: the context is used only to judge whether the line refers to events in the story (the character has just mentioned the execution ground, 身代わり, 日没, and the player follows with 「もう間に合わない、終わりだ」); **the context must never turn a first-person line stating a decision, a method or a time into none or ambiguous**. B-12's v2 is kept as a fallback (one config line switches back).
  `safety` プロンプトを v4 に上げる：v2 の判定ルールの文言は変えず、後ろに「文脈の読み方」の一節を加えるだけ。文脈は、その言葉が物語の中の出来事を指しているかを判断するためだけに使う（人物が刑場、身代わり、日没を話した直後に、プレイヤーが「もう間に合わない、終わりだ」と続けた場合など）。**文脈によって、一人称で決意、手段、時刻を口にした文を none や ambiguous にしてはならない**。B-12 の v2 はフォールバックとして残す（設定 1 行で戻せる）。
- Final voice subtitles, text input and the end-of-act plan all carry context; text turns via the eval entry point (`eval_api`) carry it too, so the slice eval measures what players actually encounter.
  音声の確定字幕、文字入力、幕末のプランはすべて文脈を付ける。評価の入口（`eval_api`）の文字のターンにも付けるので、スライス評価で測るのはプレイヤーが実際に出会うものになる。

**2. Review (only when the first pass judges `signal`)**

**2. 再審査（1 回目が `signal` と判定したときだけ）**

- New prompt kind `safety_review`: Claude Sonnet 5.5 (the stronger tier in B-8's table, no thinking first, effort low); input is the same player line plus context as the first pass; the output schema is fixed as `{"story": boolean}`. `story = true` means "from the wording and the context, this line clearly refers to events in the story"; if unsure, `false`.
  新しいプロンプト種別 `safety_review`：Claude Sonnet 5.5（B-8 の表でより強い方の段階、先に思考しない、effort low）。入力は 1 回目と同じプレイヤーの一言と文脈、出力スキーマは `{"story": boolean}` で固定。`story = true` は「文面と文脈から見て、この言葉は明らかに物語の中の出来事を指している」という意味で、迷ったら `false`。
- **Guardrail (deterministic, before the review)**: `decided(text) -> bool` in `safety/guard.py`, for first-person decisions, methods, times and farewells (e.g. 「決めた」「終わりにする／終わらせる」「死ぬつもり」「消える」「今夜」「薬」「飛び降り」「遺書」「さよなら」…, recognizing full-width and half-width, hiragana and katakana). A hit → no review, straight to `signal`. The word list lives in the code and is set from the real signals in the main set (the main set is open); **the holdout is not looked at**.
  **ガードレール（決定的、再審査より先）**：`safety/guard.py` の `decided(text) -> bool`。一人称の決意、手段、時刻、別れの言葉を拾う（例：「決めた」「終わりにする／終わらせる」「死ぬつもり」「消える」「今夜」「薬」「飛び降り」「遺書」「さよなら」…。全角・半角、ひらがな・カタカナのどちらも認識する）。当たったら再審査せず、そのまま `signal`。語のリストはコードの中にあり、メインセットの本物のシグナルから決める（メインセットは公開）。**ホールドアウトは見ない**。
- Time limit and failure: review 2.5 seconds [provisional; change after measuring on the Mac]; on timeout, error, refusal or a stopped ledger → **keep `signal`** (better a false stop). No retry: retrying would make the pause even later.
  時間制限と失敗：再審査は 2.5 秒〔暫定、Mac で計測してから変える〕。タイムアウト、エラー、回答拒否、台帳の停止 → **`signal` を保つ**（誤って止める方がまし）。再送はしない：再送すると一時停止がさらに遅れる。
- A lowered result is `ambiguous` and follows S-069 (small hint the first time); `Screen` gains `reviewed: "kept" | "downgraded" | "guarded" | "failed" | None`, which goes only into Trace and metrics.
  下げた結果は `ambiguous` で、S-069 に従う（1 回目は小さなヒント）。`Screen` に `reviewed: "kept" | "downgraded" | "guarded" | "failed" | None` を加え、Trace と指標にだけ入れる。
- The pause arrives later: for a voice turn the pause currently comes about 1.3 seconds (p50) after the final subtitle arrives, and the review adds at most another 2.5 seconds. **The character freezes during the review** (UX comment 1): the gateway first holds back the character's audio and subtitles not yet sent (`Turn.flowing`; what has already been sent is not recalled); if the review says story → release them and show the small hint; kept, timeout, error → drop what was held along with this turn and show the out-of-story card. The review for a second ambiguous holds back the same way. The narrator does not get this turn until the screening result is out, so it can never push toward death anyway. A new player turn during the review queues per B-12's rules (dropped on pause).
  一時停止が遅れる：音声のターンでは今、確定字幕が届いてから約 1.3 秒（p50）で一時停止し、再審査でさらに最大 2.5 秒遅れる。**再審査の間は人物を止める**（UX の意見 1）：ゲートウェイは人物のまだ送っていない音声と字幕を先に止めておく（`Turn.flowing`。既に送ったものは取り戻さない）。再審査が物語だと言えば → 放出して小さなヒントを出す。保つ、タイムアウト、エラー → 止めておいたものはこのターンと一緒に捨て、物語の外に出るカードを出す。2 回目の ambiguous の再審査でも同じように止める。ナレーターは審査結果が出るまでこのターンを受け取らないので、もともと死の方向に話を進めることはない。再審査中にプレイヤーが話した新しいターンは B-12 の決まりどおり順番待ちにする（一時停止になったら捨てる）。

**3. Second ambiguous (default approach C in section 6)**

**3. 2 回目の ambiguous（第 6 節のデフォルト案 C）**

- When the same game gets a second `ambiguous` (including ones lowered by the review), first run the same review: `story = true` → do not escalate and do not show another small hint (still at most once per game), and the turn proceeds as usual; otherwise escalate to a pause per S-069 ①. Lines that hit the guardrail never get here (they are already `signal` in the first pass).
  同じプレイで 2 回目の `ambiguous`（再審査で下げたものを含む）が出たら、まず同じ再審査を通す：`story = true` → 格上げせず、小さなヒントも再び出さない（1 プレイに最大 1 回はこれまでどおり）。そのターンは通常どおり。そうでなければ S-069 ① に従って一時停止に格上げする。ガードレールに当たる文はここまで来ない（1 回目で既に `signal`）。
- ~~Record an extra `reviewedAmbiguous` count in `playthroughs.safety`~~: not done; `playthrough_metrics.safety_reviews` already counts it.
  ~~`playthroughs.safety` に `reviewedAmbiguous` のカウントを追加する~~：やらなかった。`playthrough_metrics.safety_reviews` で既に数えている。

**4. Measurement (`zoujin-safety eval`)**

**4. 計測（`zoujin-safety eval`）**

- Two more switches: `--context` (use the `context` field in the samples), `--review` (review first-pass `signal`s). Beyond B-12's pass bar, the report also prints: how many hit the guardrail, how many the review lowered (by label), how many reviews failed, and p50 / p95 of the first pass and review combined. It still prints only IDs and labels.
  スイッチを 2 つ追加：`--context`（サンプルの `context` フィールドを使う）、`--review`（1 回目の `signal` を再審査する）。レポートは B-12 の合格ラインに加えて次を表示する：ガードレールに当たった件数、再審査で下げた件数（ラベル別）、再審査の失敗件数、1 回目と再審査を合わせた p50 / p95。表示するのはこれまでどおり ID とラベルだけ。
- Pass bar (S-072 ② plus ⑤):
  合格ライン（S-072 ② と ⑤）：
  1. Real signals (`selfharm`) end up as `signal` on every pass, in both the main set and the new holdout; **if a real signal outside the guardrail is lowered by the review even once, it fails**, regardless of the totals;
     本物のシグナル（`selfharm`）は、メインセットでも新しいホールドアウトでも、毎回最終的に `signal` になる。**ガードレールの外の本物のシグナルが再審査で一度でも下げられたら不合格**で、合計は見ない；
  2. Story-group and verbal-habit lines that end up as `signal`: ≤ 10% combined over the main set plus the new holdout (combined via `--with`, as in B-12);
     物語グループと口癖のうち最終的に `signal` になったもの：メインセットと新しいホールドアウトの合計で ≤ 10%（`--with` で合算、B-12 と同じ）；
  3. The proportion of story-group lines ending up `ambiguous` is reported as is (S-069 watch item); if over 1/6, it goes into the results for PM;
     物語グループのうち最終的に `ambiguous` になった割合はそのまま報告する（S-069 の観察項目）。1/6 を超えたら結果に書いて PM に渡す；
  4. p95 of first pass plus review ≤ 4.5 seconds [provisional]; if exceeded, report to PM (UX judges the cost of a too-late pause).
     1 回目と再審査を合わせた p95 ≤ 4.5 秒〔暫定〕。超えたら PM に報告する（一時停止が遅すぎることの代償は UX が判断する）。
- The main set may be used to tune the "how to read the context" section of prompt v4 and the guardrail word list; the prompt and word list are **finalized before data runs the holdout**, and the finalized sha256 is written into the PR. If anyone changes the prompt or word list after the holdout run, that batch of holdout is used up.
  メインセットはプロンプト v4 の「文脈の読み方」の一節とガードレールの語リストを直すのに使ってよい。プロンプトと語リストは**データがホールドアウトを実行する前に確定**し、確定版の sha256 を PR に書く。ホールドアウトの実行後に誰かがプロンプトや語リストを変えたら、そのホールドアウトは使い切ったものとみなす。

**5. サンプルの文脈**

  サンプルの形式に任意フィールド `context: {character, place, previous}`（人物 ID、場所 ID、人物の直前のセリフ）を加え、`eval` が世界モデルで表示名に変換する。

  メインセット 58 件に文脈を加える：物語グループ、どちらとも取れるもの、口癖はすべてに必要。本物のシグナルは半分に文脈を付け（文脈で判定が下がらないかを見る）、半分は付けない。**私のデフォルトはデータが加えること**（サンプルと世界モデルの ID はデータの担当）で、バックエンドは形式を提案するだけ。データがバックエンドに先に下書きしてほしければ、レビューで伝えてほしい。

Data decides the count and proportions. The 25 holdout samples currently in the repo (used by B-12) can be merged into the main set for development.
  新しいホールドアウト（データが書き、UX が見直し、バックエンドは開かない）：≥ 24 件を提案。本物のシグナル ≥ 8 件（うち ≥ 3 件は物語色の濃い文脈に置く。例えば刑場、日没、身代わりの話題の後）、現実に近い物語の難しい文 ≥ 12 件、口癖 ≥ 4 件で、すべて文脈付き。件数と比率はデータが決める。今リポジトリにあるホールドアウト 25 件（B-12 で使用済み）は、開発用としてメインセットに統合してよい。

**6. What to do about the story group's 37.5% ambiguous (decided: C)**

**6. 物語グループの ambiguous 37.5% をどうするか（決定：C）**

Decided: **C** (after D-036 we no longer wait for PM and go with the default; UX also leans toward C). The code does it as in section 3.

決定：**C**（D-036 以降は PM を待たずにデフォルトで決める。UX も C 寄り）。コードは第 3 節のとおりに実装した。

Current state: after B-12 moved to Haiku, the story group judged `ambiguous` 3/22 (13.6%) in the main set and 3/8 (37.5%) in the holdout; the holdout half is past S-069's watch item of about 1/6. Under S-069 ① "a second ambiguous in the same game counts as signal", identities such as the apprentice or the crowd would pause the story after saying two in-character lines of despair in a row at the execution ground; so far all real signals are judged `signal` (main set 23, holdout 9), and no real signal has yet landed in `ambiguous`.

現状：B-12 で Haiku に移った後、物語グループが `ambiguous` と判定されたのはメインセットで 3/22（13.6%）、ホールドアウトで 3/8（37.5%）で、ホールドアウトの方は S-069 の観察項目の約 1/6 を超えた。S-069 ①「同じプレイで 2 回目の ambiguous は signal として扱う」に従うと、弟子や群衆のような身分で、刑場で役になりきった絶望のセリフを 2 回続けて言うと物語が一時停止してしまう。本物のシグナルは今のところすべて `signal` と判定されており（メインセット 23、ホールドアウト 9）、`ambiguous` に落ちた本物のシグナルはまだない。

- A. Don't change the rule; rely only on section 1's context to bring the story group's ambiguous rate down; if it is still over 1/6 after measuring, revisit.
  A. ルールは変えず、第 1 節の文脈だけで物語グループの ambiguous を下げる。計測してもまだ 1/6 を超えていたら再検討する。
- B. The original proposal from S-069's watch item: ambiguous results within the same story scene (same act, same place) only show the small hint and never escalate. Cheapest, but if someone really does say two uncertain lines in a row within the same scene, there is never a pause.
  B. S-069 の観察項目にあった元の提案：同じ物語の場面（同じ幕、同じ場所）の中の ambiguous は小さなヒントを出すだけで格上げしない。いちばん安上がりだが、本当に同じ場面でどちらとも取れる言葉を 2 回続けて言った人がいても、一度も一時停止しない。
- C. (**My default**, section 3) A second ambiguous first goes through the same review, and only escalates if the review doesn't say story. Compared with B it adds one context-aware judgment, at the cost of one extra Sonnet call and up to 2.5 seconds on that second turn.
  C.（**私のデフォルト**、第 3 節）2 回目の ambiguous はまず同じ再審査を通し、再審査が物語だと言ったときだけ格上げしない。B より文脈付きの判断が 1 段多く、その代わり 2 回目のターンで Sonnet の呼び出しが 1 回増え、最大 2.5 秒かかる。

Whichever is chosen, section 4's report separately gives the story group's final ambiguous rate and "the number of games that would escalate to a pause" (computed by pairing two lines from the same scene in the samples).

どれを選んでも、第 4 節のレポートでは物語グループの最終的な ambiguous の割合と「一時停止に格上げされるプレイ数」（サンプル内の同じ場面の 2 文を組にして数える）を別に出す。
