## 目标

做完以后：

1. 正式网关有 `GET /v1/books/{bookId}/manifest`，内容全部从仓库里的东西生成，不手写：
   - 世界模型：书、身份、场景和地点、人物、幕、时钟、注音词表；
   - B-6 的声音清单：人物的预录句、固定演出的预录句；
   - 前端的场景包清单：每个场景的入口地址和版本。
2. manifest 的地址不带版本，缓存靠 `ETag`：内容没变，前端每次只拿到一个 304；录音和场景包的文件自己长缓存。api-contract 2.1 那一句跟着改（B-6 卡把这件事交给本卡）。
3. 只有真能加载的东西才进 manifest：没有场景包的场景、开局场景没有包的身份、声音清单里和世界模型对不上的句子，都不出现。前端拿到的每一个地址都能用。
4. mock 和正式网关用同一个生成器，前端在 mock 上看到的 manifest 和正式的一样。
5. 正式网关也发 `/assets/voice/…` 的录音文件（只发清单里的），本机和第一次评审部署不用另配静态服务；以后放 CDN 是部署那张卡的事。

## 范围

### 做

**1. 生成器**（`services/backend/src/zoujin_backend/manifest.py`，纯函数，不碰数据库）

输入：一本书的世界模型（`Book`）、声音清单（可以没有）、场景包目录。输出：过 Schema 的 manifest。

| 字段 | 从哪来 |
|---|---|
| `book` | 世界模型 `book` 的 `id`、`title`、`author` |
| `roles` | `release` ≤ 开放的版次（配置 `ZJ_RELEASE`，默认 1）的身份，世界模型里的顺序。`name`；`summary` = `Role.summary`（新字段，见「契约的小改」）；`startSceneId` = `startPlace` 的 `sceneRef`；`startActId` = `startAct`。开局场景没有包的身份不出，启动日志记一行身份 ID |
| `scenes` | 世界模型 `scenes` 里有包的那些（见第 2 条）。`places` = `sceneRef` 指向它的地点，世界模型里的顺序 |
| `characters` | 世界模型的全部人物，世界模型里的顺序。`name`；`reading` = `Character.reading`（数据补上）；`talkable`；`prerecorded` 见第 3 条 |
| `acts` | `actId`、`title`；`sceneIds` = `Act.scenes` 里有包的场景 |
| `clock` | `deadlineT` = `clock.deadline.t`；`sunsetMinuteOfDay`；`days` = `clock.labels.days` |
| `ruby` | 世界模型的注音词表（新字段，见「契约的小改」），原样 |
| `setPieceVoices` | 见第 3 条；一个键都没有时省略 |
| `manifestVersion` | `{worldModelVersion}+{内容 hash 前 8 位}`，例 `hashire-merosu@1.0.0-slice.3+4f3a91c2`。hash 按除它以外的整份 manifest（键排序的 JSON）算：世界模型、声音清单、任何一个场景包变了，版本就变；同样的输入每次一样 |

- 生成的结果过 `ManifestResponse` 的 Schema，不过就报错（启动时，见第 4 条）。
- 生成的 manifest 里不带世界模型的内部字段（`note`、`inferred`、`cite`、`access` 之类）：只有上表这些。

**2. 场景包**（`scenes[].assetUrl`、`assetVersion`）

- 场景包目录用配置 `ZJ_SCENE_PACKS`，默认仓库的 `assets/scenes`。部署构建现场生成场景包（S-075），部署那张卡把它指到构建的输出，版本就和真正发出去的文件一致。仓库里那份清单在不同机器上 sha256 可能差一点（S-075），所以版本只在同一份文件上比。
- 每个场景 `scene.x` 看目录 `<场景包目录>/x/`：
  - 有 `index.json`（F-10 一个场景多个包）就用它，否则用 `scene.json`（广场）；
  - `assetVersion` = 那个文件的 sha256 前 8 位。入口文件里列着每个文件的 sha256（`files[]`），任何一个文件变了，入口文件就变；
  - `assetUrl` = `/scenes/x/<assetVersion>/<那个文件名>`，例 `/scenes/syracuse-square/1a2b3c4d/scene.json`。版本放在路径里（前端评审 #93），不用查询参数：
    - `AssetPath` 的 pattern 不许有 `?`；
    - 部署传文件要一段时间，用 `?v=新` 时，新 manifest 的玩家可能在新文件传完之前就请求，CDN 会把旧文件按新键缓存一年；放在路径里，没传完的只会 404；
    - 拿着旧 manifest 玩到一半的玩家，下一幕还能加载旧版的包（F-10），新旧两版可以同时在。
  - 包里别的文件的地址相对 `assetUrl` 算（F-10），自动带上版本。`/scenes/<目录>/<版本>/` 下的文件都长缓存（`immutable`）。本地开发时 vite 发场景的中间件去掉版本那一段（前端在 F-2d 做）。
  - 两个都没有：这个场景没有包，不进 `scenes`，也不进任何一幕的 `sceneIds`，启动日志记一行。
- 部署那张卡记一句：网关算 `assetVersion` 和前端上传场景包，用同一次构建的输出（`ZJ_SCENE_PACKS` 指到构建的输出，两边读同一份）；旧版本的目录等没有 manifest 指向它以后再删。

**3. 预录句**（读 `assets/voice/{bookId}/voices.json`，B-6 的格式）

- 清单没有：人物都不带 `prerecorded`，没有 `setPieceVoices`（前端照没有预录处理，api-contract 2.1 已写）。
- `characters[].prerecorded`：清单里有、而且 `talkable` 的人物才带（Schema 说不能对话的人物没有；mock 里フィロストラトス的例子）。
- 和世界模型核对，对不上的不出，启动日志记键名（不记文字）：
  - `setPieceVoices` 的每个键：世界模型里有这条固定演出，第 n 行是人物说的话，`text` 和那一行的 `line` 一字不差；
  - `cues.arrival_capped`：只放在 `clock.deadline.earliestArrivalCue.speaker`（梅洛斯）那个人物的 `prerecorded` 里，`text` 和它的 `line` 一字不差。同一条里的 `narration` 是地の文，不是人物的声音，不核对、不录（数据评审 #93）。
  - 人物的 6 句是 UX 的台词稿，世界模型里没有，不核对。
- `voices.json` 的 `worldModelVersion` 和这本书的版本不同时照样用，靠上面逐句核对；日志记一行两个版本号。

**4. 正式网关的路由**（`gateway/rest.py`、`gateway/app.py`）

- `GET /v1/books/{bookId}/manifest`：
  - 要登录，同 mock（邀请制，没有会话回 401 `unauthenticated`）；
  - 书 ID 不是网关这本书（`Library.current`）回 404 `not_found`；
  - 响应头 `ETag: "<manifestVersion>"`、`Cache-Control: private, no-cache`；请求带的 `If-None-Match` 对上就回 304，不带内容；
  - 进程启动时生成一次放内存里，换世界模型、声音或场景包都要重启（部署就是重启）。生成出错网关起不来，错误写清是哪一样、哪个文件。
- `GET /assets/voice/{bookId}/{name}`：照 mock 的规矩（只发清单里列着的文件，不要登录，`Cache-Control: public, max-age=31536000, immutable`，`Content-Type: audio/mp4`；清单外的路径、清单本身、别的书回 404）。部署时前面挂 CDN 还是搬到 Cloud Storage 由部署那张卡定，地址不变。
- 测试 `test_gateway.py` 的 `test_routes_b0_does_not_mount_are_404` 去掉 manifest 那一项。

**5. mock 用同一个生成器**（`mock/core.py`）

- mock 的 manifest 改成调第 1 条的生成器（mock 用的世界模型、`assets/voice`、`assets/scenes`），去掉 `fixtures/mock/rest/manifest/hashire-merosu.json` 和 `voices.json` 换预录的那段。
- mock 的 manifest 响应头和正式的一样（`ETag`、304）。现在 mock 写的是 `immutable`，跟着改。
- 契约的例子 `packages/contracts/examples/valid/api/rest/manifest/200/doc-2.1.json` 不动（它是 api-contract 2.1 的例子）。
- 前端现在还不读 REST 的 manifest（`apps/web/src` 里没有 `/v1/books`），换生成器不碍前端。

**6. 配置和文档**

- `config.py`：`ZJ_RELEASE`（默认 1）、`ZJ_SCENE_PACKS`（默认 `assets/scenes`，绝对路径）。`services/backend/README.md` 的环境变量一行跟着加。
- api-contract 2.1 改成 v1.0.9（见「契约的小改」），backend-design 3.6、第 4 节各补一句（manifest 不长缓存、`ETag`；录音长缓存）。

### 不做

- 前端读 manifest、按 `assetVersion` 加载和缓存场景包、预载录音（前端的卡）。
- 部署：Cloud Storage、CDN、负载均衡的分流、部署构建里生成场景包（部署那张卡，要 zg 同意）。
- 一局锁定的世界模型版本和 manifest 不一致的情况：manifest 只描述开新局用的那个版本（`Library.current`）。评审部署期间换世界模型版本时，老局的人物名、场景可能和 manifest 有出入；R1 只用一个版本，先不处理，在 backend-design 第 12 节记一条风险。
- 第二版的身份（`release: 2`）、P1 的 `npc_line`、分享。
- 注音词表里放哪些词（数据定，UX 看）。
- 保证玩家玩到一半能到的场景都有包：开局场景一定有（第 1 条）。到了没有包的场景（草稿世界模型的王城），前端留在当前画面、只出字幕和旁白（前端评审 #93 第 4 问，前端已兜底），api-contract 2.1 写这一句。上线前开放的身份能走到的场景都要有包，由部署那张卡查。

## 契约的小改

**数据契约（数据改，和后端的代码 PR 分开；后端的 PR 叠在上面）**：数据开了 #101（契约 1.10，生成器读 `roles[].summary`、`world.get("ruby", [])`、`characters[].reading`）。

1. `Role.summary`（必填，一句，玩家看的日语）：身份页和 manifest 用。现在世界模型里只有 `note`，是写给我们自己的，不能给玩家看。文字 UX 定（切片只有旅人，mock 里示意的是「シラクスの市に着いたばかりの旅の者。」）。
2. 世界模型顶层加注音词表 `ruby: [{ word, reading }]`：frontend-design 说几十个词，读音来自原文（青空文库的注音，`worlds/hashire-merosu/sources/melos_ruby.txt`），哪些词数据定。
3. `Character.reading` 字段契约里已有（可选），现在两份世界模型都没填。manifest 的 Schema 要求每个人物都有：请数据填全，片假名的名字照抄。`build_world` 查第一版的人物都有 `reading`。

**api-contract 2.1（v1.0.9，后端的代码 PR 里改，不改 Schema）**：

- 第一句「URL 带版本，`Cache-Control: public, max-age=31536000, immutable`」改成：地址不带版本；`ETag` 是 `manifestVersion`，`Cache-Control: private, no-cache`，前端每次带 `If-None-Match` 问，没变回 304。录音和场景包的文件自己长缓存。
- 加：`manifestVersion` 的形状（`{worldModelVersion}+{hash}`，只用来比相等）；`roles` 只出 `release` ≤ 开放版次、开局场景有包的身份；`scenes` 只出有包的场景，`acts[].sceneIds` 跟着；`assetUrl` 是 `/scenes/<目录>/<assetVersion>/<入口文件>`（`index.json` 或 `scene.json`），`assetVersion` 是入口文件的内容 hash，`/scenes/<目录>/<版本>/` 下的文件都长缓存；`characters` 是世界模型的全部人物；`cues.arrival_capped` 只在说这句的人物身上；玩家到了没有包的场景，前端只出字幕和旁白。
- 2.2 加一句（UX 评 #100，PM 转）：今天的开局次数用完时，`POST /v1/playthroughs` 先回 429 `daily_limit`，不回 409。不然玩家选「新しく始める」，前端先删了旧局，开新局才回 429，旧局没了新局也开不了。正式网关和 mock 现在都不拦次数（B-0 只显示），拦次数的那张卡照这个顺序做。
- mock 的 manifest 从 fixture 改成同一个生成器，`fixtures/mock/README.md` 里那句「预录台词和资源路径是示意」删掉。

## 验收

不联网，CI 只用仓库里的文件和测试里造的小目录。

1. **生成规则**（草稿和切片两份世界模型各跑一遍，都过 `ManifestResponse` 的 Schema）：
   - `scenes[].places`、`roles[].startSceneId`、`acts[].sceneIds` 照 2.1 的规则；
   - 草稿世界模型、`ZJ_RELEASE=1`：出旅人、石屋の弟子（开局场景都是广场）；村の牧童的开局场景（村）没有包，不出；`release: 2` 的不出；`ZJ_RELEASE=2` 时王城の侍女、警吏也照「开局场景有没有包」处理；
   - 没有包的场景（王城、村、归途）不在 `scenes`，也不在任何一幕的 `sceneIds`；测试目录里给王城放一份 `scene.json`，它就出现，`assetUrl` 是 `/scenes/castle-throne/<8 位>/scene.json`；
   - 有 `index.json` 的目录用 `index.json`；
   - 人物是世界模型的全部，`talkable` 照世界模型（切片只有梅洛斯和老爺）。
2. **预录句**：
   - 没有声音清单：没有 `prerecorded`、没有 `setPieceVoices`；
   - 有清单：梅洛斯和老爺的 `prerecorded` 就是清单里的；フィロストラトス在清单里也不出（不能对话）；
   - 改掉清单里一条固定演出的 `text` → 那个键不出，别的键照旧；指向世界模型里没有的固定演出、或者指向地の文那一行 → 不出；`arrival_capped` 的文字对不上 → 只少这个 cue；清单里别的人物带 `arrival_capped` → 那个人物不带这个 cue。
3. **版本**：
   - 同样的输入生成两次，`manifestVersion` 一样；
   - 改世界模型、声音清单、任何一个场景入口文件中的一个字节，`manifestVersion` 和对应的 `assetVersion` 变。
4. **路由**（真 PostgreSQL 的网关端到端）：
   - 没登录 401；别的书 404 `not_found`；
   - 200 带 `ETag` 和 `Cache-Control: private, no-cache`；带同一个 `If-None-Match` 回 304、没有内容；
   - `/assets/voice/…`：清单里的文件 200、`immutable`、`audio/mp4`；清单外、`voices.json` 本身、别的书 404；不要登录；
   - 生成出错（例：测试里给一个缺 `Role.summary` 的世界模型）网关起不来，错误里有字段名。
5. **mock**：manifest 和正式网关对同样的输入一样（除了 mock 自己的会话）；去掉 fixture 以后 `test_mock.py`、`test_voice.py` 的 manifest 测试照旧通过（改成对生成器）。
6. **日志**：启动日志只有 ID、键名、版本号、个数，没有台词和文字。

全量 pytest、ruff、mypy 照旧。CI 停着时按 PM 的排法（`pm/ci-freeze-plan.md`）在 PR 上贴本地跑的同一套检查。

## 评审

- **前端**：
  1. 场景入口：`assetUrl` = `/scenes/<目录>/index.json`，没有就 `scene.json`，对不对？和 `sceneBase()` 的约定一致吗？
  2. `assetVersion` 是入口文件的 sha256 前 8 位。场景包里的文件名不带 hash，前端打算怎么让缓存跟着版本走（换路径、加查询参数，还是 Service Worker 按版本存）？如果要后端在 `assetUrl` 里带上版本（例 `/scenes/<版本>/<目录>/…`），在这里说，本卡一起改。
  3. manifest 不长缓存、`ETag` + 304，前端每次进游戏问一次，可以吗？
  4. 没有包的场景、开局场景没有包的身份都不出现：前端照 manifest 显示，够不够？
  5. mock 换成同一个生成器，前端的开发流程有没有要留的 fixture？
- **数据**：
  1. 「契约的小改」三样：`Role.summary`、顶层 `ruby`、填全 `Character.reading`。字段名和放的位置你定，后端跟着读。哪个 PR 加、什么时候能开？
  2. 生成规则里用到的世界模型字段（`release`、`startPlace` → `sceneRef`、`Act.scenes`、`clock.deadline`、`earliestArrivalCue`、`setPieces[].lines`）有没有用错的。
