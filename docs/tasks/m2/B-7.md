## Goal / 目標

When done:

完了後：

1. The real gateway has `GET /v1/books/{bookId}/manifest`, entirely generated from what is in the repo, with nothing hand-written:
   本番のゲートウェイに `GET /v1/books/{bookId}/manifest` があり、中身はすべてリポジトリにあるものから生成し、手書きしない：
   - world model: book, identities, scenes and places, characters, acts, clock, ruby glossary;
     世界モデル：本、身分、場面と場所、人物、幕、時計、ルビ語リスト；
   - B-6's voice list: characters' pre-recorded lines, set-piece pre-recorded lines;
     B-6 の音声リスト：人物の事前収録セリフ、固定演出の事前収録セリフ；
   - the frontend's scene-pack listing: each scene's entry URL and version.
     フロントエンドのシーンパックの一覧：各場面の入口の URL とバージョン。
2. The manifest URL carries no version; caching relies on `ETag`: if the content hasn't changed, the frontend gets just a 304 each time; recording and scene-pack files are long-cached on their own. That sentence in api-contract 2.1 changes accordingly (the B-6 card handed this to this card).
   manifest の URL にはバージョンを付けず、キャッシュは `ETag` に頼る：中身が変わっていなければ、フロントエンドは毎回 304 を受け取るだけ。録音とシーンパックのファイルはそれ自体を長くキャッシュする。api-contract 2.1 のその一文も合わせて直す（B-6 カードがこの件をこのカードに渡した）。
3. Only things that can really be loaded go into the manifest: scenes without a scene pack, identities whose starting scene has no pack, and lines in the voice list that don't match the world model are all left out. Every URL the frontend gets works.
   本当に読み込めるものだけを manifest に入れる：シーンパックのない場面、開始場面にパックのない身分、音声リストのうち世界モデルと合わないセリフは、どれも出さない。フロントエンドが受け取る URL はすべて使える。
4. The mock and the real gateway use the same generator, so the manifest the frontend sees on the mock is the same as the real one.
   モックと本番のゲートウェイは同じジェネレーターを使うので、フロントエンドがモックで見る manifest は本番と同じ。
5. The real gateway also serves the `/assets/voice/…` recording files (only those in the list), so neither the local setup nor the first deployment for reviewers needs a separate static server; putting them on a CDN later belongs to the deployment card.
   本番のゲートウェイも `/assets/voice/…` の録音ファイルを返す（リストにあるものだけ）ので、ローカルでも最初のレビュー用デプロイでも別の静的サーバーを用意する必要はない。後で CDN に載せるのはデプロイのカードの担当。

## Scope / 範囲

### In scope / やること

**1. Generator** (`services/backend/src/zoujin_backend/manifest.py`, a pure function, no database access)

**1. ジェネレーター**（`services/backend/src/zoujin_backend/manifest.py`、純粋関数で DB に触れない）

Input: one book's world model (`Book`), the voice list (may be absent), the scene-pack directory. Output: a manifest that passes the schema.

入力：1 冊の本の世界モデル（`Book`）、音声リスト（なくてもよい）、シーンパックのディレクトリ。出力：スキーマを通る manifest。

| Field / フィールド | Source / 出どころ |
|---|---|
| `book` | `id`, `title`, `author` of the world model's `book` / 世界モデルの `book` の `id`、`title`、`author` |
| `roles` | Identities with `release` ≤ the released edition (config `ZJ_RELEASE`, default 1), in world-model order. `name`; `summary` = `Role.summary` (new field, see "Small contract changes"); `startSceneId` = the `sceneRef` of `startPlace`; `startActId` = `startAct`. Identities whose starting scene has no pack are left out, with one line logged at startup with the identity ID / `release` ≤ 公開版次（設定 `ZJ_RELEASE`、デフォルト 1）の身分を、世界モデルの順に。`name`。`summary` = `Role.summary`（新しいフィールド、「契約の小さな変更」を参照）。`startSceneId` = `startPlace` の `sceneRef`。`startActId` = `startAct`。開始場面にパックのない身分は出さず、起動ログに身分 ID を 1 行記録する |
| `scenes` | Those in the world model's `scenes` that have a pack (see item 2). `places` = places whose `sceneRef` points to it, in world-model order / 世界モデルの `scenes` のうちパックがあるもの（第 2 項を参照）。`places` = `sceneRef` がそれを指す場所で、世界モデルの順 |
| `characters` | All characters in the world model, in world-model order. `name`; `reading` = `Character.reading` (filled in by data); `talkable`; `prerecorded` see item 3 / 世界モデルのすべての人物を、世界モデルの順に。`name`。`reading` = `Character.reading`（データが補う）。`talkable`。`prerecorded` は第 3 項を参照 |
| `acts` | `actId`, `title`; `sceneIds` = the scenes in `Act.scenes` that have a pack / `actId`、`title`。`sceneIds` = `Act.scenes` のうちパックのある場面 |
| `clock` | `deadlineT` = `clock.deadline.t`; `sunsetMinuteOfDay`; `days` = `clock.labels.days` / `deadlineT` = `clock.deadline.t`、`sunsetMinuteOfDay`、`days` = `clock.labels.days` |
| `ruby` | The world model's ruby glossary (new field, see "Small contract changes"), as is / 世界モデルのルビ語リスト（新しいフィールド、「契約の小さな変更」を参照）をそのまま |
| `setPieceVoices` | See item 3; omitted when there are no keys / 第 3 項を参照。キーが 1 つもなければ省く |
| `manifestVersion` | `{worldModelVersion}+{first 8 hex of content hash}`, e.g. `hashire-merosu@1.0.0-slice.3+4f3a91c2`. The hash covers the whole manifest except this field (key-sorted JSON): if the world model, the voice list or any scene pack changes, the version changes; the same input always gives the same result / `{worldModelVersion}+{first 8 hex of content hash}`、例 `hashire-merosu@1.0.0-slice.3+4f3a91c2`。ハッシュはこのフィールド以外の manifest 全体（キーを並べ替えた JSON）で計算する：世界モデル、音声リスト、どれか 1 つのシーンパックが変わればバージョンが変わり、同じ入力なら毎回同じ |

- The generated result is validated against the `ManifestResponse` schema, and an error is raised if it fails (at startup, see item 4).
  生成結果は `ManifestResponse` のスキーマで検証し、通らなければエラーにする（起動時。第 4 項を参照）。
- The generated manifest carries none of the world model's internal fields (`note`, `inferred`, `cite`, `access` and the like): only what is in the table above.
  生成した manifest には世界モデルの内部フィールド（`note`、`inferred`、`cite`、`access` など）を含めない：上の表にあるものだけ。

**2. Scene packs** (`scenes[].assetUrl`, `assetVersion`)

**2. シーンパック**（`scenes[].assetUrl`、`assetVersion`）

- The scene-pack directory is configured with `ZJ_SCENE_PACKS`, defaulting to the repo's `assets/scenes`. The deployment build generates scene packs on the spot (S-075), and the deployment card points this at the build output, so the version matches the files actually shipped. The listings in the repo may differ slightly in sha256 across machines (S-075), so versions are only compared on the same copy of the files.
  シーンパックのディレクトリは設定 `ZJ_SCENE_PACKS` で、デフォルトはリポジトリの `assets/scenes`。デプロイのビルドでシーンパックをその場で生成し（S-075）、デプロイのカードがこれをビルドの出力に向けるので、バージョンは実際に配信するファイルと一致する。リポジトリにある一覧はマシンによって sha256 が少し違うことがある（S-075）ので、バージョンは同じファイル同士でだけ比べる。
- For each scene `scene.x`, look at the directory `<scene pack dir>/x/`:
  各場面 `scene.x` について、ディレクトリ `<scene pack dir>/x/` を見る：
  - if there is an `index.json` (F-10, several packs per scene), use it; otherwise use `scene.json` (the square);
    `index.json`（F-10、1 つの場面に複数のパック）があればそれを使い、なければ `scene.json`（広場）を使う；
  - `assetVersion` = the first 8 hex of that file's sha256. The entry file lists each file's sha256 (`files[]`), so if any file changes, the entry file changes;
    `assetVersion` = そのファイルの sha256 の先頭 8 桁。入口のファイルには各ファイルの sha256 が並んでいる（`files[]`）ので、どれか 1 つのファイルが変われば入口のファイルも変わる；
  - `assetUrl` = `/scenes/x/<assetVersion>/<that file name>`, e.g. `/scenes/syracuse-square/1a2b3c4d/scene.json`. (Changed in the #114 frontend 2 review to `/scenes/<assetVersion>/x/<that file name>`, where the version is the hash of all files in the directories reachable from the entry; see api-contract 2.1.) The version goes in the path (frontend review #93), not in a query parameter:
    `assetUrl` = `/scenes/x/<assetVersion>/<that file name>`、例 `/scenes/syracuse-square/1a2b3c4d/scene.json`。（#114 のフロントエンド 2 のレビューで `/scenes/<assetVersion>/x/<that file name>` に変更。バージョンは入口からたどれるディレクトリ内のすべてのファイルのハッシュ。api-contract 2.1 を参照。）バージョンはクエリパラメータではなくパスに入れる（フロントエンドのレビュー #93）：
    - the `AssetPath` pattern doesn't allow `?`;
      `AssetPath` のパターンは `?` を許さない；
    - uploading files during deployment takes a while; with `?v=new`, a player with the new manifest might request a file before the new one has finished uploading, and the CDN would cache the old file under the new key for a year; with the version in the path, files not yet uploaded just 404;
      デプロイでのファイルのアップロードには時間がかかる。`?v=new` を使うと、新しい manifest を持ったプレイヤーが新しいファイルのアップロード完了前にリクエストし、CDN が古いファイルを新しいキーで 1 年キャッシュしてしまう。パスに入れれば、アップロードが終わっていないものは 404 になるだけ；
    - a player halfway through with the old manifest can still load the old pack for the next act (F-10), so old and new versions can coexist.
      古い manifest のまま途中までプレイしたプレイヤーも、次の幕で古い版のパックを読み込める（F-10）ので、新旧 2 つの版が同時に存在できる。
  - Other files in the pack have URLs relative to `assetUrl` (F-10), so they automatically carry the version. Files under `/scenes/<dir>/<version>/` are all long-cached (`immutable`). In local development, vite's scene-serving middleware strips the version segment (the frontend does this in F-2d).
    パック内のほかのファイルの URL は `assetUrl` からの相対で計算する（F-10）ので、自動的にバージョンが付く。`/scenes/<dir>/<version>/` 以下のファイルはすべて長くキャッシュする（`immutable`）。ローカル開発では、vite の場面を返すミドルウェアがバージョンの部分を取り除く（フロントエンドが F-2d でやる）。
  - Neither exists: this scene has no pack; it goes neither into `scenes` nor into any act's `sceneIds`, and one line is logged at startup.
    どちらもない：この場面にはパックがなく、`scenes` にもどの幕の `sceneIds` にも入れない。起動ログに 1 行記録する。
- The deployment card notes: the gateway's computation of `assetVersion` and the frontend's upload of scene packs use the output of the same build (`ZJ_SCENE_PACKS` points to the build output, so both read the same copy); old version directories are deleted only once no manifest points to them.
  デプロイのカードに一言書く：ゲートウェイが `assetVersion` を計算するのと、フロントエンドがシーンパックをアップロードするのは、同じビルドの出力を使う（`ZJ_SCENE_PACKS` をビルドの出力に向けて、両者が同じものを読む）。古いバージョンのディレクトリは、それを指す manifest がなくなってから削除する。

**3. Pre-recorded lines** (reads `assets/voice/{bookId}/voices.json`, B-6's format)

**3. 事前収録セリフ**（`assets/voice/{bookId}/voices.json` を読む。B-6 の形式）

- No list: no character carries `prerecorded`, and there is no `setPieceVoices` (the frontend handles it as no pre-recorded lines; api-contract 2.1 already says so).
  リストがない：どの人物にも `prerecorded` を付けず、`setPieceVoices` もない（フロントエンドは事前収録がないものとして扱う。api-contract 2.1 に既に書いてある）。
- `characters[].prerecorded`: only characters in the list who are also `talkable` carry it (the schema says characters who can't be talked to have none; フィロストラトス is the example in the mock).
  `characters[].prerecorded`：リストにあり、かつ `talkable` の人物だけに付ける（スキーマでは話せない人物には付けない。モックのフィロストラトスがその例）。
- Cross-check against the world model; what doesn't match is left out, and the key name (not the text) is logged at startup:
  世界モデルと照合し、合わないものは出さず、起動ログにキー名を記録する（文字は記録しない）：
  - each `setPieceVoices` key: the world model has this set piece, line n is spoken by a character, and `text` matches that line's `line` character for character;
    `setPieceVoices` の各キー：世界モデルにその固定演出があり、第 n 行が人物のセリフで、`text` がその行の `line` と一字一句同じ；
  - `cues.arrival_capped`: placed only in the `prerecorded` of the character in `clock.deadline.earliestArrivalCue.speaker` (Melos), with `text` matching its `line` character for character. The `narration` in the same entry is 地の文, not a character's voice; it is neither checked nor recorded (data review #93).
    `cues.arrival_capped`：`clock.deadline.earliestArrivalCue.speaker` の人物（メロス）の `prerecorded` にだけ置き、`text` がその `line` と一字一句同じ。同じ項目の `narration` は地の文で人物の声ではないので、照合も録音もしない（データのレビュー #93）。
  - The characters' 6 lines are UX's script and aren't in the world model, so they aren't checked.
    人物の 6 つのセリフは UX の台本で世界モデルにはないので、照合しない。
- When `voices.json`'s `worldModelVersion` differs from this book's version, it is used anyway, relying on the line-by-line check above; one line with both version numbers is logged.
  `voices.json` の `worldModelVersion` がこの本のバージョンと違っても、そのまま使い、上の 1 行ずつの照合に任せる。2 つのバージョン番号を 1 行ログに記録する。

**4. Routes on the real gateway** (`gateway/rest.py`, `gateway/app.py`)

**4. 本番ゲートウェイのルート**（`gateway/rest.py`、`gateway/app.py`）

- `GET /v1/books/{bookId}/manifest`:
  `GET /v1/books/{bookId}/manifest`：
  - requires login, same as the mock (invite-only; no session gets 401 `unauthenticated`);
    ログインが必要で、モックと同じ（招待制。セッションがなければ 401 `unauthenticated`）；
  - a book ID that isn't this gateway's book (`Library.current`) gets 404 `not_found`;
    本の ID がこのゲートウェイの本（`Library.current`）でなければ 404 `not_found`；
  - response headers `ETag: "<manifestVersion>"`, `Cache-Control: private, no-cache`; if the request's `If-None-Match` matches, return 304 with no body;
    レスポンスヘッダーは `ETag: "<manifestVersion>"`、`Cache-Control: private, no-cache`。リクエストの `If-None-Match` が一致すれば、本文なしで 304 を返す；
  - generated once at process startup and kept in memory; changing the world model, voices or scene packs requires a restart (deploying is a restart). If generation fails, the gateway doesn't start, and the error says clearly which input and which file.
    プロセスの起動時に 1 回生成してメモリに置く。世界モデル、声、シーンパックを替えるには再起動が必要（デプロイは再起動）。生成に失敗したらゲートウェイは起動せず、エラーにはどの入力のどのファイルかをはっきり書く。
- `GET /assets/voice/{bookId}/{name}`: follows the mock's rules (serves only files listed in the list, no login required, `Cache-Control: public, max-age=31536000, immutable`, `Content-Type: audio/mp4`; paths not in the list, the list itself, and other books get 404). Whether a CDN sits in front at deployment or the files move to Cloud Storage is decided by the deployment card; the URL doesn't change.
