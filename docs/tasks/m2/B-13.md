## 目标

做完以后：

1. 叙事者提交一轮的事件时，给在场或听说了的人物每人最多写一条记忆：Claude Haiku 写人物视角的一句日语，过三道过滤（个人信息规则、Model Armor、长度和引号里的命令句），不过就只留事件不写记忆。`via` 确定性地填。
2. 关系（`trust` 和五档标签）从没删的记忆算，不存。
3. `GET …/memories` 返回記憶帳的四栏（约定、为你做的、你做的、记忆），`GET …/memories/{id}/impact` 返回删除前的「不会撤销的后果」一句（缓存），`DELETE …/memories/{id}` 当场生效。
4. 删除当场：清空这条记忆的文字和产生它的整轮原话（玩家和人物的都清），约定类的追加 `forget` 事件把开着的约定设为 `voided`，重算关系，这个人物的语音会话开着就用新的局势说明重建。世界的后果不撤销。
5. `DELETE /v1/playthroughs/{id}` 删整局（L2）；评测入口的 `memories`、`delete_memory`、`delete_playthrough`、`new_playthrough`、`trust`、`db_absent` 和 setup 里的 `memory` 都做了，E6 不再整例跳过。

## 范围

### 做

**1. 表（迁移 0007）**

- `memory_items`：`memory_id`、`playthrough_id`（随整局删）、`character`、`kind`、`text`（删了置空）、`from_events`（JSONB）、`t`、`trust_delta`、`salience`、`via`、`promise_id`、`keeps`（「不会撤销的后果」一句的缓存，可为空）、`keeps_done`（算过没有，算出 null 也缓存）、`created_at`、`deleted_at`。
- 索引 `(playthrough_id, character) WHERE deleted_at IS NULL`（局势说明和算关系都走它，数据定）；删除时 `text`、`keeps` 都置空；`schema_version` 写当前的契约版本。
- `playthrough_metrics` 加 `cost_memory_usd`（记忆一句和后果一句）、`memories_written`、`memories_filtered`（三道过滤没过的）、`memories_deleted`、`memories_failed`（模型出错、超时）。列名数据定了照这几个。

**2. 写记忆（叙事者第 7 步前后）**

- 哪些事件写（数据评审）：这一轮**已提交的事件都可以**（`check.status` 是 passed / rewritten），包括 `effects` 空、只推时钟的 `say`（E6-001、002、004、005、007 都是这种）；不含 `forget`、`correction`、`act-transition`、`ending`。人物以外的事件玩家看不到（`zoujin_worldsim.sees`）就不写。
- **一个人物一轮最多一条**：同一轮和他有关的几条事件合成一条，`fromEvents` 列全（排第一的是定 `kind` 的那条），`kind` 取下表最靠前的一行；约定那一行排最前，所以 `promiseId` 照样挂得上。删除本来就清整轮的原话，一轮一条才删得干净，评测的 `delete_memory(character, from_step)` 也唯一。一轮最多写 3 个人物（按 salience）。
- 对照表（数据定，`narrator/memory.py` 的 `ROWS`）：

  | 条件（这一轮的事件） | kind | trustDelta | salience |
  |---|---|---:|---:|
  | 有 `promise` 效果 `made`，约定的一方是他 | promise | +5 | 0.8 |
  | 玩家兑现了和他的约定（`kept`） | help | +10 | 0.8 |
  | 玩家违背了和他的约定（`broken`） | harm | -15 | 0.9 |
  | `actor: player`、`beneficiary` 是他 | help | +10 | 0.7 |
  | `actor: player`，他的信任类变量（`var.<他>.trust`）降了，或把他带走（`relocate`，他不是 beneficiary） | harm | -10 | 0.7 |
  | `actor` 是他、`beneficiary` 是玩家 | shared-moment | +3 | 0.5 |
  | 节拍（`origin: schedule`）发生、玩家看得到、他亲历（`zoujin_worldsim.lived`，#154） | shared-moment | +2 | 0.6 |
  | `actor: player` 的 `say`，有 `learn` 效果写明他学到了，或 `improv` 成了他的即兴设定（玩家说自己的事） | claim | 0 | 0.5 |
  | 其余 `actor: player` 的事件：说话只给这一轮说话的对象，动作给在场的人 | impression | 0 | 0.3 |

  - `keyMoment: true` 的 salience 加 0.2（上限 1）；trustDelta 夹在 -20〜20。世界变量 `var.<他>.trust` 只用正负号挑行，不抄进 trustDelta。claim 和 impression 分不清时写 impression。
  - 记忆模型多给一个 `weight`（1〜3，这件事对他有多重），salience 再加 `0.1 × (weight - 1)`，夹在这一行的值到 1 之间；数还是代码算，模型只给档（E6-007：节约档只带 4 条，也要记得「家族は王に殺された」）。局势说明同分时 `t` 新的在前。
- 模型：新的提示类型 `memory`（Claude Haiku 5.5、关思考、5 秒），输入只有这一轮和他有关的事件的 `summary`、`visibleEffects`、人物的人设摘要和 `via`，不给原话（原话删了以后记忆也不该带着它）。输出 `{text, weight}`。
- 一句的写法（UX 评审，写进提示）：人物自己的口吻和用词，写他记得你的什么，不是事件概述；20 字左右；不带「」、句末不带「。」（前端会加引号；代码也会去掉整句外的「」和句末的「。」）；不写身份名，提到玩家用「あなた」「あの人」「あの旅の者」（契约 1.8 的身份名替换只管 `summary`）。
- 三道过滤，任一不过就不写这条（事件照留）：
  1. 个人信息规则（`safety.pii`，和 R6 同一套）；
  2. Model Armor（`sanitizeModelResponse`，注入、RAI HIGH、SDP；1 秒、出错当没命中，和 B-12 一样）；
  3. 规则：引号里的命令句；身份名；长度上限 30 字（NFKC 以后按字数、含标点；UX 要 30、数据给 40，取严的 30），超了当过滤没过，不截断（截断会截出半句）。
- `via`：事件之前他在事件的地点，或亲历了这个节拍（`lived`） = `witnessed`；事件里有 `learn` 效果写明他学到了 = `told`；切片不写 `rumor`（没在场也没被告知的人物不写记忆，留给 M3 的传话链）。
- `trustDelta`、`salience` 按事件类型和 `visibleEffects` 确定性地算（表在常量里），不让模型给数。
- 时机：模型调用不放进提交的数据库事务里。提交事件的事务先不 NOTIFY；事务之后并行写记忆，再开一个事务存记忆、写 `turns.result.memories`、NOTIFY，`commit.memories[]` 带 `added`（写代码时定的，比「提交之前写」少拖住提交）。模型超时或出错 → 这一轮不写记忆、计数，不重发，照常 NOTIFY。
- 关系：`trust` = 起始值（身份认识这个人物 +10，否则 0）+ 没删的记忆的 `trustDelta` 之和，夹在 -100〜100；五档按契约第 4 节的表。`commit.memories[]` 带新的 `relationLabel`、`relationLevel`。

**3. 局势说明里带记忆**

- 开会话时按 `salience` 取这个人物没删的最多 8 条（节约档 4 条），给后端 3 的 `gateway/brief.py`：`build(…)` 多一个 `memories` 参数，和 B-12 的 `notes` 一样由 `Voices._brief` 取好传进去（本卡给 `memories_for_brief(c, pid, who, limit)`，放在「# いまの状況」后面的「# 覚えていること」，和后端 3 对过再定）。

**4. 記憶帳的三个接口（`gateway/rest.py`）**

- `GET /v1/playthroughs/{id}/memories`：只有玩家见过的人物，四栏照契约 2.7 的形状；`voided` 的约定照样返回（前端不显示）；空栏是 `[]`。
- `GET …/memories/{memoryId}/impact`：`{keeps, voidsPromise}`。`keeps` 第一次请求时用 Haiku 从来源事件的 `summary` 和 `visibleEffects` 写一句（新的提示类型 `keeps`，不读原话），存进 `memory_items.keeps`，以后直接读；`voidsPromise` = 这条记忆指向的约定还开着。删了的或不存在的 → 404。
  - 时限 2 秒（UX 评审：前端在它回来之前把〔忘れてもらう〕置灰）。超时、出错、过不了过滤 → `null`，**不缓存**，下次打开再算；只缓存真算出来的一句和模型说「没有后果可说」的 `null`。
  - 写法（写进提示，代码也挡）：一句 30 字以内，前端套在「ただし、すでに起きたことは元に戻りません。（例：…）」里，句末不带「。」；只写玩家已经看到的后果；人物用名字，不用「彼」「彼女」；`voidsPromise` 为真时不写这个约定本身（下一行就是「この約束も、なかったことになります」）；不写「覚えている」「忘れる」。
- `DELETE …/memories/{memoryId}`：带 `Idempotency-Key`（和别的 POST 同一套），回 `{memoryId, deleted, character, relationLabel, relationLevel, promiseVoided, sessionRebuilt}`。别人的局 403，删过的或不存在的 404（同一个 key 重放回原来的 200）。

**5. 删除当场生效（契约第 4 节、data-design 5.3 的 L1）**

同一个事务里：
1. 这条记忆 `text` 置空、`deleted_at` 写上；
2. 顺着 `from_events → events.turn_id → utterances.turn_id` 清空整轮原话（玩家和人物的），`turns.result` 里这一轮打算的原文按 B-4 的写法清掉，这一轮开着的意图确认草稿按「不是」丢掉；
3. `promise_id` 指向开着的约定 → 写一个 `forget` 事件（`origin: "memory"`、`actor: "player"`、`dt: 0`，效果 `{op: "promise", change: "voided"}`，`summary` 是中立的「〜との約束は、なかったことになった」，不写「覚えていない」「忘れた」），走叙事者正常的提交（`commit` 照常推，不进地图时间线和「その頃」，回放事件得到同一个状态）；已经 `kept` / `broken` 的不动；
4. 重算关系，`commit.memories[]` 推 `deleted`。

事务之后：
5. 网关：丢掉这一轮在内存里的最近对话；这个人物的会话开着 → 用新的局势说明重建（后端 3 的 `Voices.rebuild`，推 `session_preparing { reason: "rebuild" }`），`sessionRebuilt: true`；断线寄存的会话和最近对话用 `Gateway.forget(局)` 丢掉。
6. 世界的后果不撤销（事件留着，契约第 4 节第 2 条）。

**6. 删除整局（L2）**

- `DELETE /v1/playthroughs/{id}`：带 `Idempotency-Key`，回 202；后台按 data-design 5.2 的 L2 删（这一局所有的表按外键级联；Cloud Storage、BigQuery 的部分等部署以后的卡）；开着的 WebSocket 用 4004 关掉；`Gateway.forget(局)`。之后这一局的接口都是 404。

**7. 评测入口**

- `memories(character)`：MemoryItem 的列表，删了的带 `deletedAt`、`text` 是空的。
- `delete_memory(character, from_step)`：删这个人物来源于第 `from_step` 步提交的事件的那条记忆（一人一轮一条，所以唯一），走和 REST 同一个函数；没有这样的记忆就报错，不静默成功（数据评审）。
- `delete_playthrough()`、`new_playthrough()`（同一个账号、同一个起点，之后的查询答新局）。
- `trust(character)`（int，只算記憶帳的关系）、`db_absent(tables)`（`{表: 剩几行}`，真去查建了的表；data-design 5.3 里还没建、名字在写死名单里的（`briefs`，局势说明不存库）答 0；名单外不认识的表名不答，评测报「后端没回这张表」，免得表名写错也是 0 混过去）。
- setup 的事件带 `memory: {character, kind, text}` → 直接种一条记忆（不调模型，过同样的三道过滤）。
- 写记忆、后果一句在评测里也走同一个提示（假模型和回放；真模型只在 Mac 上）。

### 不做

- 同一个人物对同一件事连着几轮都是 impression 时用 `updated` 改那一条（UX 评审「不挡」）：切片先每轮一条，等 E6 和 R1 看了記憶帳的样子再定合并的规则（数据定对照）。

- 结局里怎么用记忆（B-9）；结局后原话清空、30 天不活动的 L2（S-035，部署以后的定时任务）。
- 地图（連鎖反応マップ）的数据（另一张卡）；記憶帳的前端（F-12 已合）。
- 真 Live 会话里记忆怎么写进系统指令的文字（后端 3 的 brief；本卡只给取记忆的函数）。
- 记忆的相关度排序（切片只按 `salience`；相关度到 M3）。
