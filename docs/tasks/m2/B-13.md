## Goal / 目標

When this is done:

完了すると：

1. When the narrator commits a turn's events, it writes at most one memory per character who was present or heard about it: Claude Haiku writes one Japanese line from the character's point of view, which passes three filters (personal-information rules, Model Armor, length and imperative sentences in quotes); if it fails, only the event is kept and no memory is written. `via` is filled deterministically.
   ナレーターが 1 ターンのイベントをコミットするとき、その場にいた、または話を聞いた登場人物それぞれに最大 1 件の記憶を書く。Claude Haiku が人物の視点の日本語の一文を書き、3 段のフィルター（個人情報ルール、Model Armor、長さと鉤括弧内の命令文）を通す。通らなければイベントだけを残し、記憶は書かない。`via` は決定的に埋める。
2. Relations (`trust` and the five-level label) are computed from undeleted memories, not stored.
   関係（`trust` と 5 段階のラベル）は削除されていない記憶から計算し、保存しない。
3. `GET …/memories` returns the four columns of the 記憶帳 (promises, what they did for you, what you did, memories); `GET …/memories/{id}/impact` returns the "consequences that will not be undone" line shown before deletion (cached); `DELETE …/memories/{id}` takes effect immediately.
   `GET …/memories` は記憶帳の 4 欄（約束、あなたのためにしてくれたこと、あなたがしたこと、記憶）を返し、`GET …/memories/{id}/impact` は削除前に出す「元に戻らない結果」の一文を返し（キャッシュする）、`DELETE …/memories/{id}` はその場で反映される。
4. On deletion, immediately: clear the memory's text and all utterances of the turn that produced it (both the player's and the character's); for promise memories, append a `forget` event that sets the open promise to `voided`; recompute the relation; if this character's voice session is open, rebuild it with the new situation briefing. Consequences in the world are not undone.
   削除したらその場で：この記憶のテキストと、それを生んだターンの発話すべて（プレイヤーのものも人物のものも）を消す。約束の記憶なら `forget` イベントを追加し、開いている約束を `voided` にする。関係を再計算する。この人物の音声セッションが開いていれば、新しい状況説明で再構築する。世界の結果は元に戻さない。
5. `DELETE /v1/playthroughs/{id}` deletes the whole playthrough (L2); the eval entry point's `memories`, `delete_memory`, `delete_playthrough`, `new_playthrough`, `trust`, `db_absent` and `memory` in setup are all implemented, so E6 no longer skips whole cases.
   `DELETE /v1/playthroughs/{id}` でプレイ全体を削除する（L2）。評価入口の `memories`、`delete_memory`、`delete_playthrough`、`new_playthrough`、`trust`、`db_absent` と setup の `memory` をすべて実装し、E6 がケースごとスキップされることはなくなる。

## Scope / 範囲

### In scope / やること

**1. Table (migration 0007) / テーブル（マイグレーション 0007）**

  `memory_items`：`memory_id`、`playthrough_id`（プレイと一緒に削除）、`character`、`kind`、`text`（削除時に空にする）、`from_events`（JSONB）、`t`、`trust_delta`、`salience`、`via`、`promise_id`、`keeps`（「元に戻らない結果」の一文のキャッシュ。空でもよい）、`keeps_done`（計算済みかどうか。計算結果が null でもキャッシュする）、`created_at`、`deleted_at`。

  インデックス `(playthrough_id, character) WHERE deleted_at IS NULL`（状況説明も関係の計算もこれを使う。データが決定）。削除時は `text` と `keeps` をどちらも空にする。`schema_version` には現在の契約のバージョンを書く。
- `playthrough_metrics` gains `cost_memory_usd` (memory line and consequence line), `memories_written`, `memories_filtered` (failed the three filters), `memories_deleted`, `memories_failed` (model errors, timeouts). Data has settled these column names.
  `playthrough_metrics` に `cost_memory_usd`（記憶の一文と結果の一文）、`memories_written`、`memories_filtered`（3 段のフィルターを通らなかったもの）、`memories_deleted`、`memories_failed`（モデルのエラー、タイムアウト）を追加。列名はデータが決めたこの名前を使う。

**2. Writing memories (around the narrator's step 7) / 記憶を書く（ナレーターのステップ 7 の前後）**

- Which events are written (Data review): **any committed event in this turn** (`check.status` passed / rewritten), including `say` with empty `effects` that only advances the clock (E6-001, 002, 004, 005 and 007 are all of this kind); excluding `forget`, `correction`, `act-transition` and `ending`. Events by others that the player cannot see (`zoujin_worldsim.sees`) are not written.
  書くイベント（データのレビュー）：このターンの**コミット済みのイベントならどれでも**（`check.status` が passed / rewritten）。`effects` が空で時計だけを進める `say` も含む（E6-001、002、004、005、007 はすべてこの種類）。`forget`、`correction`、`act-transition`、`ending` は含まない。人物以外のイベントでプレイヤーから見えないもの（`zoujin_worldsim.sees`）は書かない。
- **At most one per character per turn**: the several events of a turn that concern him are merged into one memory, with every one listed in `fromEvents` (the first is the one that set `kind`), and `kind` taken from the topmost matching row of the table below; the promise row is first, so `promiseId` still attaches. Deletion clears the whole turn's utterances anyway, so one per turn is what makes deletion clean, and it also makes the eval's `delete_memory(character, from_step)` unique. At most 3 characters per turn (by salience).
  **1 人物 1 ターンにつき最大 1 件**：同じターンでその人物に関わる複数のイベントを 1 件にまとめ、`fromEvents` にすべて列挙する（先頭は `kind` を決めたもの）。`kind` は下の表で最も上の行を取る。約束の行が一番上なので、`promiseId` も問題なく付けられる。削除はもともとターン全体の発話を消すので、1 ターン 1 件にしてこそきれいに削除でき、評価の `delete_memory(character, from_step)` も一意になる。1 ターンに書く人物は最大 3 人（salience 順）。
- Mapping table (decided by Data, `ROWS` in `narrator/memory.py`):
  対応表（データが決定、`narrator/memory.py` の `ROWS`）：

  | Condition (events in this turn) / 条件（このターンのイベント） | kind | trustDelta | salience |
  |---|---|---:|---:|
  | There is a `promise` effect `made` and he is a party to the promise / `promise` 効果 `made` があり、約束の相手が彼 | promise | +5 | 0.8 |
  | The player kept a promise with him (`kept`) / プレイヤーが彼との約束を果たした（`kept`） | help | +10 | 0.8 |
  | The player broke a promise with him (`broken`) / プレイヤーが彼との約束を破った（`broken`） | harm | -15 | 0.9 |
  | `actor: player`, `beneficiary` is him / `actor: player`、`beneficiary` が彼 | help | +10 | 0.7 |
  | `actor: player`, and his trust-type variable (`var.<him>.trust`) fell, or he was taken away (`relocate`, and he is not the beneficiary) / `actor: player` で、彼の信頼系の変数（`var.<彼>.trust`）が下がった、または彼を連れ去った（`relocate`、彼は beneficiary ではない） | harm | -10 | 0.7 |
  | `actor` is him, `beneficiary` is the player / `actor` が彼、`beneficiary` がプレイヤー | shared-moment | +3 | 0.5 |
  | A beat (`origin: schedule`) happens, the player can see it, and he experiences it firsthand (`zoujin_worldsim.lived`, #154) / ビート（`origin: schedule`）が起き、プレイヤーから見え、彼が自ら体験する（`zoujin_worldsim.lived`、#154） | shared-moment | +2 | 0.6 |
  | `say` with `actor: player` where a `learn` effect states he learned something, or `improv` became his improvised detail (the player talks about themselves) / `actor: player` の `say` で、`learn` 効果に彼が知ったと明記されている、または `improv` が彼の即興の設定になった（プレイヤーが自分のことを話す） | claim | 0 | 0.5 |
  | Other `actor: player` events: speech goes only to whoever was addressed this turn, actions go to those present / その他の `actor: player` のイベント：発話はこのターンで話しかけた相手だけ、アクションはその場にいる人へ | impression | 0 | 0.3 |

  - `keyMoment: true` adds 0.2 to salience (capped at 1); trustDelta is clamped to -20–20. The world variable `var.<him>.trust` is used only by its sign to pick the row, and is not copied into trustDelta. When claim and impression cannot be told apart, write impression.
    `keyMoment: true` なら salience に 0.2 を足す（上限 1）。trustDelta は -20〜20 に収める。世界変数 `var.<彼>.trust` は行を選ぶのに符号だけを使い、trustDelta には写さない。claim と impression の区別がつかなければ impression と書く。
  - The memory model also returns a `weight` (1–3, how much this matters to him), and salience gains `0.1 × (weight - 1)`, clamped between the row's value and 1; the numbers are still computed by code, and the model only gives the level (E6-007: even the economy tier, which carries only 4 memories, must remember 「家族は王に殺された」). In the situation briefing, ties are broken by newer `t` first.
    記憶モデルは `weight`（1〜3、そのことが彼にとってどれだけ重いか）も返し、salience に `0.1 × (weight - 1)` を足して、その行の値から 1 の間に収める。数値の計算はあくまでコードが行い、モデルは段階だけを返す（E6-007：4 件しか持たない節約モードでも「家族は王に殺された」は覚えていなければならない）。状況説明では同点なら `t` が新しいものを先にする。
- Model: a new prompt type `memory` (Claude Haiku 5.5, thinking off, 5 seconds). Its input is only the `summary` and `visibleEffects` of this turn's events concerning him, the character's persona summary and `via`; never the utterances (once the utterances are deleted, the memory should not carry them either). Output `{text, weight}`.
  モデル：新しいプロンプト種別 `memory`（Claude Haiku 5.5、思考オフ、5 秒）。入力はこのターンで彼に関わるイベントの `summary`、`visibleEffects`、人物のキャラクター設定の要約、`via` だけで、発話そのものは渡さない（発話を削除した後も記憶がそれを抱えていてはならない）。出力は `{text, weight}`。
- How the line is written (UX review, written into the prompt): in the character's own voice and words, about what he remembers of you, not a summary of the event; around 20 characters; no 「」 and no trailing 「。」 (the frontend adds the quotes; the code also strips 「」 around the whole line and a trailing 「。」); no identity names, and the player is referred to as 「あなた」「あの人」「あの旅の者」 (the identity-name replacement in contract 1.8 only covers `summary`).
  一文の書き方（UX のレビュー。プロンプトに書く）：人物自身の口調と言葉づかいで、彼があなたについて覚えていることを書き、イベントの要約にはしない。20 字前後。「」を付けず、文末に「。」を付けない（フロントエンドが引用符を付ける。コードでも文全体を囲む「」と文末の「。」を取り除く）。身分名は書かず、プレイヤーは「あなた」「あの人」「あの旅の者」と呼ぶ（契約 1.8 の身分名の置き換えは `summary` だけが対象）。
- Three filters; failing any one means the memory is not written (the event stays):
  3 段のフィルター。どれか一つでも通らなければこの記憶は書かない（イベントは残す）：
  1. Personal-information rules (`safety.pii`, the same set as R6);
     個人情報ルール（`safety.pii`。R6 と同じもの）。
  2. Model Armor (`sanitizeModelResponse`: injection, RAI HIGH, SDP; 1 second, errors treated as no hit, same as B-12);
     Model Armor（`sanitizeModelResponse`：インジェクション、RAI HIGH、SDP。1 秒、エラーはヒットなしとみなす。B-12 と同じ）。
  3. Rules: imperative sentences in quotes; identity names; a length cap of 30 characters (counted after NFKC, including punctuation; UX wants 30 and Data gave 40, so the stricter 30 is used); going over counts as failing the filter, with no truncation (truncating would leave half a sentence).
     ルール：鉤括弧内の命令文。身分名。長さの上限 30 字（NFKC 後の文字数で数え、句読点を含む。UX は 30、データは 40 としたので、厳しい方の 30 を取る）。超えたらフィルターを通らなかったものとし、切り詰めはしない（切り詰めると文が途中で切れる）。
- `via`: he was at the event's location before the event, or experienced the beat firsthand (`lived`) = `witnessed`; the event has a `learn` effect stating that he learned it = `told`; the slice does not write `rumor` (characters who were neither present nor told get no memory; left to M3's word-of-mouth chain).
  `via`：イベントの前に彼がイベントの場所にいた、またはそのビートを自ら体験した（`lived`）= `witnessed`。イベントに彼が知ったと明記した `learn` 効果がある = `told`。スライスでは `rumor` は書かない（その場におらず、知らされてもいない人物には記憶を書かない。M3 の伝聞の連鎖に回す）。
- `trustDelta` and `salience` are computed deterministically from the event type and `visibleEffects` (the table lives in constants); the model never gives numbers.
  `trustDelta` と `salience` はイベントの種類と `visibleEffects` から決定的に計算し（表は定数に置く）、モデルに数値を出させない。
- Timing: model calls are kept out of the commit's database transaction. The transaction that commits the events does not NOTIFY yet; after it, memories are written in parallel, then another transaction stores the memories, writes `turns.result.memories` and NOTIFYs, and `commit.memories[]` carries `added` (settled while writing the code; it holds up the commit less than "write before committing"). On model timeout or error → no memory for this turn, counted, no resend, and NOTIFY as usual.
  タイミング：モデルの呼び出しはコミットのデータベーストランザクションに入れない。イベントをコミットするトランザクションではまだ NOTIFY しない。その後で記憶を並行に書き、別のトランザクションで記憶を保存し、`turns.result.memories` を書いて NOTIFY する。`commit.memories[]` には `added` を載せる（コードを書く中で決めたもので、「コミット前に書く」よりもコミットを引き止めない）。モデルがタイムアウトかエラー → このターンは記憶を書かず、回数を数え、再送せず、いつもどおり NOTIFY する。
- Relations: `trust` = starting value (+10 if the identity knows this character, otherwise 0) + the sum of `trustDelta` over undeleted memories, clamped to -100–100; the five levels follow the table in contract section 4. `commit.memories[]` carries the new `relationLabel` and `relationLevel`.
  関係：`trust` = 初期値（身分がこの人物と知り合いなら +10、そうでなければ 0）+ 削除されていない記憶の `trustDelta` の合計を、-100〜100 に収めたもの。5 段階は契約第 4 節の表どおり。`commit.memories[]` に新しい `relationLabel`、`relationLevel` を載せる。

**3. Memories in the situation briefing / 状況説明に記憶を含める**

- When a session opens, take up to 8 of this character's undeleted memories by `salience` (4 in the economy tier) and pass them to Backend 3's `gateway/brief.py`: `build(…)` gains a `memories` parameter, fetched by `Voices._brief` and passed in just like B-12's `notes` (this card provides `memories_for_brief(c, pid, who, limit)`, placed as 「# 覚えていること」 after 「# いまの状況」, to be finalized after checking with Backend 3).
  セッションを開くとき、この人物の削除されていない記憶を `salience` 順に最大 8 件（節約モードは 4 件）取り、バックエンド 3 の `gateway/brief.py` に渡す：`build(…)` に `memories` 引数を一つ足し、B-12 の `notes` と同じく `Voices._brief` が取得して渡す（このカードは `memories_for_brief(c, pid, who, limit)` を提供する。「# いまの状況」の後の「# 覚えていること」に置く。バックエンド 3 とすり合わせてから確定する）。

**4. The three 記憶帳 endpoints (`gateway/rest.py`) / 記憶帳の三つのエンドポイント（`gateway/rest.py`）**

- `GET /v1/playthroughs/{id}/memories`: only characters the player has met, the four columns shaped per contract 2.7; `voided` promises are still returned (the frontend hides them); empty columns are `[]`.
  `GET /v1/playthroughs/{id}/memories`：プレイヤーが会ったことのある人物だけ。4 欄は契約 2.7 の形どおり。`voided` の約束もそのまま返す（フロントエンドは表示しない）。空の欄は `[]`。
- `GET …/memories/{memoryId}/impact`: `{keeps, voidsPromise}`. On the first request, `keeps` is written by Haiku as one line from the source events' `summary` and `visibleEffects` (a new prompt type `keeps`, which does not read utterances), stored in `memory_items.keeps`, and read directly thereafter; `voidsPromise` = the promise this memory points to is still open. Deleted or nonexistent → 404.
  `GET …/memories/{memoryId}/impact`：`{keeps, voidsPromise}`。`keeps` は最初のリクエスト時に Haiku が出典イベントの `summary` と `visibleEffects` から一文を書き（新しいプロンプト種別 `keeps`。発話は読まない）、`memory_items.keeps` に保存し、以後はそれを直接読む。`voidsPromise` = この記憶が指す約束がまだ開いている。削除済みまたは存在しない → 404。
  - Time limit 2 seconds (UX review: the frontend greys out 〔忘れてもらう〕 until it returns). On timeout, error or failing the filters → `null`, **not cached**, recomputed the next time it is opened; only an actually computed line, or a `null` meaning the model said "there is no consequence to mention", is cached.
    制限時間は 2 秒（UX のレビュー：フロントエンドは結果が返るまで〔忘れてもらう〕をグレーアウトする）。タイムアウト、エラー、フィルター不通過 → `null` で、**キャッシュしない**。次に開いたときに改めて計算する。キャッシュするのは実際に計算できた一文と、モデルが「言うべき結果はない」とした `null` だけ。
  - How it is written (in the prompt, and also enforced by code): one line within 30 characters, which the frontend wraps in 「ただし、すでに起きたことは元に戻りません。（例：…）」, with no trailing 「。」; only consequences the player has already seen; characters by name, never 「彼」「彼女」; when `voidsPromise` is true, do not write about the promise itself (the next line is 「この約束も、なかったことになります」); never 「覚えている」 or 「忘れる」.
    書き方（プロンプトに書き、コードでも防ぐ）：30 字以内の一文。フロントエンドが「ただし、すでに起きたことは元に戻りません。（例：…）」に入れるので、文末に「。」を付けない。プレイヤーがすでに見た結果だけを書く。人物は名前で呼び、「彼」「彼女」は使わない。`voidsPromise` が真のときはその約束自体を書かない（次の行が「この約束も、なかったことになります」）。「覚えている」「忘れる」は書かない。
- `DELETE …/memories/{memoryId}`: with `Idempotency-Key` (the same mechanism as the other POSTs), returns `{memoryId, deleted, character, relationLabel, relationLevel, promiseVoided, sessionRebuilt}`. Someone else's playthrough → 403; already deleted or nonexistent → 404 (replaying the same key returns the original 200).
  `DELETE …/memories/{memoryId}`：`Idempotency-Key` を付ける（他の POST と同じ仕組み）。`{memoryId, deleted, character, relationLabel, relationLevel, promiseVoided, sessionRebuilt}` を返す。他人のプレイなら 403、削除済みまたは存在しないなら 404（同じ key の再送は元の 200 を返す）。

**5. Deletion takes effect immediately (contract section 4, L1 of data-design 5.3) / 削除はその場で反映（契約第 4 節、data-design 5.3 の L1）**

In the same transaction:

同じトランザクションの中で：

1. Null this memory's `text` and set `deleted_at`;
   この記憶の `text` を空にし、`deleted_at` を書く。
2. Follow `from_events → events.turn_id → utterances.turn_id` and clear the whole turn's utterances (the player's and the character's); clear the original plan text of this turn in `turns.result` the way B-4 does; drop this turn's open intent-confirmation draft as if answered "no";
   `from_events → events.turn_id → utterances.turn_id` をたどり、ターン全体の発話（プレイヤーのものも人物のものも）を消す。`turns.result` にあるこのターンのプランの原文を B-4 のやり方で消す。このターンで開いている意図確認の下書きは「いいえ」として捨てる。
3. If `promise_id` points to an open promise → write a `forget` event (`origin: "memory"`, `actor: "player"`, `dt: 0`, effect `{op: "promise", change: "voided"}`, with a neutral `summary` 「〜との約束は、なかったことになった」, never 「覚えていない」 or 「忘れた」), going through the narrator's normal commit (`commit` is pushed as usual; it does not enter the map timeline or 「その頃」, and replaying the events yields the same state); promises already `kept` / `broken` are left alone;
   `promise_id` が開いている約束を指している → `forget` イベントを書く（`origin: "memory"`、`actor: "player"`、`dt: 0`、効果 `{op: "promise", change: "voided"}`。`summary` は中立的な「〜との約束は、なかったことになった」とし、「覚えていない」「忘れた」とは書かない）。ナレーターの通常のコミットを通す（`commit` はいつもどおり送る。マップのタイムラインや「その頃」には入れず、イベントをリプレイすれば同じ状態になる）。すでに `kept` / `broken` のものは触らない。
4. Recompute the relation, and push `deleted` in `commit.memories[]`.
   関係を再計算し、`commit.memories[]` で `deleted` を送る。

After the transaction:

トランザクションの後で：

5. Gateway: drop this turn from the recent conversation in memory; if this character's session is open → rebuild it with the new situation briefing (Backend 3's `Voices.rebuild`, pushing `session_preparing { reason: "rebuild" }`), `sessionRebuilt: true`; sessions and recent conversations parked during a disconnect are dropped with `Gateway.forget(playthrough)`.
   ゲートウェイ：メモリ上の直近の会話からこのターンを捨てる。この人物のセッションが開いていれば → 新しい状況説明で再構築し（バックエンド 3 の `Voices.rebuild`。`session_preparing { reason: "rebuild" }` を送る）、`sessionRebuilt: true`。切断中に預かっているセッションと直近の会話は `Gateway.forget(プレイ)` で捨てる。
6. Consequences in the world are not undone (the events stay; contract section 4, rule 2).
   世界の結果は元に戻さない（イベントは残す。契約第 4 節の第 2 条）。

**6. Deleting a whole playthrough (L2) / プレイ全体の削除（L2）**

- `DELETE /v1/playthroughs/{id}`: with `Idempotency-Key`, returns 202; deletion runs in the background per L2 in data-design 5.2 (all of the playthrough's tables cascade via foreign keys; the Cloud Storage and BigQuery parts wait for a post-deployment card); any open WebSocket is closed with 4004; `Gateway.forget(playthrough)`. After that, every endpoint for this playthrough returns 404.
  `DELETE /v1/playthroughs/{id}`：`Idempotency-Key` を付け、202 を返す。バックグラウンドで data-design 5.2 の L2 に従って削除する（このプレイのすべてのテーブルを外部キーでカスケード。Cloud Storage と BigQuery の部分はデプロイ後のカードで扱う）。開いている WebSocket は 4004 で閉じる。`Gateway.forget(プレイ)`。以後、このプレイのエンドポイントはすべて 404。

**7. Eval entry point / 評価入口**

- `memories(character)`: a list of MemoryItems; deleted ones carry `deletedAt` and empty `text`.
  `memories(character)`：MemoryItem のリスト。削除済みのものは `deletedAt` を持ち、`text` は空。
- `delete_memory(character, from_step)`: deletes this character's memory whose source is the events committed at step `from_step` (one per character per turn, so it is unique), through the same function as REST; if there is no such memory it raises an error rather than silently succeeding (Data review).
  `delete_memory(character, from_step)`：この人物の、第 `from_step` ステップでコミットされたイベントを出典とする記憶を削除する（1 人物 1 ターン 1 件なので一意）。REST と同じ関数を通す。該当する記憶がなければエラーにし、黙って成功させない（データのレビュー）。
- `delete_playthrough()`, `new_playthrough()` (same account, same starting point; subsequent queries answer for the new playthrough).
  `delete_playthrough()`、`new_playthrough()`（同じアカウント、同じ開始地点。以後の問い合わせは新しいプレイについて答える）。
- `trust(character)` (int, only the 記憶帳 relation), `db_absent(tables)` (`{table: rows remaining}`, actually querying the tables that exist; tables in data-design 5.3 that do not exist yet and are on the hard-coded list (`briefs`; situation briefings are not stored) answer 0; unknown table names not on the list get no answer, and the eval reports "the backend did not answer for this table", so a misspelled table name cannot slip through as 0).
  `trust(character)`（int。記憶帳の関係だけを計算）、`db_absent(tables)`（`{テーブル: 残りの行数}`。実際に作られたテーブルを本当に問い合わせる。data-design 5.3 にあってまだ作られておらず、固定のリストに名前があるもの（`briefs`。状況説明はデータベースに保存しない）は 0 と答える。リストにない未知のテーブル名には答えず、評価側が「バックエンドがこのテーブルに答えなかった」と報告する。テーブル名の書き間違いが 0 として通ってしまわないように）。

  評価でも、記憶と結果の一文の書き込みは同じプロンプトを通す（偽モデルとリプレイ。本物のモデルは Mac でのみ）。

## Prohibited / 禁止事項

- No URLs, passwords, keys or model IDs in the repo, docs or chat. Any deployment needs zg's explicit consent.
  URL、パスワード、Key、モデル ID をリポジトリ、ドキュメント、チャットに書かない。デプロイはすべて zg の明確な同意が必要。
- Memory text, utterances and the consequence line never go into logs or Trace (only IDs and counts).
  記憶の文言、発話、結果の一文はログにも Trace にも入れない（ID と回数だけを記録する）。
- The memory-writing model never reads utterances; safety screening verdicts are not written into memory (S-057).
  記憶を書くモデルは発話を読まない。安全スクリーニングの判定結果は記憶に書かない（S-057）。
- Deletion does not undo consequences in the world; the ending never says "he remembers you".
  削除は世界の結果を元に戻さない。エンディングで「彼はあなたを覚えている」とは言わない。
- CI and containers never call real models or the real Model Armor; tests do not use the network.
  CI とコンテナでは本物のモデルも本物の Model Armor も呼ばない。テストはネットワークにつながない。
