## Goal / 目標

The quality tiers (L0–L3, starting self-test, tier changes, high-tier textures downloaded in the background) have so far only been measured on the plaza. The four scenes (plaza, river, village, throne room) use the same `World` and the same `quality`, so this card does the part outside any one scene that all scenes share: saving power and staying cool, not flip-flopping between tiers when the phone heats up during long play, and almost no downloads on a second visit or when changing scenes. Each scene's own asset budget (`scenes` in `assets/budgets.json`) is added by the thread building that scene, in its pipeline, not in this card.

画質の段階（L0〜L3、開始時の自己測定、ティアの昇降、高ティアのテクスチャのバックグラウンドでのダウンロード）は、今は広場でしか測っていない。4 つのシーン（広場、川、村、王座の間）は同じ `World` と同じ `quality` を使うので、このカードはシーンの外で全シーンが共用する部分を作る：省電力と発熱の抑制、長く遊んで発熱したときにティアを行き来しないこと、2 回目の入場とシーンの切り替えでほとんどダウンロードしないこと。各シーン自身のアセットの予算（`assets/budgets.json` の `scenes`）は、そのシーンを作るスレッドが自分のパイプラインで加え、このカードには含めない。

## Scope / 範囲

1. **Stop 3D behind full-screen pages** (10.4): when the end-of-act page, the act-change pages (その頃, skipping days), 記憶帳, 連鎖反応マップ or the safety card is open, the `Canvas` loop stops and the picture stays on the last frame; loading continues in the background as usual. The frame-time histogram skips this gap.
   **全画面のページの裏では 3D を止める**（10.4）：幕末のページ、幕替えのページ（「その頃」、日付の飛び越し）、記憶帳、連鎖反応マップ、安全カードが開いているときは `Canvas` のループを止め、画面は最後のフレームのままにする。読み込みは従来どおりバックグラウンドで進める。フレーム時間のヒストグラムはこの空白を飛ばす。
2. **Heat** (10.6.4): a unit test simulates 20 minutes of continuous play with the phone getting hotter and hotter, to see whether downgrades flip-flop. The simulation showed it would upgrade back after 60 seconds and then drop again, so "no upgrade after a downgrade" is changed to 5 minutes (10.6.3 already updated).
   **発熱**（10.6.4）：単体テストで 20 分の連続プレイとスマートフォンがだんだん熱くなる状況を模擬し、降格が行き来しないかを見る。模擬では 60 秒後に昇格し直してまた降格したので、「降格後は昇格しない」を 5 分に変えた（10.6.3 は変更済み）。
3. **Service Worker** (10.2 item 5, S-024): precache the shell and the 3D code; scene packs (versioned URLs) are stored in the cache on first download, as is the next scene prefetched at the end of an act; old versions' caches are deleted when a new version activates. A second visit, reopening after the page was evicted, and changing scenes all download almost nothing. Registered only in production builds, not under `?test` or the dev server. No new npm dependencies.
   **Service Worker**（10.2 第 5 項、S-024）：シェルと 3D のプログラムを事前にキャッシュする。シーンパック（バージョン付きのアドレス）は最初にダウンロードしたときにキャッシュに入れ、幕末に先読みした次のシーンも入れる。古いバージョンのキャッシュは新しいバージョンが有効になったときに削除する。2 回目の入場、ページが回収された後の再表示、シーンの切り替えのいずれでもほとんどダウンロードしない。登録は本番のビルドだけで、`?test` と開発サーバーでは登録しない。新しい npm の依存は加えない。
4. **Measurement page**: once the other scenes are built, the measurement page (`?measure`) switches scenes with `?scene=` (the route and viewpoints come from the thread building that scene). Until then, it is only noted here.
   **計測ページ**：他のシーンができたら、計測ページ（`?measure`）は `?scene=` でシーンを切り替える（経路と見どころはそのシーンを作るスレッドが出す）。それまではここに記しておくだけ。

## Acceptance check / 受け入れ確認

- `pnpm test`: the three "20 minutes warming up" cases in `governor.test.ts` (a high-end phone downgrades once and stops; a baseline phone stays put, and drops to L0 when too hot; a phone that can upgrade, once it has upgraded and then downgraded, does not upgrade again).
  `pnpm test`：`governor.test.ts` の「20 minutes warming up」の 3 件（ハイエンドの端末は 1 回降格して止まる。最低ラインの端末は動かず、熱くなりすぎたら L0 まで下がる。昇格できる端末は、一度昇格した後に降格したら、二度と昇格しない）。
- e2e `gate.spec.ts` step 8: while 記憶帳 is open, 3D does not draw a single frame, and it draws again when closed.
  e2e の `gate.spec.ts` 第 8 ステップ：記憶帳が開いている間は 3D を 1 フレームも描かず、閉じたらまた描く。
- e2e `sw.spec.ts`: on the second page load, the shell and 3D code both come from the cache, and the page opens even offline; versioned scene files go into the cache on first download, and versions no longer mentioned by the book's manifest are deleted.
  e2e の `sw.spec.ts`：2 回目にページを開いたとき、シェルと 3D のプログラムはどちらもキャッシュから来て、ネットワークが切れていても開ける。バージョン付きのシーンファイルは最初のダウンロードでキャッシュに入り、本の一覧に載らなくなったバージョンは削除される。
- The main 3D chunk is still ≤ 250 KB; the Service Worker registration is in the shell, and the shell is ≤ 120 KB.
  3D のメインチャンクは引き続き ≤ 250 KB。Service Worker の登録はシェルの中にあり、シェルは ≤ 120 KB。
