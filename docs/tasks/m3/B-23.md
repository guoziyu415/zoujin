## Goal / 目標

After step 26 passes, one command on zg's Mac, `infra/deploy/deploy.sh all`, deploys the first version to the zoujin project: two Cloud Run services (gateway and narrator), Cloud SQL, invite-only access, going live at 0% traffic → smoke test → shift traffic → re-check that anonymous access is rejected. This card only writes scripts and configuration; it does not create anything in the cloud.

第 26 ステップを通った後、zg の Mac で 1 つのコマンド `infra/deploy/deploy.sh all` を実行すると、初版が zoujin プロジェクトにデプロイされる：ゲートウェイとナレーターの 2 つの Cloud Run サービス、Cloud SQL、招待制のアクセス。トラフィック 0% で公開 → スモークテスト → トラフィックを切り替え → 匿名アクセスが拒否されることを再確認、の順に進む。このカードはスクリプトと設定を書くだけで、クラウド上には何も作らない。

## Scope / 範囲

1. The gateway serves the frontend build and scene packs from the same origin (`ZJ_WEB_DIST`, `gateway/web.py`, `Manifest.scene_file`), with no load balancer or CDN; when deployed, every response carries `X-Robots-Tag: noindex, nofollow`.
   ゲートウェイが同じオリジンでフロントエンドのビルドとシーンパックを配信する（`ZJ_WEB_DIST`、`gateway/web.py`、`Manifest.scene_file`）。ロードバランサーや CDN は使わない。デプロイ時はすべてのレスポンスに `X-Robots-Tag: noindex, nofollow` を付ける。
2. Service-to-service identity for the narrator: with `ZJ_NARRATOR_AUTH=iam`, the narrator accepts calls (Cloud Run's IAM has already verified the gateway service account's OIDC token), and the gateway fetches a token from the metadata server and attaches it (`IdToken`).
   ナレーターのサービス間の身元：`ZJ_NARRATOR_AUTH=iam` のとき、ナレーターは呼び出しを受け付ける（Cloud Run の IAM がゲートウェイのサービスアカウントの OIDC トークンを検証済み）。ゲートウェイはメタデータサーバーからトークンを取得して付ける（`IdToken`）。
3. `infra/deploy/`: `deploy.sh` (setup, build, migrate, up, promote, verify, invite, rollback, pause, resume, all), `Dockerfile`, `dbsetup.py` (database, two application accounts, permissions), `smoke.py` (smoke test and anonymous rejection), `README.md` (the commands for step 27, the topology, and where it differs from the design).
   `infra/deploy/`：`deploy.sh`（setup、build、migrate、up、promote、verify、invite、rollback、pause、resume、all）、`Dockerfile`、`dbsetup.py`（データベース、2 つのアプリケーションアカウント、権限）、`smoke.py`（スモークテストと匿名の拒否）、`README.md`（第 27 ステップのコマンド、トポロジー、設計と違う箇所）。
4. Rules: use only the project of gcloud's `zoujin` configuration, and stop if it points at another project; service and instance names are random; project IDs, URLs, passwords and invite codes live only in the Mac's `~/.zoujin/deploy/` (700) and Secret Manager; v1 is only for invited people aged 18 or over.
   ルール：gcloud の `zoujin` 構成のプロジェクトだけを使い、別のプロジェクトを指していたら止まる。サービス名とインスタンス名はランダム。プロジェクト ID、アドレス、パスワード、招待コードは Mac の `~/.zoujin/deploy/`（700）と Secret Manager にだけ置く。v1 は招待された 18 歳以上の人だけが対象。

## Acceptance check / 受け入れ確認

- `test_b23.py`: serving pages, frontend routes falling back to `index.html`, long caching for hashed files, 404 for paths escaping the directory, `/v1`'s 404 unchanged, scene packs serving only the versions and directories the manifest references; the narrator accepting only under the development switch or `iam`; the gateway attaching a token and renewing it every 50 minutes.
  `test_b23.py`：ページの配信、フロントエンドのルートが `index.html` を返す、ハッシュ付きのファイルの長期キャッシュ、ディレクトリの外に出るパスは 404、`/v1` の 404 は従来どおり、シーンパックは manifest が参照するバージョンとディレクトリだけを配信する。ナレーターは開発用スイッチか `iam` のときだけ受け付ける。ゲートウェイはトークンを付け、50 分ごとに更新する。
- Locally, start the narrator (`iam`) and the gateway from an image built with this Dockerfile, and `smoke.py smoke` passes in full (fake model).
  ローカルでこの Dockerfile でビルドしたイメージからナレーター（`iam`）とゲートウェイを起動し、`smoke.py smoke` がすべて通る（偽モデル）。
- `dbsetup.py` on a local PostgreSQL: the application accounts can read and write, cannot create tables, and cannot change `alembic_version`.
  ローカルの PostgreSQL での `dbsetup.py`：アプリケーションアカウントは読み書きができ、テーブルを作れず、`alembic_version` を変えられない。
