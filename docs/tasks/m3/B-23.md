## 目标

第 26 步过了以后，zg 的 Mac 上一条命令 `infra/deploy/deploy.sh all` 把第一版部署到 zoujin 项目：网关和叙事者两个 Cloud Run 服务、Cloud SQL、邀请制访问，照 0% 流量上线 → 冒烟 → 切流量 → 复查匿名被拒。本卡只写脚本和配置，不在云上建任何东西。

## 范围

1. 网关同源发前端构建和场景包（`ZJ_WEB_DIST`、`gateway/web.py`、`Manifest.scene_file`），不上负载均衡和 CDN；部署时所有回应带 `X-Robots-Tag: noindex, nofollow`。
2. 叙事者的服务间身份：`ZJ_NARRATOR_AUTH=iam` 时叙事者接受调用（Cloud Run 的 IAM 已验网关服务账号的 OIDC 令牌），网关从元数据服务器拿令牌带上（`IdToken`）。
3. `infra/deploy/`：`deploy.sh`（setup、build、migrate、up、promote、verify、invite、rollback、pause、resume、all）、`Dockerfile`、`dbsetup.py`（库、两个应用账号、权限）、`smoke.py`（冒烟和匿名被拒）、`README.md`（第 27 步的命令、拓扑、和设计不一样的地方）。
4. 规则：只用 gcloud 的 `zoujin` 配置的项目，指到别的项目就停；服务名、实例名随机；项目 ID、地址、密码、邀请码只在 Mac 的 `~/.zoujin/deploy/`（700）和 Secret Manager；v1 只给邀请的 18 岁以上的人。

## 验收

- `test_b23.py`：发页面、前端路由回 `index.html`、带 hash 的文件长缓存、走出目录 404、`/v1` 的 404 照旧、场景包只发 manifest 引用的版本和目录；叙事者只在开发开关或 `iam` 时接受；网关带令牌、50 分钟换新。
- 本机用这个 Dockerfile 构建的镜像起叙事者（`iam`）和网关，`smoke.py smoke` 全部通过（假模型）。
- `dbsetup.py` 在本机 PostgreSQL 上：应用账号能读写、不能建表、不能改 `alembic_version`。
