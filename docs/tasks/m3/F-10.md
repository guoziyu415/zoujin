## Goal / 目標

The journey home follows S-081 option C, in this order: first build B's 4 stops (the river first, as the most expensive and riskiest), then replace the time cards with running road segments. This card does only the river: act 2's calm river and wooden bridge (05:15, early twilight), and act 4's 濁流 (muddy torrent) and broken bridge (11:45, noon after rain). The two packs share the riverbanks and a roadside material pack, and the loader picks a pack by act (in act 2 the bridge is always intact, in act 4 always broken). When this is done, the test page lets you stand at the two landing points and see the first view UX 1.4 describes: the person at the bridgehead, the bridge (or broken piles), the water, the far bank, the road toward the 峠 (pass) and the gap in the distance.

帰り道は S-081 の選択肢 C に従って作る。順番は、まず B の 4 つの停留地点（最も高くつきリスクも大きい川から）、次に時間カードを走る区間に置き換える。このカードは川だけを作る：第二幕の穏やかな川と木の橋（05:15 薄明）、第四幕の濁流と落ちた橋（11:45 雨上がりの正午）。2 つのパックは川岸と道端のマテリアルパック 1 つを共用し、ローダーは幕に応じてパックを選ぶ（第二幕では橋は必ず無事で、第四幕では必ず落ちている）。完成すると、テストページで 2 つの着地点に立ち、UX 1.4 が書いた最初の眺めを見られる：橋のたもとの人、橋（または折れた杭）、水、対岸、峠へ向かう道と遠くの切れ目。

7. **Scene IDs and pack selection** (decided by data, #79 review): one scene ID per stop: `scene.road-river`, `scene.road-pass`, `scene.road-spring`, `scene.road-field`. Reason: moving within one scene costs 0 minutes, so 「ひとりで先へ行く」 would let the player get from the river to the pass in 0 minutes; splitting them uses the walking minutes already in `Place.adjacent`. The world model's `sceneRef` is changed by data in a separate PR and does not block this card. Two packs under the single scene ID `scene.road-river`: the generated index `assets/scenes/road-river/index.json` picks a pack by the act the frontend can see: `act.2` → `road-river-calm`, `act.4` → `road-river-flood`. The frontend has no world variables (contract 2.8; snapshots have no `vars`), so it does not pick by `var.bridge`; each entry also records a `bridge` field with the corresponding world model value (`intact` / `destroyed`), for verification only: data has shown that on reaching the river in act 2 it is always `intact`, and in act 4 always `destroyed`. `check_scene.mjs` checks that "every act whose `Act.scenes` in the world model includes `scene.road-river` selects exactly one pack". Later scenery changes from the plaza to the execution ground follow the same pattern. The same directory also gets a generated `scene.json` (`sceneId: scene.road-river`, combining the two packs' `places`, `spots`, `exits` and `startSpots`): the backend's Library and data's `build_world` both read it from the directory named after the scene. The two packs' own layouts use the pack names (`road-river-calm`, `road-river-flood`), not `scene.road-river`. `check_scene.mjs`'s world model check accepts this combined manifest. Each pack's `scene.json` emits `materials.floor` (dirt road) and shadow proxy `blockers` (ridge, broken piles, hut) like the plaza, which `Lighting.tsx` needs for the ambient ground and lit-fraction. The `scene.road-river-calm` / `scene.road-river-flood` in the header of the table in UX design doc section 1 are aligned to two pack names under the scene `scene.road-river` (PM has already told UX).
   **シーン ID とパックの選択**（データが決定、#79 のレビュー）：停留地点ごとにシーン ID を 1 つ：`scene.road-river`、`scene.road-pass`、`scene.road-spring`、`scene.road-field`。理由：同じシーンの中の移動は 0 分なので、「ひとりで先へ行く」でプレイヤーが 0 分で川から峠へ行けてしまう。分ければ `Place.adjacent` に既にある徒歩の分数を使える。世界モデルの `sceneRef` はデータが別の PR で変え、このカードの妨げにはしない。`scene.road-river` という 1 つのシーン ID の下に 2 つのパック：生成されるインデックス `assets/scenes/road-river/index.json` が、フロントエンドが得られる幕によってパックを選ぶ：`act.2` → `road-river-calm`、`act.4` → `road-river-flood`。フロントエンドには世界の変数がない（契約 2.8、スナップショットに `vars` がない）ので、`var.bridge` では選ばない。各エントリには対応する世界モデルの元の値（`intact` / `destroyed`）を書いた `bridge` フィールドも記録するが、照合のためだけに使う：データは、第二幕で川に着いたときは必ず `intact`、第四幕では必ず `destroyed` であることを確認済み。`check_scene.mjs` は「世界モデルで `Act.scenes` に `scene.road-river` を含むどの幕も、ただ 1 つのパックを選べる」ことを確認する。今後の広場から刑場への背景の切り替えも、この書き方に従う。同じディレクトリに `scene.json`（`sceneId: scene.road-river`、2 つのパックの `places`、`spots`、`exits`、`startSpots` を合わせたもの）も生成する：バックエンドの Library とデータの `build_world` はどちらもシーン名のディレクトリからこれを読む。2 つのパック自身のレイアウトはパック名（`road-river-calm`、`road-river-flood`）を使い、`scene.road-river` とは書かない。`check_scene.mjs` の世界モデルとの照合は、この合わせた一覧を対象にする。各パックの `scene.json` は広場と同じく `materials.floor`（土の道）と影の代役 `blockers`（尾根、折れた杭、小屋）を出す。`Lighting.tsx` の環境光の地面と受光の割合に必要になる。UX の設計文書の第 1 節の表の見出しにある `scene.road-river-calm` / `scene.road-river-flood` は、シーン `scene.road-river` の下の 2 つのパック名に合わせる（PM から UX に伝え済み）。
