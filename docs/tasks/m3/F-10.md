## 目标

归途按 S-081 选项 C 做，顺序是先做 B 的 4 个停留点（先川，最贵、风险最大），再把时间卡换成跑的路段。本卡只做川：第二幕的平静的河和木桥（05:15 薄明），第四幕的濁流和断桥（11:45 雨后正午）。两个包共用河岸和一个路边材质包，加载器按幕挑包（第二幕的桥一定完好，第四幕一定断了）。做完以后，在测试页里能站在两个落地点，看到 UX 1.4 写的第一眼：桥头的人、桥（或断桩）、水、对岸、往峠去的路和远处的豁口。

## 范围

**做**

1. **流水线**：`assets/pipeline/road/`。复用广场的步骤（占位贴图、Blender 摆场景、物理天空、烘焙、编码、打包、检查），能共用的脚本直接调用，不复制；要给共用脚本加参数（场景 ID、输入文件名、烘焙时刻）的地方先和第一个前端线程对好，只加不改，广场的输出逐字节不变（CI 的复现检查证明）。一条命令出两个包：
   - `assets/scenes/road-river-calm/`：第二幕。东岸落地，完整木桥，平静的河道（中间约 8 m），西岸低滩的芦苇，栈桥和两条小船，船夫小屋。上游浅滩处河道变宽到 x −3〜13，中间露出一片干的卵石滩（x 3〜7、y 10〜15）。地面干、有露水。烘 05:15。
   - `assets/scenes/road-river-flood/`：第四幕。西岸落地，两岸之间全是水（高出约 1.5 m），三对木桩按 UX 1 的表歪、断，栈桥只剩桩，小屋门开着，岸上新淤的泥和水位线，系船桩上有扯断的绳头，水上漂几根冲下来的树枝（实例化）。西岸路的最后 3 m（x −8〜−5）浅浅没在水里：路面照常建、上面盖一层水面。上游浅滩的卵石滩没在水下，但这一片水面平、有三四块石头冒出水面。地面湿：土路、露头、碎石深一档，坑里有积水反着天，用同一张图的材质参数开关（UX 0.4、1.5），不另做贴图。烘 11:45。
   - 河岸、白杨、柳、路的几何两个包共用同一份源（`build_road_river.py` 按状态开关），坐标照 UX 1.1、1.2，+x = 90°。河岸两个包各带一份（玩过第二幕到第四幕会再下一次，约 1 MB 级，可以接受）。
2. **共用路边材质包** `assets/scenes/road-common/`：石灰岩的土路、干草地、石灰岩露头、碎石、干砌石墙、树和灌木的卡片（UX 0.4）。只下一次，后面三个点共用。容器里先用占位贴图（和广场一样按固定种子生成），CC0 扫描材质在 zg 的 Mac 上下载，经第一个前端线程的资产流程走，到了重新生成。时代考证的「不放」清单写进检查脚本的注释，评审时对截图核。
3. **强机 2048 材质**（UX 第 9 节，用广场已有的两档流水线）：共用包的土路、干草地、石灰岩露头；川两个包共用的河岸湿岩和泥；第四幕近景的断桩。其余标准档。
4. **水**（新着色器，`apps/web/src/three/water/`）：
   - 平静：一张水面，滚动法线 + 天空的环境反射 + 贴水面的雾，1 个 draw call。雾在河道里约 2.5〜3 m 高（桥面离水约 2.2 m，人走过桥时腿在雾里），往岸上淡掉。
   - 濁流：浑黄不透明（泥的黄褐，不是红褐），顺流的法线和泡沫，水面加密（约 5k 三角形）做小浪，木桩处溅起的水花用实例化面片（约 200 片）。比平静多 3〜4 个 draw call。一张流速遮罩：上游浅滩一片压低流速和泡沫（「流れの緩い浅瀬を探す」看得出来但不显眼），西岸没在水里的路面上是薄而缓的水。远景雾比广场淡一点（雨洗过）。
5. **光**：
   - 每个包在 `scene.json` 里记一条东边山脊的仰角（川约 7°）；太阳低于它时直射光为 0（烘焙和实时都关），越过以后实时光照常。
   - 第二幕的天按太阳 −1.5° 生成（只换天，太阳方向不变），出地影和西边的粉色带；另出一张「落地提前到 04:55」的对照，两张给 UX 挑。
   - 第四幕北边（上游）山上的暗雨云：远景剪影上的一层云卡片，不做体积云。
6. **布局**：每个包一个 `layout.json`（可走区域、地点、位置点、起点、出口），位置点照 UX 1.2（`road-west`、`melos-bridgehead`、`melos-pray`、`swim-in`、`swim-out`、`shallows-in`、`shallows-out`、`far-bank`、`road-east`、`melos-wash`、`way.west`、`way.east`），演出用的 `auto: false`。第四幕可走区域是西岸到 x = −5.3 为止，包括浅浅没在水里的那 3 m 路面（`melos-bridgehead`、`melos-pray` 在这一段里）；不能走的是河道；第二幕两岸、桥面、栈桥都能走。落地点背后 9 m 只留路和矮草。
7. **场景 ID 和挑包**（数据定，#79 评审）：每个停留点一个场景 ID：`scene.road-river`、`scene.road-pass`、`scene.road-spring`、`scene.road-field`。理由：同一场景里走动 0 分，「ひとりで先へ行く」会让玩家 0 分从川到峠；拆开就用 `Place.adjacent` 里现成的步行分钟。世界模型的 `sceneRef` 由数据另开 PR 改，不挡本卡。`scene.road-river` 一个场景 ID 下两个包：生成的索引 `assets/scenes/road-river/index.json` 按前端拿得到的幕挑包：`act.2` → `road-river-calm`，`act.4` → `road-river-flood`。前端没有世界变量（契约 2.8，快照里没有 `vars`），所以不按 `var.bridge` 挑；每条再记一个 `bridge` 字段写它对应的世界模型原值（`intact` / `destroyed`），只作核对：数据已证第二幕到川时一定是 `intact`、第四幕一定是 `destroyed`。`check_scene.mjs` 查「世界模型里 `Act.scenes` 含 `scene.road-river` 的每一幕，都挑得出唯一一个包」。以后广场到刑场的换布景也照这个写法。同一个目录里再生成一份 `scene.json`（`sceneId: scene.road-river`，两个包的 `places`、`spots`、`exits`、`startSpots` 合起来）：后端的 Library 和数据的 `build_world` 都按场景名的目录读它。两个包自己的布局用包名（`road-river-calm`、`road-river-flood`），不写 `scene.road-river`。`check_scene.mjs` 的世界模型核对认这份合起来的清单。每个包的 `scene.json` 照广场出 `materials.floor`（土路）和影子替身 `blockers`（山脊、断桩、小屋），`Lighting.tsx` 的环境光地面和受光比例要用。UX 设计文档 1 表头的 `scene.road-river-calm` / `scene.road-river-flood` 对齐成场景 `scene.road-river` 下的两个包名（已经过 PM 告诉 UX）。
8. **页面**：`loadScene` 能按索引加载 `scene.road-river` 的两个包（现在只认广场）。水的着色器、索引挑包、子包和共用包的加载放进按场景懒加载的块，不进 3D 主包。山脊挡光改 `Lighting.tsx` / `sun.ts`，等第一个前端线程的 #69 合了再加；太阳在山脊下时，生成环境图的天空里太阳那团光也压掉。测试页（开发用的 `?scene=` 参数）能选「川・第二幕 05:15」「川・第四幕 11:45」，能拖时间看光。梅洛斯和玩家用现有的人体模型站在 `melos-bridgehead`（第二幕 `melos-wash`）和落地点。
9. **CI**：两个包和共用包的下载大小进 `assets/budgets.json`，按包名新加一段（`scenes.road-common`、`scenes.road-river-calm`、`scenes.road-river-flood`），不改广场在用的 `scene` 一段，检查脚本两种都认；`assets.yml` 的 `paths` 加上 `assets/pipeline/road/**` 和 `assets/scenes/road-*/**`，草稿档生成两遍比清单；Playwright 在两个落地点各截一张图，两个川的包也跑两档颜色一致的检查（`tierMeanColourMaxDiff` ≤ 0.1）。

**不做**

- 梅洛斯的专属动作（跪着祈祷、跳进濁流、游、抓住柳树、洗脸）和 beat.18 的演出镜头：和结局的专属动作一起排，另开卡。
- 「とても渡れそうにない」那一行和水边的可调查物（M3 数据和服务端定，前端只按下发的显示）。
- 跑的路段、时间卡、侧后方镜头（B → C 的第二步，另开卡）；峠、泉、野の道（各一张卡）。
- 夜路（第二幕从泉到川）的路面。
- 麦：跟野の道那张卡做，到时加进共用包（共用包按版本缓存，加一种材质只多下那一张）。
- 白杨叶子风吹翻出银白的背面：等植被有风的做法再做。
- 两档贴图的分辨率按现有档位做（D-019）；F-2c 的 iPhone 数字到了再调。

## 接口

不改 `packages/contracts`。世界模型的 `sceneRef`（四个停留点各一个场景 ID）由数据另开 PR 改。前端新加的是自己的清单格式：`assets/scenes/road-river/index.json`（按幕挑包，附 `var.bridge` 的对应值）和 `scene.json` 的 `ridgeElevationDeg`、`water` 两个字段。B-7 的 manifest 路由（`scenes[].assetUrl`）指 `scene.road-river` 的索引，两个包的地址相对它。

## 验收

- 一条命令跑通；草稿档两次生成的清单逐字节一致；广场的清单不变。
- 大小〔推算，F-2c 实测后调〕：共用包 ≤ 2.2 MB；每个川的包进场 ≤ 2.6 MB；第一次进川（共用包 + 一个川的包）≤ 4.7 MB（原估 1.8 / 4；#103 实测川自己的贴图约 1.2 MB 比估的多，UX、前端同意按实测加约 10%：川不是首次进入，换幕的书页盖得住，条件是上一幕就预取下一幕的包、CC0 扫描换上后再量）。档 B 的 draw call：平静 ≤ 45、濁流 ≤ 50（不含人物）。
- 测试页在两个落地点的截图：第四幕从 `road-west` 朝东，看得见桥头、三对断桩（歪、齐水面断、挂着树枝）、濁流、对岸的柳和白杨、往东上坡的路和远处的豁口；第二幕从 `road-east` 朝西，看得见站在 `melos-wash` 的梅洛斯、木桥、贴着雾的水、对岸的路，西边天上的粉色带，西边远山山顶一点淡金。另拍一张 11:45 从 `road-west` 那侧朝南（下游）：浪尖逆光一片闪光（beat.18 的镜头以后从这里拍）。
- 05:15 河谷没有直射光，05:45 有；11:45 影子缩在脚下。
- 计测页上濁流比平静多出的一帧 GPU 时间有数字，写进 PR〔目标 ≤ 2 ms，待测〕。iPhone 上补测，不挡 PR，经 PM 安排。
- 3D 包（S-083 ⑤，现在 248.8/250 KB）：CI 的 `threeChunkKb` 不变、照常卡；新加的懒加载块自己的大小写进 PR。
- 控制台无错误；导航网格的单测：第四幕点河道（x > −5）寻路失败、能从 `road-west` 走到 `melos-bridgehead`；第二幕能从东岸过桥走到西岸。
