## Goal / 目標

`apps/web` runs one full round of text conversation locally against B-1's mock service: log in with an invite code → cover → pick a role → world screen (3D is a placeholder for now) → type a line → see the character's subtitles, the light feedback for an event and the clock advancing → drop the network and reconnect, with resent messages neither duplicated nor lost. CI is all green.

`apps/web` がローカルで B-1 のモックサービスを相手に、テキストの会話を 1 ラウンド最後まで通す：招待コードでログイン → カバー → 身分の選択 → 世界画面（3D はまずプレースホルダー）→ 1 文を入力 → 登場人物の字幕、イベントの軽いフィードバック、時計が進むのが見える → ネットワークが切れて再接続し、再送されたメッセージに重複も欠落もない。CI がすべてグリーン。

## Scope / 範囲

**In scope**

**やること**

1. Project: Vite 8 + React 19 + React Compiler + TypeScript strict, ESLint, Prettier, Vitest, Playwright. Directories split by layer: `screens/`, `stores/`, `net/`, `audio/` (filled by F-1), `three/` (filled by F-2), `telemetry/`, `ui/`.
   プロジェクト：Vite 8 + React 19 + React Compiler + TypeScript strict、ESLint、Prettier、Vitest、Playwright。ディレクトリは層ごとに分ける：`screens/`、`stores/`、`net/`、`audio/`（F-1 が埋める）、`three/`（F-2 が埋める）、`telemetry/`、`ui/`。
2. Types come only from what `packages/contracts` generates; no message or response types are hand-written.
   型は `packages/contracts` が生成したものだけを使い、メッセージやレスポンスの型を手で書かない。
3. Routes: login, cover, role selection, world, ending (the ending page is a placeholder for now); any 401 or WebSocket 4001 goes back to login, and after logging in returns to the original playthrough.
   ルート：ログイン、カバー、身分の選択、世界、エンディング（エンディングページはまずプレースホルダー）。401 または WebSocket の 4001 を受けたらログインに戻り、ログイン後は元のプレイに戻る。
4. State: four zustand stores, `world` / `player` / `voice` / `ui`, with fields per frontend-design section 6; REST data uses TanStack Query.
   状態：zustand の `world` / `player` / `voice` / `ui` の 4 つの store。フィールドは frontend-design 第 6 節に従う。REST のデータは TanStack Query を使う。
5. Network layer:
   ネットワーク層：
   - REST: cookie authentication; `/v1/me`'s `activePlaythrough`; on a 409 when starting a playthrough, go through 「新しく始める」 (delete first, then create); errors are mapped to UI states per api-contract section 5.
     REST：Cookie による認証。`/v1/me` の `activePlaythrough`。プレイ開始で 409 になったら「新しく始める」を通す（先に削除してから作成）。エラーは api-contract 第 5 節に従って画面の状態に対応付ける。
   - One WebSocket: `hello { lastSeq }` → `welcome`; `commit`s are applied by `fromSeq..seq` and de-duplicated, with gaps filled via `GET /events?afterSeq=`; `turn_settled`; `ping` every 20 seconds; reconnect with exponential backoff after disconnection; unknown message types are ignored and counted (api-contract section 0: additions only).
     WebSocket は 1 本：`hello { lastSeq }` → `welcome`。`commit` は `fromSeq..seq` に従って適用して重複を除き、番号が欠けたら `GET /events?afterSeq=` で補う。`turn_settled`。`ping` は 20 秒ごと。切断後は指数バックオフで再接続する。知らないメッセージ種別は無視して数える（api-contract 第 0 節：追加のみ）。
   - Received messages are only written to stores; components never touch the socket directly.
     受信したメッセージは store にだけ書く。コンポーネントはソケットに直接触れない。
6. The world screen's HUD skeleton (placeholder styling; the visuals are done later by UX's card): `TextInput`, `Subtitles` (including `source`, the 「……」 wait, and the explanatory text for `text: null`), `SunBand`, `NearbyList`, `WorldReactionToast`, `ConnectionBanner`, `ResumeGate`.
   世界画面の HUD の骨格（スタイルは仮のもので、ビジュアルは後で UX のカードで作る）：`TextInput`、`Subtitles`（`source`、「……」の待ち、`text: null` のときの説明文を含む）、`SunBand`、`NearbyList`、`WorldReactionToast`、`ConnectionBanner`、`ResumeGate`。
7. A text turn works end to end: `text { via: "typed" }` → `transcript` → `commit` (events, memories, narration) → `turn_settled`.
   テキストのターンが最後まで通る：`text { via: "typed" }` → `transcript` → `commit`（イベント、記憶、ナレーション）→ `turn_settled`。
8. Telemetry skeleton: batch-send `POST /v1/telemetry` per frontend-design section 11; this card only wires the network metrics (`screen_view` is not added: each step of the 9.1 funnel has its own event, decided by data on 2026-10-11); frame time and voice metrics are wired by F-1 and F-2.
   テレメトリの骨格：frontend-design 第 11 節に従って `POST /v1/telemetry` をまとめて送る。このカードはネットワーク系の指標だけをつなぐ（`screen_view` は加えない：9.1 のファネルは各ステップに専用のイベントがある。データが 2026-10-11 に決定）。フレーム時間と音声の指標は F-1、F-2 がつなぐ。
9. CI: type checking, unit tests, Playwright running the round in "Goal" above against the mock, and first-screen JS ≤ 120KB (brotli), going red if exceeded.
   CI：型チェック、単体テスト、Playwright で上の「目標」の 1 ラウンドをモック相手に実行、最初の画面の JS ≤ 120KB（brotli）。超えたら赤。

**Out of scope**

**やらないこと**

- Voice (F-1), the 3D scene and quality tiers (F-2), the final ending page, 記憶帳, 連鎖反応マップ (M2 cards).
  音声（F-1）、3D シーンと画質の段階分け（F-2）、エンディングページの正式版、記憶帳、連鎖反応マップ（M2 のカード）。
- Finalizing UX's visuals and Japanese copy (use the copy in the mock and placeholder styling).
  UX のビジュアルと日本語の文言の確定（モックの文言と仮のスタイルを使う）。

## Interfaces / インターフェース

Everything comes from `packages/contracts`: the responses in api-contract section 2, the client messages in 3.2, the server messages in 3.3, and the errors in section 5. Playwright runs against B-1, and every message B-1 returns is validated in CI against the same schemas.

すべて `packages/contracts` から来る：api-contract 第 2 節の各レスポンス、3.2 のクライアントのメッセージ、3.3 のサーバーのメッセージ、第 5 節のエラー。Playwright は B-1 を相手に実行し、B-1 が返すすべてのメッセージを CI で同じスキーマに沿って検証する。

## Acceptance check / 受け入れ確認

- `pnpm -F web test` and `pnpm -F web e2e` (against `zoujin-mock`) are all green; the commands are as R-0 defines them.
  `pnpm -F web test`、`pnpm -F web e2e`（`zoujin-mock` 相手）がすべてグリーン。コマンドは R-0 が決めたものに従う。
- e2e covers: login, 401 back to login, 409 on starting a playthrough, one text turn, dropping the network for 5 seconds and reconnecting (resends neither duplicated nor lost), unknown message types not causing errors.
  e2e で網羅するもの：ログイン、401 でログインに戻る、プレイ開始の 409、テキストの 1 ターン、ネットワークを 5 秒切って再接続（再送に重複も欠落もない）、知らないメッセージ種別でエラーにならない。
- First-screen JS ≤ 120KB (brotli), enforced in CI.
  最初の画面の JS ≤ 120KB（brotli）。CI で止める。
- No component uses WebSocket directly (checked by a lint rule or a test).
  コンポーネントの中で WebSocket を直接使う箇所がない（lint ルールまたはテストで確認）。

## Forbidden / 禁止事項

No deploying, no touching secrets or deployment URLs, no calling real models (mock only), no spending money, no third-party monitoring scripts.

デプロイしない。秘密鍵やデプロイ先のアドレスに触れない。本物のモデルを呼ばない（モックだけを相手にする）。お金を使わない。サードパーティの監視スクリプトを加えない。

バックエンドはネットワーク層とメッセージの処理を見る。UX は画面の流れと待ちの状態を見る。
