  - ruff、mypy、pytest 都排除 `spikes/` 和 `packages/worldsim/reference/`（原样搬的参考代码）。根目录 pytest 设 `testpaths = services packages evals`；`spikes/backend/tests` 依赖 Google 的库，那 43 个离线测试不进 CI。

  - 测试禁网用 pytest-socket：`--disable-socket`，只放行 127.0.0.1 和 localhost，加 `--allow-unix-socket`，这样 PostgreSQL 服务容器连得上。

  - `.nvmrc` 写 `24`（Vite 8 要 Node 20.19 以上；zg 的 Mac 是 v24，CI 用同一个）。
  - **prettier 和 eslint 排除搬进来的文件**，不然「原样复制」的文档第一次 CI 就红。`.prettierignore`：`docs/`、`worlds/`、`evals/`、`spikes/`、`fixtures/`、`packages/worldsim/reference/`、`packages/contracts/**/generated/`、`assets/**/reports/`、`pnpm-lock.yaml`。eslint 的 flat config 同样忽略 `spikes/`。

**5. 合并规则和仓库设置**（D-024：过了 CI 和两个角色评审的 PR，Claude 可以合进 main）

- 根目录 `CONTRIBUTING.md` 写清合并前查的四件：PR 最新的提交上 CI 全绿；卡上写的两个角色在这个提交上评审通过（改 `packages/contracts` 的三方，碰 PRD 数字的加 PM）；没有没处理的「要改」；PR 里没有部署、花钱和真模型调用。合并用 squash，由写卡的角色线程合。
- `.github/pull_request_template.md`：卡号、做了什么、怎么验的、两个评审角色。所有线程在 GitHub 上是同一个身份，用不了 GitHub 的批准，评审写成 PR 评论，第一行固定是「评审通过 · <角色> · <提交前 7 位>」或「要改 · <角色>」。
- 仓库设置：只允许 squash 合并，合并后自动删分支。
- 分支保护：GitHub 免费版的私有仓库开不了（GitHub 文档：私有仓库要 Pro 或团队版），开不了就不开，靠上面的流程；开得了的话，给 main 加「合并前必须过 CI 的各项检查」「不许强推、不许删除」，不设「必须几个批准」。
- 空仓库先推一个只有一行 README 的提交建 main，R-0 的其余部分走分支和 PR，按这套规则评审、合并。
