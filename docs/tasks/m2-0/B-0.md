## 目标

在一台没有任何云凭证的机器上，做完以后能看到：

1. 一条命令（`docker compose up`）起 PostgreSQL、gateway、narrator。
2. 用邀请码登录 → 开局 → 连 WebSocket → `hello` / `welcome` → `focus` 一个人物 → `session_ready` → 说一轮：
   - 用假 Live（fakeVoice：服务端回录好的音频和字幕），或者发一条 `text`；
   - 网关把这一轮交给叙事者 → 叙事者用**假文本模型**提取候选事件 → 规则检查 → **单事务提交**；
   - 前端收到 `commit` 和 `turn_settled`。
3. 用「世界模型初值 + 按 `seq` 应用全部 effects」重放，结果和 `world_state` 缓存完全一样。
4. 评测入口 `eval_api` 有最小的几步，E-0 能对着它跑完 100 个种子用例不崩。

这就是 dev-plan M2-0 过关条件的第 3 条。

## 范围

### 做

**1. 代码位置和技术**

- `services/backend/`：一个 Python 包，是仓库 uv 工作区的成员。
- 两个入口 `zoujin-gateway`、`zoujin-narrator`，以后是同一个镜像、两个 Cloud Run 服务。
- Python 3.13、FastAPI、pydantic v2、SQLAlchemy 2（async，psycopg 3）、Alembic。模型 ID 只写在配置里。

**2. 数据库**

- 用 Alembic 迁移建这些表。列按 data-design 和契约定；本卡用不到的表先不建。
  - `users`
  - `invite_codes`：只存哈希
  - `sessions`
  - `playthroughs`
  - `turns`：ID、状态、租约，不存原话
  - `utterances`
  - `events`
  - `world_state`
  - `idempotency_keys`
  - `playthrough_metrics`：先放轮数和各部分花费的列
- `alembic upgrade head` 和 `alembic downgrade base` 都能跑。

**3. 鉴权**

- `POST /v1/auth/login`：邀请码换会话 Cookie（`HttpOnly; Secure; SameSite=Lax`，30 天，每次使用滑动续期）。本地 http 下，`Secure` 由开发开关关掉。
- `POST /v1/auth/logout`、`GET /v1/me`。
- WebSocket 握手查 Cookie 和 `Origin`；会改数据的 REST 查 `Content-Type: application/json` 和 `Origin`。
- 邀请码用命令行生成（`uv run zoujin-admin invite create`）：明文只打印一次，库里只存哈希。
- 邀请码格式：`inv-` 加 4 组、每组 4 个 Crockford base32 字符（80 位随机），写法示意：`inv-XXXX-XXXX-XXXX-XXXX`（只有这个全是 X 的占位写法在秘密扫描的白名单里）。R-0 的秘密扫描按这个格式查。登录时不分大小写，忽略空格和多余的短横线，按 Crockford 的规则把 I、L 当 1，O 当 0。测试在运行时生成邀请码，不把任何一个写进仓库。

**4. REST**

- `POST /v1/playthroughs`（带 `Idempotency-Key`）、`GET …/snapshot`、`GET …/events?afterSeq=`。
- 其他接口这张卡不挂路由，按第 5 节回 `404 not_found`，后续卡补。第 5 节的错误码表里没有「未实现」，不另加。

**5. WebSocket**

- 做这些：`hello` / `welcome`（补发 `lastSeq` 之后的 `commit`）、`ping` / `pong`、`focus` / `unfocus`、`session_preparing` / `session_ready`、`activity_start` / 上行二进制 / `activity_end`、`text`、`transcript`、下行二进制、`turn_complete`、`commit`、`turn_settled`、`error`。
- 收到 SIGTERM 时先推 `goaway`。
- 其他消息类型：忽略，只在日志里记类型名，不断开连接。

**6. 模型接口**

Live 和文本模型各定义一个接口。本卡做假实现和回放实现，不做真实现：

- **假 Live**：读 `fixtures/fake-voice/`。每句回答 = 24 kHz PCM + 人物字幕 + 玩家字幕，按真实间隔吐分片。PCM 用合成的声音（例如按句长生成的音调），不放任何真人或模型录的声音。
- **假文本模型**（`fake`，CI 和 E-0 的默认）：每种提示类型有一个确定的、过 Schema 的默认输出（例：提取 → 没有候选事件；人物文字回答 → 一句固定的话），对任何请求都有回答，不会因为没见过的请求而崩。剧本要的特定输出放在 `fixtures/fake-text/`，按提示类型加简单条件（例：玩家的话里含某个词）覆盖默认值。
- **回放**（`replay`）：按（模型、提示版本、规范化请求的 sha256）从 `fixtures/model-replays/` 查。查不到就抛 `ReplayMissing`（异常类名就叫这个，E-0 按它记「回放缺失或过期」），不悄悄回空、不退回到假模型。
- **回放格式**这张卡定下来：JSONL，每行 `key`、`kind`（提示类型）、`model`、`promptVersion`、`request`（脱敏后）、`response`、`usage`（token 数）、`costUsd`、`recordedAt`。以后在 Mac 上录真模型、E-0 的 `live` 自动存回放，都用这个格式；录的代码不在本卡。
- 每个提示有版本号（提示文本的哈希即可），写进 Trace 和回放。
- 真模型的实现不写。代码里没有读取 Google 凭证的路径；`ZJ_MODEL` 只认 `fake` 和 `replay`。

**7. 叙事者骨架**

1. 按局取最早的待处理轮次：`FOR UPDATE SKIP LOCKED` 加租约。
2. 在事务外调假提取，记下读取时的 `lastSeq`。
3. 规则检查用 W-1 的 `check_effects`（引用存在、值合法、变量范围），有问题的候选判否决。R1〜R7 本卡不做，模型检查（R5、R6）也不做，在事件的 `check` 里记 `skipped`。W-1 的 `apply` 对非系统事件里的 `{op: "beat", to: "happened"}` 会抛异常：这种候选在这一步就判否决，不能走到 `apply`。
4. **单事务提交**：
   - 锁住这一局，校验 `lastSeq` 没变；
   - 给这一轮的事件分配 `eventId` 和 `seq`（W-1 的 `apply` 记即兴设定和约定要用 `eventId`），按 `seq` 用 W-1 的 `apply` 应用；
   - 用 W-1 的 `settle` 结算到新时钟为止到点的节拍和期限，把返回的系统事件草稿补成完整事件（`summary` 用节拍或变体的 `summary`，`prevented` 的原因写进 `check.reason`）接着写；同一时刻先节拍、再期限、最后事件（W-1 已定）；
   - 写这一轮的全部事件，被否决的也写；写库前每个事件都按数据契约 Event 的类型校验，不过就整轮回滚；
   - 更新 `world_state`，标记轮次完成。
   - 开局时同样做：W-1 的 `initial_state(world, role)`，再 `settle` 到身份的 `startT`，开局前到点的节拍（例 `beat.01`）写成系统事件。
   - `world_state` 表存 W-1 的 `SimState`（JSON，带它对应的 `seq`）；对外的 WorldState 用 W-1 的 `world_state()` 现算。
5. 提交后 `NOTIFY`，网关推 `commit` 和 `turn_settled`。
6. `lastSeq` 变了就丢弃这次结果，从规则检查重来。任何一步失败整轮回滚，用同一个幂等键重试。
7. gateway 调 narrator：本地走 HTTP（两个进程），形状按以后 Cloud Run 内部调用的样子。OIDC 校验在本地关掉，留开关。

**8. 重放**

`uv run zoujin-admin replay <playthroughId>`：从 `initial_state` 加全部事件按 `seq` 用 W-1 的 `apply` 重建 `SimState`，和 `world_state` 表里的比，不一致就以非零状态退出。

**9. `eval_api` 最小版**

- Python 包内调用，不开 HTTP。入口和参数名照 api-contract 第 7 节，E-0 直接接。
- `setup`：做 `role`、`place`、`budgetTier`（只记下，不生效），起点做 `scenario`（只用 W-1 推演）和 `checkpoint`（用 W-1 推演到那一刻，把结果写成这一局的初始事件），以及 `events`（直接写入，trace 里标成评测布置；只给了 `effects` 的按 api-contract 第 7 节补成完整事件，`check.checker` 写 `eval-setup`）。`sc.canon` 是原著路径。`persona` + `seed`（模拟局）不做：带 `persona` 的 `setup` 一调用就抛 `EvalNotImplemented("persona")`（E7 的 11 例和 E5-001 是这种）。
- 步骤做 `say(to, text)`、`advance(minutes)` 和 `check(candidate, turn, modelChecks?)`。`say` 走和 `text` 轮次同一条叙事者流程。`check` 把候选事件直接交给第 3 步、不提交（S-2 的数据 `evals/s2/` 就是这样跑）；本卡没有第 4 步，R5、R6 的模型部分记 `skipped`。
- 查询做 `state()`、`events()`。
- 第 7 节其余的步骤和查询，本卡没做的，调用时抛同一个异常类（例：`EvalNotImplemented("delete_memory")`），E-0 记成「跳过：后端未实现」，不算过，也不会让运行器崩。
- 每一步返回第 7 节所列字段里本卡能给的：人物回答的文字、这一步的全部候选事件（含被否决的，带 `check.status`、`failedRules`、`origin`、`effects`）、时钟前进了几分钟。

**10. 最小剧本**（放在 `fixtures/`）

旅人在广场对町の老爺说一句话 → 假提取出两个候选事件，一个有 effects、一个被否决 → 提交。

## 接口

- 发出的每条 WebSocket 消息和 REST 响应都用 C-1 生成的类型构造，测试里再用 Schema 校验一遍。
- 事件和世界状态：`packages/contracts/schemas/data/` 的 Event、WorldState。
- 规则：`packages/worldsim`（W-1）的 `initial_state`、`apply`、`settle`、`world_state`、`check_effects`。
- `recordedAt` 按 C-2 的 `RecordedAt`，必须以 `Z` 结尾。Python 的 `datetime.isoformat()` 给的是 `+00:00`，要自己格式化。

## 验收

`docker compose up` 之后，`uv run pytest services/backend` 全过，其中必须有这几组测试：

1. **端到端**：真 PostgreSQL、两个进程、一个 WebSocket 测试客户端。
   - 登录 → 开局 → `hello` → `focus` → 假 Live 说一轮。
   - 依次收到：`transcript`（玩家先 `final: false` 再 `final: true`，人物 `final: true` 带 `source`）、下行二进制、`turn_complete`、`commit`（`fromSeq` = 上一次 `seq` + 1）、`turn_settled`。
   - 同样一轮用 `text` 再走一次。
2. **Schema**：测试里拦截全部发送，每条消息都过 C-1 的 Schema。
3. **单事务**：在提交的每一步注入失败，库里没有半轮数据；重试后的结果和一次成功的一样。
4. **并发**：
   - 同一局同时塞进两轮，按顺序提交，`seq` 连续；
   - 两局并行，互不阻塞；
   - 到点的节拍改了 `lastSeq` 时，这次结果被丢弃并重来。
5. **重放**：走完最小剧本后，`replay` 一致。
6. **重连**：`hello { lastSeq }` 补发缺的 `commit`。
7. **鉴权**：
   - 没有 Cookie 的 REST 回 401，WebSocket 握手被拒；
   - `Origin` 不对回 403；
   - 邀请码表里没有明文。
8. **不联网**：pytest 里拦截 socket，只放行本机。
9. **评测入口**：`evals/s2/s2_dev.jsonl` 的 10 条起点都能起，候选事件经 `check` 返回过 Schema 的 `CheckResult`（判得对不对是 M2 叙事者卡的验收，不在本卡）；`setup(checkpoint=…)` + `say` + `state()` 跑通，结果和同一起点的 W-1 推演一致；没做的步骤、带 `persona` 的 `setup` 都抛 `EvalNotImplemented`。
10. **回放**：`ZJ_MODEL=replay` 时，fixture 里有的请求原样返回；改了提示版本或请求，报「回放缺失或过期」。

CI 里用 PostgreSQL 服务容器跑同样的测试，全绿。
