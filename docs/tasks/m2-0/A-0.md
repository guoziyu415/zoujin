## 目标

用一个人物（梅洛斯）把写实人物的流水线完整走一遍，回答一个问题：**只用免费素材和脚本，能不能做出过得了 UX 检查点 3（和人面对面，像不像一个真的人）的人物，要花多少下载量、帧时间和人工。**

做完以后能看到：zg 在 iPhone 上打开一个私有测试页，在广场 17:30、真昼、18:50 逆光三个时刻里和梅洛斯面对面，他会眨眼、看着你、跟着三句日语动嘴、对话待机；探索镜头里看他跑；能在同一个镜头里切档 B 和强机对比。

## 步骤

| # | 步骤 | 做法 | 在哪做 |
|---|---|---|---|
| 1 | 建模（高档，约 4 万面） | MPFB 2 + 官方 CC0 系统素材：男性、二十多岁、瘦长有肌肉、晒黑的牧人；皮肤、眼、眉、睫毛、牙、舌、短发 | Mac |
| 2 | 衣服 | 系统素材里没有古希腊服装：用最接近的长衣改成 exomis（露一侧肩），加皮凉鞋；或者用脚本在 Blender 里做。颜色按 5.4 | Mac（建模）＋容器（脚本） |
| 3 | 表情和口型 | 加载 `faceunits01`（ARKit 52）和 `visemes02`（15）。日语元音：あ=`viseme_aa`、い=`viseme_I`、う=`viseme_U`、え=`viseme_E`、お=`viseme_O`，闭嘴=`viseme_PP` / `viseme_sil` | Mac |
| 4 | 减面出三个版本 | 高档对话版 4 万面；标准档对话版 2〜3 万面（删掉衣服下面的身体、用较低的拓扑）；走动版 8k 面、2 个材质、不带表情（用 MPFB 的低模代理拓扑） | 容器（脚本） |
| 5 | 绑骨 | MPFB 的游戏用骨架（走动版 ≤ 60 根骨骼）；脸靠形变不靠骨骼 | Mac 或容器 |
| 6 | 动作 | UX 验收要的两个：对话待机（呼吸、很小的重心移动）和跑（身体前倾、重心起伏、脚不打滑）；另带走路（产品里人物走动要用）。来源用 CC0 动作捕捉（Quaternius Universal Animation Library 免费部分，或 CMU 动作库），重定向到上面的骨架；所有人物共用 | 下载在 Mac，重定向在容器 |
| 7 | 导出和压缩 | glTF（蒙皮、形变、动作）→ gltf-transform：几何 meshopt、颜色贴图 KTX2 ETC1S、法线 UASTC；形变只存脸部顶点并量化；高档皮肤（含脸）的颜色和法线 2048，其余 1024 | 容器 |
| 8 | iPhone 上看特写 | 私有 claude.ai 测试页（和 S7 一样，不是部署），按验收文件第 1 节第 2 条：广场 17:30（第一屏）/ 真昼 / 18:50 日没逆光三个时刻；越肩双人镜头（脸约占屏高 12〜15%）和探索镜头（人物 40〜80px）；每 3〜6 秒眨眼、视线看玩家、眉三种；三句日语（≤ 0.5 秒的相槌、约 3 秒、8 秒以上带停顿），声音用 `ux/casting-audio/casting/` 里 UX 选的梅洛斯候选之一（最后定哪个等 S-074 盲听）；口型默认按音量开合（frontend-design 7.3），「元音＋音量」只做对比开关，嘴比声音晚 ≤ 约 90ms；对话待机和跑；强制档 B / 强机在同一个镜头里切换和并排截图；同屏 2 个档 B、4 个强机的加压计时（S7 的方法） | 容器做页面，zg 用手机看并录屏 |

**容器做不了的部分和原因**（2026-10-10 查的）：容器里 Blender 5.2 能用，但网络只通 npm 和 PyPI，访问不了 GitHub、Blender 扩展站、MakeHuman 素材站、Quaternius、Poly Haven，所以 MPFB、它的系统素材和动作捕捉都下不了。npm 上有一份 2016 年的 MakeHuman 旧数据，没有脸部表情形变，文件头还写着 AGPL，只能当替身量体积和帧时间，不能当正式的梅洛斯。所以第 1、3 步和素材下载要在 zg 的 Mac 上做（Blender 5.2.1 已装）。做法是 PM 定的 (b)：在前端线程里开 Remote Control，zg 的 Mac 上起一个 Claude Code 会话，负责安装、下载和打开 Blender；建模和调形状由前端线程通过设备连接操作 Mac 上的 Blender MCP、看截图来做。条件：只在新建的 `~/Developer/zoujin-art/` 里工作，不碰 `~/Developer/zoujin-spike`、gcloud 和凭证；装 MPFB 扩展、下 CC0 素材和任何会改 Mac 的命令，先在前端线程把清单和命令给 zg 看；拉回容器的只有模型、贴图和脚本。

**先在容器里做的**（2026-10-10 已做完，见 `frontend/spikes/a0-melos/README.md`）：用替身把第 4、7、8 步的脚本和测试页做好、量好，Mac 那边一次跑完就能接上。

## 验收

**画面**：以 `A-0-acceptance-ux.md` 第 2〜4 节为准（UX 定），这里不重复。

**交给 UX 的东西**（验收文件第 1 节）：三个 glTF 和各自的下载大小；测试页链接；zg 的 iPhone 上的竖屏录屏（三个时刻 × 两档，每段 20 秒以上，有说话和不说话）；帧时间；每一步的工时、哪些要在 Blender 界面里手调；每样素材的来源和许可。

**数字**

| 项 | 线 |
|---|---|
| 标准档对话版下载 | ≤ 4MB |
| 高档对话版下载 | ≤ 6.5MB |
| 走动版下载 | ≤ 0.5MB |
| 共用动作（对话待机、走、跑） | ≤ 0.3MB |
| 对话版 draw call | ≤ 10（5 个材质 × 含阴影） |
| 广场 + 2 个档 B 对话版，一帧 GPU 耗时推到 iPhone 12（× 3.4） | ≤ 25ms（L1 的起始档条件；zg 手机上约 ≤ 7.3ms〔推算〕） |
| 广场 + 4 个强机对话版，zg 的手机上一帧 GPU 耗时 | ≤ 12ms（L2 的条件；UX 验收文件已改成同一个数） |
| 形变的代价 | 记下 52 + 15 个形变时每帧的 CPU 和 GPU 耗时（10.6.4），以及形变贴图占的显存（替身：标准档 25.7MB、高档 43.8MB；打算只让头带形变） |

**记录**

- 每个素材的来源网址、授权、sha256 写进清单；正式版只用 CC0（或 PM 问过 zg 同意的）。
- 每一步花了多久、哪些要手工调，用来估 6〜8 个人物的工作量。

## 禁止

不花钱，不买素材，不部署，不把非 CC0 素材放进正式版，不碰密钥。在 zg 的 Mac 上装东西和下载，先在前端线程给 zg 看清单和命令。

UX 看画面是否过标准；PM 看结论。
