## 目标

在世界屏幕里按住说话：mock 的假 Live 回声音和字幕，打断、作废、识别改正都能用；语音状态机的每个状态都在界面上看得到。行为和 S2 测试页一致（S2 在 iPhone 4G 上测过：松手到听见中位 1.03 秒，本地打断在按下的那一刻）。

## 范围

**做**

1. `audio/`：AudioWorklet 采集（重采样到 16 kHz）、播放缓冲（24 kHz）、音量和口型电平输出给 3D；iOS 的音频解锁和 `audioSession`。
2. 语音状态机（XState，名字和画面按 frontend-design 7.6 / UX 7.4），状态写 `voice` store。
3. 一轮：按下 → `activity_start`（人物在说话时先本地停播清空缓冲 = 打断）→ 音频帧 → 松开 `activity_end`；会话没就绪时最多缓存 2 秒；按住 < 250ms 算误触；上滑取消。
4. 字幕：`transcript` 的 `live` / `script` / `fallback` 三种来源（7.5），8 秒兜底。
5. 作废和改正：「取り消す」「言い直す」、12 秒没回应自动作废、`too_late` 显示旁白「……もう伝わってしまった。」。
6. `safety_pause`：第 12 节的七步（声音 0.2 秒淡出、清缓冲、丢弃这轮后面的帧、按住中就停止并丢弃、默认释放麦克风、卡片和焦点）和 `safety_resume` 的恢复。
7. 遥测：`talk_turn`（每轮一条，被打断的那一轮在打断时发 `interrupted: true`）、延迟分段（7.7）。
8. 把 S2 的 e2e 场景搬成 Playwright 用例（对 mock 的 `fakeVoice`），包括 S2 修过的两种打断：服务端没说完时打断、服务端说完但手机还在播时打断。
9. **M2-0 前端关口那一轮的端到端测试**（F-0、F-1、F-2 都合进 main 后，对 B-1 的 mock 跑完整一轮）：邀请码登录 → 选身份 → 进广场（F-2 的场景，无头 Chromium 软件渲染）→ 点地走到人物旁边（发 `action { kind: "move" }`，store 里的位置跟着变）→ 按住说话（Chromium 假麦克风放一段录好的日语 wav）→ 人物字幕出来 → `commit` 的事件出现轻反馈、时钟前进 → `turn_settled`。每一步截图，控制台无错误。

**不做**

- 真 Live（只对 mock 的 `fakeVoice`）、蓝牙耳机和 F-3 的真机测量（S-073 ②，M2 末评审部署时补）、3D 人物的口型（F-2 / M2 的人物卡读这里输出的电平）。
- 麦克风常开还是每轮开关：照 S-073 ③ 的暂定（进入对话拿麦克风、对话之间静音、离开 2 分钟或幕末释放），做成一个开关，F-3 有数字后再定默认。

## 接口

`packages/contracts`：3.1 的帧格式、3.2 / 3.3 的语音相关消息。音频帧不走 JSON Schema，按 3.1 写单元测试。

## 验收

- Playwright 对 mock：一轮语音、两种打断、取り消す、言い直す、12 秒自动作废、`too_late`、`safety_pause` 的全过程（含按住中被暂停）、断线后语音状态回到可说话。
- 被打断的那一轮也有 `talk_turn` 记录（S-073 ④）。
- 本地打断：按下到停播 ≤ 50ms（容器里用假时钟量）。
- 不记录麦克风设备名（可能含人名），只记类别（耳机 / 内置）。
- 关口那一轮（范围第 9 条）在 CI 里对 mock 跑通。

## 禁止

不部署，不碰密钥，不调真 Live，不花钱。

## 评审

后端看协议和时序；UX 看每个语音状态的画面和文案位置。
