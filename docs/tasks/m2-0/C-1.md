**2. Schema 的写法**

- 每种 WebSocket 消息是一个 `$defs` 条目，`type` 用 `const`；整体是按 `type` 区分的 `oneOf`。
- 我们发出的消息和响应写严格，可选字段照文档标可选。「前端忽略不认识的字段」是前端运行时的宽容，不是 Schema 放宽：以后加字段先改 Schema。
- 关死的写法和 C-2 一样：**普通对象写 `additionalProperties: false`**。json-schema-to-typescript 不认 `unevaluatedProperties`、默认又放开多余字段，每个接口都会多出 `[k: string]: unknown`；datamodel-code-generator 也是看 `additionalProperties: false` 才禁止多余字段（前端对 C-2 的评审）。`unevaluatedProperties: false` 只用在 `allOf` 拼出来的外层；接口 Schema 尽量不用 `allOf`。
- 引用数据契约的类型：
  - 形状和数据类型一样的，整个 `$ref` 过去；`$defs` 里没有的子结构用 JSON 指针（例：`data/ending.schema.json#/$defs/Ending/properties/characters`），不在 `data/` 里为它多加 `$defs`。
  - 接口在数据类型上加了或去了字段的（api-contract 2.8：`card` = `Ending.card` 加 `fallbackImageUrl`；结局的 `world`、`you` 改过形状），写成接口自己的关死对象，每个字段用 JSON 指针 `$ref` 到数据那边的字段（例：`…/properties/card/properties/title`），字数等约束不抄第二份。不用 `allOf` 去扩展 C-2 的类型：C-2 的对象已经关死，扩展出来的字段会被拒。
  - 测试列出每个这种对象和数据类型的字段差（例：`card` 只多 `fallbackImageUrl`），和 api-contract 写的不一样就红。数据契约以后加了可选字段，要不要给前端由 api-contract 决定，不会自动跟着出去。
- 运行时 ID 用 C-2 在 `data/common.schema.json` 里定的模式（前缀加 ULID）。
- 日语文字字段只约束类型和长度；文档写了上限的照写（例：`text` ≤ 200 字）。
- 只在非生产环境有的东西（`hello.debug`、`fakeVoice`、`event_rejected`、`POST /v1/test/playthroughs/{id}/advance`）照样写 Schema，`description` 里标「非生产」。
- `npc_line`（P1）不进 v1.0；分享接口（2.10，P1）不进。

**3. 生成**（接口和数据的 Schema 一起生成）

- 一条命令（`uv run contracts-gen`，或 R-0 定的任务入口）。
- TypeScript：json-schema-to-typescript（前端评审时可以换工具）。WebSocket 消息生成按 `type` 区分的联合类型。
- Python：datamodel-code-generator 生成 pydantic v2 模型，服务运行时用它们构造和解析。WebSocket 消息要能按 `type` 一次解析到对的类；工具做不到时，允许在生成目录外手写一个很薄的 `TypeAdapter` 包装。测试里另用 `jsonschema` 库直接对原始 Schema 校验，免得生成器和 Schema 有出入时没人发现。
- 生成结果提交进仓库；CI 重新生成后跑 `git diff --exit-code`。

**4. 例子**

- 把 api-contract 里的每个 JSON 例子原样抄进 `examples/valid/`。文档里的 `…` 补成合法值，补了什么在 `examples/README.md` 里列出。
- 每种 WebSocket 消息和每个 REST 响应都至少 1 个合法例子。
- 挑容易错的写反例：少了必填字段、多了字段、`type` 拼错、ID 前缀错、`text` 超长、`turnSeq` 超出 uint32。

**5. 契约测试**（进 CI，不联网）

- 每个 Schema 对 2020-12 元 Schema 合法，所有 `$ref`（包括指向 `data/` 的）都能解析。
- 合法例子全过，反例全不过。
- **关死检查**：除了 `Record` 的值和 `allOf` 的外层，`api/` 里每个 `type: object` 都有 `additionalProperties: false`；生成的 TypeScript 里没有 `[k: string]: unknown`（`Record` 生成的除外）。
- **覆盖检查**：从 `docs/backend/api-contract.md` 3.2、3.3 的表格里读出全部 `type` 名，和 Schema 里的 `const` 一一对应，少一个、多一个都红。这样文档和 Schema 不会悄悄分叉。
- 合法例子经 pydantic 解析再导出（`by_alias`，去掉 None）后，和原文件相同。
- 一个用到生成类型的 TypeScript 小文件过 `tsc --noEmit`（strict）。
