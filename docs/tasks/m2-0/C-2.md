## Scope / 範囲

### In scope / やること

**1. Write the 8 schemas**

**1. 8 つのスキーマを書く**

- Copy type by type from the TypeScript notation in `contracts.md`:
  `contracts.md` の TypeScript の書き方から型を 1 つずつ書き写す：
  - `?` = optional; everything else goes into `required`;
    `?` = 任意、それ以外はすべて `required` に入れる。
  - `| null` allows `null`; where it is not written, `null` is not allowed;
    `| null` は `null` を許す。書かれていなければ許さない。
  - Literal unions (`"pending" | "happened" | …`) become `enum`;
    リテラルの共用体（`"pending" | "happened" | …`）は `enum` にする。
  - `unknown` (`set`'s `value`, `Condition.value`, `StateVar.default`, the values of `WorldState.vars`) gets no constraint;
    `unknown`（`set` の `value`、`Condition.value`、`StateVar.default`、`WorldState.vars` の値）には制約を付けない。
  - `Record<K, V>` becomes `additionalProperties`, with `propertyNames` added where the keys have an ID format.
    `Record<K, V>` は `additionalProperties` にし、キーに ID の形式があるものは `propertyNames` を加える。
- Numbers, lengths and counts stated in comments are written in as is:
  コメントに書かれた数値、長さ、個数はそのまま書く：
  - `Cite.quote` ≤ 80 characters, `para` ≥ 1; `seq` ≥ 1; `trustDelta` −20 to 20; `salience` 0 to 1; `trust` −100 to 100; `level` 1 to 5; `attempts` 1 to 3;
    `Cite.quote` ≤ 80 字、`para` ≥ 1。`seq` ≥ 1。`trustDelta` −20〜20。`salience` 0〜1。`trust` −100〜100。`level` 1〜5。`attempts` 1〜3。
  - Ending card `title` ≤ 14, `subtitle` ≤ 26, `contrast` ≤ 48, each `characterLines` line ≤ 40, and 2–3 `characterLines` (the card lays out at most 3 lines);
    エンディングカードの `title` ≤ 14、`subtitle` ≤ 26、`contrast` ≤ 48、`characterLines` は各行 ≤ 40 で 2〜3 行（カードは最大 3 行で組む）。
  - `CharacterEnding.yours` is 1–3 sentences (omitted when `unchanged: true`, never an empty array); `rank` is an integer ≥ 1 or `null`;
    `CharacterEnding.yours` は 1〜3 文（`unchanged: true` のときは省略し、空配列は書かない）。`rank` は ≥ 1 の整数または `null`。
  - "Every sentence cites at least one event": `epilogue[].cites`, `didForYou[].cites`, `youDid[].cites`, `yours[].cites` all have `minItems: 1`; `title.causedBy` and `fate.causedBy` are non-empty (`minItems: 1`); `world.variant.causedBy` has at least 2.
    「各文が少なくとも 1 つのイベントを引用する」：`epilogue[].cites`、`didForYou[].cites`、`youDid[].cites`、`yours[].cites` はすべて `minItems: 1`。`title.causedBy`、`fate.causedBy` は空でない（`minItems: 1`）。`world.variant.causedBy` は少なくとも 2 つ。
- `Effect` is a `oneOf` discriminated by `op`, with one branch for each of the 8 kinds (`set`, `inc`, `beat`, `learn`, `relocate`, `promise`, `improv`, `hold`), and `op` as a `const`. `learn.fact` may be a `FactId` or a `RunFactId` (1.1).
  `Effect` は `op` で区別する `oneOf` で、8 種（`set`、`inc`、`beat`、`learn`、`relocate`、`promise`、`improv`、`hold`）にそれぞれ 1 つの分岐を持ち、`op` は `const` にする。`learn.fact` は `FactId` でも `RunFactId` でもよい（1.1）。
- Write strictly: **plain objects use `additionalProperties: false`**; only intersection types composed with `allOf` (`sampleLines`'s `Cite & { since?, until?, when? }`) use `unevaluatedProperties: false` on the outer layer, and the intersected definitions must not be closed first, or `since` would be rejected; how to split it is up to the session, and the tests must cover it. Both forms validate equally strictly, but json-schema-to-typescript does not understand `unevaluatedProperties` and allows extra fields by default, so every interface would get an extra `[k: string]: unknown` and a misspelled field name would still pass type checking; Python's datamodel-code-generator also forbids extra fields only when it sees `additionalProperties: false` (frontend review). The `additionalProperties` of a `Record` is the schema of its values and is not affected by this rule.
  厳密に書く：**普通のオブジェクトには `additionalProperties: false` を書く**。`allOf` で組み立てた交差型（`sampleLines` の `Cite & { since?, until?, when? }`）だけは外側に `unevaluatedProperties: false` を使う。交差される側の定義を先に閉じてはならない。閉じると `since` が拒否される。どう分けるかはセッションが決め、テストで網羅する。どちらの書き方も検証の厳しさは同じだが、json-schema-to-typescript は `unevaluatedProperties` を理解せず、既定で余分なフィールドを許すので、すべてのインターフェースに `[k: string]: unknown` が付き、フィールド名を書き間違えても型チェックを通ってしまう。Python の datamodel-code-generator も `additionalProperties: false` を見たときだけ余分なフィールドを禁止する（フロントエンドのレビュー）。`Record` の `additionalProperties` は値のスキーマなので、この規則の影響を受けない。
- Every main type and `$defs` entry carries a `title` (= the type name, except `Promise` as above) and a one-sentence `description` (taken from the comments in contracts.md).
  各主要な型と `$defs` には `title`（= 型名。`Promise` は上記の例外）と 1 文の `description`（contracts.md のコメントから取る）を付ける。
- **Schemas govern shape only, not cross-field rules.** E.g. `quote` must be an exact substring of that passage of the original text, events' `t` must not decrease in `seq` order, `world.outcome` must equal the category judged per 2.9, events in `causes` must exist. These already live in `build_world`, W-1, B-0 and the ending validation, and are not moved into the schemas.
  **スキーマは形だけを扱い、フィールドをまたぐ規則は扱わない。** 例：`quote` は原文の該当段落の正確な部分文字列でなければならない、イベントの `t` は `seq` 順に減らない、`world.outcome` は 2.9 に従って判定した区分と一致しなければならない、`causes` の中のイベントは存在しなければならない。これらは既に `build_world`、W-1、B-0、エンディングの検証にあり、スキーマには移さない。

**3. 契約テスト**（`packages/contracts/tests/`、CI に入れ、ネットワークは使わない）

- Every schema is valid against the 2020-12 meta-schema, and every `$ref` resolves.
  すべてのスキーマが 2020-12 のメタスキーマに対して妥当で、すべての `$ref` が解決できる。

  妥当な例はすべて通り、反例はすべて通らない。
- **Checked against the doc**: read every `type X = …` from the ```` ```ts ```` code blocks in `docs/data/contracts.md` and match them one to one with the `$defs` in the 8 files (currently 37); one missing or one extra goes red. ## Interfaces / インターフェース

This card produces `packages/contracts/schemas/data/`. C-1's API schemas point here with `$ref`; B-0 validates against `Event` before writing to the database; W-1's `world_state()` is validated against `WorldState`.

このカードは `packages/contracts/schemas/data/` を作る。C-1 のインターフェースのスキーマは `$ref` でここを指す。B-0 はデータベースに書く前に `Event` で検証する。W-1 の `world_state()` は `WorldState` で検証する。
