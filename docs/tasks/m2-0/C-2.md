## 和 C-1 的约定

C-1 卡里写的，这里照做：

- 目录：`packages/contracts/schemas/data/`（本卡）、`schemas/api/`（C-1）。生成的 `ts/`、`python/` 由 C-1 做，放在 `packages/contracts/` 下另外的目录。
- JSON Schema 2020-12；`$id` 用相对路径（例：`data/event.schema.json`），`$ref` 相对引用，不写任何域名。
- 8 个文件名不变（C-1 按这些名字引用）。子类型放在各文件的 `$defs` 里，`$defs` 的名字用 `contracts.md` 里的类型名：

| 文件 | 顶层 `$ref` 指向 | `$defs`（contracts.md 的类型） |
|---|---|---|
| `data/common.schema.json` | 没有主类型 | `Cite`，加下面的公共定义 |
| `data/playthrough.schema.json` | `Playthrough` | `Playthrough` |
| `data/world-model.schema.json` | `WorldModel` | `WorldModel`、`Character`、`DesignLine`、`MutualAid`、`PromiseTemplate`、`Place`、`Scene`、`Fact`、`Beat`、`BeatVariant`、`Activity`、`Condition`、`CausalEdge`、`Clock`、`StateVar`、`Role`、`Act`、`ActExit`、`EnRoute`、`EnRouteChoice`、`WorldEnding`、`EndingSignature`、`Affordance`、`Item` |
| `data/event.schema.json` | `Event` | `Event`、`Effect`、`CheckResult` |
| `data/utterance.schema.json` | `Utterance` | `Utterance` |
| `data/world-state.schema.json` | `WorldState` | `WorldState`、`RunFact` |
| `data/memory.schema.json` | `MemoryItem` | `MemoryItem`、`Relationship`、`Promise`（约定） |
| `data/ending.schema.json` | `Ending` | `Ending`、`CharacterEnding` |

- `common.schema.json` 的公共定义，名字现在定好，C-1 直接引用：
  - `SchemaVersion`：`"1.0"`〜`"1.5"`；
  - `StoryTime`：`t`，整数，≥ 0；
  - `TLabel`：字符串；
  - `RecordedAt`：ISO 8601 UTC，以 `Z` 结尾（用 `pattern` 校验，不靠 `format`，免得多装依赖）；
  - 运行时 ID（前缀加 26 位 Crockford base32 的 ULID）：`PlaythroughId`（`pt_`）、`TurnId`（`turn_`）、`EventId`（`ev_`）、`MemoryId`（`mem_`）、`UtteranceId`（`utt_`）、`EndingId`（`end_`）、`PromiseId`（`prm_`）、`RunFactId`（`rf_`）；
  - 静态 ID（类型前缀加小写 slug，slug 里可以有 `.` 和 `-`）：`CharacterId`、`PlaceId`、`SceneId`、`ActId`、`BeatId`、`FactId`、`VarId`、`RoleId`、`EdgeId`、`AidId`、`PromiseTemplateId`、`AffordanceId`、`ItemId`、`ExitId`、`RuleId`；世界结局的 ID 不带前缀（`WorldEndingId`，例 `canon-reunion`）；
  - `Actor`：`"player"`、`"system"`、`"narrator"` 或 `CharacterId`。
- `Promise` 的 `title` 写 `StoryPromise`（契约第 3.1 节的注释），生成的 TypeScript 不会盖掉 JS 的 `Promise`。生成器按 `title` 起名，C-1 配置时照这个用。
- 和前端常用的名字撞了的 `Event`（DOM）、`Scene`、`Clock`（three.js）**不改名**：前端一律按命名空间导入（`Data.Event`、`Data.Scene`），F-0 加 lint 规则管。C-1 要原样复用 `Ending.card` 时用 JSON 指针引用（`ending.schema.json#/$defs/Ending/properties/card`），不为它多加 `$defs`。

## 范围

### 做

**1. 写 8 个 Schema**

- 照 `contracts.md` 的 TypeScript 写法逐个类型抄：
  - `?` = 可选，其余都进 `required`；
  - `| null` 允许 `null`，没写的不允许；
  - 字面量联合（`"pending" | "happened" | …`）写 `enum`；
  - `unknown`（`set` 的 `value`、`Condition.value`、`StateVar.default`、`WorldState.vars` 的值）不加约束；
  - `Record<K, V>` 写 `additionalProperties`，键有 ID 格式的加 `propertyNames`。
- 注释里写明的数值、长度和个数照写：
  - `Cite.quote` ≤ 80 字、`para` ≥ 1；`seq` ≥ 1；`trustDelta` −20〜20；`salience` 0〜1；`trust` −100〜100；`level` 1〜5；`attempts` 1〜3；
  - 结局卡 `title` ≤ 14、`subtitle` ≤ 26、`contrast` ≤ 48、`characterLines` 每句 ≤ 40，`characterLines` 2〜3 条（卡片按最多 3 行排）；
  - `CharacterEnding.yours` 1〜3 句（`unchanged: true` 时省略，不写空数组）；`rank` 是 ≥ 1 的整数或 `null`；
  - 「每句至少引用一个事件」：`epilogue[].cites`、`didForYou[].cites`、`youDid[].cites`、`yours[].cites` 都 `minItems: 1`；`title.causedBy`、`fate.causedBy` 非空（`minItems: 1`）；`world.variant.causedBy` 至少 2 个。
- `Effect` 是按 `op` 区分的 `oneOf`，8 种（`set`、`inc`、`beat`、`learn`、`relocate`、`promise`、`improv`、`hold`）各一个分支，`op` 用 `const`。`learn.fact` 可以是 `FactId` 或 `RunFactId`（1.1）。
- 写严格：**普通对象写 `additionalProperties: false`**；只有 `allOf` 拼出来的交叉类型（`sampleLines` 的 `Cite & { since?, until?, when? }`）在外层用 `unevaluatedProperties: false`，被交叉的定义自己不能先关死，否则 `since` 会被拒，怎么拆由会话定，测试要覆盖。两种写法校验时一样严，但 json-schema-to-typescript 不认 `unevaluatedProperties`、默认又放开多余字段，每个接口都会多出 `[k: string]: unknown`，写错字段名也能过类型检查；Python 的 datamodel-code-generator 也是看 `additionalProperties: false` 才禁止多余字段（前端评审）。`Record` 的 `additionalProperties` 是值的 Schema，不受这条影响。
- 每个主类型和 `$defs` 都带 `title`（= 类型名，`Promise` 例外见上）和一句 `description`（从 contracts.md 的注释取）。
- **Schema 只管形状，不管跨字段的规矩。** 例：`quote` 必须是原文那一段的精确子串、事件按 `seq` 的 `t` 不递减、`world.outcome` 要等于按 2.9 判出的那一类、`causes` 里的事件要存在。这些已经在 `build_world`、W-1、B-0 和结局的校验里，不搬进 Schema。

**2. 例子**

- 放在 `packages/contracts/examples/valid/data/<名字>/*.json` 和 `examples/invalid/data/<名字>/*.json`（和 C-1 的 `examples/` 同一套目录）。
- 合法例子：
  - 把 contracts.md 第 6 节的 JSON 原样抄进来（Fact、Beat、CausalEdge 各一条，两个事件）。`…` 补成合法值；第二个事件只是片段，补成完整的 Event。补了什么写在 `examples/README.md`。
  - 每个主类型至少 1 个；`Effect` 的 8 种各 1 个；`Promise`、`RunFact`、`Relationship`、`CharacterEnding` 各 1 个。
  - `world.json` 本身是 WorldModel 最大的合法例子，直接校验，不复制。
- 反例，挑容易错的：少了必填字段；多了字段；ID 前缀错（`evt_`）或 ULID 位数不对；`schemaVersion: "1.6"`；没有的 `op`；`beat` 的 `to` 写成不存在的值；`failedRules` 里有 `R8`；`quote` 81 字；`t` 是负数或小数；`trustDelta` 25；`level` 6；`sampleLines` 里多了字段；`characterLines` 4 条；`epilogue` 里一句的 `cites` 是空数组。

## 禁止

- 不部署、不碰密钥、不调真模型、不花钱（dev-plan 2.2）。
- 测试不联网：Schema 之间只用相对引用。

- `world.json` 过不了 Schema 时，不为了过而放宽 Schema，也不改世界模型。先看是不是 Schema 抄错了；如果是世界模型和契约真的对不上，停下来在 PR 里列出，数据决定改世界模型（另开 PR，重新生成）还是给契约加字段（只做加法，写进变更记录）。数据已核对过一遍：`world.json` 各类对象的顶层字段都在契约里，嵌套的字段由本卡的测试查。
