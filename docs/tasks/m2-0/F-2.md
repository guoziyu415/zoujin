## Goal / 目標

The world screen shows S7's Syracuse plaza (the first screen is the southwest corner at 17:30). The player can walk around the plaza (tap the ground / joystick, staying on the ground and not passing through walls), and the sun moves with the world clock; quality is split into L0–L3 per D-019, the starting tier comes from a stress self-test on entry, and dropped frames lower the tier. CI enforces scene asset size and draw calls.

世界画面には S7 のシラクスの広場がある（最初の画面は 17:30 の南西の角）。プレイヤーは広場を歩ける（地面をタップ / ジョイスティック。地面に沿い、壁を抜けない）。太陽は世界の時計に合わせて動く。画質は D-019 に従って L0〜L3 に分け、開始ティアは入場時の負荷による自己測定で決め、フレームが落ちたらティアを下げる。CI でシーンのアセットのサイズと draw call を止める。

## Scope / 範囲

**In scope**

**やること**

1. Bring the asset pipeline into the repo: S7's `build_plaza.py`, `sky.py`, `sunpos.py`, `bake.py`, `encode.py` and the gltf-transform scripts go into `assets/pipeline/`, and one command generates the plaza's glTF (meshopt), KTX2 textures, lightmaps and navmesh. Where the generated files live follows 2.1 (decided after A-0's measurements).
   アセットパイプラインをリポジトリに入れる：S7 の `build_plaza.py`、`sky.py`、`sunpos.py`、`bake.py`、`encode.py` と gltf-transform のスクリプトを `assets/pipeline/` に置き、1 つのコマンドで広場の glTF（meshopt）、KTX2 テクスチャ、ライトマップ、navmesh を生成する。生成物の置き場所は 2.1 に従う（A-0 の計測後に決める）。
2. `three/`: `SceneLoader` (loads by `sceneRef`; walkable first, details filled in after), `Lighting` (real-time sun + baked occlusion + physical sky, following `world.clock`), fog, post-processing (bloom, color grading, vignette, Neutral tone mapping), `CameraRig` (third person, drag to rotate the view, framing during conversation), `Player` (navmesh pathfinding and ground snapping). Characters use S7's gray mannequins for now (replaced in M2 by A-0's realistic characters).
   `three/`：`SceneLoader`（`sceneRef` で読み込み、まず歩けるようにしてから細部を補う）、`Lighting`（リアルタイムの太陽 + ベイクした遮蔽 + 物理的な空。`world.clock` に従う）、霧、ポストプロセス（ブルーム、カラーグレーディング、ビネット、Neutral トーンマッピング）、`CameraRig`（三人称、ドラッグで視点を回す、会話時の構図）、`Player`（navmesh による経路探索と接地）。登場人物はまず S7 の灰色のマネキンを使う（M2 で A-0 のリアルな人物に替える）。
3. Renderer: if T-002 has results, use them; if not, use WebGLRenderer (S7's and D-019's numbers were all measured with it, and the bundle is small). The code uses only standard materials and a little custom shading, so it runs on either.
   レンダラー：T-002 に結果があればそれに従う。なければ WebGLRenderer を使う（S7 と D-019 の数値はどれもこれで測ったもので、バンドルも小さい）。コードは標準マテリアルと少しのカスタムシェーディングだけを使い、どちらでも動くようにする。
4. Quality tiers L0–L3 (10.6.3): an off-screen stress self-test sets the starting tier; every 5 seconds look at p95, and two consecutive readings over budget drop one level, with only resolution taking effect immediately; upgrades only at camera cuts and when entering or leaving a conversation; low power (locked to 30 fps) never upgrades; high-tier assets are downloaded in the background only at L2.
   画質の段階 L0〜L3（10.6.3）：画面外の負荷による自己測定で開始ティアを決める。5 秒ごとに p95 を見て、2 回連続で予算を超えたら 1 段下げる。すぐに効くのは解像度だけ。昇格はカメラ切り替え時と会話の出入りのときだけ。低電力（30 フレームに固定）では昇格しない。高ティアのアセットは L2 になって初めてバックグラウンドでダウンロードする。
5. Telemetry: `perf_sample` (including `qualityLevel`, `assetTier`, `lowPower`) and `quality_changed` (including `probeGpuMs`, `assetMbps`) per data-design 9.3.
   テレメトリ：`perf_sample`（`qualityLevel`、`assetTier`、`lowPower` を含む）、`quality_changed`（`probeGpuMs`、`assetMbps` を含む）を data-design 9.3 に従って送る。
6. A measurement page (reusing S7's stress method), used later for S4, S5 and real-device measurements on old iPhones; it can be published as a private claude.ai page and opened on an iPhone, with no deployment needed.
   計測ページ（S7 の負荷方式を引き継ぐ）。今後 S4、S5 と古い iPhone の実機計測でも使う。claude.ai の非公開ページとして公開して iPhone で開けるので、デプロイは不要。
7. CI: entry bundle ≤ 8MB, scene environment total ≤ 10MB (high tier ≤ 19MB), first-entry total ≤ 10MB, 3D chunk ≤ 250KB (WebGPU ≤ 380KB), draw calls counted in headless Chromium ≤ 120; the average colors of the two tiers' textures match (art-direction 9.5).
   CI：入場時のバンドル ≤ 8MB、シーンの環境の合計 ≤ 10MB（高ティア ≤ 19MB）、初回入場の合計 ≤ 10MB、3D のチャンク ≤ 250KB（WebGPU ≤ 380KB）、ヘッドレス Chromium で数えた draw call ≤ 120。2 ティアのテクスチャの平均色が一致する（art-direction 9.5）。

## How it splits into PRs (D-023: one PR per card, split if it gets large, with the order written in the card) / PR の分け方（D-023：1 枚のカードに 1 つの PR。大きくなったら分け、順番はカードに書く）

Generated files do not go into the repo, only the manifest; CI and deployment builds generate them on the spot (decided by PM on 2026-10-10, because pushing Git LFS from the project container is blocked by network policy). Three conditions: reproducible (two generations from the same input give the same sha256; where this is not possible, state which step); CI generates only when the pipeline or the scene changes, with the duration written into the PR description; the LFS rules in `.gitattributes` stay. Details are in `assets/pipeline/plaza/README.md`.
   **F-2a アセットパイプライン**：範囲の第 1 項と、第 7 項のうちシーンのアセットに関わる部分。`assets/pipeline/plaza/` が 1 つのコマンドで広場（ジオメトリ、2 ティアの KTX2 テクスチャ、ライトマップ、ナビゲーションメッシュ）を生成する。`assets/scenes/syracuse-square/layout.json` で歩ける範囲、地点の境界、位置点、出口を定める。`scene.json` の一覧はリポジトリに入れる。CI が予算と 2 ティアの色を確認し、クリーンな環境でドラフト品質で最初から一度実行する。生成物はリポジトリに入れず一覧だけを置き、CI とデプロイのビルドでその場で生成する（PM が 2026-10-10 に決定。プロジェクトのコンテナから Git LFS への push がネットワークポリシーで阻まれたため）。条件は 3 つ：再現できること（同じ入力から 2 回生成すると sha256 が一致する。できない場合はどのステップかを明記する）。CI はパイプラインかシーンを変えたときだけ生成し、所要時間を PR の説明に書く。`.gitattributes` の LFS のルールは残す。詳細は `assets/pipeline/plaza/README.md` にある。

## Interfaces / インターフェース

Reads `world.clock`, `player.place / spot`, `characters[id].place / spot / activity` (the store's shape per frontend-design section 6); sending `action { kind: "move" }` when the player moves is the job of F-0's network layer, and this card only calls the store's methods. Before C-1 and F-0 are merged into main, use the fake types and fake store under this card's `three/dev/` (containing only the fields above); after they are merged, switch to the types generated by `packages/contracts` and F-0's store, and delete the fakes.

`world.clock`、`player.place / spot`、`characters[id].place / spot / activity` を読む（store の形は frontend-design 第 6 節に従う）。プレイヤーの移動で `action { kind: "move" }` を送るのは F-0 のネットワーク層の役目で、このカードは store のメソッドを呼ぶだけ。C-1、F-0 が main にマージされるまでは、このカードの `three/dev/` の下にある偽の型と偽の store（上のフィールドだけを持つ）を使う。マージされた後は `packages/contracts` が生成した型と F-0 の store に切り替え、偽物を削除する。

## Forbidden / 禁止事項

No deploying, no touching secrets, no calling models, no spending money, no buying assets. Note that S7's stone textures come from the Sponza sample scene (a license requiring attribution, suitable only for validation); the final version switches to CC0 scanned materials (Poly Haven, ambientCG, etc.), with each one's source, license and sha256 recorded in the manifest under `assets/`; downloads have to run somewhere that can reach those sites (the project container currently cannot; see A-0).

デプロイしない、秘密鍵に触れない、モデルを呼ばない、お金を使わない、素材を買わない。S7 の石のテクスチャは Sponza のサンプルシーンから取ったもの（帰属表示が必要なライセンスで、検証用にしか向かない）なので、正式版では CC0 のスキャンマテリアル（Poly Haven、ambientCG など）に替え、1 枚ずつ出典、ライセンス、sha256 を `assets/` の一覧に記録する。ダウンロードはこれらのサイトにアクセスできる場所で実行する（プロジェクトのコンテナは今はアクセスできない。A-0 を参照）。
