# H-1：主角书房与多书入口

## 体验约定

- zoujin 是进入多本书的入口；《走れメロス》只是当前已开放的一本。目录只展示服务端明确发布的书，尚无第二本内容时不造假书名、封面或试玩入口。
- 家属于读者，不属于某一本书的时间线。书房不连接故事 WebSocket、不请求语音权限、不推进时钟、不创建体验。
- 空间主导首页。上方品牌与简短欢迎语，底部两个等效入口「本棚」「回想録」。有进行中体验时，显示服务端真实身份与时刻的「しおりの続きから」。
- 美术由独立原创欧式书房场景承担：高窗、木书柜、灰泥墙、黄铜灯、实体书与回忆册。参照既有 art-direction 的写实光、暗部颜色、克制调色和手机预算，布局与几何不照搬书内场景。

## 操作路径

1. 站点密码 → 原邀请码账号 → 书房；未通过账号认证时不加载书房 3D chunk。
2. 本棚 → 对应 `/books/:bookId` 封面 → `/books/:bookId/roles` 身份 → 用户点击后才创建局。
3. 进行中体验 → 故事菜单「書斎に戻る」 → 书房「しおりの続きから」返回同一个 `playthroughId`。返回只卸载连接，不发创建或删除请求。
4. 回想录 → 已落库的真实结局 → 原完整结局页（世界、自己、人物、结局卡和因果图）→ 书房。
5. 已结束但尾声尚未落库的记录单独显示「物語を綴じています」，打开后复用既有幂等生成任务；不能展示成已经完成的结局。
6. 单账号仍仅有一个进行中体验；新开冲突继续沿用明确的二次删除确认，不因换书或回家自动删局。

## 手机与可访问性

- 家内物体点击与 DOM 按钮等效；视力、键盘或 WebGL 受限用户可完成全部选书、继续和回忆操作。
- 目录与回忆使用原生 `<dialog>`；打开时焦点进入面板，背景不可操作，Escape 关闭且恢复焦点；从空回忆录切换到书架时将焦点移到新面板的关闭按钮。
- 手机为底部面板，最高 78dvh；宽屏为右侧 430px 面板，留出可见房间。最小按钮高度 44px，考虑 safe area 与横屏。
- reduced-motion 停止界面动画；3D 独立处理减少动态偏好与页面隐藏。
- 网络失败与空记录明确区分，并提供重试；未开放书禁用进入按钮，未知书 URL 给出返回路径。

## 数据与私密性

- 书架只使用 `/v1/books`；进度和结局只使用 `/v1/library`。不给客户端所有预设结局、不用 localStorage 推测完成情况。
- 从存档的 `bookId` + `worldModelVersion` 定位 manifest，身份来自服务器记录；旧版本资源不可用时明确失败，不默默改为新版本。旧 `/roles` 链接只作为梅洛斯兼容入口。
- 账号切换或失效时清空 React Query、内存故事状态、结局画面、交接快照和旧遥测队列（包括晚到的重试），防止上一邀请码的内容残留。
- 站点密码失效的 `X-Site-Access: required` 直接整页跳转服务端密码页，不陷入邀请码重试循环。WS 在 accept 前被拒时浏览器通常报告 1006；异常断线触发单并发、30 秒限速的 `/v1/me` 探测，使同一个 REST 门禁恢复路径生效。
- 停用离线 SW；清理旧 `zoujin-*` 缓存与旧 worker。撤销 worker 不拦截请求。服务器仍需覆盖 HTML、JS、GLB、声音、API、WS 并返回 private/no-store。
- 本地开发仅监听 127.0.0.1；没有部署、公开链接或第三方资产上传。

## 验证记录

- TypeScript 类型检查通过。
- 前端单测：317 通过；补入本机真实场景资产后，先前跳过的 17 个场景检查也已执行。
- 构建通过；首屏 JS 107.6 KB brotli（预算 120），世界 chunk 235.6 KB（预算 250）。书房独立 chunk，未静态并入首屏。
- Chrome 浏览器流程：12/12 通过（书架空态、未开放书、真实历史/生成中状态、回家继续同一局且零创建/删除、邀请码和 401 恢复、原有冲突二次确认、断线事件恢复、旧离线缓存清理）。最初 Playwright 自带 Chromium 缺失，随后使用本机 Chrome 临时测试 profile 完成。
- 390×844 手机与 1440×960 桌面的裸场景/集成书房/书架/回忆录已各截图复核，共 8 张，存于仓库外 `~/.zoujin/qa/h1-home/review-*.png`。画布填满，无 DPR 黑边，页面无 JS 异常；图片使用本机测试目录投影，不上传。
- 第一轮独立美术复核提出窗光/接触阴影不足、木纹重复偏程序化的问题；后续三轮调整与结果见下方。这些截图不代表手机真机最终美术/性能验收。手机欢迎副标压亮色檐线的问题已隐藏副标解决，保留主标题。
- 交叉审查：后端历史 SQL 先限定 owner 与 active/ended 状态再 join；生成中记录不冒充完成；GET ending 只唤醒既有队列任务。发现历史 manifest 使用最新版本的风险，后端和前端均已改为按实际存档版本读取。
- 书内场景 build 已复制到本工作树供本机集成；通过资源检查不等于全书视觉验收。手机真机帧率和真实语音未在本卡声称完成。

## 第三轮与最终代码复核

- `review3-{phone,desktop}-integrated.png`：窗光调整后，书柜、墙面、椅子出现明确的侧光和投影，木纹对比降低；集成页面填满、按钮可读，没有新增阻断项。窗外和书脊规律感仍可后续精修，不扩大本轮范围。
- 保留颜色的顶点合批后，本机 Chrome 手机 390×844（内部 585×1266）首个完整帧为 94 draw calls / 235,382 triangles，桌面 1440×960 为 96 / 235,510，包含阴影、AO 与后处理。手机主场景单独绘制为 20 / 62,776；静止观测 0.5–1 秒没有额外 GPU draw。符合现有每帧 120 draw calls 和 300k 可见三角形预算；不代替真机帧时间。
- 书房尺寸变化、减少动态偏好、普通卸载的几何/纹理/材质/后处理释放已独立审查；初始化异常走同一逆序清理，补足 GTAOPass 漏掉的两个材质，卸载主动释放 WebGL context。人物群体代表已避开真实 crowd 初始位置，玩家靠近不会触发下次状态更新时自动挪走，结局演出时隐藏，避免重绘同一角色。
- 默认页面标题改为 `zoujin`。账号缓存、旧 SW 与 CacheStorage 的清理只影响浏览器；不会调用创建/删除局接口，也不会删除服务器进度与结局。
- 最终 `final-{phone,desktop}-integrated.png` 来自 127.0.0.1:8091 真实 gateway + production build，经过站点密码和邀请码、读取本机数据库真实进度，没有接口注入。两端无 pageerror、标题正确、跨面板键盘焦点正确；主动触发 context loss 后，DOM 书架仍可打开。已知离线时不发认证探测，恢复网络后的握手失败会重新检查门禁。
