# fixtures

Fixed data for tests: recorded model replays, fake Live lines, and mock data and scenarios. Replays are recorded only from synthetic inputs (dev-plan 2.5) and stored by model, prompt version and request hash; if a prompt changes, CI reports "replay stale". B-0 and E-0 put things in here.

テスト用の固定データ：録画済みのモデルリプレイ、偽 Live の台詞、mock のデータとシナリオ。リプレイは合成入力からのみ録画し（dev-plan 2.5）、モデル・プロンプトバージョン・リクエストハッシュごとに保存する。プロンプトを変えると CI が「リプレイ期限切れ」を報告する。B-0、E-0 がここに置く。

The lines and summaries here are written for testing: no sentences from the original work, no recordings of real people or things real people said, and no addresses, project IDs or invite codes.

ここの台詞と要約はテスト用に書いたもの：原作の文、実在の人物の録音や発言は入れず、住所、プロジェクト ID、招待コードも入れない。

| Directory / ディレクトリ | Read by / 読むもの | What it is / 内容 |
|---|---|---|
| `mock/rest/`, `sessions/` | `zoujin-mock` (B-1) / `zoujin-mock`（B-1） | The mock's REST responses and WebSocket scenarios, see their READMEs / mock の REST レスポンスと WebSocket シナリオ。各 README を参照 |
| `fake-voice/lines.json` | Fake Live (B-0, `models/live.py`) / 偽 Live（B-0、`models/live.py`） | For each character, a series of "what the player says + the character's answer", used in turn and restarting from the beginning when exhausted. The player subtitle of a voice turn is `player` (the fake has no speech recognition); a text turn uses only `reply`. The character's audio is synthesized from the length of the answer, not recorded. Characters not listed use `default` / 人物ごとに「プレイヤーの発言 + 人物の返答」の列があり、順番に使い、尽きたら最初に戻る。音声ターンのプレイヤー字幕は `player`（偽物には音声認識がない）、テキストターンは `reply` だけを使う。人物の音声は返答の文字数から合成したもので、録音ではない。列挙されていない人物は `default` を使う |
| `fake-text/*.json` | Fake text model (`ZJ_MODEL=fake`, default) / 偽テキストモデル（`ZJ_MODEL=fake`、デフォルト） | Each prompt kind (`triage`, `extract`, `check`, `rewrite`, `reply`, `narrate`, `plan`, `ending`, `ending-check`, `safety`) has a schema-passing default output: safety screening (B-12 `safety`) judges none, triage judges "possible", extraction has no candidates, checks all pass, rewrite returns the text unchanged (degraded; it cannot do more), and the reply is the single line 「……そうか。」. The `rules` here override it by prompt kind and condition `when`; the first match wins. Conditions: `character` (who is being spoken to), `playerContains` / `replyContains` (the original words of this turn contain certain characters), `summaryContains` (the candidate's summary), `confirmOpen` (B-4: whether the extraction request has a pending clarifying question awaiting an answer); other keys must equal the same-named value in the request (e.g. `mode`). The B-9 `ending` default deterministically writes, from the request, an ending that passes validation (the epilogue is assembled from the summaries of the last few events that happened as in the original, each sentence citing that event; `variant` is null, and the characters' `claims` are empty arrays); the B-17 `ending-check` (the model check of the ending) defaults to making sense. Rules can also set `output` (the whole output), `broken` (`ending` only: empty references, to test rewrite and template), `fail` (`check` only: `{rule, reason}`, the matching candidate fails this rule and all others pass), `error` (`rate-limit` / `invalid` / `unavailable` / `refusal` (B-12: the model refuses to answer)), `latencyMs` (wait this long first, to test the time limit), `times` (use at most this many times). Specific outputs a scenario needs go here / 各プロンプト種別（`triage`、`extract`、`check`、`rewrite`、`reply`、`narrate`、`plan`、`ending`、`ending-check`、`safety`）にスキーマを通るデフォルト出力がある：安全審査（B-12 `safety`）は none、振り分けは「可能性あり」、抽出は候補なし、チェックは全通過、書き換えは原文のまま（劣化動作で、それ以上はできない）、返答は「……そうか。」の一言。ここの `rules` がプロンプト種別と条件 `when` でそれを上書きし、最初に一致したものが有効。条件：`character`（誰に話すか）、`playerContains` / `replyContains`（このターンの原文に特定の文字を含む）、`summaryContains`（候補の要約）、`confirmOpen`（B-4：抽出リクエストに回答待ちの聞き返しがあるか）。その他のキーはリクエスト内の同名の値と等しい必要がある（例：`mode`）。B-9 の `ending` のデフォルトはリクエストから検証を通る結末を決定的に書く（エピローグは原作どおりに起きた最後の数件のイベントの要約から組み立て、各文がそのイベントを引用する。`variant` は null、人物の `claims` は空配列）。B-17 の `ending-check`（結末のモデルチェック）のデフォルトは筋が通っている。ルールには `output`（出力全体）、`broken`（`ending` のみ：引用を空にして、書き直しとテンプレートをテスト）、`fail`（`check` のみ：`{rule, reason}`、一致した候補はこのルールで不合格、他は全て合格）、`error`（`rate-limit` / `invalid` / `unavailable` / `refusal`（B-12：モデルが回答を拒否））、`latencyMs`（先にこの時間待つ。時間制限のテスト用）、`times`（最大使用回数）も書ける。シナリオが必要とする特定の出力はここに置く |
| `fake-armor/*.json` | Fake Model Armor (B-12, `models/armor.py`) / 偽 Model Armor（B-12、`models/armor.py`） | Defaults to no hits at all. `rules`: `method` (`prompt` player input / `response` character output; if omitted, both match), `contains` (substring), `result` (`pi`, `rai`, `sdp`, `uri`, same as `ArmorResult`), `error: "unavailable"`, `latencyMs`; the first match wins / デフォルトは一切ヒットしない。`rules`：`method`（`prompt` プレイヤー入力 / `response` 人物出力、省略すると両方に一致）、`contains`（部分文字列）、`result`（`pi`、`rai`、`sdp`、`uri`、`ArmorResult` と同じ）、`error: "unavailable"`、`latencyMs`。最初に一致したものが有効 |
| `model-replays/*.jsonl` | Replay (`ZJ_MODEL=replay`) / リプレイ（`ZJ_MODEL=replay`） | The subdirectory `armor/*.jsonl` is for Model Armor (key `armor\|<template config version>\|<method>\|<sha256 of the text>`, `response` is an `ArmorResult`); otherwise each line is one text-model call: `key`, `kind`, `provider`, `model`, `promptVersion`, `request`, `response`, `usage`, `costUsd`, `recordedAt`. `key` = `<model>\|<prompt version>\|<sha256 of the normalized request>`, recomputed on read, and a mismatch is an error. A request not found throws `ReplayMissing` ("replay missing or stale") and does not fall back to the fake model / サブディレクトリ `armor/*.jsonl` は Model Armor 用（キー `armor\|<テンプレート設定のバージョン>\|<メソッド>\|<テキストの sha256>`、`response` は `ArmorResult`）。それ以外は 1 行が 1 回のテキストモデル呼び出し：`key`、`kind`、`provider`、`model`、`promptVersion`、`request`、`response`、`usage`、`costUsd`、`recordedAt`。`key` = `<モデル>\|<プロンプトバージョン>\|<正規化したリクエストの sha256>`、読み込み時に再計算し、一致しなければエラー。見つからないリクエストは `ReplayMissing`（「リプレイが無いか期限切れ」）を投げ、偽モデルにはフォールバックしない |

## After making changes / 変更した後

- After changing prompt text (`models/prompts.py`), the requests the narrator sends to the model, or the `fake-text` output: `b0-minimal.jsonl` becomes stale. Rewrite it (needs a test database, see `services/backend/README.md`):
  プロンプトテキスト（`models/prompts.py`）、ナレーターがモデルに送るリクエスト、または `fake-text` の出力を変えた場合：`b0-minimal.jsonl` が期限切れになる。書き直す（テスト用データベースが必要。`services/backend/README.md` を参照）：

  ```sh
  ZJ_UPDATE_REPLAYS=1 DATABASE_URL=… uv run pytest services/backend/tests/test_eval_api.py -k fixture
  ```

  It runs through the minimal scenario's one turn (the traveler says a line to 老爺 in the plaza) and writes each fake-model call (reply, triage, extraction, check, rewrite) in the replay format. Review the diff during review.
  最小シナリオの 1 ターン（旅人が広場で老爺に一言話しかける）を実行し、偽モデルの各呼び出し（返答、振り分け、抽出、チェック、書き換え）をリプレイ形式で書き出す。レビュー時に差分を見る。

  The ending replay `b9-ending.jsonl` (the `ending` of the slice's two paths and the B-17 `ending-check` call: 「市に残り」 reaches the grand finale at sunset, and メロス's deadline settlement when he is too late; the Mac probe measures these two requests) is rewritten the same way: `… pytest services/backend/tests/test_b9.py -k fixture`. The real-model ending replay waits for the Mac probe (B-9 acceptance item 13).
  結末のリプレイ `b9-ending.jsonl`（スライスの 2 つの経路の `ending` と B-17 の `ending-check` 呼び出し：「市に残り」は日没の大団円に至り、メロスが間に合わない場合は期限の清算。Mac プローブがこの 2 つのリクエストを計測する）も同様に書き直す：`… pytest services/backend/tests/test_b9.py -k fixture`。実モデルの結末リプレイは Mac プローブを待つ（B-9 受け入れ第 13 項）。
- Replays recorded with a real model are recorded in M2 only on zg's Mac (G-7): set `ZJ_RECORD_REPLAYS=<directory>`; the format is the same as above, and `request` contains only synthetic input. Replays of the held-out set do not go in the repo; point `ZJ_REPLAYS` at them to read them.
  実モデルで録画したリプレイは M2 では zg の Mac でのみ録画する（G-7）：`ZJ_RECORD_REPLAYS=<ディレクトリ>` を設定する。形式は上と同じで、`request` には合成入力のみが入る。ホールドアウトセットのリプレイはリポジトリに入れず、`ZJ_REPLAYS` でそこを指して読む。
- Changing the fake model's output also changes the E-0 report: update `evals/tests/snapshots/fake` in the same PR (the command is at the top of `evals/tests/test_cli.py`).
  偽モデルの出力を変えると E-0 のレポートも変わる：同じ PR で `evals/tests/snapshots/fake` を更新する（コマンドは `evals/tests/test_cli.py` の冒頭にある）。
