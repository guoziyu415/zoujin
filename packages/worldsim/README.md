# packages/worldsim

Shared rules library for world state (W-1): initial state, applying effects, beats that come due, time propagation, ending classification. The narrator, evals, and data tools all use only this one set of rules. Owned by Data, reviewed by Backend. Standard library only.

世界状態の共有ルールライブラリ (W-1)：初期状態、effects の適用、期限が来たビート、時間の伝播、エンディング分類。ナレーター、評価、データのツールはすべてこの 1 セットのルールだけを使う。データ担当、バックエンドがレビュー。標準ライブラリのみ。

## Using event-by-event simulation / イベント単位の推演の使い方

```python
from zoujin_worldsim import apply, check_effects, initial_state, role_of, settle

s = initial_state(world, "role.traveler")
drafts, s = settle(world, s, role_of(world, "role.traveler")["startT"])  # beats due before the opening are also written as system events / 開局前に期限が来たビートもシステムイベントとして書く
# Each round: check the candidate event first, apply after committing, then settle to the new clock
# 毎ラウンド：まず候補イベントを検査し、確定後に apply、その後新しい時計まで settle する
problems = check_effects(world, s, event["effects"], event["origin"])
s = apply(world, s, event)
drafts, s = settle(world, s, s["t"])
```

- The state `SimState` is derived only from events and can be stored directly as JSON. The state `settle` returns is the result of applying the drafts in order, so replaying from `initial_state` plus the event log yields the same state (contract 3.1).
  状態 `SimState` はイベントのみから導かれ、そのまま JSON として保存できる。`settle` が返す状態は草稿を順に `apply` した結果なので、`initial_state` とイベントログから再生すると同じ状態になる（契約 3.1）。
- At the same moment: beats first, then deadlines, then events. `settle` to the event's `t` before `apply`ing it, and the next `settle` is no earlier than that `t`.
  同時刻の順序はビート、期限、イベントの順。イベントの `t` まで先に `settle` してから `apply` し、次の `settle` はその `t` より前にならない。
- A draft is `{event, beat, variant, reason, reasonCode}`: `event` is a subset of the contract Event (`actor: "system"`, `origin: "schedule"`, `dt: 0`); B-0 fills in `eventId`, `seq`, `summary`, etc. before writing to the database; a `prevented` draft carries a one-line Japanese reason.
  草稿は `{event, beat, variant, reason, reasonCode}`：`event` は契約 Event の部分集合（`actor: "system"`、`origin: "schedule"`、`dt: 0`）。B-0 が `eventId`、`seq`、`summary` などを補ってからデータベースに書く。`prevented` の草稿には日本語の理由が 1 文付く。
- Each run writes one system event for the deadline (`type: "action"`); when none of the `onDeadline` conditions hold, `effects` is empty: the state uses it to record that the deadline has been settled.
  期限ごとに 1 局につきシステムイベントを 1 つ書く（`type: "action"`）。`onDeadline` がどれも成立しない場合 `effects` は空になる：状態はこれで期限の精算が済んだことを記録する。
- `check_effects` judges by `origin`: events that are not `schedule` (narrator candidate events, director events) must not write `{op: "beat", to: "happened"}`, and it also judges by `StateVar.valueRequires` (contract 1.6).
  `check_effects` は `origin` で判定する：`schedule` でないもの（ナレーターの候補イベント、ディレクターイベント）は `{op: "beat", to: "happened"}` を書いてはならない。また `StateVar.valueRequires`（契約 1.6）でも判定する。

## Opening to the starting point / 開局から起点まで

```python
from zoujin_worldsim import opening, parse_checkpoint

sc_id, until = parse_checkpoint("sc.canon@beat.05")  # or "sc.king-hardened@t=1235"
events, s = opening(world, "role.traveler", scenarios.get(sc_id), until, place=None)
```

- Order: `place` writes one event at clock 0 → the scenario's beat changes are merged into one event at clock 0 → `settle` to the role's `startT` → the scenario's events are `settle`d then written in order of `t` → stop at the starting point. `until=None` simulates to the end (`scenario`).
  順序：`place` が時計 0 でイベントを 1 つ書く → シナリオのビート変更を時計 0 の 1 イベントにまとめる → 身分の `startT` まで `settle` → シナリオのイベントを `t` 順に、先に `settle` してから書く → 起点で停止。`until=None` なら最後まで推演する（`scenario`）。
- Stopping at a beat: stop right after writing the event where that beat happens; later beats at the same moment are left for the next `settle`. If it did not happen in this run (it was prevented), that is an error: the checkpoint is wrong.
  ビートで停止する場合：そのビートが発生するイベントを書いた直後に止まり、同時刻の後続ビートは次の `settle` に回す。この局でそれが発生しなかった（阻止された）なら、チェックポイントの誤りとしてエラーにする。
- Stopping at a moment: beats and deadlines due at that moment count, while scenario events exactly at that moment do not (stop first); if there is no event at that moment, write an event that only advances the clock (empty `effects`).
  ある時刻で停止する場合：その時刻に期限が来たビートと期限は計算に含め、シナリオのイベントがちょうどその時刻にあっても含めない（先に停止する）。その時刻にイベントがない場合は、時計だけを進めるイベント（`effects` が空）を 1 つ書く。
- Each event is a draft plus `source` (`place` / `scenario` / `schedule` / `clock`); those that are not `schedule` also carry a one-line Japanese `note` (if a scenario event wrote its own `note`, that is used); B-0 uses it to write `summary` and marks it in the trace as an eval setup. `event.seq` is consecutive from 1, and B-0 fills in the remaining fields before writing to the database.
  各イベントは草稿に `source`（`place` / `scenario` / `schedule` / `clock`）を加えたもの。`schedule` 以外には日本語の `note` が 1 文付く（シナリオのイベントが自分で `note` を書いていればそれを使う）。B-0 はこれを `summary` に使い、トレースでは評価用の設定として印を付ける。`event.seq` は 1 から連続し、残りのフィールドは B-0 が補ってデータベースに書く。
- `setup.events` (eval setup) is not handled here; B-0 appends it after the starting point per section 7 of api-contract.
  `setup.events`（評価用の設定）はここでは扱わない。B-0 が起点の後に api-contract の第 7 節に従って追加する。

## Narrator rule primitives / ナレーター規則のプリミティブ

```python
from zoujin_worldsim import activity, knows, travel_minutes

knows(world, s, "char.selinuntius", "fact.promise")  # R4: knows only from beat.06 on / R4：beat.06 以降にのみ知っている
knows(world, s, "player", "fact.city-silent")  # player = the role's initialKnowledge + what was learned in this run / プレイヤー = 身分の initialKnowledge + この局で学んだこと
travel_minutes(world, "place.road-to-city", "place.syracuse-square")  # R3: 60; None if unreachable / R3：60。到達不能なら None
activity(world, s, "char.crowd")  # R7, snapshot: "absent" before beat.s1, "idle" after being taken to the execution ground / R7、スナップショット：beat.s1 より前は "absent"、刑場へ連れて行かれた後は "idle"
```

- `knows` follows contract 2.1: facts in `Character.knows` whose `since` has happened (or `pre`), facts learned via `learn` in this run, and the character's own improvised settings; facts with `trueFrom` that did not happen in this run count as known to nobody (2.3). (1.7) Player = the role's `initialKnowledge` + what `learn` writes for `player`: characters telling the player is extracted by the narrator; when a beat happens the player is at the beat's place, and `settle` writes `learn` for `public` facts in that system event.
  `knows` は契約 2.1 に従う：`Character.knows` のうち `since` が発生済み（または `pre`）のもの、この局で `learn` により学んだもの、本人の即興設定。`trueFrom` があってこの局で発生しなかった事実は誰も知らないものとして数える（2.3）。（1.7）プレイヤー = 身分の `initialKnowledge` + `learn` が `player` に書いた学習内容：人物がプレイヤーに伝えたことはナレーターが抽出する。ビートが発生するときプレイヤーはビートの地点にいて、`settle` はそのシステムイベント内で `public` の事実に `learn` を書く。
- `travel_minutes` takes the shortest path by the walking minutes in `places.adjacent`; between two places in the same scene it uses `pacing.sceneWalkMinutes` (0 minutes, S-038). It measures only the player's movement and `relocate` outside schedules; characters moving by schedule follow the schedule (backend-design 2.4). River crossing (`crossing`) and the way home are added in M3: the four places on the way home are in the same scene, so they are currently 0 minutes from each other.
  `travel_minutes` は `places.adjacent` の徒歩分数で最短経路を取り、同一シーン内の 2 地点間は `pacing.sceneWalkMinutes`（0 分、S-038）を使う。測るのはプレイヤーの移動とスケジュール外の `relocate` だけで、スケジュールに従って動く人物はスケジュールを見る（backend-design 2.4）。川渡り（`crossing`）と帰り道の歩き方は M3 で追加する：帰り道の 4 地点は同一シーンなので、現在は互いに 0 分。
- `activity` follows contract 2.4 (1.1): at the opening it is `initialActivity` (omitted = `idle`); after a beat happens it is what the beat's `activities` gives this character, until the next beat that gives him one or a move; if he moved and no new one was given, it is `idle`. Participating characters first move to the beat's place (contract 3.1), and the `relocate` in the beat's `outcomes` follows the outcome actually used in this run (variant, player's prior changes). The state has no event history, so replaying the beats that have happened computes where he should be per the beats; if `locations` differs now, he was moved by an event = `idle`. This is only the part given by the world model; the narrator derives more from the dialogue (backend-design 2.7); R7 does not allow dialogue with `absent` characters (S-077 ⑩).
  `activity` は契約 2.4（1.1）に従う：開局時は `initialActivity`（省略 = `idle`）、ビート発生後はビートの `activities` でこの人物に与えられたもので、次に彼に与えるビートか移動までが有効。移動して新しい指定がなければ `idle`。参加人物はまずビートの地点へ移動し（契約 3.1）、ビート `outcomes` の `relocate` はこの局で実際に使われた結果（バリアント、プレイヤーが事前に変えたもの）に従う。状態にはイベントの履歴がないので、発生済みのビートを再生してビートどおりにいるはずの地点を算出する。現時点の `locations` が異なれば、イベントで動かされた = `idle`。これは世界モデルが与える部分だけで、ナレーターが対話に応じてさらに推論する（backend-design 2.7）。`absent` の人物とは R7 が対話を許さない（S-077 ⑩）。

## Changing the rules / ルールの変更

To change a rule, change `reference/worldsim.py` first, then run `python3 -I packages/worldsim/tests/golden/gen_golden.py` to regenerate the golden files, then change the package until `pytest packages/worldsim` passes again. If something looks like a bug during porting, do not fix it in the port; go back and fix it in the reference implementation (the last item under "Not doing" on the W-1 card).

ルールを変更するときは、先に `reference/worldsim.py` を変更し、`python3 -I packages/worldsim/tests/golden/gen_golden.py` を実行してゴールデンファイルを再生成し、そのあとパッケージを変更して `pytest packages/worldsim` が再びすべて通るようにする。移植中にバグらしきものを見つけても移植側では直さず、参考実装に戻って直す（W-1 カードの「やらないこと」の最後の項目）。
