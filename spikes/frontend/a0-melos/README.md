状态：**梅洛斯第四版（UX 第 4 轮评审后：衣服穿模、褶子、包袱、颜色、冲刺）做好，测试页第 9 版，等 UX 第 5 轮评审**（MPFB 2 在 zg 的 Mac 上建，容器里改衣服、减面、压缩、打包；动作是 Quaternius 的 CC0 动作捕捉）。2026-10-10，前端。
卡：`docs/tasks/m2-0/A-0.md`。验收标准（UX）：`docs/tasks/m2-0/A-0-acceptance.md`。依据：`docs/ux/art-direction.md` 5.1〜5.6、9.1〜9.6；`docs/frontend/frontend-design.md` 10.6.2、10.6.4。

## 一句话

用替身把「建模 → 减面出三个版本 → 绑骨 → 动作 → 表情口型 → 导出压缩 → 手机测试页」整条路走通了。
三个版本和动作的下载都在预算内，对话版 draw call 正好 10；只让头带表情以后，表情占的显存降到原来的三分之一。
真梅洛斯要在 zg 的 Mac 上建（容器下不了 MPFB 和 CC0 素材），建好后用同一套脚本一次跑完。

**替身不是梅洛斯。** 它用 npm 上一份 2016 年的 MakeHuman 数据拼成（`makehuman-data@0.0.2`，同一套 hm08 人体拓扑；文件头 AGPL，衣服 CC BY），只用来量体积和帧时间，不进产品。

### 口型

- 声音：S-1 casting 时录下的 Gemini Live **Fenrir**。zg 10-10 定梅洛斯用 Fenrir（D-025），测试页第 4 版去掉了「仮の声」和 Puck（`pack.py` 只打包 Fenrir；`gen_lines.py` 仍会生成两个声音，Puck 留作对照）。`build/gen_lines.py` 按 UX 定的剪法（10-10）做三句：相槌「いや」（Fenrir 剪 own2 的 0.02〜0.48 秒，Puck 到 0.30 秒，10ms 淡出）；约 3 秒 own2「いや、まだ陽は沈まぬ。」；长句全用梅洛斯自己的台词：own2 + 停 0.7 秒 + own3 + 停 0.7 秒 + own1，约 10.7 秒，句子里本来的停顿正好用来看嘴会不会合上。MP3 64kbps（开源 Chromium 解不了 AAC），两个声音六句共约 0.22 MB，只在这一页用。Puck 的 own3 在 casting 表里标了「读走样」，UX 量过录音没被切掉，多半是转写没跟上。
- **默认「只用音量」**（UX 验收 3.4、frontend-design 7.3 的第一版做法）：A-0 要回答的是，在约 2 厘米高的脸上只开合会不会像木偶。
- 「元音 + 音量」只做对比：每 10ms 算 MFCC（26 个 mel 带、12 维），和五个元音模板比，得到あいうえお的权重；模板和实时特征都减去平均（倒谱均值归一化），类似 Unity 的 uLipSync。模板来自 Open JTalk 合成的元音（另一个声音），对 Fenrir / Puck 不太准。离线对 Open JTalk 自己的台词测，元音大约对一半多（`build/lipcheck.py`）。如果 zg 觉得元音版明显更像，再改 frontend-design 的口型设计（每个 Gemini 声音离线做一份模板），M2 的事。
- **对时**：每句台词加载时先离线分析好（每 10ms 一帧：响度、元音权重）。每帧按「耳朵现在听到的位置」查表：播放位置 − 浏览器报告的输出延迟，再提前 60ms 抵消平滑和一帧显示。照这样算，嘴和声音的时差理论上接近 0；手调滑杆（−150〜+250ms）给蓝牙耳机用，浏览器报的蓝牙延迟常常不准。UX 的线是嘴比声音晚 ≤ 约 90ms。产品里播放的 Worklet 知道同样的播放位置，做法能直接搬。

## 流水线里新加的三步（Mac 上跑真梅洛斯时也要）

1. **材质合并**（`lod_export.py` 的 `merge_parts`）：头发、眉、睫毛的颜色图拼成一张 1024 图（色调直接烘进像素），牙和舌拼成一张 1024×512。8 个材质 → 5 个。
2. **法线贴图检查**（`compress.mjs`）：UV 岛外面的黑底填成平的法线；整张图平均偏离正前方超过 10° 就自动校正并在报告里记 `leanDeg`。替身衣服的法线图歪了 34°，让布料每个三角形都看得出棱角，校正后正常。导出也带上切线（没有法线图的网格由 gltf-transform 去掉）。
3. **减面保表情**（`decimate_keep_keys`）：先减面，再用 Surface Deform 绑回原网格逐个算形变，把小于 0.1mm 的噪声清零，导出器才能只存脸部顶点。

3. 建梅洛斯（20 多岁、瘦长有肌肉、晒黑的牧人；exomis 露一侧肩，皮凉鞋，赭和未染羊毛色，短发），改名成脚本用的对象名（Body / Eyes / Brows / Lashes / Teeth / Tongue / Hair / Tunic / EyesLow / Rig），存 .blend。
4. 把 .blend 和动作文件传回容器：`assets/pipeline/lod_export.py` → `assets/pipeline/compress.mjs` → `build/pack.py` → 更新测试页。
5. 做法 PM 定了 (b)：前端线程里开 Remote Control（zg 10-10 已允许），Mac 上的会话只在新建的 `~/Developer/zoujin-art/` 里装 MPFB、下素材、开 Blender；建模由前端线程通过设备连接操作 Mac 上的 Blender MCP。不碰 `~/Developer/zoujin-spike`、gcloud 和凭证；装和下载之前先给 zg 看清单和命令。

## 文件

- `assets/pipeline/`（真梅洛斯和以后的人物都用，不在这个目录）：`lod_export.py`（三个版本＋切头＋导出）、`compress.mjs`（KTX2＋meshopt＋法线检查）、`inspect.mjs`、`morphmem.mjs`。
- `build/`：`mhload.py`（读 MakeHuman 数据）、`build_standin.py`（搭替身）、`anims.py`（占位动作：待机、走、跑）、`retarget.py`（把 UAL 的动作重定向到 MPFB 骨架，再改跑和冲刺的步幅）、`melos_clothes_v2.py` / `melos_clothes_v3.py` / `melos_clothes_v4.py` / `melos_clothes_v5.py` / `melos_clothes_v6.py`（衣服、包袱、带子、绳子；v4 是第 4 轮的穿模、腰、布边、肩上的结，v5 是第 5 轮的腰和包袱的结，v6 是第 6 轮的腋下和腰绳）、`melos_prep.py`、`melos_tex.py`、`preview.py`（Cycles 预览）、`gen_voice.py`（元音模板用的测试声音）、`gen_lines.py`（从 casting 录音剪三句台词）、`lipcheck.py`（离线口型检查）、`pack.py`（打包测试页）、`test_page.mjs`（无头浏览器自测）。
- `page/index.src.html`：测试页源文件（`/*MANIFEST*/` 由 pack.py 填）。
- 减面和压缩报告、声音元数据（`reports/`）和截图（`shots/`）只在项目文件夹 `frontend/spikes/a0-melos/` 里，替身的生成物不进仓库。
