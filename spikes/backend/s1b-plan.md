## 1. zg 的决定（D-017）

iPhone 4G 实测要一个手机能打开的 HTTPS 地址。zg 选了 **A：在走进物语的 GCP 项目里临时开一个 Cloud Run 服务，测完当天删掉**。理由：路径和正式上线一样（手机 → 东京 → 美国的 Live），S-017 的验收数字（中位数 ≤ 1.8 秒、p95 ≤ 3 秒）能直接用。没选的：B 从 Mac 开隧道（数字含家里网络，不能验收）；C 不测手机。

## 2. 为什么非要公网地址

- iPhone 上的网页只有在 HTTPS 下才能用麦克风；`localhost` 只在 Mac 自己的浏览器里算安全。
- 要测的是 4G（关掉 Wi-Fi），手机必须从外网连进来。
- LINE 内置浏览器能不能用麦克风、WebSocket 握手带不带 Cookie，只能在真实地址上测（前端第 2、7 节）。

## 4. 第二段怎么做（选项 A）

**会创建的东西（测完全部删除）：**

| 东西 | 设置 |
|---|---|
| 1 个 Cloud Run 服务，名字随机（`s-` 加 8 位，部署时在 Mac 上生成，记在 `~/.zoujin-spike/s1b-service`） | asia-northeast1；最多 1 个实例，最多 4 个连接；最少 0 个（不用时不花钱）；请求超时 60 分钟；不连数据库、不挂存储；不用流量标签 |
| 1 个镜像仓库 `spike-images`（Artifact Registry） | 在 Mac 上用 Docker 构建（`linux/amd64`），推到这里；不用 Cloud Build |
| 1 个服务账号 `s1b-proxy` | **只给** `roles/aiplatform.user`（调 Gemini Live）；不用默认的 Compute 服务账号（它带编辑者权限）。这是对 G-7「验证阶段不建服务账号」的一处改动，因为云端服务必须有一个身份。v0.7 起，zg 自己的账号在这个服务账号上多一个「服务账号令牌创建者」角色，只用于部署前的 `sacheck`（以它的身份在 Mac 上连一次 Live，不建密钥）；这个角色挂在服务账号上，`down` 删服务账号时一起消失 |

**要多开的 API（4 个）：** Cloud Run、Artifact Registry、IAM，以及 v0.7 新加的 IAM Service Account Credentials（`sacheck` 借服务账号身份要经过它；不开的话，这个请求会记到 zg 登录文件里写的日々の森项目上）。都不收费。

**服务里跑什么：**
- 后端的语音代理：api-contract 第 3 节的一个子集（`hello` / `welcome`、`focus` / `session_ready`、`activity_start` / `activity_end`、上下行音频帧、`transcript`、`interrupted`、`turn_complete` 带 `serverReleaseToFirstAudioMs`）。用这个子集，是为了让前端测试页的代码以后能直接留进产品。
- 前端的 S2 测试页，和代理同源（和正式上线一样）。
- 一个人物（メロス，S-1 `casting` 选出的声音），固定的短人设；没有叙事者、没有世界状态。不支持作废一轮（要叙事者）。

**D-017 的三个条件怎么落实：**
1. **网址随机、猜不出来**：Cloud Run 的网址由服务名和项目编号组成，服务名每次部署随机生成；不用流量标签（第一次部署本来就不能用 0% 流量，改用「先私有」，见下面的上线顺序）。
2. **网址、页面、响应头、报错文字里没有产品名和 zg 的名字**：服务名随机；Cookie 名是 `sid`；不发 `Server` 响应头；占位页面只有「準備中です。」；所有报错是通用的日语短句。离线自检逐项检查过页面、响应头、Cookie 和 WebSocket 报错里没有「走进物语」「zoujin」。前端测试页的标题和文字也按这条写（已告诉前端）。镜像仓库、服务账号、本机目录不出现在网址里，前两个也换成了中性的名字。
3. **一次性测试码**：见下面的访问保护。

**访问保护：**
- **一次性测试码**（12 位，约 59 位随机）：在 Mac 上生成，写进 `~/.zoujin-spike/s1b-code`（只有 zg 能读），屏幕上不显示；服务里只存加盐哈希。iPhone 第一次打开时输入，换成 `HttpOnly; Secure; SameSite=Lax` 的 Cookie（12 小时）。同一地址错 5 次锁 10 分钟，全部累计错 100 次停止登录。
- 没有 Cookie：页面以外的接口一律 401，WebSocket 连上后立即以 `4001` 关闭（和 api-contract 第 4 节一致），什么都收不到。`Origin` 不对：登录和 WebSocket 握手都被拒（403）。
- 公开后 Cloud Run 层面允许匿名访问（手机浏览器没法带 Google 的身份），所以保护靠上面这两条，和正式版的邀请码 + Cookie 是同一套做法。
- **用量上限**：服务内累计花费到 3 美元就停掉声音（推 `degraded`）；每个连接最长 30 分钟；第一个配额错误（429）就停掉声音。
- 不保存声音和文字。服务日志只写计时、大小和花费，不写字幕内容（离线自检检查过）。地址只写在 `~/.zoujin-spike/s1b-url`，脚本不打印。

**上线顺序（zg 的规范）：**
Cloud Run 新建服务时第一个版本不能设 0% 流量，所以「0% 流量」用「私有」代替：第一次部署成只有 zg 的 Google 身份能访问的私有服务，效果等于不对公众开放。脚本 `s1b_deploy.sh`，每步单独执行：

1. `prepare`：开 4 个 API，建镜像仓库和服务账号。`sacheck`：在 Mac 上以服务账号的身份连一次 Live（不说话、不花钱），每 20 秒试一次，最多 7 分钟，连上才能 `up`。`build`：在 Mac 上构建镜像，先在本机断网、以服务实际用的非 root 用户跑一次检查（能读全部代码和页面，`/health` 和页面都是 200），通过才推送（docker 登录用 1 小时的临时令牌，推完就登出，不改 docker 的永久设置）。
2. `up`：部署成私有服务 → 确认没有 Google 身份的访问被拒 → 带 zg 的身份冒烟：没有 Cookie 时 REST 401、WebSocket 4001，错的测试码 401，别的网站发起的登录和 WebSocket 403，正确的测试码能登录，两句话都有声音回答。
3. `open`：打开公开访问 → 再查一次匿名访问被拒。
4. zg 用 iPhone 测（第 5 节）。
5. `logs`：把计时字段拉回 `out/s1b/`（只留时间戳和计时字段，不含项目 ID 和地址）。
6. `down`：**当天删除**服务、镜像仓库、服务账号，确认原地址返回 404，删掉本地的测试码和地址文件。开着的 4 个 API 不花钱，留着。

**地址怎么到 iPhone 上：** 用 AirDrop 或「通用剪贴板」从 Mac 发到 iPhone。地址和测试码不贴进聊天、不写进文档。

**费用（推算）：** Live 约 40〜60 轮，0.5〜1 美元；Cloud Run 和镜像存储加起来不到 0.1 美元。计入验证阶段 20 美元的上限；服务内的 3 美元上限是第二道保险。

**时间：** Mac 上准备和冒烟约 30 分钟（Mac 上的 Claude 做），zg 用 iPhone 测约 40 分钟。

## 5. iPhone 上测什么

| # | 测什么 | 怎么测 | 通过标准 | 谁看结果 |
|---|---|---|---|---|
| 1 | 松手到出声（4G） | 关 Wi-Fi，Safari，和メロス说 20 句（外放 10、AirPods 10） | 端到端中位数 ≤ 1.8 s、p95 ≤ 3 s（S-017）；前端三段：采集到第一包上行 ≤ 60 ms，第一个下行包到出声 ≤ 150 ms | 后端、前端 |
| 2 | 打断 | 人物说话时按下说话，10 次 | 打断到停播 ≤ 200 ms（S-014） | 前端 |
| 3 | AirPods：麦克风常开 vs 每轮开关 | 页面上的开关切两种做法，各 5 轮；记切换时第一包上行的延迟和主观音质 | 给 F-3 定方案的数据 | 前端、UX |
| 4 | 静音键开着能不能出声 | 拨到静音再说 2 轮 | 能听到 | 前端 |
| 5 | 小声说话（睡前的音量） | 页面上的「小声模式」：手机麦克风 5 句、耳机麦克风 5 句，固定句子在 `zj_spike/data/s1b_lines.json`（取自 S-1a，带专有名词） | 字错率记下来，和 S-1a 的正常音量比较 | 后端、市场调研 |
| 6 | LINE 内置浏览器 | 在 LINE 里打开同一个地址 | 记下：能不能拿麦克风；握手带没带 Cookie（收到 `welcome`，里面 `cookieSeen: true` = 带了；连上后被 `4001` 关闭 = 没带） | 前端 |
| 7 | 切后台 1 分钟再回来 | 对话中切到别的 App | 一次点击能恢复声音（S-024、前端 S6 的语音部分） | 前端 |
| 8 | Wi-Fi 对照 | 开 Wi-Fi 再说 5 句 | 和第 1 项比较 | 后端 |

**没有 AirPods 时**（10-07，zg 用别的耳机）：表里的「AirPods」都换成 zg 手边的耳机，结果里把「AirPods」换成实际型号，并写明是蓝牙还是有线（只写在 Mac 的结果记录里，不进测试页和日志）。蓝牙耳机：第 1、3、5 项照原计划；iOS 开麦时蓝牙要切到通话模式，这和 AirPods 是同一个机制，第 3 项的数据对 F-3 仍然有用，只是机型不同、延迟会有差别。有线耳机：没有这种切换，第 3 项可以跳过或照常跑当对照，第 1、5 项照做。第 3 项本来就没有通过线，只记数据，出现断流或回声也记下（前端）。第 1 项的耳机组若因为蓝牙的输出延迟超过 1.8 秒而外放组通过，两组分开报，不重测。

测试页（前端，`frontend/spikes/s2-voice/`）自己计时，结果显示在页面上，也通过 `POST /v1/telemetry` 写进服务日志（只收数字和固定的英文短词，例如 `{turnId, item:"t5", mode:"quiet-phone", clientReleaseToAudibleMs, cerPct}`）；第 1、2、8 项的服务端数字同时写进日志。测完 `s1b_deploy.sh logs` 一次拉回。

## 6. 选项 B（Mac 隧道）如果选它

在 Mac 上跑同一个代理和测试页，用一个临时隧道给它一个公网 HTTPS 地址；测试码、Cookie、用量上限都一样。不需要开 GCP 的新 API、不建服务账号。缺点：数字包含家里的上行网络，不能用来验收 S-017；Mac 必须一直开着不睡眠；隧道的服务方也是第三方。测完关掉隧道，原地址失效。

## 修订记录

- v0.7（2026-10-07）：第三次部署时冒烟测试停在「会话就绪」：云上的服务账号建 Live 会话被拒（Live 关闭了连接，google-genai 报 APIError），原文没有记下来。最可能的原因是服务账号刚授权、权限还没生效（同一个包用 zg 的身份能连通），但无法确认。改成：代理把上游错误的关闭码、状态和原文写进服务日志，写之前去掉项目 ID、项目编号、网址和账号；发给手机的只多一个固定的分类词；`up` 的冒烟测试没过时，脚本把这几行日志显示出来；新增 `sacheck`，部署前在 Mac 上以服务账号身份连一次 Live，连上才允许 `up`。为此 `prepare` 多开一个 API，并给 zg 在服务账号上加令牌创建者角色。
- v0.6（2026-10-07）：第二次部署服务正常、确实是私有的（匿名访问 `/` 是 403），但 `up` 用 `/healthz` 查匿名访问被拒，Cloud Run 保留以 z 结尾的路径，在前端就回 404，所以检查永远不过，脚本按规则停下并 down。改成：健康检查路径改为 `/health`；`up` 查 `/` 应为 401/403，`down` 查 `/` 应为 404；离线测试加一条：代理的路由和脚本探测的路径都不以 z 结尾、不以 `/_ah/` 开头。又把 up、open、down 整条对照 Cloud Run 前端的行为过了一遍，补了三处可能误判的地方：① 新服务、公开设置、删除服务在 Google 前端生效都有延迟，所以 up、open、down 的网址检查都改成每 10 秒问一次（up 最多 80 秒，等到 401/403；出现 200 立即停，说明不是私有的；open 最多 3 分钟，等到匿名打开页面 200，再查没有测试码什么都做不了；down 最多 2 分钟，等到 404）；② 新建的服务账号调用 Gemini 的权限可能要几分钟才生效，up 的冒烟测试如果只有声音那几项没过、访问保护全过，等 2 分钟整套再跑一次，只重跑这一次；③ `http_code` 连不上时会输出「000000」，改成「000」。
