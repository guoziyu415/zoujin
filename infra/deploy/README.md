# Deployment (B-23) / デプロイ（B-23）

The first-version cloud environment: only for invited people aged 18 and over. Runs only on zg's Mac, with the project being the one in the gcloud `zoujin` configuration (the script switches to that configuration itself and stops if it points at another project). The repo contains no project ID, addresses, passwords, or invite codes.

第一版のクラウド環境：招待された 18 歳以上の人だけが遊べる。zg の Mac でのみ実行し、プロジェクトは gcloud の `zoujin` 構成にあるもの（スクリプトが自分でこの構成に切り替え、別のプロジェクトを指していれば停止する）。リポジトリにはプロジェクト ID、アドレス、パスワード、招待コードを含めない。

## Step 27: one command / 第 27 ステップ：1 コマンド

```sh
cd ~/Developer/zoujin && git pull && infra/deploy/deploy.sh all
```

`all` = `setup` → `build` → `migrate` → `up` → `promote`. If a step stops, fix it and rerun `all` or that step; finished work is skipped (existing instances, secrets, and accounts are not recreated). The first run takes about 30 minutes, mostly creating the database instance (about 10 minutes) and building images. When it finishes:

`all` = `setup` → `build` → `migrate` → `up` → `promote`。どこかのステップで止まったら、直してから `all` かそのステップを再実行する。済んだものはスキップされる（既存のインスタンス、シークレット、アカウントは作り直さない）。初回は約 30 分で、大部分はデータベースインスタンスの作成（約 10 分）とイメージのビルド。完了後：

```sh
open "$(cat ~/.zoujin/deploy/url)"      # open the production address / 本番のアドレスを開く
infra/deploy/deploy.sh invite 5         # 5 invite codes, written to ~/.zoujin/deploy/invites-*.txt, one per person / 招待コード 5 個を ~/.zoujin/deploy/invites-*.txt に書き出す（1 人 1 個）
```

Prerequisites before running (ignore those the Mac already has):

実行前に必要なもの（Mac にすでにあるものは気にしなくてよい）：

- The gcloud `zoujin` configuration and zg's application default credentials (`~/.config/gcloud/application_default_credentials.json`);
  gcloud の `zoujin` 構成と zg のアプリケーションデフォルト認証情報（`~/.config/gcloud/application_default_credentials.json`）。
- Docker running (image builds and the Cloud SQL proxy both run in Docker);
  Docker が起動していること（イメージのビルドも Cloud SQL プロキシも Docker 内で動く）。
- `zoujin-claude` in the keychain (stored into Secret Manager on the first setup);
  キーチェーンの `zoujin-claude`（初回の setup で Secret Manager に保存される）。
- The model IDs for the two Claude tiers: `ZJ_CLAUDE_HAIKU` and `ZJ_CLAUDE_SONNET` exported in the terminal, or written into `~/.zoujin/deploy/config.env` (exporting once records them automatically);
  Claude 2 ティアのモデル ID：ターミナルで export した `ZJ_CLAUDE_HAIKU` と `ZJ_CLAUDE_SONNET`、または `~/.zoujin/deploy/config.env` に書いたもの（一度 export すれば自動的に記録される）。
- The scene packs and character models: `assets/scenes/<directory>/build/` and `assets/cast/build/` previously generated by the frontend pipeline in this repo (not in git, S-075). `build` first compares them using `packs.py` against the manifest in the commit being deployed; missing and stale ones (not generated by this commit's pipeline: compare inputs where they exist, otherwise compare structure; character files by sha256; texture and baked bytes differ slightly across machines and do not count as stale) are listed along with the pipeline commands to run, and it stops; if only "stale" ones remain and you are sure to deploy as is, add `ZJ_ALLOW_STALE=1`.
  シーンパックとキャラクターモデル：このリポジトリのフロントエンドのパイプラインで生成済みの `assets/scenes/<ディレクトリ>/build/` と `assets/cast/build/`（git には入れない、S-075）。`build` はまず `packs.py` で、今回デプロイするコミットのマニフェストと比べる。欠けているものと古いもの（このコミットのパイプラインで生成されていないもの：inputs があれば inputs を比べ、なければ構造を比べる。キャラクターファイルは sha256 で比べる。テクスチャとベイクのバイト列はマシンが変わると少し異なるが、古いとは数えない）を、実行すべきパイプラインコマンドとともに一覧し、停止する。「古い」だけが残り、そのままデプロイすると確定している場合は `ZJ_ALLOW_STALE=1` を付ける。

モデルは開発期（D-028）に従う：Claude は `zj-claude` を使い、Gemini Live、文字起こしの補完、Model Armor（テンプレート `zoujin-safety-v1`）はサービスアカウントを使う。各インスタンスの台帳は `/tmp` にあり、上限は `config.env` の `ZJ_MAX_CLAUDE_USD`、`ZJ_MAX_GOOGLE_USD`（既定はそれぞれ 10 米ドル、インスタンスの再起動でゼロに戻る。合計額はプロジェクトの予算アラート G-2 に頼る）。

## Release flow (zg's rules) / リリースフロー（zg のルール）

1. `up`: new versions of the narrator and gateway go live with `--no-traffic --tag next` (the first time there is no old version: it is created as a private service, accessible only by zg's identity); run `smoke.py smoke` against the candidate address: home page, smoke account login, manifest, scene packs, start a session (the narrator writes the opening, which also verifies the gateway's identity when calling the narrator), WebSocket handshake with cookie, delete the session, then check that anonymous access is rejected.
   `up`：ナレーターとゲートウェイの新バージョンを `--no-traffic --tag next` で公開する（初回は旧バージョンがないので、非公開サービスとして作成し、zg の ID だけがアクセスできる）。候補アドレスに対して `smoke.py smoke` を実行：トップページ、スモーク用アカウントのログイン、manifest、シーンパック、1 局の開始（ナレーターが開局を書く。ゲートウェイがナレーターを呼ぶときの ID の検証も兼ねる）、Cookie 付きの WebSocket ハンドシェイク、その局の削除、そのうえで匿名が拒否されることを確認する。
2. `promote`: switch both services to the new version, keeping the existing private IAM setting; smoke the production address once more, checking that pages, assets, REST, and WebSocket without the site password are all rejected. The script never opens public access on its own.
   `promote`：両サービスを新バージョンに切り替え、既存の非公開 IAM 設定を維持する。本番アドレスでもう一度スモークを行い、サイトパスワードなしのページ、アセット、REST、WebSocket がすべて拒否されることを確認する。スクリプトが自動で公開アクセスを開くことはない。
3. If the production smoke fails: `deploy.sh rollback` switches back to the previous version.
   本番のスモークが通らない場合：`deploy.sh rollback` で前のバージョンに戻す。

The invite code used for smoke is in `~/.zoujin/deploy/smoke-code`, a dedicated account that can start at most 5 sessions per day (S-019, deleted ones also count); each `migrate` swaps in a new one, so reruns do not hit the limit. `build` skips if the same commit has already been built; add `ZJ_REBUILD=1` if the scene packs were replaced and need rebuilding.

スモークに使う招待コードは `~/.zoujin/deploy/smoke-code` にある専用アカウントで、1 日に最大 5 局まで開始できる（S-019、削除した局も数える）。`migrate` のたびに新しいものに替えるので、再実行しても回数制限に当たらない。`build` は同じコミットがすでにビルド済みならスキップする。シーンパックを入れ替えて再ビルドが必要なときは `ZJ_REBUILD=1` を付ける。

## Differences from the design / 設計と異なる点

- **gcloud scripts, not Terraform**: Terraform is not installed on the Mac, the first version has few resources, and the scripts are written to "skip if it already exists".
  **Terraform ではなく gcloud スクリプト**：Mac に Terraform が入っておらず、第一版はリソースが少ないので、スクリプトは「すでにあればスキップ」として書いてある。
- **The narrator's ingress is all, not internal**: internal ingress would require the gateway to use VPC egress, and reaching Anthropic would also need Cloud NAT, which the first version does not add; what blocks anonymous callers is Cloud Run's IAM (which accepts only the gateway service account's OIDC token).
  **ナレーターの ingress は internal ではなく all**：internal にするとゲートウェイが VPC egress を使う必要があり、Anthropic に接続するには Cloud NAT も必要になるが、第一版では追加しない。匿名を防ぐのは Cloud Run の IAM（ゲートウェイのサービスアカウントの OIDC トークンだけを受け付ける）。
- **Database accounts use passwords, not IAM login**: the code only reads `DATABASE_URL`; passwords are randomly generated and exist only in Secret Manager. The two application accounts have the same privileges; narrowing them per table (backend-design 2.1) first requires sorting out where the gateway writes the narrator's tables in the code, which is left to Backend.
  **データベースアカウントは IAM ログインではなくパスワードを使う**：コードは `DATABASE_URL` だけを読む。パスワードはランダム生成され、Secret Manager にのみ存在する。2 つのアプリケーションアカウントの権限は同じで、テーブル単位への絞り込み（backend-design 2.1）には、コード内でゲートウェイがナレーターのテーブルに書き込む箇所を整理する必要があり、バックエンドに任せる。
- **No Cloud Tasks or Cloud Scheduler**: the code does not use them yet; to be added when endings and retention-period deletion are wired in.
  **Cloud Tasks も Cloud Scheduler もない**：コードがまだ使っていない。エンディングと保持期間経過後の削除をつなぐときに追加する。

### H-1 private site gate / H-1 非公開サイトのゲート

The site password secret is named `zj-site-password` and is granted read access only to the gateway service account. When the secret is absent, `setup` generates a random value and writes it through standard input without printing the password; `up` stops if the secret is missing. The gateway reads it through a `ZJ_SITE_PASSWORD` Secret reference, and the smoke test receives it through the `ZJ_SMOKE_PASSWORD` environment, never on the command line or in logs; after passing the gate an invite code is still required.

サイトパスワードのシークレット名は `zj-site-password` で、ゲートウェイのサービスアカウントにのみ読み取りを許可する。`setup` はシークレットがなければランダムな値を生成して標準入力経由で書き込み、パスワードは表示しない。`up` はシークレットがなければ停止する。ゲートウェイは `ZJ_SITE_PASSWORD` のシークレット参照から読み取り、スモークは環境変数 `ZJ_SMOKE_PASSWORD` で渡し、コマンドラインやログには出さない。ゲートを通過した後も招待コードが必要。

In production, a missing password makes all content return 503; `/health` returns only an empty 204. The old `/healthz` still works for local use, but Cloud Run reserves some paths ending in `z`, so the cloud smoke test must use `/health` ([official known issue](https://docs.cloud.google.com/run/docs/known-issues#reserved_url_paths)). The smoke test first verifies that anonymous pages, scripts, characters, scenes, audio, and the API are all blocked by the password, then verifies a full session with password plus invite code. Rotating the password immediately invalidates old signed tickets. All site content is `private, no-store`.

本番ではパスワードがないとすべてのコンテンツが 503 を返し、`/health` は空の 204 だけを返す。旧 `/healthz` はローカル利用向けに互換性があるが、Cloud Run は `z` で終わる一部のパスを予約しているので、クラウドのスモークでは `/health` を使わなければならない（[公式の既知の問題](https://docs.cloud.google.com/run/docs/known-issues#reserved_url_paths)）。スモークはまず、匿名でのページ、スクリプト、キャラクター、シーン、音声、API がすべてパスワードで遮断されることを確認し、次にパスワードと招待コードによる完全なセッションを確認する。パスワードをローテーションすると古い署名付きチケットはただちに無効になる。サイトのコンテンツはすべて `private, no-store`。

Local changes or passing tests do not mean the production site is already locked behind encryption. Deployment must again receive the user's explicit approval; when going live, disable/revoke the old Service Worker, clear existing public caches, and check old versions and tagged candidate URLs. Offline files already saved in browsers cannot be withdrawn by a new version. Any extra static server/CDN in any future environment must also have the same gate and must not serve scene packs publicly.

ローカルでの変更やテストの通過は、本番がすでに暗号化されて閉じられていることを意味しない。デプロイにはもう一度ユーザーの明示的な承認が必要。公開時には古い Service Worker を無効化/撤回し、既存の公開キャッシュを消去し、旧バージョンとタグ付き候補 URL を確認する。ブラウザにすでに保存されたオフラインファイルは、新バージョンから取り消せない。今後どの環境でも、追加の静的サーバー/CDN には同じゲートが必要で、シーンパックを直接公開してはならない。

`promote` now only switches traffic: it does not modify IAM and does not automatically add `allUsers`, and newly created gateways are private by default. Every `up` / `promote` / `verify` reads the actual IAM to decide whether the smoke test carries an identity token, and does not treat a historical `OPENED` marker as the current public state or as public authorization. If `privacy-lock.json` exists in the deployment state directory and IAM is still public, the script stops immediately; this script never deletes that lock. Restoring anonymous entry requires separate explicit user approval and must be done separately, after both the password gate and anonymous resource rejection have been verified. Before rolling back to an old version without the password gate, Cloud Run IAM must be kept private.

`promote` は現在トラフィックを切り替えるだけで、IAM を変更せず、自動で `allUsers` を追加することもなく、新規作成されたゲートウェイは既定で非公開になる。`up` / `promote` / `verify` のたびに実際の IAM を読み、スモークが ID トークンを付けるかどうかを決める。過去の `OPENED` マーカーを現在の公開状態や公開の承認とはみなさない。デプロイ状態ディレクトリに `privacy-lock.json` があり IAM がまだ公開なら、ただちに停止する。このスクリプトがそのロックを削除することはない。匿名の入口を復元するにはユーザーの別途明示的な承認が必要で、パスワードゲートと匿名リソースの拒否の両方を確認したあとに別途実行する。パスワードゲートのない旧バージョンにロールバックする前に、Cloud Run の IAM を非公開に保たなければならない。

The access state must be queried successfully: a failure in the service list, IAM policy, or identity token query stops the script and must not be treated as private. Only a successful, empty service list means the service does not exist yet, and that is allowed only before the first `up`. Besides `allUsers` / `allAuthenticatedUsers`, the flag that disables invoker IAM is also checked; if either is present it counts as public. The anonymous gate in `promote` is retried up to six times and must explicitly pass once before continuing to the full smoke and writing `DEPLOYED`; on failure it stops and keeps the privacy lock.

アクセス状態は必ず取得に成功しなければならない：サービス一覧、IAM ポリシー、ID トークンの問い合わせのいずれかが失敗したら停止し、失敗を非公開とみなしてはならない。サービス一覧の取得に成功して空だった場合のみサービスがまだ存在しないことを意味し、それは最初の `up` の前だけ許される。`allUsers` / `allAuthenticatedUsers` のほかに、invoker IAM を無効にするフラグも確認し、どちらかがあれば公開とみなす。`promote` の匿名ゲートは最大 6 回リトライし、明示的に 1 回通過してはじめて完全なスモークと `DEPLOYED` の書き込みに進める。失敗した場合は停止し、プライバシーロックを維持する。

### Authorized external review entry (2026-10-13) / 承認済みの外部レビュー用入口（2026-10-13）

After the user explicitly asked for a password-protected external review entry to be prepared, only the gateway allows HTTPS requests to reach the application, and the narrator stays IAM-private. Site content continues to be blocked by the site password, and progress and the API additionally require an invite code; reviewers need no Google login or email. Before opening, all traffic tags on the gateway are cleared, so historical version addresses do not inherit service-level permissions.

ユーザーがパスワード付きの外部レビュー用入口を準備するよう明示的に求めたので、HTTPS リクエストがアプリケーションに到達できるのはゲートウェイだけとし、ナレーターは IAM 非公開のままにする。サイトのコンテンツは引き続きサイトパスワードで遮断され、進捗と API にはさらに招待コードが必要。レビュアーに Google ログインやメール受信は不要。公開前にゲートウェイのすべてのトラフィックタグを消去し、過去のバージョンのアドレスがサービスレベルの権限を引き継がないようにする。

The local `reviewer-access.json` records the user's authorization and the gateway, image, version, password secret reference, and traffic that have been verified with the password; it does not contain the password. The privacy lock remains, and this exception is allowed only when that version holds 100% of traffic, has no temporary tags, and the password secret reference exists. The exception is not bound to the secret's specific value or version. `verify` can check the external password gate; `up`, `promote`, and `rollback` all require IAM to be restored to private before changing versions or creating candidate addresses, to prevent unverified candidates or old versions without a password from being exposed.

ローカルの `reviewer-access.json` には、ユーザーの承認と、パスワードで検証済みのゲートウェイ、イメージ、バージョン、パスワードのシークレット参照、トラフィックが記録される。パスワード自体は含まない。プライバシーロックは残り、このバージョンがトラフィックの 100% を占め、一時タグがなく、パスワードのシークレット参照が存在する場合にのみ、この例外を許可する。ここではシークレットの具体的な値やバージョンは紐付けない。`verify` は外部パスワードゲートを確認できる。`up`、`promote`、`rollback` は、バージョンの変更や候補アドレスの作成の前に IAM を非公開に戻すことを必須とし、未検証の候補やパスワードのない旧バージョンが公開されるのを防ぐ。

The private submission notes are in the local `reviewer-instructions-ja.txt`, containing the deployment URL, site password, primary invite code, and two spare invite codes, used only for the contest's non-public 「動作確認の方法」. The primary account keeps real play progress and is not seeded with fictional endings; the spare accounts are independent. Credentials, account IDs, and the production URL do not go into the repo or public articles.

### Protected local development preview / ローカルの保護された開発プレビュー

First start the local PostgreSQL and finish `pnpm --filter @zoujin/web build`, then run `uv run python infra/deploy/local-preview.py` at the repo root. The script listens only on `127.0.0.1:8091` (internal narrator `8092`), serves `apps/web/dist` through the actual gateway, and enables both the site-wide password and the invite code; it does not use the Vite static entry.
